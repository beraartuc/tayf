### 2.3 `.github/workflows/ci.yml` — `bench-regression` job

**Mevcut workflow** (`.github/workflows/ci.yml`): `test` (ubuntu + macos matrix) + `audit` (ubuntu only). Yeni `bench-regression` job aynı dosyaya eklenir (cohesion).

**Yeni job yapısı:**

```yaml
  bench-regression:
    name: Bench regression (${{ matrix.os }})
    runs-on: ${{ matrix.os }}
    needs: test  # only run if test passes (don't bench broken code)
    strategy:
      fail-fast: false  # ubuntu + macos independent
      matrix:
        os: [ubuntu-latest, macos-latest]
    steps:
      - uses: actions/checkout@v5
      - uses: dtolnay/rust-toolchain@stable
      - uses: Swatinem/rust-cache@v2
      - name: Install jq
        run: |
          if ! command -v jq &> /dev/null; then
            sudo apt-get update && sudo apt-get install -y jq || brew install jq
          fi
      - name: Run benches
        run: cargo bench --bench throughput
      - name: Smoke test estimates.json shape
        run: |
          for bench in apply_rules/ipv4-heavy apply_rules/mixed-syslog apply_rules/captures-heavy passthrough/write_all; do
            file="target/criterion/${bench}/new/estimates.json"
            test -f "$file" || { echo "::error::missing $file"; exit 1; }
            jq -e '.mean.point_estimate' "$file" > /dev/null || { echo "::error::unexpected schema in $file"; exit 1; }
          done
      - name: Compare against baseline
        id: compare
        run: |
          baseline="benches/baselines/latest/${{ matrix.os }}.json"
          test -f "$baseline" || { echo "::warning::no baseline at $baseline; skipping comparison"; exit 0; }

          breach_found=0
          for bench in apply_rules/ipv4-heavy apply_rules/mixed-syslog apply_rules/captures-heavy passthrough/write_all; do
            new_mean=$(jq '.mean.point_estimate' "target/criterion/${bench}/new/estimates.json")
            base_mean=$(jq --arg b "$bench" '.benches[$b].mean_ns' "$baseline")

            # Threshold: apply_rules/* > 20% slower; passthrough/write_all > 30% slower (sub-µs jitter band)
            if [[ "$bench" == "passthrough/write_all" ]]; then
              threshold_pct=30
            else
              threshold_pct=20
            fi

            delta_pct=$(echo "scale=2; ($new_mean - $base_mean) / $base_mean * 100" | bc)
            # Use awk for comparison (bc has portability issues with conditional)
            breach=$(awk -v d="$delta_pct" -v t="$threshold_pct" 'BEGIN { print (d > t) ? 1 : 0 }')

            if [[ "$breach" == "1" ]]; then
              breach_found=1
              # Strict mode: fail; otherwise: warning
              if [[ "${{ contains(github.event.pull_request.labels.*.name, 'bench-ci-strict') }}" == "true" ]]; then
                echo "::error::${bench} regressed +${delta_pct}% vs baseline (threshold: ${threshold_pct}%)"
              else
                echo "::warning::${bench} regressed +${delta_pct}% vs baseline (threshold: ${threshold_pct}%) — strict mode opt-in via [bench-ci-strict] label"
              fi
            fi
          done

          # Exit with failure only if strict + breach
          if [[ "$breach_found" == "1" && "${{ contains(github.event.pull_request.labels.*.name, 'bench-ci-strict') }}" == "true" ]]; then
            exit 1
          fi
```

**Trigger:** mevcut workflow'la aynı (`push: branches: [main]` + `pull_request: branches: [main]`). Bench job push + PR'da çalışır; main push'larında baseline write için gözlem amaçlı, PR'larda regression detection için canonical.

**Why `needs: test`:** broken code'da bench çalıştırmak zaman israfı. Test geçmeden bench çalışma.

**Runtime:** ~3-5 dk per OS × 2 OS paralel × ~3-5 dk gate = ~4-5 dk total wall clock. Mevcut CI ~1-2 dk; bench ekleyince ~5-7 dk. Kabul edilebilir.

### 2.4 Threshold contract

- `apply_rules/*`: **>%20 slower → annotation** (warning). Strict mode: **error → workflow auto-fail**.
- `passthrough/write_all`: **>%30 slower → annotation** (warning, sub-µs jitter band'in üstünde). Strict mode: **error → workflow auto-fail**.

Threshold'lar spec §6.3 per-group floor'undan **farklı**:
- Spec §6.3 floor: human-judgment review-gate (apply_rules/* >%5, passthrough >%25). Release-blocking thresholds (apply_rules/* >%20, passthrough yok).
- CI threshold: **CI's coarse single-number annotation rule** — sub-µs jitter koruması için release-block thresholds'a hizalı (apply_rules/* %20, passthrough %30 = release-block + jitter overhead).

İki katman ayrı policy:
- **CI annotation:** operasyonel uyarı, false-positive-tolerant (sub-µs jitter).
- **Spec §6.3 floor:** ship-time human judgment, finer-grained.

Umbrella §4.2 explicit'ti: "İki katman ayrı politika" — bu spec normative yapar.

### 6.3 Threshold breach disposition (CI'da)

Workflow annotation aşağıdaki shape:
- Non-strict: `::warning::apply_rules/captures-heavy regressed +28.4% vs baseline (threshold: 20%) — strict mode opt-in via [bench-ci-strict] label`
- Strict: `::error::apply_rules/captures-heavy regressed +28.4% vs baseline (threshold: 20%)` + workflow `exit 1`

PR reviewer iki şekilde yanıt verir:
1. **Annotation seen, kabul edilebilir tradeoff:** PR merge; eğer regression intentional ise release ceremony'de baseline güncellenir.
2. **Annotation seen, tradeoff kabul edilemez:** PR fix until threshold under. Veya `[bench-ci-strict]` label ile gate hard fail.

`[bench-ci-strict]` label tipik use case: kod patch'i bench-critical bir path'a dokunuyorsa label'la, reviewer regression kaçırmasın.
