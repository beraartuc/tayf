# tayf v0.2.1 — Config Hot Reload Tasarım Dokümanı

**Tarih:** 2026-05-22
**Kapsam:** v0.2.1 — Çalışan tayf instance'ı içinde config dosyasını değişiklikten sonra yeniden yükleme
**Prereqs:** v0.2.0 (TOML config) + `chore(deps): bump signal-hook 0.3 → 0.4` (`7da37d0`) tamamlanmış.

Master tasarım (`tayf-tasarim.md` §6.15) hot reload'u "notify ile izle + atomik swap" şeklinde tanımlar; v1'de yok demiş ama biz onu v0.2.1'de kapatıyoruz. v0.2.0 spec'i (§1 hedef olmayanlar listesi) hot reload'u açıkça v0.2.1'e ertelemişti. Bu doc o hat üzerinde kanonik.

---

## 1. Vizyon

v0.2.0 ile birlikte kullanıcı `~/.config/tayf/config.toml` yazabilir, fakat değiştirdiğinde **tayf'i yeniden başlatmadan** etkisini göremez. v0.2.1 bunu kapatır: dosya değiştiğinde tayf 200ms içinde yeni rule set'i devreye alır; hataysa eski seti korur ve uyarır.

### Hedefler

- **Sıfır kullanıcı eylemi.** Editör save → tayf otomatik fark eder ve yeniden yükler.
- **Atomik swap.** Pipeline reload sırasında *kısmen yeni* rule görmez; her satır ya tamamen eski ya tamamen yeni set ile işlenir.
- **Çocuk shell'e dokunma.** Reload sadece in-process state'i değiştirir; spawn edilmiş shell, PTY, tty guard hiçbir şey görmez.
- **Hatada fail-safe.** Yeni config parse/compile başarısız olursa eski set in-effect kalır; kullanıcı bir sonraki edit'e kadar tehlikesiz devam eder.
- **SIGHUP manuel tetikleyici.** `pkill -HUP tayf` veya `kill -HUP <pid>` ile aynı reload akışı zorlanır (file watcher event ile özdeş code path).
- **Sessiz default + opt-in verbose.** Başarılı reload'lar `TAYF_LOG=info` veya üstü ile, başarısız reload'lar `TAYF_LOG=warn` (default) ile stderr'e yazılır.

### Hedef olmayan (v0.2.2+'a)

- `--no-hot-reload` flag — varsa hot reload her zaman aktif (file watcher zaten ucuz; opt-out v0.3+'a ertelendi).
- Watcher debug TUI / `tayf config status` komutu — v0.5+ (master §6.15 sonrası).
- Capture-group renklendirme — v0.5.
- Reload sırasında inline kullanıcı uyarısı (`tayf: config reloaded` overlay banner) — v0.3 ile (alt-screen aware logic gerektirir, master §6.10 OSC 133 markers ile birlikte).
- `--config <path>` ile gelen dosyanın watcher kapsamı — **bu spec'te aktif** (8. açık sorularda netleştir).

## 3. Yeni / Değişen Modüller

### 3.1 Yeni modül: `src/watch.rs`

```rust
//! File-system watcher abstraction around the `notify` crate.
//! Spawns a watcher thread that translates notify events into
//! [`ReloadRequest::FileChanged`] on a channel.

pub(crate) struct ConfigWatcher {
    handle: Option<JoinHandle<()>>,
    // `_watcher` lives as long as the thread; drop closes the kqueue/inotify fd.
    _watcher: notify::RecommendedWatcher,
}

pub(crate) enum ReloadRequest {
    FileChanged,
    SignalHup,
}

impl ConfigWatcher {
    /// Begin watching `path`. Events are debounced internally; one
    /// `ReloadRequest::FileChanged` per quiescent window is sent.
    ///
    /// # Errors
    /// Returns [`Error::Watch`] if the OS refuses the inotify/FSEvents
    /// registration (e.g. inotify watch limit reached) or the watcher
    /// thread fails to spawn.
    pub(crate) fn spawn(path: &Path, tx: Sender<ReloadRequest>) -> Result<Self>;
}

impl Drop for ConfigWatcher {
    fn drop(&mut self) {
        // `_watcher` Drop releases the OS resource. The internal channel
        // closes when the thread sees the Drop and exits. Join is
        // best-effort.
        if let Some(h) = self.handle.take() {
            let _ = h.join();
        }
    }
}
```

**Debounce stratejisi (manuel, no dep):**

```rust
// İç döngü pseudo-code
let mut last_event = Instant::now();
let mut pending = false;
loop {
    let timeout = if pending {
        DEBOUNCE_WINDOW.saturating_sub(last_event.elapsed())
    } else {
        Duration::from_secs(60) // long idle wait
    };

    match watcher_rx.recv_timeout(timeout) {
        Ok(_event) => {
            last_event = Instant::now();
            pending = true;
            // not deliver yet; wait for quiescence
        }
        Err(RecvTimeoutError::Timeout) if pending => {
            tx.send(ReloadRequest::FileChanged).ok(); // controller channel
            pending = false;
        }
        Err(RecvTimeoutError::Timeout) => continue,
        Err(RecvTimeoutError::Disconnected) => break,
    }
}
```

`DEBOUNCE_WINDOW` = 200ms sabit, test ile override'lanabilir (`#[cfg(test)]` parametre).

}

impl Drop for ReloadOrchestrator {
    fn drop(&mut self) {

        }
    }
}

### 3.3 `src/pipeline.rs` değişiklikleri

`Pipeline::rules` field tipi `Compiled` → `Arc<ArcSwap<Compiled>>`. Her `apply_rules` çağrısı:

```rust
pub(crate) fn apply_rules<W: Write>(
    line: &[u8],
    compiled_handle: &ArcSwap<Compiled>,
    out: &mut W,
) -> std::io::Result<()> {
    // Snapshot once per line; the rest of the function references the local Arc.
    let snapshot: Arc<Compiled> = compiled_handle.load_full();
    let compiled: &Compiled = &snapshot;
    // ...mevcut logic aynen...
}
```

`Pipeline::feed`/`tick`/`drain` aynı patterni izler. Hot path ekstra maliyet: `Arc::clone` (atomic increment, ≈3-5ns x86_64).

`Pipeline::new` artık `Arc<ArcSwap<Compiled>>` kabul eder. `__bench__::apply_rules` da güncellenir (bench surface).

### 3.4 `src/signals.rs` değişiklikleri

Mevcut `SIGINT`/`SIGTERM`/`SIGWINCH` setine `SIGHUP` eklenir. Signal thread:

```rust
let mut signals = Signals::new([SIGWINCH, SIGINT, SIGTERM, SIGHUP]).map_err(Error::Signal)?;
// ...
for sig in &mut signals {
    match sig {
        SIGWINCH => { /* mevcut */ }
        SIGINT | SIGTERM => { /* mevcut */ }
        SIGHUP => {
            // Best-effort: reload channel kapalıysa (orchestrator çıkmış)
            // sessiz drop. Geri kalanı orchestrator halleder.
            let _ = reload_tx.send(ReloadRequest::SignalHup);
        }
        _ => {}
    }
}
```

`spawn_handler` imzası `reload_tx: Option<Sender<ReloadRequest>>` ekler. `None` → SIGHUP ignore (config yokken bile crash etmesin diye; ama §2 karar 11 ile re-eval yapacağız, bu yüzden pratikte hep `Some` olacak).

### 3.5 `src/lib.rs` (Tayf::run facade) genişleme

```rust
let depth = terminfo::detect_depth();
let apply_colors = /* mevcut */;
let effective_depth = /* mevcut */;
let spec = shell::discover(/* mevcut */)?;

let loaded = config::load(args.config.as_deref())?;
let config_ref = loaded.as_ref().map(|(c, _)| c);
let config_path_buf: Option<PathBuf> = loaded.as_ref().map(|(_, p)| p.clone());
let config_path_str: Option<String> = config_path_buf.as_ref().map(|p| p.display().to_string());

let compiled = rules::Compiled::load(config_ref, config_path_str.as_deref(), effective_depth)?;
let rules_handle = Arc::new(ArcSwap::from_pointee(compiled));

let guard = tty_guard::TtyGuard::engage()?;
let session = pty::PtySession::spawn(&spec)?;
let (reader, writer, resizer, child) = session.into_parts()?;
let child_pid = child.pid();

let (reload_tx, reload_rx) = std::sync::mpsc::channel::<reload::ReloadRequest>();

let _signal_guard =
    signals::spawn_handler(resizer, child_pid, Some(reload_tx.clone()))?;

let _watcher = config_path_buf
    .as_deref()
    .map(|p| watch::ConfigWatcher::spawn(p, reload_tx.clone()))
    .transpose()?;
// reload_tx'ı orchestrator'a değil; orchestrator zaten reload_rx alır.
// reload_tx Drop'unda channel kapanır, orchestrator çıkar.

let _orchestrator = reload::ReloadOrchestrator::spawn(
    Arc::clone(&rules_handle),
    config_path_buf.clone(),
    effective_depth,
    reload_rx,
);

drop(reload_tx); // remaining clones live in signal thread + watcher thread

let exit_code =
    runtime::run(reader, writer, child, Arc::clone(&rules_handle), apply_colors)?;

drop(guard);
// _watcher, _orchestrator, _signal_guard hepsi Drop sırasıyla temizlenir.
```

Lifetime ipuçları:
- `reload_tx` kopyaları (signal + watcher) thread'lerden çıkışta drop olur → orchestrator `reload_rx.recv()` `None` döner → orchestrator çıkar → drop tarafından join'lenir.
- `_watcher` Drop'u inotify/FSEvents fd'sini kapatır, watcher thread'i join'ler.
- `_signal_guard` Drop'u signal-hook handle'ını kapatır, signal thread'i join'ler.

## 5. Güvenlik

CLAUDE.md §3 mandate'leri ile tutarlı.

| Tehdit | Çözüm |
|---|---|
| **Adversarial config swap (TOCTOU)** | `config::load_with` zaten canonicalize + `starts_with` whitelist + `is_file` doğrulaması yapıyor (`src/config.rs:check_default_path`). Reload yolu aynı entry-point'u kullanır; ek expose yok. |
| **inotify limit DoS** | Watcher init başarısız olursa `Error::Watch` döner, tayf normal başlar ama hot reload disabled (SIGHUP manual yine çalışır). Stderr'e tek `log::warn_msg!`. Crash YOK. |
| **Senin-bilmediğin reload bombası (sembol)** | 200ms debounce + `read_capped` (1 MB cap) + regex compile size limit (mevcut, v0.2.0'dan miras): adversarial bir process saniyede 100x edit yapsa bile reload thread CPU'sunun azı kadar harcanır. Hot path etkilenmez. |
| **Reload sırasında kısmi state** | `arc_swap::ArcSwap::store` wait-free atomik pointer write. Pipeline'da snapshot per-line; reload satır ortasında ÇALIŞMAZ. |
| **Reload thread paniği** | Yeni `Compiled::load` çağrısı `Result` döner — `unwrap` YOK. Panic kaynağı yalnızca thread runtime'ı; o durumda main `JoinHandle::join` Err alır, ignore eder; pipeline eski Arc ile devam eder. Tty guard etkilenmez. |
| **SIGHUP yanlış kullanımı** | SIGHUP terminal hang-up ile gelirse (controlling terminal kapanır), child shell zaten exit edecek; reload akışı bunu da tetikler ama orchestrator için zararsız no-op (file değişmedi). |
| **Watcher fd / handle leak** | `ConfigWatcher::Drop` → `notify::Watcher` Drop → OS resource release. `JoinHandle` Drop'ta join. RAII pattern v0.2.0'dakine eş. |
| **Cross-user race** | Watcher kullanıcı home dir altında. Diğer kullanıcı yazma yetkisi yoksa erişemez. Multi-user shared home senaryosu CLAUDE.md §3 threat modeli dışı. |

**Yeni SECURITY review gate:** `security-review` skill'i ile diff'in son audit'i, milestone tamamlanmadan önce.

## 6. Test Stratejisi

### 6.1 Unit (TDD)

**`src/watch.rs`:**
- Debounce: 50ms aralıklarla 5 event push et → 200ms sonra TEK `ReloadRequest::FileChanged` yayılmalı (test parametresi `DEBOUNCE_WINDOW = 50ms` ile hızlandırılır).
- Quiescent → tek event → bir reload, sonra başka event → ikinci reload.
- Channel close → thread exit.

**`src/reload.rs`:**
- `reload_once`: geçerli config file → `ArcSwap` yeni `Compiled`'ı tutar.
- `reload_once`: parse error → `ArcSwap` ESKİ pointer'ı korur, return `Err`.
- `reload_once`: regex compile error → aynı: eski pointer korunur.
- Orchestrator: `ReloadRequest::FileChanged` → `reload_once` çağrılır; `Err` ise warn, eski Arc.

**`src/signals.rs`:**
- SIGHUP handle: signal thread iterator'una SIGHUP push'la (test helper, signal-hook'un manuel iterator helper'ı) → `Sender` üzerinden `ReloadRequest::SignalHup` çıktığını doğrula.
- `reload_tx = None` → SIGHUP no-op (no panic).

### 6.2 Integration (smoke, gerçek I/O)

**`tests/integration_hot_reload.rs` (yeni):**

1. **Reload changes pattern color.** Tempdir + `config.toml` (initial yellow) → tayf spawn et + echo komutu → output yellow doğrula → config'i `red`'e yaz → 300ms bekle → echo komutu → output red doğrula.
2. **Reload failure preserves old set.** Initial valid → tayf spawn → bozuk TOML yaz → 300ms bekle → echo komutu → output ESKİ rule'ları kullanmalı + stderr'de warning mesaj.
3. **SIGHUP forces reload.** Initial valid → tayf spawn → config edit → SIGHUP gönder → echo komutu → yeni rule devrede.
4. **Config absent + later created.** Tayf without config → SIGHUP → config dosyası mevcut → load oldu doğrula. (Veya: watcher path konfigüre edildi mi yoksa bu durumda dışarda mı? §8 karar 4'e bağlı.)

PTY tabanlı integration test mevcut harness'a (`tests/common/mod.rs`) genişleme yapar.

### 6.3 SIGWINCH delivery integration test (KAZANÇ — code reviewer önerisi, ayrı eklenmeli)

Code review (signal-hook 0.4 bump): "no integration test exercises actual signal delivery" notuyla SIGWINCH için bir test eklenmesi tavsiyesi var. v0.2.1 başlangıcında, SIGHUP eklemeden ÖNCE SIGWINCH test'ini eklemek doğru disiplin:

- `openpty` ile master + slave aç
- Tayf spawn et (slave'i tty olarak)
- Master'a `TIOCSWINSZ` ioctl ile yeni boyut yaz
- Slave'in `winsize` ile güncellendiğini assert et

Bu test düzeneği SIGHUP testleri için de altyapı sağlar (aynı PTY harness'i).

### 6.4 Manual (release-öncesi)

- Gerçek terminal, gerçek `~/.config/tayf/config.toml`, kullanıcı vim ile edit eder; çıkışta hot reload görsel onayla.
- `htop`'tan inotify watch sayısı tek (tayf için).
- `strace -e inotify_*` ile inotify sistem çağrılarının makul olduğu (her saniye yeniden register etmediği) doğrulanır.
- Process tree: `pstree`'de tayf altında shell ve onun çocukları kalır; reload sırasında yeniden spawn yok.

3. **`--config <path>` ile başlatıldığında:** ✅ **Watcher AKTİF;** explicit path da hot reload edilir. UX tutarlılığı.
4. **Config dosyası silinirse:** ✅ **Eski rule set'i koru, warn yaz, watcher path'i izlemeye devam.** Editör save dance'inde güvenli; tamamen silinmede de eski set in-effect kalır.
5. **Başarılı reload log seviyesi:** ✅ **`info_msg!` sessiz default** (TAYF_LOG=info ile aç). Başarısız reload `warn_msg!` ile default'ta görünür. Spec §2 karar 8 ile tutarlı.
6. **Debounce penceresi:** ✅ **200ms sabit.** Env var override (`TAYF_RELOAD_DEBOUNCE_MS`) YAGNI — v0.2.1'de eklemeyiz.
7. **notify feature seti:** ✅ **`default-features = false, features = ["macos_fsevent"]`.** Linux inotify her zaman var. PollWatcher fallback ihtiyaç olunca eklenir.
8. **Ek dependency:** ✅ **Yok.** Sadece `arc-swap 1.9` + `notify 8.2`. `tempfile` zaten dev-dep, integration testler ondan yararlanır.
