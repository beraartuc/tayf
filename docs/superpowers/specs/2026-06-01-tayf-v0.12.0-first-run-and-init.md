# tayf v0.12.0 — First-run setup & `tayf init`

**Status:** approved design (2026-06-01). Built on [[project-v0-11-0-shipped]].

**Goal:** Make a freshly-installed tayf usable in one step. After installing the
binary, the user runs **`tayf init`** and tayf is set up to run automatically in
new terminals with our default colors. Customization happens later through the
`tayf config` TUI — which must no longer dead-end on its first save.

---

## 1. Context & motivation

v0.10.0/v0.11.0 made tayf installable on every channel (crates.io, Homebrew,
`curl | sh`, signed binaries). But after the binary lands there is no smooth
"now make it work" step, and two concrete gaps block first-run use:

1. **The TUI dead-ends on a fresh machine.** With no config file present,
   `tayf config` opens an *empty* snapshot whose `source_path` is `None`
   ([src/config_tui/mod.rs](../../../src/config_tui/mod.rs) `run`, the
   `Ok(None)` arm → `ConfigSnapshot::empty()`). Both save paths then fail:
   - `Ctrl+S` → `"no source_path; first-run save requires init"`
     ([src/config_tui/save.rs:178](../../../src/config_tui/save.rs#L178)).
   - `Shift+D` (init-from-dump) → `"Cannot init: no config path bound."`
     ([src/config_tui/events.rs:846](../../../src/config_tui/events.rs#L846)).

   There is no path bound, so the TUI cannot create the very file it needs.

2. **No one-step onboarding.** Running tayf automatically needs the rc guard
   from the README (`[[ $- == *i* && -t 1 && -z $TAYF_SESSION ]] && exec tayf`),
   which the user must currently hand-copy into `~/.zshrc`/`~/.bashrc`. There is
   no command that does this for them.

**The intended onboarding flow** is: `install → tayf init → done`. tayf's
built-in rules are *already* active without any config file, so what actually
makes it "work with our defaults" is the **shell hook** (auto-run in new
shells). The default config file `tayf init` writes is a *starting point for
customization* and the thing that fixes gap (1).

This cycle is **sub-project A of a three-part effort** (decided 2026-06-01):

- **A — First-run & init (this spec):** the blocker fix + `tayf init`.
- **B — TUI UX & polish** (separate spec): color-picker overhaul, live-preview
  fidelity, `n` discoverability, in-TUI theming.
- **C — Profile rework** (separate spec): user-centric composable profiles.

B and C are **out of scope here** and get their own spec → plan → implementation
cycles. See §9.

## 2. Scope

**In scope**

- **CLI:** a new top-level `tayf init` subcommand (`Cmd::Init(InitArgs)`).
- **Config creation:** write the built-in default config to the resolved target
  path when absent (reusing the existing `default_config_toml()` generator).
- **Shell hook:** install the always-on rc guard for **bash and zsh**
  automatically (timestamped backup, idempotent marker block, atomic rewrite,
  `--uninstall`). For **fish and other shells**, print the correct snippet for
  manual paste (no auto-edit) — per the 2026-06-01 shell-coverage decision.
- **TUI first-run fix:** bind the default config path on an empty snapshot
  (`ConfigSnapshot::empty_at`) so `Ctrl+S` / `Shift+D` create the file.
- **Small refactor:** relocate `default_config_toml()` to a neutral location so
  the non-TUI `init` module does not depend on `config_tui::save` internals.
- Docs: README onboarding section, `--help`, CHANGELOG, module doc-comments.

**Out of scope**

- All sub-project B items (color picker, live-preview fidelity, `n` hint, TUI
  visual/color theming) and sub-project C (profile rework).
- Auto-editing fish/other-shell rc files (those get `--print` only).
- Auto-`exec` of the *current* shell after init (decision: print a hint only).
- Creating a config at an explicit `--config <missing-path>` *from inside the
  TUI* (use `tayf init --config <path>` instead; the TUI fix covers the default
  no-config case only).
- Deleting the config file; Windows shells (PowerShell/cmd).

## 3. Module layout

New module `src/init/`:

- `src/init/mod.rs` — `tayf init` orchestration: argument handling, config-file
  creation, dispatch to the shell-hook step, and the final activation hint.
  Owns the public entry `pub fn run(args: InitArgs) -> ExitCode` called from
  `main.rs`.
- `src/init/shell_hook.rs` — shell detection, rc-path resolution, marker-block
  composition (bash/zsh + fish snippet), idempotency check, backup, atomic
  append, and `--uninstall` removal. Env/paths are **injected** (mirroring
  `config::load_with`) so the logic is unit-testable without touching the real
  `$HOME`/`$SHELL`.

Both files carry a module-level doc-comment (purpose, public API, invariants)
per CLAUDE.md §2. If `shell_hook.rs` approaches ~400 lines, split detection from
the file-mutation half.

**Refactor — single source of default config:** move `default_config_toml()`
from [src/config_tui/save.rs:270](../../../src/config_tui/save.rs#L270) to
`src/config.rs` as `pub(crate) fn default_config_toml() -> String`. Update the
two existing callers (`config_tui::save`, `apply_init_from_dump`) to call the
new location. Behavior is byte-identical — pin with a golden test asserting the
relocated output equals the pre-refactor string.

## 4. Part 1 — TUI first-run fix (the blocker)

**Snapshot constructor.** Add `ConfigSnapshot::empty_at(path: PathBuf)` next to
the existing `empty()` ([src/config_tui/snapshot.rs:93](../../../src/config_tui/snapshot.rs#L93)):
same empty `doc`/`parsed`/`raw_bytes`/zero hash as `empty()`, but
`source_path = Some(path)`.

**Bind the path on launch.** In [src/config_tui/mod.rs](../../../src/config_tui/mod.rs)
`run`, change the `Ok(None)` arm: compute the target path with
`config::config_base(|| env XDG_CONFIG_HOME, || env HOME).map(|b| b.join("config.toml"))`
and use `empty_at(path)` when a base resolves. If `config_base` returns `None`
(neither `$XDG_CONFIG_HOME` nor `$HOME` set — a degenerate environment), fall
back to `empty()` and keep the genuine last-resort guard (see below).

**Save creates the file.** With `source_path` now bound, `Ctrl+S` proceeds.
Parent-directory creation is already handled: `write_atomic_to`
([save.rs:402](../../../src/config_tui/save.rs#L402)) and the primary save
persist strategy ([save.rs:367](../../../src/config_tui/save.rs#L367)) both call
`create_dir_all(parent)`. **Verification task:** confirm the `Ctrl+S` save path
reaches a `create_dir_all` before first write; add one if a gap exists. First
save writes the user's staged edits over the (empty) base, producing a valid
`config.toml`.

**Last-resort message reword.** The string at
[save.rs:181](../../../src/config_tui/save.rs#L181) is now only reachable when
`config_base` yielded nothing. Reword to an accurate, actionable sentence, e.g.
`"cannot determine a config location: set $HOME or $XDG_CONFIG_HOME, or run
'tayf init --config <path>'"`. Same for the `Shift+D` toast at events.rs:846.

**Explicit `--config <missing>` is unchanged** (still errors in
`config::resolve_path`); documented as use-`tayf init` territory.

## 5. Part 2 — `tayf init` command

### 5.1 CLI surface (`src/cli.rs`)

Add `Init(InitArgs)` to `Cmd`. `InitArgs`:

| Flag | Type | Meaning |
|------|------|---------|
| `--shell <SHELL>` | `Option<String>` | Override detected shell (`zsh`/`bash`/`fish`). Default: basename of `$SHELL`. Unknown value → exit 64. |
| `--no-shell-hook` | `bool` | Create the config only; never touch any rc file. |
| `--print` | `bool` | Write nothing; print the snippet for the (detected/`--shell`) shell to stdout, then exit 0. |
| `--uninstall` | `bool` | Remove tayf's marked block from the rc file; leave the config untouched. |
| `--force` | `bool` | Overwrite an existing config with defaults (default: keep, report "already exists"). |
| `--config <PATH>` | `Option<PathBuf>` | Target config path (default: resolved `config_base()/config.toml`). |

`--print` and `--uninstall` are terminal modes (mutually exclusive with each
other; `--print` implies no writes). `main.rs` routes `Cmd::Init` to
`init::run` and propagates its `ExitCode`.

### 5.2 Default behavior (no flags)

`tayf init` is an **explicit, user-typed command**, so its default action is to
set tayf up — no interactive prompt (decision 2026-06-01). It:

1. **Config step.** If the target config exists and `--force` is not set, report
   `config already exists at <path>` and continue. Otherwise write
   `default_config_toml()` atomically (creating parent dirs) and report
   `created <path>`.
2. **Shell-hook step** (skipped under `--no-shell-hook`/`--print`):
   - Detect the shell → `Zsh | Bash | Fish | Other`.
   - **Zsh/Bash (auto):** resolve the rc path (zsh: `$ZDOTDIR/.zshrc` else
     `~/.zshrc`; bash: `~/.bashrc`, with a printed note that macOS login
     Terminals read `~/.bash_profile`). If the marker block is already present,
     report `already installed` and stop (idempotent; `--force` rewrites the
     block in place). Otherwise: back up the rc to `<rc>.tayf-backup-<unix_ts>`
     (only if it exists), then atomically append the marker block. Report what
     was added, where, and the backup path.
   - **Fish/Other (print only):** do **not** edit any file. Print the correct
     snippet (fish syntax for `Fish`, the POSIX guard for `Other`) plus a
     one-line "add this to <file>" instruction.
   - **Non-interactive guard:** because the default does not prompt, behavior is
     identical with or without a TTY; scripts can rely on it. (`--no-shell-hook`
     remains the way to suppress rc edits in automation.)
3. **Activation hint.** Always finish (on success, non-`--print`) with:
   `tayf will start in new terminals. To start now: exec tayf`. The current
   shell is **never** auto-replaced (decision 2026-06-01).

### 5.3 Marker block

bash/zsh (`~/.zshrc` / `~/.bashrc`):

```sh
# >>> tayf init >>>
# Managed by `tayf init`. Remove with `tayf init --uninstall`.
[[ $- == *i* && -t 1 && -z $TAYF_SESSION ]] && exec tayf
# <<< tayf init <<<
```

fish (printed for manual paste into `~/.config/fish/config.fish`):

```fish
# >>> tayf init >>>
status is-interactive; and not set -q TAYF_SESSION; and test -t 1; and exec tayf
# <<< tayf init <<<
```

The markers are the idempotency and `--uninstall` anchor: detection and removal
operate on the exact `# >>> tayf init >>>` / `# <<< tayf init <<<` pair.

## 6. Error handling & exit codes

`init::run` returns an `ExitCode`, consistent with the existing config-TUI
convention:

- `0` — success (including "already exists"/"already installed" no-ops).
- `64` (`EX_USAGE`) — invalid `--shell` value, or `--print` + `--uninstall`
  together.
- `70` (`EX_SOFTWARE`) — I/O failure (config write, backup copy, rc rewrite).

Every error is a full, actionable sentence naming what failed, why, and the next
step (CLAUDE.md §4). No `unwrap`/`expect` outside tests and proven-unreachable
paths.

## 7. Security (CLAUDE.md §3)

- **Atomic writes** for both the config file and the rc file (temp-in-same-dir
  + `persist`/rename, reusing the `TmpFileGuard` pattern). A failed init never
  leaves a truncated rc that could break the user's login shell.
- **Backup before edit:** the rc is copied to a timestamped sibling before any
  modification; the report prints its path.
- **Explicit consent by command:** dotfile editing happens only as the
  documented action of an explicitly-invoked `tayf init`; `--print` previews and
  `--no-shell-hook` opts out. (The earlier objection was to *package-manager*
  auto-editing without consent — not applicable here.)
- **No shell-out, no eval.** The guard line is a static string. The only
  user-derived value is the shell name, validated against the
  `{zsh,bash,fish}` allowlist before it selects a fixed snippet.
- **Idempotent markers** prevent duplicate or runaway appends across reruns.
- rc paths are constructed under `$HOME`/`$ZDOTDIR`; no traversal outside.

## 8. Testing (TDD)

**Unit (`src/init/`, injected env/paths):**
- shell detection: `$SHELL` basename, `--shell` override, unknown → `Other`/64.
- rc-path resolution per shell (zsh `$ZDOTDIR` vs `~/.zshrc`; bash; fish).
- marker-block composition: exact guard strings for bash/zsh and fish, marker
  wrapping.
- idempotency: a second run over an rc that already contains the markers makes
  no change and reports `already installed`.
- `--uninstall` removes exactly the marked block and leaves surrounding lines
  byte-identical; absent block → friendly no-op.
- config target-path resolution (XDG vs HOME).
- relocated `default_config_toml()` golden (byte-equal to pre-refactor).

**Integration (`tests/integration_init.rs`, new):**
- `tayf init --no-shell-hook` in a temp `$HOME` creates the config at the
  expected path; rerun without `--force` is a reported no-op; `--force`
  overwrites.
- `tayf init --print --shell fish` prints the fish snippet and writes nothing.
- `tayf init --shell zsh` against a seeded fake `~/.zshrc` appends the block and
  creates a backup; rerun is a no-op; `tayf init --uninstall` restores the
  original content.

**TUI first-run (`tests/` config-TUI suite):**
- from `empty_at(path)`, a save writes a valid file (parent dirs created, atomic
  rename), and the `"requires init"` error no longer fires for the default
  no-config case.

## 9. Decomposition & follow-ups

Locked 2026-06-01 (A→B→C, each its own spec):

- **B — TUI UX & polish:** color-picker overhaul (top-of-panel direct hex entry;
  drop the 256-color swatch grid in favor of code entry; bold/italic/underline
  beneath it; clearer selected/current state); live-preview fidelity (preview
  must reflect the real default rules — e.g. `ipv4` shows azure, not orange on a
  fresh install); surface the `n` = "new pattern" keybinding in the UI; TUI
  visual theming for readability (the chrome is currently monochrome).
- **C — Profile rework:** replace the fixed `aws`/`gcp`/… embedded profiles with
  **user-centric composable profiles** — an editable default profile plus
  user-created profiles that compose built-in rules, user rules, and opt-in
  rule packs (aws/docker/…), addable/removable at will. Architectural; touches
  `profiles.rs`, the embedded catalog model, the TUI Profiles tab, and config
  schema.

## 10. Decisions log

- **A→B→C decomposition**, init first (it unblocks TUI testing); profile rework
  last (highest risk). — 2026-06-01
- **`tayf init` does both** config creation and shell-hook install; the TUI also
  self-heals first-run save. — 2026-06-01
- **Command surface:** top-level `tayf init` (new `Cmd::Init`). — 2026-06-01
- **Shell coverage:** bash + zsh auto-edited; fish/other get `--print` snippets
  only. — 2026-06-01
- **No prompt by default:** the explicit command is the consent; safety via
  backup + idempotency + `--uninstall` + `--print`. — 2026-06-01
- **Activation:** print a `exec tayf` hint; never auto-replace the current
  shell. — 2026-06-01
