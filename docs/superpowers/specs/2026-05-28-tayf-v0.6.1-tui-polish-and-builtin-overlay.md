### 3.2 Builtin overlay route — synth-UserRule (dedupe-then-mutate-or-push)

#### Problem (v0.6 limitation)

`compile_pending` (`src/config_tui/compile_pending.rs:107-118`) sadece `RuleId::UserConfig(name)` entry'leri için overlay uygular. `RuleId::Builtin`, `RuleId::Embedded`, `RuleId::DiskProfile` silently skipped. ColorPicker bir builtin rule'a bind edilince edits.rules'a yazılır, toast "color bound" der, ama compile_pending overlay'i no-op olduğu için preview değişmez (events.rs:473-481 inline limitation comment).

#### Çözüm (rev2)

`compile_pending` içinde overlay loop, dört variant için aynı stratejiyi uygular:

1. **`RuleId::UserConfig(name)`** → mevcut path: `user_rules` içinde name'le bul, in-place edit.
2. **`RuleId::Builtin(name)` | `RuleId::Embedded { rule: name, .. }` | `RuleId::DiskProfile { rule: name, .. }`** → eğer `user_rules` zaten same name ile bir entry içeriyorsa **in-place mutate**; aksi halde **synth UserRule push**.

`compile_from_config` (`src/rules.rs`) → `apply_user_rules_with_source` (config.rs:539-560 yöntem, name-match-then-in-place-mutate) → `seen: HashSet` (config.rs:470-504 duplicate guard, **same-vec duplicate** rejection).

#### Neden dedupe-then-mutate-or-push? (Rust rev1 B1 fix)

rev1'in "push synth" sketch'i, snapshot zaten user-config'te aynı isimli `[[rules]]` entry'sini içerdiğinde apply_user_rules_with_source `seen` HashSet'i SECOND occurrence için `Error::Config { message: "rule '<n>': defined more than once..." }` döner → preview red banner. rev2 fix: compile_pending overlay loop, `user_rules` vec'inde aynı isimli entry **arayıp bulursa in-place mutate** eder; bulamazsa append. Bu, `apply_user_rules_with_source`'a giden vec'te isim duplicate'i bırakmaz. Sonuç: kanonik disk-config "user wrote `[[rules]]` once + ColorPicker edited it" semantic'i ile bire bir aynı.

#### Edge case'ler

- **Snapshot zaten user-config override içerir (en kritik):** ipv4 için disk'te `[[rules]] name = "ipv4" style = {...}` var; TUI'de ColorPicker yeni renk bind eder. dedupe-then-mutate sayesinde aynı entry'nin style'ı update edilir, ikinci push olmaz. Test #7 explicit.
- **Embedded / DiskProfile rule isimleri:** profile.append_rules step (rules.rs:762-781) bunları `rules` vec'ine USER-CONFIG ÖNCESİ ekler. Sonra apply_user_rules_with_source (line 794-799) name-match'le bulup mutate eder. Symmetric for our synth UserRule too.
- **Pattern overlay None semantics:** `apply_user_rules_with_source` (config.rs:539-546) `if let Some(p) = &ur.pattern { existing.pattern.clone_from(p); ... }` — `pattern: None` synth UserRule = "no pattern override". ✓ §4.1 sketch bunu sağlar.
- **Style field None semantics (Rust rev1 I2):** `style: Some(UserStyle::default())` synth = all-zero attributes; `apply_user_rules_with_source` `to_style` çağrısı "no visible effect" rejection ile `Error::Config` döner. Fix: `style: edits.styles.get(&Default).map(new_style_to_user_style)` — sadece Default style edited ise Some, aksi halde None. ✓ §4.1 sketch explicit.
- **`edits.deleted` non-UserConfig variants:** v0.6.1 sadece UserConfig delete (item 10 + Group C scope); diğer variantlar **DEFER v0.7** (memory `feedback_consume_prior_review` discipline — explicit).

#### events.rs:473-481 limitation comment

Group A son adımında silinir. Yerine `apply_pending_and_recompile` doc-comment'ine kısa paragraf: "Builtin / Embedded / DiskProfile rules apply via synth-UserRule overlay in `compile_pending` (dedupe-then-mutate-or-push); see §3.2 of v0.6.1 design."

### 3.2.5 Trace: UserRule named after a Builtin → in-place mutate (TUI rev1 B5)

Reviewer TUI B5 spec'in `compile_from_config` merge semantic'inin **untraced** olduğunu işaretledi. Burada explicit trace:

`compile_from_config` (`src/rules.rs:680+`) içerisinde:

1. `let mut rules = builtin_rules();` — 12 BuiltinRule entry'si.
2. Layer 3: theme apply (varsa). `apply_user_rules_with_source(path, &mut rules, &theme_cfg.rules, RuleSource::Theme)`.
3. Step 4: profile.append_rules — name-collision yok (Phase 1 validate edildi).
4. Step 5: user config apply. `apply_user_rules_with_source(path, &mut rules, &c.rules, RuleSource::UserConfig)`.

`apply_user_rules_with_source` (`src/config.rs:524+`):

```text
for ur in user_rules:
    if !seen.insert(ur.name.as_str()):
        return Error::Config { ... }  // duplicate within same slice rejection
    match rules.iter_mut().find(|r| r.name == ur.name):
        Some(existing):
            if let Some(p) = &ur.pattern:
                existing.pattern = p.clone()
                existing.source = source
            if let Some(s) = &ur.style:
                existing.style = s.to_style(...)?
                existing.source = source
            if let Some(sg) = &ur.styles:
                existing.styles_override = Some(sg.clone())  // REPLACE
                existing.source = source
        None:
            rules.push(BuiltinRule { name, pattern, style, source, ... })  // append
```

**Sonuç:** UserRule whose name matches an existing entry (built-in OR theme-modified OR profile-appended) → IN-PLACE MUTATE; no duplicate. UserRule with new name → APPEND. compile_pending'in dedupe-then-mutate-or-push döngüsü kullanıcı tarafında **aynı semantic'i** taklit ederek `seen` guard'ı tetiklemez.

```rust
//! Reusable name-list filter for Patterns / Themes / Profiles tabs.
//!
//! Filters a name iterator by case-insensitive substring match.
//! Returns the matching names in iter order.

pub(crate) fn filter_names_lowercase<'a>(
    names: impl Iterator<Item = &'a str>,
    filter: &str,
) -> Vec<&'a str> {
    if filter.is_empty() {
        return names.collect();
    }
    let needle = filter.to_lowercase();
    names.filter(|n| n.to_lowercase().contains(&needle)).collect()
}
```
