# tayf v0.8.1 — Profile-first I/O & pipeline optimizasyonu

**Tür:** Performance cycle, **iki fazlı tek cycle** (measurement-first). Faz 1 = attribution (src/ sıfır); Faz 2 = veri-güdümlü optimizasyon (Faz 1 checkpoint'inde scope'lanır).
**Base:** `v0.8.0` @ `9b4049a` (CI green run 26677383785, 2026-05-30).
**Kapsam:** v0.8.0 e2e harness'ı tayf'in `cat`'e göre ~6–15x yavaş olduğunu, darboğazın sadece scanner değil I/O loop olduğunu (prose bile ~8x) gösterdi. Bu cycle önce maliyeti stage'lere ayırır, sonra en yüksek-ROI darboğazları optimize eder.

**Hedef:** v0.8.0 `e2e_overhead` baseline'a göre **≥Nx throughput iyileştirmesi** (N, Faz 1 attribution'ından sonra sabitlenir). Spec §7'nin literal `<%20-vs-cat`'ı bir byte-dönüştüren wrapper için ulaşılamaz olabilir; onu hedef yapmıyoruz — relative ilerleme + güncellenmiş `BASELINE.md` disposition.

> **DOKUNULMAZ duruşu — bu cycle için DEĞİŞTİ (kullanıcı onaylı):** v0.8.1 `src/runtime.rs` / `src/pty.rs` / `src/pipeline.rs`'e **dokunabilir**, ANCAK bu modüllere dokunan her değişiklik faz sonu **`security-review` gate**'inden geçer (CLAUDE.md §3 — termios / raw-mode / signal-forwarding / sinyal-hedefleme bu modüllerde yaşar). Faz 1 src/'ye hiç dokunmaz; DOKUNULMAZ ihlali yalnızca Faz 2'de, gate ile.

## 2. Faz 1 — Attribution (src/ sıfır değişiklik)

Amaç: toplam pipeline overhead'ini stage'lere ayır. İki bağımsız ölçüm, sonuçlar `BASELINE.md`'ye attribution tablosu olarak.

### 2.1 Bedava bypass-diferansiyeli (e2e harness genişletmesi)

`benches/e2e_overhead.rs`'e **üçüncü bir ölçüm sütunu** eklenir: `tayf --bypass --shell /bin/sh`.

- `--bypass` → `apply_colors=false` ([lib.rs:166](src/lib.rs#L166)) → `runtime::run` pipeline'ı hiç beslemez, ham `stdout.write_all` ([runtime.rs:214](src/runtime.rs#L214)). Yani tam I/O loop (çift-PTY hop + read + blocking write) AMA sıfır pipeline işlemesi.
- Üç sayı, her shape için: `cat` (denominator) / `tayf --bypass` / `tayf` (full).
  - `bypass_overhead% = (bypass − cat)/cat` → **saf I/O-loop overhead** (PTY-hop + tty discipline + write batching eksikliği).
  - `pipeline_cost% = (full − bypass)/bypass` → **toplam pipeline maliyeti** (AnsiSm + line_buffer + apply_rules + per-line write).
- Sıfır enstrümantasyon, sıfır src/ değişiklik. Mevcut `timed_run` deseni; sadece bir env/args varyantı daha.

### 2.2 In-process `Pipeline::feed` micro-bench

Yeni `benches/pipeline_feed.rs` (`harness = false` veya criterion — §2.4'te karar). `Pipeline::feed(big_chunk, &mut sink)`'i izole ölçer — PTY yok, stdout yok (`Vec`/`io::sink()` hedefi). Stage ayrıştırması için alt-bench'ler:

- **passthrough-ansi:** önceden-SGR'li chunk → çoğunlukla `AnsiSm::step` + verbatim path; line_buffer/apply_rules minimal. AnsiSm tabanını izole eder.
- **prose (no-match):** düz metin → AnsiSm + line_buffer + RegexSet-miss apply_rules. **H1 (line_buffer O(L²)+saat) burada görünür.**
- **log (high-match):** IP/timestamp/level → tam apply_rules + SGR emit.

Aynı `benches/inputs/e2e_*.txt` corpus'ları yeniden kullanılır (DRY).

### 2.3 Gerekli src/ test-surface eki (Faz 1, davranış-nötr)

`Pipeline::feed` şu an `pub(crate)`. Micro-bench için `#[doc(hidden)] pub` `__bench__` modülü üzerinden expose edilir (mevcut `BenchScratch`/`apply_rules` deseni gibi — [lib.rs:1061](src/lib.rs#L1061)). **Bu, `pipeline.rs`'in davranışına dokunmaz** — yalnızca `lib.rs`'te bir re-export + muhtemelen `pipeline.rs`'te `pub(crate) fn new`/`feed`'in zaten var olan görünürlüğü. Eğer bu `src/pipeline.rs`'e (DOKUNULMAZ) bir `pub(crate)`→`pub` veya yeni bir küçük ctor eklemek gerektiriyorsa, **o ek de Faz 1 sonunda security-review değil, ama final cross-cutting review'da "davranış-nötr test shim" olarak işaretlenir** (mevcut `__bench__` precedent'i ile aynı sınıf). Tercih: expose'u `lib.rs::__bench__` içinde tut, `pipeline.rs` diff'ini minimumda tut.

### 2.4 Faz 1 açık kararları (implementasyonda netleşir)
- Micro-bench harness'ı criterion mı (stage'ler in-process, criterion'un asıl alanı — `throughput.rs` precedent'i) yoksa `harness=false` mı. **Eğilim: criterion** (in-process, PTY yok → criterion'un iterasyon modeli uygun; e2e'den farklı olarak burada subprocess yok).
- Sink tipi (`io::sink()` vs `Vec` vs `Cursor`) — write maliyetini ölçümden çıkarmak için `io::sink()` eğilimli.

### 2.5 Faz 1 çıktısı
`BASELINE.md`'ye `## v0.8.1 — Phase 1 attribution` bölümü: bypass-diferansiyel tablosu + micro-bench stage tablosu + "fundable kazançlar" özeti (hangi stage toplam'ın ne %'si, DOKUNULMAZ-içi/dışı işareti).

## 4. Faz 2 — Optimizasyon (veri-güdümlü; checkpoint sonrası)

Faz 1'in doğrulayacağı hipotezler (kod okumasından; **veri kazanır**, hiçbiri profiling'den önce uygulanmaz):

| # | Hipotez | Konum | DOKUNULMAZ? | Risk | Önerilen fix yönü |
|---|---|---|---|---|---|
| **H1** | `feed_byte_with_overflow` byte başına: `Instant::now()` + `extend_from_slice(&[byte])` + `memchr_newline` tüm buffer'ı tarar → satır başına O(L²) + ~16M saat okuması/16MB | `line_buffer.rs` | **Hayır** | Düşük | chunk-level feed + tek saat okuması/chunk + `memchr` crate veya pozisyon-takibi |
| **H2** | satır başına çift `Arc::load_full()` (`apply_or_passthrough` + `apply_rules`) | `pipeline.rs` | **Evet** | Orta | tek snapshot/satır, alt çağrıya geçir |
| **H3** | chunk başına `stdout.flush()`, `BufWriter` yok | `runtime.rs` | **Evet** | Orta | `BufWriter` + tick/drain'de açık flush (interaktiflik korunur) |
| **H4** | per-byte `AnsiSm::step` + tek-byte line_buffer feed | `pipeline.rs` | **Evet** | Yüksek | chunk-level tarama (Data run'larını toplu işle) |

Her Faz 2 optimizasyonu:
- **TDD davranış-koruma testi ZORUNLU** — özellikle `pipeline.rs`/`line_buffer.rs`: UTF-8 sınır güvenliği, SGR fidelity, satır-sınırı semantiği, overflow davranışı **byte-identical** kalmalı. Mevcut 782 lib + integration suite regresyon ağı.
- Kendi atomik commit'i + e2e baseline'a karşı before/after ölçüm (`BASELINE.md`'ye delta).
- Sıra: önce DOKUNULMAZ-dışı düşük-risk (H1) → ölç → sonra DOKUNULMAZ-içi (veri sırasına göre).

## 5. Güvenlik (CLAUDE.md §3) — Faz 2 DOKUNULMAZ dokunuşları

Faz 2 `runtime.rs`/`pty.rs`/`pipeline.rs`'e dokunursa, faz sonunda **`security-review` skill** çalıştırılır. Özel dikkat:
- **`BufWriter` (H3):** stdout buffering eklemek, exit/panik/sinyal yollarında **flush garantisini** bozmamalı — `runtime::run` shutdown sırası + `drain` + tick `flush()` korunmalı; aksi halde son satır/prompt kaybolur. Drop-flush davranışı test edilir.
- **chunk-level pipeline (H4):** byte-for-byte fidelity + TUI passthrough mode + OSC payload drain sırası bozulmamalı (mevcut `feed` invariant'ları).
- **termios/raw-mode/signal-forwarding'e dokunulmaz** (bu cycle perf, güvenlik sınırı değil) — yalnızca byte-işleme/buffering hot-path'i.
- ReDoS/memory-cap (line_buffer 64KB cap H1'de korunmalı) invariant'ları byte-identical kalmalı.
