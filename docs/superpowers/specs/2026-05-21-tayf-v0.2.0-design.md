# tayf v0.2.0 — TOML Config Tasarım Dokümanı

**Tarih:** 2026-05-21
**Kapsam:** v0.2.0 — TOML konfigürasyon ile özelleştirilebilir kural seti
**Prereqs:** v0.1.0 + v0.1.1 cleanup tamamlanmış olmalı (CI çalışıyor, tick-flush aktif)

Master tasarım hâlâ otorite. v0.1 spec'i mevcut implementasyonu yansıtıyor; bu doc onun üzerine v0.2.0 katmanını ekler. Çatışma olursa bu doc kanonik.

---

## 1. Vizyon

v0.1 8 hardcoded pattern ile çalışıyor. v0.2.0 kullanıcının kendi pattern'lerini eklemesini, built-in'leri override etmesini veya devre dışı bırakmasını mümkün kılar.

### Hedefler

- **Sıfır config çalışır.** Config dosyası yoksa v0.1 davranışı (8 built-in pattern aktif).
- **Append + override by name.** Kullanıcı `[[rules]] name = "ipv4"` yazarsa built-in'i override eder. Yeni `name` yeni rule eklenir.
- **Friendly errors.** Regex compile hatası → satır numarası + pozisyon + öneri.
- **Güvenli config yolu.** Symlink traversal koruması; path canonicalize + whitelist.
- **`--config <path>` flag** ile farklı dosya seçilebilir.

### Hedef olmayan (v0.2.1+'a)

- Hot reload (notify crate) — **v0.2.1**
- `tayf config` interaktif TUI — **v0.2.1**
- `tayf --bypass` escape hatch — **v0.2.1**
- Profile sistemi (`[profiles.network]`) — **v0.5**
- Capture group renklendirme — **v0.5**

## 3. Config Schema (TOML)

```toml
# ~/.config/tayf/config.toml

[general]
respect_existing_colors = true   # v0.3'te VTE awareness aktive olunca etkili olur; v0.2.0'da kabul edilir ama ignore'lanır

# Built-in override örneği: log_level rengini değiştir
[[rules]]
name = "log_level"
style = { fg = "yellow", bold = true }   # built-in BrightRed yerine

# Built-in devre dışı bırak
[[rules]]
name = "fqdn"
enabled = false

# Yeni custom pattern
[[rules]]
name = "kubernetes-pod"
pattern = '\b[a-z][a-z0-9-]+-[a-z0-9]{5}-[a-z0-9]{5}\b'
style = { fg = "magenta", italic = true }

[[rules]]
name = "uuid"
pattern = '\b[0-9a-fA-F]{8}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{12}\b'
style = { fg = "#888888" }
```

### Style alanları

`Style` struct'ı v0.1'deki ile aynı. TOML'da:
- `fg`, `bg`: string (ANSI ismi `"red"`, hex `"#ff8800"`, indexed `"color(178)"`, veya `rgb(r, g, b)`)
- `bold`, `italic`, `underline`, `dim`: bool

### Mevcut built-in isimleri (override edilebilir)

`ipv4`, `ipv6`, `mac`, `log_level`, `http_status`, `filename`, `fqdn`, `duration`.

## 4. Mimari Değişiklikler

### 4.1 Yeni modül: `config.rs`

```rust
pub(crate) mod config {
    pub(crate) struct Config {
        pub(crate) general: GeneralSection,
        pub(crate) rules: Vec<UserRule>,
    }

    pub(crate) struct UserRule {
        pub(crate) name: String,
        pub(crate) pattern: Option<String>,    // None ⇒ built-in override
        pub(crate) style: Option<UserStyle>,
        pub(crate) enabled: bool,              // default true
    }

    pub(crate) struct UserStyle { ... }        // serde-deserializable, mirrors style::Style

    pub(crate) fn load(path: Option<&Path>) -> Result<Option<Config>>;
}
```

`load` cascade:
1. `--config <path>` verildiyse: orayı kullan; yoksa hata.
2. `$XDG_CONFIG_HOME/tayf/config.toml` varsa onu yükle.
3. `~/.config/tayf/config.toml` varsa onu yükle.
4. Hiçbiri yoksa `Ok(None)` döner.

`Ok(None)` durumu: rules engine yalnızca built-in'leri yükler (v0.1 davranışı).

### 4.2 `rules.rs` değişiklikleri

`Compiled::load_builtins()` → `Compiled::load(config: Option<&Config>) -> Result<Self>`:

```rust
pub(crate) fn load(config: Option<&Config>) -> Result<Self> {
    let mut rules = builtin_rules();  // 8 built-in BuiltinRule

    if let Some(config) = config {
        apply_user_rules(&mut rules, &config.rules);
    }

    // Compile to RegexSet + Vec<Regex>
    // ...
}

fn apply_user_rules(builtin: &mut Vec<BuiltinRule>, user: &[UserRule]) {
    for ur in user {
        if let Some(existing) = builtin.iter_mut().find(|b| b.name == ur.name) {
            if !ur.enabled {
                existing.disable();   // bir DisableFlag ekle veya remove et
            }
            if let Some(s) = &ur.style {
                existing.style = s.to_style();
            }
            if let Some(p) = &ur.pattern {
                existing.pattern = p.clone();
            }
        } else {
            // Yeni custom rule (pattern zorunlu)
            builtin.push(BuiltinRule { name: ur.name.clone(), pattern: ur.pattern.clone().unwrap_or_default(), style: ur.style.as_ref().map(|s| s.to_style()).unwrap_or_default() });
        }
    }
    // Disabled rule'ları filtrele
    builtin.retain(|r| r.is_enabled());
}
```

### 4.3 `style.rs` değişiklikleri

`Color` zaten ANSI/Indexed/Rgb destekliyor. Sadece TOML deserialization eklenecek (yeni `UserStyle` → `Style` dönüşümü).

Color string parser:
- `"red"`, `"bright_red"`, ..., `"bright_white"` → enum variant
- `"color(178)"` → `Indexed(178)`
- `"#ff8800"` → `Rgb(0xff, 0x88, 0x00)`
- `"rgb(255, 136, 0)"` → `Rgb(255, 136, 0)`

Invalid string → `Error::Config("invalid color: ...")`.

### 4.4 `error.rs` genişleme

Yeni variant:
```rust
#[error("config file error in {path}:{line}: {message}")]
Config {
    path: String,
    line: usize,
    message: String,
},
```

`toml::de::Error` ve `regex::Error` Config'e mapping.

### 4.5 `cli.rs` ekleme

```rust
/// Path to a TOML config file. Defaults to $XDG_CONFIG_HOME/tayf/config.toml,
/// then ~/.config/tayf/config.toml.
#[arg(long, value_name = "PATH")]
pub config: Option<PathBuf>,
```

### 4.6 `lib.rs` facade

`Tayf::run`'a config loading adımı eklenir:

```rust
pub fn run(args: Args) -> Result<ExitCode> {
    logging::init();
    let apply_colors = !args.no_color && terminfo::stdout_is_tty();
    let spec = shell::discover(args.shell.as_deref(), args.login)?;
    let config = config::load(args.config.as_deref())?;
    let guard = tty_guard::TtyGuard::engage()?;
    let session = pty::PtySession::spawn(&spec)?;
    let (reader, writer, resizer, child) = session.into_parts()?;
    let child_pid = child.pid();
    let _signal_guard = signals::spawn_handler(resizer, child_pid)?;
    let rules = rules::Compiled::load(config.as_ref())?;
    // ... rest unchanged
}
```

## 5. Güvenlik

CLAUDE.md §3 ile tutarlı:

| Tehdit | Çözüm |
|---|---|
| **Symlink traversal** | `canonicalize()` ile çöz; sonuç `~/.config/tayf/` altında değilse reddet (sadece `--config` ile explicit path bu kontrolden muaf, ama path'in regular file olduğunu doğrula) |
| **Adversarial user regex** | `regex::bytes::Regex::new(...)` (linear-time motor); ek olarak v0.2.0'da `regex::RegexBuilder::size_limit` ile compile-time bellek limiti |
| **Devasa config dosyası** | Maksimum 1 MB; aşılırsa `Error::Config("config too large")` |
| **Devasa pattern (anormal uzun regex string)** | Tek pattern max 4 KB; aşılırsa hata |
| **TOML parser DoS** (deeply nested vb.) | `toml` crate v0.8+ recursion limit'i var; max 32 derinlik |

## 8. Açık Sorular

1. **`~/.config/tayf/` whitelist'i `--config` flag ile bypass edilebilir mi?** Öneri: evet, `--config` mutlak öncelik. Kullanıcı `~/proj/.tayfrc` gibi proje-yerel config istiyorsa.
2. **Disable edilmiş rule TUI'da nasıl gösterilir?** v0.2.1'de TUI gelince netleşir.
3. **Built-in pattern string'lerini config dosyasından döküm olarak alma (`tayf config dump`)?** v0.2.1 ile birlikte düşünülebilir.
4. **Color depth downgrade.** v0.2.0'da kullanıcı `"#ff8800"` yazıp terminal sadece 256 destekliyorsa? Spec §5 (master): "tool runtime'da `$COLORTERM` ve `$TERM`'e bakıp truecolor değerleri 256'ya düşürür gerekirse." v0.1'de `terminfo::detect_depth` var ama kullanılmıyor; v0.2.0'da `Style::to_sgr_for_depth(depth)` ile downgrade aktive edilmeli.
