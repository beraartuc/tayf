# tayf v0.2.3 — Preset Themes Tasarım Dokümanı

**Tarih:** 2026-05-22
**Kapsam:** v0.2.3 — opt-in preset theme dosyaları (terminal arka plan taşınabilirliği için)
**Prereqs:** v0.2.2 (genişletilmiş built-in pattern seti) yayınlanmış olmalı.

Master tasarım hâlâ otorite. v0.1 spec'i 8 built-in pattern + renkleri tanımladı (dark-bg varsayımı). v0.2.0 user-config override mekanizmasını ekledi. v0.2.1 hot reload getirdi. v0.2.2 built-in seti 13'e çıkardı, aynı dark-bg varsayımıyla. v0.2.3 bu varsayımı **opt-in tema dosyalarıyla** kırıyor — yeni kod yolu değil, mevcut `apply_user_rules` cascade'inin önüne pre-loaded bir override katmanı.

---

## 1. Vizyon

Mevcut 13 built-in'in renkleri dark-bg terminallerde tasarlandı. Light-bg kullanıcıları için somut problemler:

- `permission` (`White + dim`) → light arka planda görünmüyor.
- `timestamp` (`BrightBlack`) → light arka planda neredeyse okunmuyor.
- `ipv6` (`BrightYellow`) → light arka planda görünmüyor.
- `ipv4` (`Yellow + bold`) → light arka planda solgun.
- `BrightCyan`, `BrightGreen`, `BrightMagenta` — light terminallerde genelde solgun render edilir.

Bu, "kurulduğu anda fark eder" deneyiminin yarısını kırıyor: light-bg kullanıcılar tayf'ı görmüyor bile.

### Hedefler

- En az iki tema ship: `dark` (mevcut default'larla aynı, explicit) ve `light` (light-bg için ayarlanmış).
- Theme seçimi hem `--theme <name>` CLI flag'iyle hem `[general] theme = "..."` config alanıyla yapılır. CLI > config > none.
- Yeni public API yok (theme = `Compiled::load`'a opsiyonel ek parametre).
- Yeni dependency yok (TOML parser ve serde zaten var).
- Yeni FS attack surface yok — theme dosyaları binary'ye embed edilir.

### Hedef olmayan (v0.3+'a)

- **Otomatik bg detection** (`COLORFGBG` env var, OSC 11 query) — v0.3 hedefi. Kullanıcıdan manuel seçim istemek geçici bir adım.
- **Disk-based custom theme dosyaları** (`~/.config/tayf/themes/foo.toml`) — kullanıcılar zaten user-config ile aynı şeyi yapabiliyor; ayrı bir yol açmak attack surface ve tasarım karmaşıklığı getirir.
- **Solarized-dark / solarized-light preset'leri** — v0.3'e ertelendi; bu sürümde scope creep.
- **Theme switching at runtime** (hot reload tetiği) — config dosyası değişince zaten yeniden yükleniyor; ayrı bir API gerekmiyor.
- **GUI/TUI theme seçici** — v0.4'teki `tayf config` interaktif TUI'sine aittir.

## 3. Theme dosya formatı

Theme dosyaları **user-config'in alt kümesi**: sadece `[[rules]]` blokları, her blok sadece `name` ve `style` taşır. `[general]` bölümü yok, `pattern` field'i yok, `enabled = false` yok.

`assets/themes/light.toml` örnek (kısaltılmış):
```toml
# Light-background terminals için tayf preset teması.
# Mevcut 13 built-in pattern'in stillerini override eder. Pattern'ler değişmez.
# Bu dosya repo'da; runtime'da diskten okunmaz, binary'ye embed edilir.

[[rules]]
name = "permission"
style = { fg = "black", dim = true }

[[rules]]
name = "timestamp"
style = { fg = "black", italic = true }

# ... vd. (tüm 13)
```

### Validation (theme yüklenirken)

Theme TOML aynı `config::parse` ile parse edilir, sonra ek bir doğrulama adımından geçer:

1. **`name` her built-in'in adı olmalı.** `BUILTIN_NAMES` setinde olmayan isim → compile-time bug (theme dosyaları repo'da, test'lerle yakalanır). Hata mesajı: `theme 'X': rule 'foo' is not a built-in; theme files may only override built-ins`.
2. **`pattern` field'ı set edilmemiş olmalı.** Set ise: `theme 'X': rule 'foo' must not define pattern (themes only override style)`.
3. **`enabled` efektif `true` olmalı.** Mevcut `UserRule.enabled: bool` (default `true`); theme dosyasında `enabled = false` görmek istemiyoruz. `UserRule.enabled == false` ise: `theme 'X': rule 'foo' must not set 'enabled = false' (themes only override style)`. (Serde tarafında `Option<bool>` ayrımı yok; "yazılmadı vs. açık olarak true" ayırt edilemez ve bu bilinçli — kullanıcı `enabled = true` yazsa bile no-op, sorun değil.)
4. **`style` field'ı zorunlu** (görünür effect şart, mevcut `UserStyle::to_style` validation'ı yeterli).

Bu doğrulama theme dosyaları için **fail-loud**: hata olursa binary build edilmiş bile olsa runtime'da `Compiled::load` `Error::Theme` döner. Pratikte unit test'lerle compile zamanında yakalanır.

## 4. Mimari

### 4.1 Yeni modül: `src/themes.rs`

```rust
//! Embedded preset color themes for tayf.
//!
//! Theme files live in `assets/themes/` and are baked into the binary at
//! compile time via `include_str!`. They are NOT loaded from disk; users
//! who want a custom theme should use the user-config layer (which
//! supersedes the theme layer).
//!
//! Public API (crate-internal):
//! - [`load`]: resolve a theme by name to its embedded TOML source.
//! - [`names`]: alphabetically-sorted list of available theme names.

pub(crate) fn load(name: &str) -> Result<&'static str>;
pub(crate) fn names() -> &'static [&'static str];
```

İçeride:
```rust
const DARK: &str = include_str!("../assets/themes/dark.toml");
const LIGHT: &str = include_str!("../assets/themes/light.toml");

const REGISTRY: &[(&str, &str)] = &[
    ("dark", DARK),
    ("light", LIGHT),
];
```

`load` bilinmeyen isim için:
```rust
Error::Theme {
    name: name.into(),
    available: names().iter().map(|s| (*s).into()).collect(),
}
```

### 4.2 `src/error.rs` — yeni variant

```rust
#[error("theme '{name}' not found; available: {available_list}. Run with --theme <name>.")]
Theme {
    name: String,
    available: Vec<String>,
    // available_list = available.join(", ")
}
```

`Display` mesajı CLAUDE.md §4 "ne/neden/ne yap" kuralına uyar.

### 4.3 `src/cli.rs` — yeni flag

```rust
/// Apply a preset color theme. Themes pre-load style overrides on top of
/// built-in defaults; your user config still wins. Available: dark, light.
#[arg(long, value_name = "NAME")]
pub theme: Option<String>,
```

### 4.4 `src/config.rs` — yeni alan

```rust
pub(crate) struct GeneralSection {
    pub(crate) respect_existing_colors: bool,
    /// Preset theme name. CLI `--theme` overrides this. Validated when
    /// rules are compiled; an unknown name returns Error::Theme.
    pub(crate) theme: Option<String>,
}
```

`Default::default()` ile `theme: None`. Serde rename/alias yok — kullanıcı sadece `theme = "light"` yazar.

### 4.5 `src/rules.rs::Compiled::load` — imza değişikliği

Mevcut:
```rust
pub(crate) fn load(
    config: Option<&Config>,
    config_path: Option<&str>,
    depth: ColorDepth,
) -> Result<Self>
```

Yeni:
```rust
pub(crate) fn load(
    config: Option<&Config>,
    config_path: Option<&str>,
    theme: Option<&str>,         // theme name
    depth: ColorDepth,
) -> Result<Self>
```

İç akış (yeni 3 adım kalın):
```
1. rules = builtin_rules()
2. if let Some(name) = theme:
     source = themes::load(name)?
     theme_cfg = config::parse(&format!("<embedded:theme/{name}>"), source)?
     validate_theme_rules(name, &theme_cfg)?
     apply_user_rules(&format!("<embedded:theme/{name}>"), &mut rules, &theme_cfg.rules)?
3. if let Some(c) = config:
     apply_user_rules(path, &mut rules, &c.rules)?  # mevcut
4. depth downgrade + regex compile  # mevcut
```

`validate_theme_rules` `themes.rs` içinde, yukarıda §3'teki dört kuralı uygular.

Crate-internal call site: `lib.rs::Tayf::run`. Test imzası: `Compiled::load_at_truecolor` helper'ı yeni `theme` parametresini de alır veya `None` geçer (backwards-compat değil, sadece tests).

### 4.6 `src/lib.rs` — theme reconciliation

`Tayf::run` içinde mevcut config-load adımının ardından:

```rust
let effective_theme: Option<String> = args.theme.clone()
    .or_else(|| config.as_ref().and_then(|c| c.0.general.theme.clone()));
```

`Compiled::load(config, config_path, effective_theme.as_deref(), depth)` çağrısı yapılır. Yetkisiz tema adı `Error::Theme` ile dışarı çıkar; `main.rs::map_error_to_exit_code` bu variant'ı `64` (`EX_USAGE`) ile bitirir — `Error::Config`'le aynı sınıf, çünkü kullanıcı geçersiz bir CLI/config kombinasyonu girmiş.

### 4.7 Theme dosyaları

`assets/themes/dark.toml` ve `assets/themes/light.toml`. Detaylı içerik §5'te.

### 4.8 `Cargo.toml` — `include = [...]` güncellemesi

Mevcut `include` listesi `src/**/*`, `Cargo.toml`, vd. tutuyor. **Yeni satır:** `"assets/themes/*.toml"`. Yoksa `cargo publish` ile crate'e theme dosyaları gitmez ve `include_str!` build-time fail eder.

## 5. Renk tabloları

### 5.1 `dark.toml` — explicit default

Mevcut 13 built-in'in stilini birebir yazar. v0.2.2 spec §4'teki paletle aynı.

| Rule | fg | Attrs |
|---|---|---|
| permission | white | dim |
| timestamp | bright_black | — |
| uuid | bright_magenta | — |
| url | bright_blue | underline |
| email | bright_green | — |
| ipv4 | yellow | bold |
| ipv6 | bright_yellow | — |
| mac | cyan | — |
| log_level | bright_red | bold |
| http_status | magenta | — |
| filename | bright_cyan | — |
| fqdn | blue | — |
| duration | green | — |

`dark` temasını uygulayıp uygulamamak ayırt edilemez — invariant: dark theme uygulandıktan sonra `Compiled::styles[i]` == `builtin_rules()[i].style` (renk depth downgrade'inden önce). Bu test edilir.

### 5.2 `light.toml` — light-bg ayarı

Strateji:
- `Bright*` aileler light terminallerde solgun → normal ANSI'a indir.
- `White`, `BrightYellow` light bg'de görünmez → tamamen değiştir.
- Kontrast düşüşünü `bold` veya `italic` ile telafi et.
- Her (fg, attr) tuple'ı 13 rule arasında **unique** kalmalı; aksi halde iki rule görsel olarak ayrılamaz.

| Rule | fg | Attrs | Dark eşdeğeri | Gerekçe |
|---|---|---|---|---|
| permission | black | dim | white + dim | Metadata hissi (solgun) korunur, light'ta okunur |
| timestamp | black | italic | bright_black | Log-prefix "ortam" tonu; permission'dan italic ile ayrılır |
| uuid | magenta | — | bright_magenta | BrightMagenta light'ta solgun; normal okunur |
| url | blue | underline | bright_blue + underline | Hyperlink convention; bright→normal |
| email | green | bold | bright_green | Light'ta Green solgun; bold telafi |
| ipv4 | red | bold | yellow + bold | Yellow light'ta neredeyse görünmez; Red okunur |
| ipv6 | magenta | italic | bright_yellow | Yellow imkânsız; magenta+italic ile UUID'den ayrılır |
| mac | cyan | bold | cyan | Cyan light'ta teal; bold ile vurgu |
| log_level | red | bold | bright_red + bold | Bright→normal; ipv4 ile aynı (red+bold) — **çakışıyor, aşağıda not** |
| http_status | magenta | bold | magenta | UUID (magenta düz) ve ipv6 (magenta italic) ile bold ile ayrılır |
| filename | blue | italic | bright_cyan | BrightCyan light'ta solgun; Blue+italic ile fqdn'den ayrılır |
| fqdn | blue | — | blue | Light'ta okunur |
| duration | green | — | green | Email bold ile ayrıldığı için Green düz kullanılabilir |

**Çakışma notu — ipv4 ve log_level her ikisi de `red + bold`:**

Bu yan yana çıkmaları beklenir ama context'e göre ayırt edilir (bir IP adresi rakam.rakam.rakam.rakam; log_level büyük harf kelime). Bu kabul edilebilir trade-off — alternatif `log_level`'a `red + bold + underline` vermek olabilirdi ama underline genelde URL için ayrılıyor; mevcut tayf konvansiyonunu kırmamak için pas geçildi.

**Yeni `Style` field'ı YOK** — mevcut `Color` enum'u, `bold/italic/underline/dim` flag'leri yeter.

## 6. CLI ve config örnekleri

```sh
# CLI ile geçici seçim
$ tayf --theme light

# Geçersiz tema → EX_USAGE
$ tayf --theme foo
tayf: theme 'foo' not found; available: dark, light. Run with --theme <name>.

# CLI yokken config'teki tema kullanılır
# (~/.config/tayf/config.toml içinde: [general]\ntheme = "light")
$ tayf
```

```toml
# ~/.config/tayf/config.toml
[general]
theme = "light"
respect_existing_colors = true

[[rules]]
# Kullanıcı theme'i de override edebilir:
name = "ipv4"
style = { fg = "#ff5722", bold = true }
```

`--no-color` ve `--theme` etkileşimi: `--no-color` `ColorDepth::None`'a indirir; bu `Style::downgrade` aşaması tüm fg/bg'leri striplerken bold/italic/underline/dim'i korur. Theme uygulanmış olsa da olmasa da sonuç aynı (depth = None tüm renkleri siler). **Yeni davranış yok** — sadece dokümante edilir.

## 7. Güvenlik

CLAUDE.md §3 mandate'leri:

- **Adversarial input yok.** Theme dosyaları repo-controlled, binary'ye embed. Runtime'da dışarıdan TOML okunmuyor.
- **FS attack surface yok.** Yeni path açılmıyor.
- **Memory/regex limit'leri korunur.** Theme aynı `apply_user_rules` ve `RegexBuilder` yolundan geçer; mevcut 1 MiB regex size + dfa cap'i theme tarafından bypass edilmez.
- **SGR collision.** Theme `pattern` değiştirmediği için yeni regex compile etmez. Sadece stil override eder. Mevcut SGR-collision regression test'leri theme uygulanmış kompozisyonda da geçer.
- **Theme adı validation.** `--theme foo` adı registry lookup'tan geçer; ham string asla `format!("{name}.toml")` gibi bir path'e gitmez (zaten gitmiyor; her şey embedded).
- **No new dependency.** `cargo audit && cargo deny check` çıktısı v0.2.2'den farksız.

**Security review:** Code-Review subagent her task sonrası ve final integration sonrasında.

## 8. Test stratejisi

### Unit

**`themes` modülü:**
- `themes::names() == &["dark", "light"]` (alfabetik).
- `themes::load("dark")` ve `themes::load("light")` `Ok` döner.
- `themes::load("invalid")` → `Error::Theme { available: ["dark", "light"] }`.

**Theme dosyaları (compile-time validation):**
- Her tema için: `config::parse` başarılı.
- Her tema için: tüm `UserRule.name` `BUILTIN_NAMES` setinde.
- Her tema için: hiçbir `UserRule.pattern` set değil.
- Her tema için: hiçbir `UserRule.enabled` `false` değil.
- Her tema için: her `UserRule.style` `to_style` ile geçerli görünür effect üretir.

**`Compiled::load` ile theme:**
- `Compiled::load(None, None, Some("dark"), Truecolor)` styles[i] == `builtin_rules()[i].style`. (Dark theme idempotent.)
- `Compiled::load(None, None, Some("light"), Truecolor)` permission rule styles[i].fg == `Some(Color::Black)`.
- `Compiled::load(Some(&user_cfg), Some(p), Some("light"), Truecolor)` — user override theme'i override eder: user'ın `ipv4` rengi nihai sonucta görünür.
- `Compiled::load(None, None, Some("nope"), Truecolor)` → `Error::Theme`.

**SGR-collision regression:** mevcut `apply_rules_does_not_corrupt_sgr` testi theme uygulanmış set'le de geçer.

### Integration

`tests/integration_themes.rs` (yeni):
- `tayf --theme dark` ile shell spawn et, `echo abc` çalıştır, exit kodu 0, output bozulmamış (smoke).
- `tayf --theme light` ile shell spawn et, exit kodu 0.
- `tayf --theme nonexistent` → exit kodu 64 (EX_USAGE).

Mevcut `tests/integration_smoke.rs` ve `tests/integration_hot_reload.rs` regresyona uğramamalı.

### Manual

- iTerm2 / Terminal.app dark profil: `tayf --theme dark | journalctl -n 50` — tüm 13 pattern okunaklı.
- iTerm2 / Terminal.app light profil: `tayf --theme light | journalctl -n 50` — aynı çıktı okunaklı.
- README'ye en az dark+light için bir `ls -l` ekran görüntüsü (best-effort, release-block etmez).

### CI

Yeni dependency yok → `cargo audit && cargo deny check` matrisinde sürpriz beklenmez. Linux + macOS matrisi mevcut, theme path'leri platform-bağımsız.
