**Tarih:** 2026-05-24
**Kapsam:** v0.3.6'nın yarım kalan Fix A'sını tamamla — `src/rules.rs:986-1001`'deki duplicate formatter'ı `ThemeRuleErrorKind::CaptureGroupIndexOutOfRange` `Display` impl'ine delegate et + iki gevek test assertion'ını sıkılaştır + buggy davranışı belgeleyen yorumu güncelle. **Umbrella:** v0.3.6+v0.4 umbrella vision §2 tablosuna v0.3.7 row'u **ship sonrası** insert edilir (umbrella v0.3.7'yi anticipate etmemişti — final cross-cutting review bulgusu).

## 1. Motivasyon

v0.3.6 `ThemeRuleErrorKind::CaptureGroupIndexOutOfRange` `Display` impl'ini iki branch'e böldü (`n == 0` → `"no capture groups; styles cannot be set"`, `n >= 1` → mevcut format). Ama post-ship cross-cutting review keşfetti ki **`src/rules.rs:986-1001`'de bir duplicate formatter** — `RuleSource::UserConfig` branch'i (v0.3.5 commit `77da579` ile gelen) — aynı buggy `(valid: 1..=0)` mesajını **user-config error path'ında** hâlâ üretiyor.

Bu, en yaygın user-facing trigger: kullanıcının `~/.config/tayf/config.toml`'unda no-capture-groups bir rule'a (örn. `ipv4`) `styles = { "N" = ... }` yazması. v0.3.6'nın CHANGELOG entry'si "Display now produces a meaningful message" diyor ama bu mesaj user-config path'ında değil, theme-config (`ThemeValidation`) path'ında üretiliyor. v0.3.6 yarım fix.

İki test (`src/rules.rs:2090` unit + `tests/integration_capture_groups.rs:282` integration) sadece `message.contains("valid: 1..=")` substring assert ediyor — hem broken (`valid: 1..=0`) hem fixed (`valid: 1..=3` veya `no capture groups`) wording'i tatmin ediyor. Loose assertion half-fix'i regression-guard'lamadı. Spec'in mekanik grep guard'ı string literal'a bakıyor; `{}` interpolation'dan çıkan `0` görünmez.

v0.3.7 üç şeyi yapar: (a) duplicate formatter'ı `Display`'e delegate et, (b) iki test'i exact-wording'e sıkılaştır + negative regression guard ekle, (c) buggy davranışı belgeleyen yorumu güncelle.

## 2. Değişiklik envanteri

### 2.1 Fix A — `src/rules.rs:986-1001` UserConfig branch'ini Display'e delegate et

**Mevcut:**

```rust
RuleSource::UserConfig => {
    let n = captures_len.saturating_sub(1);
    return Err(Error::Config {
        path: user_cfg_path_or_sentinel.to_owned(),
        line: 0,
        message: format!(
            "rule '{}': styles.\"{}\": rule's regex has {} capture \
             group{} (valid: 1..={})",
            rule.name,
            parsed,
            n,
            if n == 1 { "" } else { "s" },
            n
        ),
    });
}
```

**Yeni:**

```rust
RuleSource::UserConfig => {
    let kind = crate::error::ThemeRuleErrorKind::CaptureGroupIndexOutOfRange {
        group: parsed,
        captures_len,
    };
    return Err(Error::Config {
        path: user_cfg_path_or_sentinel.to_owned(),
        line: 0,
        message: format!("rule '{}': {kind}", rule.name),
    });
}
```

**Kontrat:**
- `captures_len == 1` (n == 0): mesaj artık `"rule '<name>': styles.\"<group>\": rule's regex has no capture groups; styles cannot be set"` — v0.3.6 Display fix'i otomatik geçer.
- `captures_len >= 2` (n >= 1): mesaj `"rule '<name>': styles.\"<group>\": rule's regex has N capture group(s) (valid: 1..=N)"` — pluralization helper Display'de zaten çalışıyor, byte-identical.

**Niçin Option E (Display delegation):**
- Single source of truth. `ThemeRuleErrorKind::CaptureGroupIndexOutOfRange` zaten public + Display impl'li; ikinci formatter'a gerek yok.
- v0.3.6 Display fix'i otomatik kapsar — n==0 specialization hem theme hem user-config path'ında aktif.
- Public API surface büyümez. `ThemeRuleErrorKind` zaten exported; kullanım pattern'i değişmez.
- Alternative B (free fn helper) ekstra katman; Alternative D (yeni `Error::CaptureGroupOutOfRange` variant) public API genişler — hotfix overkill.

### 2.2 Fix B — Unit test sıkılaştırma (`src/rules.rs:2090`)

**Mevcut tek assertion:**

```rust
assert!(message.contains("99"), "got: {message}");
assert!(message.contains("valid: 1..="), "got: {message}");
```

**Yeni:**

```rust
assert!(message.contains("rule 'ipv4'"), "got: {message}");
assert!(message.contains("styles.\"99\""), "got: {message}");
assert!(message.contains("no capture groups"), "got: {message}");
assert!(message.contains("styles cannot be set"), "got: {message}");
assert!(!message.contains("valid: 1..=0"), "regression guard: {message}");
```

**Kontrat:**
- Positive substrings test'in hangi path'ı assert ettiğini netleştirir — `"no capture groups"` + `"styles cannot be set"` yalnızca yeni n==0 wording'inde var, eski `valid: 1..=0` wording'ini tatmin etmez.
- Negative regression guard direkt yarım-fix'i yakalardı.
- Rule name prefix (`"rule 'ipv4'"`) ve key (`"styles.\"99\""`) format'ın diğer kısımlarını da pin'ler.
- Existing `message.contains("99")` assertion'ı `"styles.\"99\""` ile subsume edilir, ayrı tutulmaz.

### 2.3 Fix C — Integration test sıkılaştırma (`tests/integration_capture_groups.rs:282`)

**Mevcut:**

```rust
assert!(stderr.contains("valid: 1..="), "diagnostic must carry the valid range; got: {stderr}");
```

**Yeni:**

```rust
assert!(stderr.contains("rule 'ipv4'"), "diagnostic must name the rule; got: {stderr}");
assert!(stderr.contains("no capture groups"), "got: {stderr}");
assert!(stderr.contains("styles cannot be set"), "got: {stderr}");
assert!(!stderr.contains("valid: 1..=0"), "regression guard: {stderr}");
```

**Kontrat:** Unit test ile birebir paralel; user-facing CLI'da end-to-end doğru wording'in geldiğini pin'ler.

### 2.4 Fix D — Yorum güncellemesi (`tests/integration_capture_groups.rs:244-248`)

**Mevcut yanıltıcı yorum:**

```rust
// ---------------------------------------------------------------------------
// 6. User-config `styles."99"` on a rule whose regex has < 99 capture
//    groups → tayf exits 64 with a `valid: 1..=` diagnostic. ipv4 has
//    no capture groups (`captures_len = 1`), so the diagnostic prints
//    `valid: 1..=0`.
// ---------------------------------------------------------------------------
```

**Yeni:**

```rust
// ---------------------------------------------------------------------------
// 6. User-config `styles."99"` on a rule whose regex has < 99 capture
//    groups → tayf exits 64 with a `CaptureGroupIndexOutOfRange`
//    diagnostic. ipv4 has no capture groups (`captures_len = 1`), so
//    the diagnostic specializes to "rule's regex has no capture groups;
//    styles cannot be set" (v0.3.7+: routed through the shared
//    `ThemeRuleErrorKind::Display` impl).
// ---------------------------------------------------------------------------
```

Eski yorum "the diagnostic prints `valid: 1..=0`" buggy davranışı belgeliyordu; yeni yorum doğru wording'i + delegasyon mimarisini yansıtır.

## 3. CHANGELOG entry

```markdown
## [0.3.7] — TBD

### Fixed
- v0.3.6's `CaptureGroupIndexOutOfRange` Display fix now also reaches
  the user-config error path. Previously, a `~/.config/tayf/config.toml`
  with `styles = { "N" = ... }` on a rule whose regex has no capture
  groups (e.g., `ipv4`) would still emit `(valid: 1..=0)` because
  `src/rules.rs` carried a duplicate formatter that bypassed the
  `Display` impl. v0.3.7 routes that path through the same
  `ThemeRuleErrorKind` variant, producing
  `"rule's regex has no capture groups; styles cannot be set"`
  uniformly. The theme-config error path (fixed in v0.3.6) is
  unchanged.
```
