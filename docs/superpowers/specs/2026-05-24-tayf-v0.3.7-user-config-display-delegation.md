## 1. Motivasyon

v0.3.6 `ThemeRuleErrorKind::CaptureGroupIndexOutOfRange` `Display` impl'ini iki branch'e böldü (`n == 0` → `"no capture groups; styles cannot be set"`, `n >= 1` → mevcut format). Ama post-ship cross-cutting review keşfetti ki **`src/rules.rs:986-1001`'de bir duplicate formatter** — `RuleSource::UserConfig` branch'i (v0.3.5 commit `77da579` ile gelen) — aynı buggy `(valid: 1..=0)` mesajını **user-config error path'ında** hâlâ üretiyor.

Bu, en yaygın user-facing trigger: kullanıcının `~/.config/tayf/config.toml`'unda no-capture-groups bir rule'a (örn. `ipv4`) `styles = { "N" = ... }` yazması. v0.3.6'nın CHANGELOG entry'si "Display now produces a meaningful message" diyor ama bu mesaj user-config path'ında değil, theme-config (`ThemeValidation`) path'ında üretiliyor. v0.3.6 yarım fix.

İki test (`src/rules.rs:2090` unit + `tests/integration_capture_groups.rs:282` integration) sadece `message.contains("valid: 1..=")` substring assert ediyor — hem broken (`valid: 1..=0`) hem fixed (`valid: 1..=3` veya `no capture groups`) wording'i tatmin ediyor. Loose assertion half-fix'i regression-guard'lamadı. Spec'in mekanik grep guard'ı string literal'a bakıyor; `{}` interpolation'dan çıkan `0` görünmez.

v0.3.7 dört şeyi yapar: (a) **iki** duplicate formatter'ı `Display`'e delegate et (OutOfRange + KeyMalformed), (b) iki test'i exact-wording'e sıkılaştır + negative regression guard ekle, (c) buggy davranışı belgeleyen yorumu güncelle, (d) ikinci duplicate'in cleanup'ı sırasında ortaya çıkan **sanitization divergence**'ı düzelt — `KeyMalformed` user-config formatter'ı raw `key` yazıyor; `Display` impl `sanitize_for_display(key)` ile control-byte'ları kaçırır. Adversarial config'de raw key control byte'ları stderr'e leak edebilir; CLAUDE.md §3 "Adversarial input" mandate'i bunu yasaklar. Delegation otomatik olarak fix'ler.

## 2. Değişiklik envanteri

### 2.1 Fix A — `src/rules.rs:986-1001` UserConfig branch'ini Display'e delegate et

**Mevcut:**

```rust
RuleSource::UserConfig => {
    let n = captures_len.saturating_sub(1);
    return Err(Error::Config {
        path: user_cfg_path_or_sentinel.to_owned(),
        line: 0,
        message: format!(
            "rule '{}': styles.\"{}\": rule's regex has {} capture \
             group{} (valid: 1..={})",
            rule.name,
            parsed,
            n,
            if n == 1 { "" } else { "s" },
            n
        ),
    });
}
```

**Yeni:**

```rust
RuleSource::UserConfig => {
    let kind = crate::error::ThemeRuleErrorKind::CaptureGroupIndexOutOfRange {
        group: parsed,
        captures_len,
    };
    return Err(Error::Config {
        path: user_cfg_path_or_sentinel.to_owned(),
        line: 0,
        message: format!("rule '{}': {kind}", rule.name),
    });
}
```

**Kontrat:**
- `captures_len == 1` (n == 0): mesaj artık `"rule '<name>': styles.\"<group>\": rule's regex has no capture groups; styles cannot be set"` — v0.3.6 Display fix'i otomatik geçer.
- `captures_len >= 2` (n >= 1): mesaj `"rule '<name>': styles.\"<group>\": rule's regex has N capture group(s) (valid: 1..=N)"` — pluralization helper Display'de zaten çalışıyor, byte-identical.

**Niçin Option E (Display delegation):**
- Single source of truth. `ThemeRuleErrorKind::CaptureGroupIndexOutOfRange` zaten public + Display impl'li; ikinci formatter'a gerek yok.
- v0.3.6 Display fix'i otomatik kapsar — n==0 specialization hem theme hem user-config path'ında aktif.
- Public API surface büyümez. `ThemeRuleErrorKind` zaten exported; kullanım pattern'i değişmez.
- Alternative B (free fn helper) ekstra katman; Alternative D (yeni `Error::CaptureGroupOutOfRange` variant) public API genişler — hotfix overkill.

### 2.1b Fix A2 — `src/rules.rs:957-967` KeyMalformed branch'ini Display'e delegate et

**Aynı drift modu:** v0.3.5'te `RuleSource::UserConfig` arm'ı için iki ayrı duplicate formatter girdi — biri OutOfRange (Fix A), diğeri KeyMalformed. Fix A2 ikinciyi de aynı pattern'le temizler. v0.3.7 senior review'unun I-1 bulgusu (tighten scope) + cross-cutting review'un I-2 process recommendation'ı (do not ship with duplicate drift surfaces).

**Mevcut:**

```rust
RuleSource::UserConfig => {
    return Err(Error::Config {
        path: user_cfg_path_or_sentinel.to_owned(),
        line: 0,
        message: format!(
            "rule '{}': styles.\"{}\": capture-group key must be a \
             positive decimal (1, 2, ..., N) with no leading zeros",
            rule.name, key,
        ),
    });
}
```

**Yeni:**

```rust
RuleSource::UserConfig => {
    let kind = crate::error::ThemeRuleErrorKind::CaptureGroupKeyMalformed {
        key: key.to_owned(),
    };
    return Err(Error::Config {
        path: user_cfg_path_or_sentinel.to_owned(),
        line: 0,
        message: format!("rule '{}': {kind}", rule.name),
    });
}
```

**Sanitization side-effect fix:** Mevcut formatter `key` field'ını raw yazıyor. `Display` impl `sanitize_for_display(key)` ile control-byte'ları escape eder. Adversarial config (örn. `styles = { "\x07evil" = ... }`) artık BEL terminal sequence'ını leak etmeden stderr'e print eder. CLAUDE.md §3 "Adversarial input" + "Escape-sequence injection — we must never *introduce* a sequence" mandate'iyle uyumlu.

**Wording delta:** Prefix `"rule '{}': "` korunur; geri kalan Display'den gelir — benign key'lerde content byte-identical (sanitization etkisi yok). Mevcut integration test `tests/integration_capture_groups.rs:381` (`malformed_styles_key_in_user_config_emits_capture_group_key_malformed`) benign key `"01"` (leading zero) test eder; delegation sonrası **byte-identical pass eder**, dokunulmaz. Adversarial control-byte key path için yeni unit test §2.2b'de.

### 2.2b Fix B2 — Yeni unit test (Fix A2 sanitization side-effect regression guard)

**Lokasyon:** `src/rules.rs` `#[cfg(test)] mod tests`, mevcut `compiled_load_with_theme_emits_config_error_for_user_config_out_of_range` test'inden hemen sonra.

**Test:**

```rust
#[test]
fn compiled_load_with_theme_sanitizes_malformed_styles_key_in_user_config() {
    use crate::config::{Config, GeneralSection, UserRule, UserStyle};
    use std::collections::BTreeMap;
    let mut user_styles: BTreeMap<String, UserStyle> = BTreeMap::new();
    // Adversarial key: leading zero (grammar fail) + BEL control byte.
    // Before Fix A2: raw key leaks BEL to stderr. After: sanitized.
    user_styles.insert(
        "0\x07evil".to_owned(),
        UserStyle { fg: Some("red".to_owned()), ..UserStyle::default() },
    );
    let cfg = Config {
        general: GeneralSection::default(),
        rules: vec![UserRule {
            name: "ipv4".to_owned(),
            pattern: None,
            enabled: true,
            style: None,
            styles: Some(user_styles),
        }],
    };
    let err = Compiled::load_with_theme(
        Some(&cfg),
        Some("/test/config.toml"),
        None,
        crate::terminfo::ColorDepth::Truecolor,
    )
    .expect_err("should fail with Config");
    if let crate::error::Error::Config { message, .. } = &err {
        assert!(message.contains("rule 'ipv4'"), "got: {message}");
        assert!(message.contains("capture-group key must be a positive decimal"), "got: {message}");
        // Regression guard: raw BEL byte (0x07) must not appear; the
        // Display impl routes the key through sanitize_for_display.
        assert!(
            !message.as_bytes().contains(&0x07),
            "raw control byte leaked: {message:?}"
        );
    } else {
        panic!("expected Error::Config; got: {err:?}");
    }
}
```

**Kontrat:**
- Positive assertion'lar rule name + Display wording'i pin'ler.
- `!message.as_bytes().contains(&0x07)` adversarial BEL byte'ın sanitize edildiğini garanti eder.
- Önce: raw `key` formatter `0\x07evil`'i olduğu gibi yazardı; mesaj `'\x07'` byte'ı içerirdi → stderr'e print edildiğinde terminal BEL çalardı.
- Sonra: `sanitize_for_display` BEL'i `\x07` text formuna escape eder (veya benzer non-control representation; `sanitize_for_display` impl'i belirler).

## 3. CHANGELOG entry

```markdown
## [0.3.7] — TBD

### Fixed
- v0.3.6's `CaptureGroupIndexOutOfRange` Display fix now also reaches
  the user-config error path. Previously, a `~/.config/tayf/config.toml`
  with `styles = { "N" = ... }` on a rule whose regex has no capture
  groups (e.g., `ipv4`) would still emit `(valid: 1..=0)` because
  `src/rules.rs` carried a duplicate formatter that bypassed the
  `Display` impl. v0.3.7 routes that path through the same
  `ThemeRuleErrorKind` variant, producing
  `"rule's regex has no capture groups; styles cannot be set"`
  uniformly. The theme-config error path (fixed in v0.3.6) is
  unchanged.
- The parallel user-config diagnostic for malformed `styles` keys
  (e.g., `styles = { "01" = ... }` with a leading zero) is now also
  routed through the shared `ThemeRuleErrorKind::CaptureGroupKeyMalformed`
  Display impl. Benign keys produce byte-identical output; **adversarial
  keys containing control bytes are now sanitized** instead of being
  printed raw to stderr (previously a minor escape-sequence-injection
  risk per CLAUDE.md §3 mandate).

> [Note] v0.3.6's CHANGELOG read as if both Display fix paths were
> covered; in practice the parallel user-config formatters in
> `src/rules.rs::resolve_group_styles_for_rule` were literal copies
> that bypassed `ThemeRuleErrorKind::Display`. v0.3.7 closes both
> gaps in one commit and adds unit + integration regression guards
> sharp enough to catch this drift class going forward.
```
