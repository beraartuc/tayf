# tayf v0.11.0 — Universal one-line installer (`install.sh` + musl-static binaries)

**Status:** approved design (2026-06-01). Built on [[project-v0-10-0-shipped]].

**Goal:** Ship a single auditable `curl … | sh` installer that detects the OS and
architecture, downloads the matching signed release binary, verifies it, and
installs it to a no-sudo location — plus the two musl-static Linux targets that
make it genuinely portable across every Linux environment.

---

## 1. Context & motivation

v0.10.0 made tayf public on three channels: crates.io (`cargo install tayf`),
signed GitHub Releases (manual multi-step binary download), and a Homebrew tap.
The remaining install gap is a **zero-prerequisite one-liner** for users who
have neither Rust nor Homebrew — the dominant expectation on Linux servers and
containers.

Two problems block a naive installer:

1. **No one-line path.** The pre-built-binary route is a 4-step manual recipe
   (download → attestation verify → checksum verify → chmod+mv).
2. **The Linux binary is not portable.** Today's only Linux artifact is
   `x86_64-unknown-linux-gnu`, built on `ubuntu-latest` (new glibc). It fails on
   older distros (`GLIBC_2.xx not found`) and does not cover ARM Linux. A
   "universal" installer that points at it is not actually universal.

This cycle closes both: a **musl-static** build (no libc version dependency,
runs on Alpine/old-Debian/containers) for **x86_64 and aarch64**, and an
`install.sh` that wraps detect→download→verify→install.

**No crate/library code changes.** This is release infrastructure + a shell
script + docs. The `src/` tree, public API, and `Cargo.lock` dependency graph
are untouched (musl is just an additional compile target of the same source).

## 2. Scope

**In scope**
- `install.sh` at the repo root (POSIX `sh`, single auditable file).
- Two new release targets: `x86_64-unknown-linux-musl`,
  `aarch64-unknown-linux-musl` (static), with the same per-target asset set
  (`tayf-<target>`, `.sha256`, `.sigstore.json`) and `SHA256SUMS` membership.
- README "Quick install" section.
- CI: `shellcheck` lint of `install.sh`; a post-release container smoke test.

**Out of scope (YAGNI / future)**
- `cargo-binstall` metadata (user declined for this cycle).
- Custom domain / GitHub Pages short URL (`tayf.sh`).
- Distro packages (`.deb`/`.rpm`/AUR).
- Windows (tayf is Unix-only by design).
- Replacing the existing `x86_64-unknown-linux-gnu` artifact — see §6 note; we
  **add** musl rather than remove gnu, to avoid breaking anyone already
  depending on the gnu asset name.

## 3. Component: `install.sh`

Single POSIX-`sh` script (no bashisms; runs under `dash`/`busybox sh`).
`set -eu`. All network downloads via `curl -fsSL` (fallback to `wget` if curl
absent). Untrusted values (version string, install dir) are handled as data,
never `eval`'d.

### 3.1 Platform detection

| `uname -s` | `uname -m`            | target                          |
| ---------- | --------------------- | ------------------------------- |
| `Darwin`   | `arm64`               | `aarch64-apple-darwin`          |
| `Darwin`   | `x86_64`              | `x86_64-apple-darwin`           |
| `Linux`    | `x86_64` / `amd64`    | `x86_64-unknown-linux-musl`     |
| `Linux`    | `aarch64` / `arm64`   | `aarch64-unknown-linux-musl`    |
| *other*    | *other*               | error → print manual-install URL, exit 1 |

### 3.2 Version resolution
- Default: latest release. Resolve the tag via the GitHub API
  `https://api.github.com/repos/beraartuc/tayf/releases/latest` (parse
  `.tag_name` with a `grep`/`sed` extraction — no `jq` dependency).
- Override: `TAYF_VERSION=v0.11.0` env var pins an exact tag (used verbatim).

### 3.3 Download
From `https://github.com/beraartuc/tayf/releases/download/<tag>/`:
- `tayf-<target>` (the binary)
- `tayf-<target>.sha256`
- `tayf-<target>.sigstore.json` (best-effort attestation; download non-fatal)

Into a `mktemp -d` workdir, removed by an `EXIT` trap.

### 3.4 Verification
1. **Checksum — mandatory, fatal.** Recompute SHA256 (`shasum -a 256` on macOS,
   `sha256sum` on Linux) and compare to the `.sha256` content. Mismatch → print
   both digests, abort (exit 1). No install on mismatch.
2. **Attestation — best-effort, non-fatal.** If `gh` is on `PATH`, run
   `gh attestation verify <bin> --repo beraartuc/tayf --bundle <bundle>`; else if
   `cosign` is present, the documented `cosign` equivalent. On success: print
   "provenance verified". On absence/failure: print a clear note that provenance
   was **not** verified and show the exact manual `gh attestation verify` command.
   Never aborts (checksum already guaranteed integrity).

### 3.5 Install
- Destination: `${TAYF_INSTALL_DIR:-$HOME/.local/bin}`. `mkdir -p`, `install`/`mv`
  the binary as `tayf`, `chmod +x`. **No sudo.**
- If the destination is not on `PATH`, print the exact line to add it
  (shell-aware hint for the user's `$SHELL` rc file).
- Re-install/upgrade is just a re-run (overwrites in place; idempotent).

### 3.6 Output & UX
- Concise, prefixed status lines (`tayf-install: …`).
- Final line runs `"$dest/tayf" --version` and echoes it as confirmation.
- A `--help`/`-h` early-exit documenting the env vars (`TAYF_VERSION`,
  `TAYF_INSTALL_DIR`) and the verification behavior.

## 4. Component: release.yml matrix expansion

Add two entries to the `build` job matrix:

```yaml
- { os: ubuntu-latest, target: x86_64-unknown-linux-musl }
- { os: ubuntu-latest, target: aarch64-unknown-linux-musl }
```

Build details:
- **x86_64-unknown-linux-musl:** native arch, musl libc. `rustup target add` +
  `sudo apt-get install -y musl-tools` (provides `musl-gcc`), then the existing
  `cargo build --release --target … --locked` step.
- **aarch64-unknown-linux-musl:** cross-compile. Use a SHA-pinned
  `taiki-e/setup-cross-toolchain-action` (installs the cross linker so plain
  `cargo build --target … --locked` works; provides qemu so a smoke `--version`
  can run). **New CI dependency → pin to a commit SHA + one-line justification
  in the workflow comment.** Fallback if it proves unreliable: `cross`.

Everything downstream is target-generic and already loops over the matrix:
attestation, `gh attestation verify` smoke, staged asset naming
(`tayf-<target>` + `.sha256` + `.sigstore.json`), and the `github-release` job's
combined `SHA256SUMS`. **No changes** to the publish-crate or package-and-sbom
jobs.

**Validation risk (must confirm in first CI run):** tayf + its dependency graph
(notably `portable-pty`, termios usage) must compile and link statically against
musl. These are Unix/libc crates and musl implements `openpty`/`forkpty`, so it
is expected to work, but the first musl build is the proof. If a dependency
fails on musl, that becomes a blocking sub-investigation (documented, not
worked around silently).

## 5. Component: README

Add a "Quick install" block as the **first** install option:

```bash
curl -fsSL https://raw.githubusercontent.com/beraartuc/tayf/main/install.sh | sh
```

With: a one-line note on what it does (detect → download signed binary → verify
checksum → install to `~/.local/bin`), the `TAYF_VERSION` / `TAYF_INSTALL_DIR`
knobs, and a "prefer to inspect first?" line showing `curl … | less`. Keep the
existing Homebrew / Cargo / manual-binary sections below it.

## 6. Testing

- **`shellcheck install.sh`** — new fast GitHub-hosted CI job (SHA-pinned action
  or `apt-get install shellcheck`); `-S style` clean.
- **Container smoke (post-release).** A `release.yml` job (or a documented manual
  recipe if we keep it out of the gated release path) that, after assets exist,
  runs `install.sh` inside clean `alpine:latest` (musl) and `debian:oldstable`
  (proves glibc-independence of the musl binary) containers and asserts
  `tayf --version` succeeds. For PRs, a lighter check: run `install.sh` against
  the *latest published* release on the GH-hosted Linux runner.
- **Local TDD where pure:** the detection mapping (uname → target) is the one
  piece of pure logic; extract it as a shell function and unit-test it with a
  table of `(uname_s, uname_m) → expected_target` cases driven by stub/env, so
  it is tested without network.

## 7. Security considerations

- **`curl | sh` trust model.** The script is served from `raw.githubusercontent`
  off `main` — auditable, versionable, and the README shows the `curl … | less`
  inspect-first path. We do not introduce a redirector or shortener.
- **Integrity vs authenticity.** Checksum (mandatory) defends against corruption
  and a network MITM that cannot also rewrite the release. Authenticity against a
  compromised release comes from the Sigstore attestation; we verify it
  best-effort (when `gh`/`cosign` exist) and otherwise tell the user exactly how.
  This matches the project's "strong default without a hard external dependency"
  posture (CLAUDE.md §3).
- **No secrets, no eval, no sudo.** The script needs no tokens, never `eval`s
  downloaded or user-supplied strings, and installs without elevated privileges.
- **Supply-chain of the build.** The two musl artifacts are produced by the same
  SHA-pinned, attested release pipeline as the existing binaries; the new
  cross-toolchain action is pinned to a commit SHA and justified.

## 8. Version & rollout sequencing

`install.sh` on `main` installs the **latest** release. The musl assets it needs
do not exist until a release ships with the matrix expansion. Therefore:

1. Land `install.sh` + matrix + README + CI on the `v0.11.0-installer` branch.
2. Cut **v0.11.0** (bump `Cargo.toml`, CHANGELOG, SECURITY supported-versions
   table) so the release carries the musl binaries.
3. Only then does the README one-liner resolve correctly for Linux. (macOS works
   from any release that has the darwin assets, i.e. already.)

Until v0.11.0 is tagged, the one-liner is documented but Linux users would hit a
missing-asset error — so README + tag must ship together. `install.sh` itself,
being version-agnostic, is forward-compatible.

Follow the v0.10.0 process conventions: design/process docs live in
`docs/superpowers/` on the branch (preserved in history) and are removed from
HEAD at the public release; outward steps (push, tag) stay per-step gated;
EN-only in code/docs/commits; final cross-cutting review before tagging.

## 9. Decisions locked (from brainstorm)
1. Linux coverage = **musl-static x86_64 + aarch64**.
2. Verification = **checksum mandatory + attestation best-effort**.
3. Install location = **`~/.local/bin`, no sudo, PATH hint, `TAYF_INSTALL_DIR` override**.
4. Hosting = **`install.sh` in repo, raw URL, latest-by-default + `TAYF_VERSION` pin**.
5. `cargo-binstall` = **out** (YAGNI this cycle).
6. Version = **v0.11.0**.
