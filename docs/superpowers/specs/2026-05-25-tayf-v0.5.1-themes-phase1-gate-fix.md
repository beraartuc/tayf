## §1 — Özet

v0.5.0 capture-group named-key resolution'ı `RuleSource::UserConfig` için uçtan uca shipped. Ancak `RuleSource::Theme` branch'i structurally dead. `themes::validate_theme_rules` Phase-1 grammar gate ([src/themes.rs:421](src/themes.rs#L421)) her styles-map key'ini `crate::config::validate_styles_map_key`'den geçiriyor — bu helper'ın grammar'ı all-ASCII-digit (v0.3.5 dispatch'inden dört sub-version önce yazıldı). Non-digit key'ler (`"scheme"`, `"date"`, `"perm_owner"`) `CaptureGroupKeyMalformed` olarak Phase-1'de reject ediliyor — yani Step-3 named resolution'a (`resolve_group_styles_for_rule`) hiç ulaşamıyor. Net effect: dispatch'teki [src/rules.rs:1067-1076](src/rules.rs#L1067) (`CaptureGroupNameUnknown` for Theme) ve [src/rules.rs:1116-1124](src/rules.rs#L1116) (`CaptureGroupDuplicateTarget` for Theme) arm'ları production theme-load pipeline'ı üzerinden unreachable.

v0.5.1 Phase-1'i, non-digit key'leri dispatch'e delege edecek şekilde gevşetir (**option (b) — "mirror dispatch"**, review-aligned). Üç integration test yeni reachable olan her Theme dispatch arm'ını kapsar. Yeni public API yok, built-in theme'lerin (`dark`/`light`, `styles` map'i yok) davranışı değişmez, hot-path delta sıfır.

### §4.1 — Korunan invariant'lar

1. **Empty key** — `"".bytes().all(b.is_ascii_digit())` vacuous `true` döner, all-digit branch'ine düşer, `validate_styles_map_key("")` None döner ([src/config.rs:176](src/config.rs#L176)), `KeyMalformed` emit edilir. Bugünkü davranışla byte-identical. §5.1 yeni unit test'i bunu pin'ler.
2. **`"0"` key** — yukarıdaki `key == "0"` literal block tarafından intercept edilir (değişmiyor); `CaptureGroupIndexZeroForbidden` emit eder.
3. **`"01"` / leading-zero / multi-digit-malformed** — all-digit branch; `validate_styles_map_key` None döner; `KeyMalformed` emit eder. Byte-identical. Mevcut test `validate_theme_rules_collects_capture_group_key_malformed` ([src/themes.rs:1063](src/themes.rs#L1063)) byte-identical pass eder.
4. **Non-digit key (örn. `"scheme"`, `"date"`)** — Phase-1'i geçer; `Compiled::load_with_theme` Step-3 named resolution ([src/rules.rs:1054-1095](src/rules.rs#L1054)) devreyi alır.
5. **Dispatch silent-continue [src/rules.rs:1001](src/rules.rs#L1001)** — comment correctness korunur. Dispatch'in `RuleSource::Theme` + malformed-digit için silent `continue`'su Phase-1'in error'u zaten collect ettiğini varsayar; option (b) bu invariant'ı korur.

### §4.2 — Call-site enumerasyonu

`grep -rn 'validate_styles_map_key' src/` tam iki site döndürür (spec time'da verified):

- `src/themes.rs:421` — broadening hedefi.
- `src/rules.rs:996` — dispatch Step 2 (değişmiyor).

Yeni call-site eklenmedi. `feedback_phase1_grammar_gate_blind_spot` mandate'i karşılanıyor.

### §4.3 — Neden option (b), option (c) değil

Option (c) — "Phase-1 sadece empty + control-byte reject eder; her şeyi dispatch'e delege eder" — ilk sketch'ti. Spec time'da elendi:

1. Dispatch [src/rules.rs:1001](src/rules.rs#L1001) `RuleSource::Theme` arm'ı `validate_styles_map_key` → `None` için şu an silent `continue` ve comment'i: *"Already collected by themes::validate_theme_rules (Phase 1) with the original key bytes. Skip silently."* Option (c) theme TOML için `KeyMalformed` diagnostic'lerini sessizce düşürürdü. Düzeltmek dispatch'i de `theme_errors.push(KeyMalformed)`'a çevirmeyi gerektirir.

Testler `load_with_theme` üzerinden integration suite'e taşınmak zorunda kalırdı. Lost discipline + larger surface.
3. Option (b) tek dosya (sadece `src/themes.rs`). Option (c) hem `src/themes.rs` hem `src/rules.rs` etkiler ve unit testleri retire/relocate etmeyi gerektirir. v0.5.0 final review §I-1 explicit olarak option (b)'yi tavsiye ediyor.

## [0.5.1] - TBD

### Fixed
- `themes::validate_theme_rules` Phase-1 grammar gate now defers non-digit
  styles-map keys (e.g. `styles.date`, `styles.scheme`, `styles.perm_owner`)

  limited to advanced users authoring custom theme TOML.

### Tests
- Three new integration tests in `tests/integration_capture_groups.rs`
  cover the previously dead `RuleSource::Theme` dispatch arms: named-key
  happy path (`styles.date` styles a timestamp), unknown-name diagnostic
  (`styles.bogus` surfaces `CaptureGroupNameUnknown` with `available:`
  list), and duplicate-target diagnostic (`styles."1" + styles.date`
  colliding on the same slot surfaces `CaptureGroupDuplicateTarget`).
- One new unit test in `src/themes.rs` pins Phase-1 acceptance of
  non-digit styles keys.

### Internal
- No public API change. No new variants on `ThemeRuleErrorKind`. No
  signature changes. No `Cargo.toml` dependency delta. No MSRV change.
- Hot path byte-equal to v0.5.0; name → index resolution stays
  compile-time. Bench baseline regen not required.

## §11 — Forward-pointer'lar (v0.5.2 / v0.5.3 / v0.5.4)

Bu pointer'lar downstream sub-version brainstorm'ları için **load-bearing**. Original v0.5.1 bundle'ının spec-phase parallel review'undan (Rust senior + domain senior, split öncesi) gelen findings'i absorb ederler — aksi takdirde o findings sadece bu spec'i üreten chat transcript'inde kalırdı.

### §11.1 — v0.5.2 (profile system MECHANISM, no library) — Rust senior architectural sorular

Her biri v0.5.2 spec'inde implementation öncesi explicit olarak resolve edilmeli.

- **C-1. TOML deserialization shape.** `[profile.NAME]` → `HashMap<String, Profile>` non-trivial. Embedded layout (her `assets/profiles/X.toml` bir profile, header yok) vs user-config layout (`[profile.X]` header'lı, multi-profile file) farklı. Spec ayrı deserialization path'lerini pin'lemeli. `#[serde(deny_unknown_fields)]` + `#[serde(flatten)]` etkileşimine dikkat.
- **C-2. `RuleSource::EmbeddedProfile` variant gerekli.** Mevcut 3-arm taxonomy (Builtin / UserConfig / Theme) yetersiz: profile `append_rules` entry'si shipped + non-built-in + `styles` taşıyabilir. `resolve_group_styles_for_rule`'ın `Builtin` arm `unreachable!` assumption'ları (`styles_override == None`) profile rule'da fire ederdi. `compile_error_for` ([src/rules.rs:780](src/rules.rs#L780)) profile compile failure'ı `Error::RegexCompile` olarak surface etmeli (tayf bug, CLAUDE.md §3), `Error::Config` değil. Yeni variant additive olmalı (verify: `RuleSource` `#[non_exhaustive]` mi?).
- **C-3. Theme precedence 4-tier matrix.** Tam sıra: **CLI `--theme` > user-config `[general] theme` > profile.theme > bg-detect default**. v0.5.2 spec'i explicit matrix tablo + 8-combination unit test (cli × config × profile × default) içermeli.
- **C-4. Hot-reload integration with profile awareness.** `ReloadOrchestrator::spawn` ([src/reload.rs:143](src/reload.rs#L143)) startup'ta theme snapshot'lıyor. `reload_once` ([src/reload.rs:104](src/reload.rs#L104)) `theme: Option<&str>` raw alıyor — profile-blind. Profile name reload signature'una eklenmeli; `reload_once` her reload'da full precedence chain'i re-resolve etmeli. Spec `"--profile aktifken user-config edit'i correct recompile tetikler"` test'i pin'lemeli.
- **I-2. Profile-rule vs built-in name collision policy.** Bir profile `append_rules` `name = "ipv4"` define ettiğinde, biri seçilsin: (a) hard error (önerilen — shipped collision tayf bug), (b) override (user-config precedent), (c) silent append. v0.5.2 spec'i seçip test'le pin'lemeli.
- **I-3. Profile name validation predicate.** `name_is_valid` ([src/themes.rs:78](src/themes.rs#L78)) — ASCII alphanumeric + `-` + `_`, no `.`. Profile name'ler her yerde aynı predicate'i kullanır: CLI args, config TOML, disk path discovery. Spec'te mandate explicit olmalı.
- **I-5. `--profile` clap shape pre-pin.** Composition sorusu (`Option<String>` vs `Vec<String>`) v0.5 vision §3.2'de açıktı. v0.5.2 spec'i kapatmalı. Composition defer edilirse, `Vec<String>` future-extension path olarak document edilmeli; aksi takdirde sonra BREAKING flag rename gerekir.
- **I-6. Hot-path-unchanged regression test.** Profile inactive iken `Compiled::load_builtins().individuals.len() == 13` ve `BUILTIN_NAMES.len() == 13` byte-equal. ~5 LOC integer-equality test (bench-CI'ın coarse safety net'inden daha keskin).

### §11.2 — v0.5.3 (built-in profile library) — domain senior pattern audit

Orijinal 9 önerilen pattern; audit verdict matrisi aşağıda. v0.5.3 spec'i bu matrisi uygulamalı ve DROP-class pattern'ları silently re-introduce edemez.

#### §11.2.1 — DROP (unsalvageable as-shaped)
- **`namespace = \b[a-z][a-z0-9-]{1,62}[a-z0-9]\b`** — `pull-request`, `code-review`, `cargo-deny`, `rust-analyzer`, npm package adları, git branch'leri, blog slug'larını match'ler. Profile-gated bile olsa user `kubectl logs` sırasında embedded README/JSON görüyor — leak. Drop.
- **`project_id = \b[a-z][a-z0-9-]{4,28}[a-z0-9]\b`** — aynı shape, aynı problem. Drop.
- **`image_tag = name:tag`** — `key:value` (JSON), `host:port` (`localhost:8080`), `module:line` (`src/main.rs:42` — mevcut `filename` ile fight'lar), `INFO:root:msg` ile collide. Drop OR registry-host shape (`.` içermek zorunda) zorla.

#### §11.2.2 — RESHAPE before ship
- **`pod_name`**: `{8,10}` hex git short hash ile collide eder. Gerçek pod-name shape'i trailing `-[a-z0-9]{5}` suffix taşır: `\b[a-z][a-z0-9-]*-[a-f0-9]{10}-[a-z0-9]{5}\b`. Bunu kullan.
- **`container_id`** 12-hex: git short hash, MD5, UUID middle ile collide. Full 64-hex (`\b[a-f0-9]{64}\b`) OR context prefix (`(?:container[= ]|docker (?:exec|logs|stop|rm|start) )` lookbehind-equivalent) zorla. Yoksa drop.
- **`arn`**: right anchor ekle (`\b` veya whitespace class) — trailing punctuation yememeli.

#### §11.2.3 — AUDIT before ship
- **`region`**: enumeration eksik — `me-central-1`, `il-central-1`, `af-south-1`, `ap-south-2`, `ca-west-1`, `eu-central-2`, `ap-southeast-3` gerçek AWS region'ları önerilen alternation'da yok. Spec exhaustive enum + her current region için bir unit test eklemeli.

#### §11.2.4 — SHIP AS-IS
- **`instance_id = \bi-[a-f0-9]{17}\b`** — shape-unique, prose-immune. Verified.

#### §11.2.5 — DEFER
- **`gcp resource_id`** — service'a göre değişir (`projects/X/zones/Y/instances/Z` vs bare `instance-12345`); single shape yok. v0.6+'a defer.

#### §11.2.6 — Library composition implications
- Eğer `namespace` + suffix-tightened olmayan `pod_name` drop → k8s profile mevcut built-in'lerin (timestamp/log_level/uuid) whitelist'i + tightened pod_name'e daralır. Domain-specific değer küçülür.
- Eğer `project_id` + `resource_id` drop → gcp profile filter-only (timestamp + aws ile paylaşılan region). v0.5.3 brainstorm ship-or-drop kararını vermeli.
- Eğer `container_id` + `image_tag` drop → docker profile filter-only. Aynı karar.
- aws profile sağlam kalır: `instance_id` + tightened `region` + anchored `arn` = üç solid pattern.

Net: 9'dan 5 drop, 3 reshape, 1 audit, 1 ship-as-is — **4 pattern survives**. gcp ve docker profile ship-or-drop'u v0.5.3 brainstorm'a defer.
