## §4 — Architecture overview

### §4.1 — Profile semantic decision (append-only vs filter-only)

v0.5.2 schema `rules` field semantic:

- **`rules` omitted** → all 13 built-ins active (default behavior — current).
- **`rules = []`** → filter ALL built-ins out (only `append_rules` apply).
- **`rules = [name1, name2, ...]`** → whitelist filter.

v0.5.3 5 profile'ı iki gruba ayırır:

**Append-only profiles** (`rules` omit, all 13 built-ins active + append_rules):
- `aws` — 3 append_rules (instance_id, region, arn). EC2/S3/IAM/CloudWatch çıktısı tüm built-in shape'leri içerir.
- `k8s` — 1 append_rule (pod_name). kubectl çıktısı: timestamps, IPs, FQDNs, UIDs, durations, http_status, mount paths.
- `docker` — 2 append_rules (container_id, image_tag). docker ps/logs: IPs, durations, log levels.

**Filter-only profiles** (`rules = [...]` whitelist, no append_rules):
- `gcp` — 10-built-in whitelist; `permission` (Unix-perms not GCP IAM JSON), `mac` (rare in gcloud), `filename` (Cloud Storage paths already in `url` built-in) hariç.
- `network` — 8-built-in whitelist (tcpdump/netstat/dig focus); `uuid`, `permission`, `email`, `duration`, `filename` hariç (network capture context'inde noise).

Rationale: domain CLI output'unun yapısı dictates semantic. AWS/k8s/docker user'ı domain-specific shape istiyor + var olan built-in tedariği faydalı kullanır. gcp resource_id audit-DEFER edildi (v0.6+); gcp filter-only relevant subset'le ship'lenir, no append_rules. network pure focus tool — built-in surface'in ilgisiz kısmını filtreler.

## §5 — TOML content + regex shapes

### §5.1 — `assets/profiles/aws.toml`

```toml
# AWS profile — append_rules add 3 AWS-specific shapes on top of all 13
# built-ins. Activate with `tayf --profile aws` or
# `[general] profile = "aws"` in ~/.config/tayf/config.toml.

[[append_rules]]
name = "instance_id"
# Shape-unique EC2 / EBS / etc. ID prefix: i-<17 hex>.
# Examples: i-0abcd1234567890ef
# Audit verdict: SHIP-AS-IS (shape-unique, prose-immune).
pattern = '\bi-[a-f0-9]{17}\b'
style = { fg = "cyan" }

[[append_rules]]
name = "region"
# Exhaustive AWS region enumeration (snapshot 2026-05-26).
# 34 regions across commercial / GovCloud / China partitions.
# Future regions require patch release + unit test addition (see §7.2).
pattern = '''\b(?:us-east-1|us-east-2|us-west-1|us-west-2|us-gov-east-1|us-gov-west-1|ca-central-1|ca-west-1|eu-central-1|eu-central-2|eu-west-1|eu-west-2|eu-west-3|eu-north-1|eu-south-1|eu-south-2|af-south-1|me-south-1|me-central-1|il-central-1|ap-east-1|ap-south-1|ap-south-2|ap-northeast-1|ap-northeast-2|ap-northeast-3|ap-southeast-1|ap-southeast-2|ap-southeast-3|ap-southeast-4|ap-southeast-5|sa-east-1|cn-north-1|cn-northwest-1)\b'''
style = { fg = "green" }

[[append_rules]]
name = "arn"
# Amazon Resource Name — handles commercial / GovCloud / China partitions.
# Audit verdict: RESHAPE — right-anchor to prevent trailing punctuation
# (`.`, `:`, `-`) from being eaten. Last char class forced to word-char subset.
# Examples:
#   arn:aws:iam::123456789012:user/Alice
#   arn:aws:s3:::my-bucket
#   arn:aws:ec2:us-east-1:123456789012:instance/i-0abcd1234567890ef
#   arn:aws-us-gov:iam::123456789012:role/example

pattern = '''\barn:aws(?:-us-gov|-cn)?:[a-z0-9-]+:[a-z0-9-]*:[0-9]*:[a-zA-Z0-9_/.:+@*-]*[a-zA-Z0-9_/+@*-]\b'''
style = { fg = "magenta" }
```

#### §5.1.3 — `arn` right-anchor shape

ARN syntax: `arn:partition:service:region:account-id:resource`.

Partitions: `aws` (commercial), `aws-us-gov` (GovCloud), `aws-cn` (China). Pattern alternation: `aws(?:-us-gov|-cn)?`.

Region/account fields can be empty (S3 `arn:aws:s3:::bucket` no region, no account). Pattern: `[a-z0-9-]*` for both.

Resource field permissive — contains `:`, `/`, `.`, `_`, `+`, `@`, `*`, `-`. **Audit RESHAPE fix:** last char forced to word-char subset (`[a-zA-Z0-9_/+@*-]`) to prevent trailing `.` / `:` from being eaten. Negative regression test pins this (§7.3).

Examples (positive):
- `arn:aws:iam::123456789012:user/Alice`
- `arn:aws:s3:::my-bucket`
- `arn:aws-us-gov:iam::123456789012:role/example`

Examples (negative — trailing punctuation):
- Input: `Found arn:aws:s3:::my-bucket. Done.`
- Match: `arn:aws:s3:::my-bucket` (no trailing `.`).

### §5.2 — `assets/profiles/k8s.toml`

```toml
# Kubernetes profile — append_rule adds pod_name shape on top of all 13
# built-ins. Activate with `tayf --profile k8s`.

[[append_rules]]
name = "pod_name"
# K8s ReplicaSet-managed pod naming: <deploy-name>-<rs-hash:10>-<pod-hash:5>.
#
# AUDIT DEVIATION (v0.5.1 spec §11.2 recommended `[a-f0-9]{10}`):
# K8s `apimachinery/pkg/util/rand` uses base32 subset alphabet:
#   bcdfghjklmnpqrstvwxz2456789  (27 chars, no vowels, no 0/1)
# Hex-only shape would miss real pods whose hash contains g/h/j/k/l/m/n/p/
# q/r/s/t/v/w/x/z — ~99% of real pods. Strict K8s base32 alphabet preserves
# the audit's suffix-anchor SPIRIT while restoring accuracy.
#
# Examples:
#   nginx-deployment-7c79c4bf97-9hk6r
#   coredns-558bd4d5db-vwz2j
#   my-app-bcdfghjklm-xyz25
pattern = '''\b[a-z][a-z0-9-]*-[bcdfghjklmnpqrstvwxz2456789]{10}-[bcdfghjklmnpqrstvwxz2456789]{5}\b'''
style = { fg = "cyan" }
```

#### §5.2.1 — pod_name audit deviation justification

v0.5.1 spec §11.2'de domain-senior audit `[a-f0-9]{10}` önerdi. Real K8s pod hash alphabet `bcdfghjklmnpqrstvwxz2456789` — hex değil, base32-subset (Crockford-like minus vowels and 0/1).

**Coincidence rate:** Random K8s hash karakteri hex'in altkümesi olma olasılığı ≈ 11/27 (b, c, d, f, 2, 4, 5, 6, 7, 8, 9 hem K8s alphabet'inde hem hex). 10-karakter hash'in tamamı hex olma olasılığı ≈ (11/27)^10 ≈ %0.005. Audit'in `[a-f0-9]{10}` shape'i gerçek pod'ların %99.995'ini MISS eder.

**Correction:** Strict K8s alphabet. Suffix-anchor (audit'in primary concern — `\b[a-z0-9]{10}\b` over-match'ini önler) korunur, accuracy artırılır.

**Trade-off**: Future K8s `rand` alphabet değişikliği (highly unlikely; well-established API surface) requires regex update. v0.6+ K8s breaking change scan'inde flag edilebilir. Risk düşük; stable lib.

**Audit deviation governance:** Bu deviation v0.5.3 spec'inde explicit document edildi (this section). D1 Rust senior spec review verify edecek. CHANGELOG entry'sinde audit-deviation framing'i belirtilir (v0.5.1 spec §11.2 alphabet correction).

### §5.3 — `assets/profiles/docker.toml`

```toml
# Docker profile — append_rules add container_id and image_tag shapes.

[[append_rules]]
name = "container_id"
# 12-hex shape. Collisions with git short hash + MD5 chunks + UUID-internal
# 12-hex segments are ACCEPTED. Profile activation is opt-in domain context;
# user `--profile docker` implicitly accepts collision FPs in unrelated tool
# output. To disable, user-config:
#   [[rules]]
#   name = "container_id"
#   enabled = false
#
# Audit verdict: RESHAPE OR DROP. v0.5.3 brainstorm Q2 verdict: ship simple
# 12-hex shape, accept collisions, profile-as-context-signal rationale.
pattern = '\b[a-f0-9]{12}\b'
style = { fg = "cyan" }

[[append_rules]]
name = "image_tag"
# Two-branch alternation:
#   1. Registry-host required: `host.tld/path:tag`
#      Examples: gcr.io/proj/img:1.21, ghcr.io/user/repo:abc123
#      Branch shape forces at least one `.` in the host portion.
#   2. Bare `:latest`: `name:latest` (Docker default tag sentinel)
#      Examples: nginx:latest, library/redis:latest
#      Bare images with non-latest tag (e.g., nginx:1.21) do NOT match.
#
# Audit verdict: RESHAPE (registry-host required) OR DROP. v0.5.3 brainstorm
# Q3 verdict: registry-host required + bare-`:latest` extension.
#
# FP guards (negative regression in tests):
#   - JSON key:value: `{"foo":"bar"}` — no `:latest`, no host.tld/, no match.
#   - host:port: `localhost:8080` — no dot in `localhost`, no slash, no match.
#   - module:line: `src/main.rs:42` — no dot before first `/`, no match.
pattern = '''(?:\b[a-z0-9-]+(?:\.[a-z0-9-]+)+/[a-z0-9._/-]+:[a-z0-9._-]+\b|\b[a-z][a-z0-9_-]*(?:/[a-z0-9_-]+)*:latest\b)'''
style = { fg = "magenta" }
```

#### §5.3.1 — `container_id` 12-hex collision-accept rationale

User override of audit verdict (Q2 brainstorm). 12-hex shape'in çakıştığı durumlar:

| Shape | Source | Frequency in user shell |
|---|---|---|
| Git short hash (10-12 hex) | `git log`, `git rev-parse --short` | Yüksek (dev workflow) |
| MD5 hash (32-hex) | `md5sum`, checksums | Orta |
| UUID 5th segment (12-hex) | UUID v4 last group | Yüksek (logs, IDs) |
| SHA-256 prefix arbitrary 12-hex slice | Build artifacts, certificates | Düşük |

Profile activation domain signal — user `--profile docker` koştuğunda terminal context = docker workflow → 12-hex matches more likely to BE container IDs than git/MD5/UUID slices. UUID matches first (full-UUID built-in span > 12-hex internal); built-in apply order Step 1 (UUID) → Step 4 (container_id append_rule) means UUID wins on full match.

Documented behavior pinned by collision-accept positive test (§7.3 — D.2.5). User feedback channel: if FP rate proves unacceptable, v0.6+ context-prefix reshape candidate (lookbehind workaround via capture-group routing).

#### §5.3.2 — `image_tag` two-branch alternation rationale

Branch 1 (registry-host required) covers production image references:

- ECR: `012345678901.dkr.ecr.us-east-1.amazonaws.com/my-app:v1.2.3`
- GCR: `gcr.io/proj/img:latest`
- DockerHub canonical: `docker.io/library/nginx:1.21-alpine`
- GHCR: `ghcr.io/user/repo:abc123`

Branch 2 (bare `:latest`) covers Docker's default tag sentinel — `:latest` is special-case, prose-immune in shell context:

- `docker pull nginx:latest`
- `docker run -it my-app:latest sh`
- `kubectl set image deployment/web app=redis:latest`

Bare image with non-`:latest` tag (`nginx:1.21`) intentionally NOT matched. Rationale: too FP-prone (`host:port`, `key:value`, `module:line` are common shell shapes). User can opt in via user-config override:

```toml
[[rules]]
name = "image_tag"
pattern = '''(?:<existing-two-branch>|\b[a-z][a-z0-9._/-]*:[a-z0-9._-]+\b)'''
```

### §6.1 — `map_error_to_exit_code` arm split

**Dosya:** [src/main.rs](src/main.rs#L40), function `map_error_to_exit_code`, line 51.

**Önce** (v0.5.2):
```rust
Error::Profile { .. } => 64,           // EX_USAGE — bad --profile value / disk load
Error::ProfileValidation { .. } => 64, // EX_USAGE — profile body validation
```

**Sonra** (v0.5.3):
```rust
// Embedded profile RegexCompile is a tayf library bug — pattern shipped in
// `assets/profiles/*.toml` failed to compile. Maps to EX_SOFTWARE 70
// (internal programming error). Discriminator: source_path begins with
// `<embedded:profile/` (v0.5.2 LoadedProfile.path_label convention).
//
// Note: only RegexCompile splits. Other ProfileErrorKind variants (IoError,
// Parse, etc.) on embedded paths are practically unreachable (we ship the
// files) and remain EX_USAGE for the failsafe path.
Error::Profile { source_path, kind: ProfileErrorKind::RegexCompile { .. }, .. }
    if source_path.starts_with("<embedded:profile/") => 70,
Error::Profile { .. } => 64,           // EX_USAGE — disk profile / unknown name / etc.
Error::ProfileValidation { .. } => 64, // EX_USAGE — Phase-1 validation (always user-error)
```

**Match arm ordering critical:** Rust match-guard semantics — first arm wins. Split-arm (with guard) FIRST; fallback (`Error::Profile { .. }`) SECOND.

**Module doc-comment update** ([src/main.rs:5-7](src/main.rs#L5)) — EX_SOFTWARE 70 listesine "embedded profile RegexCompile (tayf library bug)" eklenir.

fn gcp_profile_filter_only_drops_permission_keeps_whitelist() {
    // gcp whitelist excludes `permission`; input with `rwxr-xr-x` MUST NOT
    // surface as permission SGR. Whitelisted built-ins (timestamp, log_level,
    // http_status) MUST still apply.
    let input = "drwxr-xr-x bucket-perms 2026-05-26T10:00:00Z INFO status=200\n";
    let bytes = run_in_pty_with_profile("gcp", input);
    let s = String::from_utf8_lossy(&bytes);
    // permission filtered out
    assert_no_sgr_span_for(&s, "rwxr-xr-x");
    // whitelist members preserved
    assert_has_some_sgr_for(&s, "2026-05-26T10:00:00Z");
    assert_has_some_sgr_for(&s, "INFO");
    assert_has_some_sgr_for(&s, "200");
}

#[test]
fn network_profile_filter_only_drops_uuid_keeps_ips() {
    // network whitelist excludes `uuid`; IPs MUST surface, UUID MUST NOT.
    let input = "192.168.1.1:443 -> 10.0.0.2:8080 \
                 (uuid 123e4567-e89b-12d3-a456-426614174000)\n";
    let bytes = run_in_pty_with_profile("network", input);
    let s = String::from_utf8_lossy(&bytes);
    assert_has_some_sgr_for(&s, "192.168.1.1");
    assert_has_some_sgr_for(&s, "10.0.0.2");
    assert_no_sgr_span_for(&s, "123e4567-e89b-12d3-a456-426614174000");
}
