## 4. H5 — No-match fast-lane (DOKUNULMAZ `src/pipeline.rs`)

### 4.1 Bugünkü davranış

`Pipeline::feed` ([pipeline.rs:469](../../../src/pipeline.rs#L469)) Ground branch'i: `memchr(0x1b, rest)` ile ESC'e kadar olan run'ı `LineBuffer::feed_data_run` ([line_buffer.rs:94](../../../src/line_buffer.rs#L94)) ile satırlara böler; her satır `apply_or_passthrough` ([pipeline.rs:649](../../../src/pipeline.rs#L649)) → `apply_rules_with` → `select_runs` ([pipeline.rs:117](../../../src/pipeline.rs#L117)) → `compiled.set.matches(line)`. Hiçbir şey eşleşmese bile her satır: bir `rules.load_full()` (atomic refcount) + 5 scratch `clear()` + per-line RegexSet scan ödüyor.

### 4.2 Fast-lane mekaniği (boolean-gate; emit YİNE per-line)

Ground branch'inde, fast-lane şartları sağlanırsa run'ı **TEK** `compiled.set.is_match(run)` ile ön-tara:
- `is_match == false` (run'da hiçbir pattern eşleşmiyor): `memrchr(b'\n', run)` ile son `\n`'i bul; `run[..=last_nl]`'i **VERBATIM** `out.write_all` et; `\n` sonrası tail'i `feed_data_run(tail)`'e ver (sadece buffer'lar). Per-line `apply_rules` + per-line `load_full` ATLANIR.
- `is_match == true`: **mevcut per-line yola düş** (`feed_data_run` + `apply_or_passthrough` döngüsü, bugünkü kod). Hiçbir değişiklik yok.
- Run'da `\n` yoksa (`memrchr == None`): verbatim yazma YOK; tüm run'ı `feed_data_run`'e ver (partial olarak buffer'lanır; sonraki chunk tamamlar). Fast-lane faydası bu run'da yok ama doğru.

> **LOAD-BEARING INVARIANT (review C-1, terminal-security):** prefilter sonucu **YALNIZCA boolean** olarak tüketilir (`is_match`). Emisyon HER ZAMAN per-line `apply_or_passthrough` üzerinden olur. Whole-run scan'dan ASLA emit edilmez. Bunun nedeni §4.4'te (whole-run *emit* anchor'lar yüzünden byte-divergent; whole-run *boolean* değil).

### 4.3 Fast-lane guard'ları (hepsi sağlanmalı)

```
fast_lane_safe
  && self.buffer.is_empty()
  && !self.line_has_sgr
  && !self.line_has_string_payload
  && run.len() <= MAX_BUFFER_BYTES
  && !compiled.set.is_match(run)
```

1. **`buffer.is_empty()` — PRIMARY guard.** Buffer doluysa run'ın ilk segmenti bekleyen partial'a eklenir (birleşik satır eşleşebilir + byte-order); fast-lane'lemeyiz. Her iki reviewer bağımsız kanıtladı: `line_has_sgr == true && buffer.is_empty()` **ulaşılamaz** — `line_has_sgr` yalnız `dispatch_completed_sequence` `Sgr` arm'ında set edilir ([pipeline.rs:621](../../../src/pipeline.rs#L621)), SGR scratch'i `\n` içermez, dolayısıyla flag true iken buffer zorunlu non-empty. Reset yalnız `apply_or_passthrough`'da, satır emit edildikten sonra ([pipeline.rs:660](../../../src/pipeline.rs#L660)).
2. **`!line_has_sgr && !line_has_string_payload` — redundant-but-safe defense-in-depth.** (1)'in kanıtı bunları gereksiz kılıyor ama tutuyoruz; gelecekte biri `buffer.is_empty()`'i "SGR flag zaten kapsıyor" diye kaldırmasın diye (gerçekte ilişki TERS: primary guard `buffer.is_empty()`).
3. **`run.len() <= MAX_BUFFER_BYTES` (64 KB) — overflow/warning divergence'ı nötrler (review 🟡).** Buffer boş + run ≤ cap ise run içindeki HİÇBİR satır cap'i aşamaz → `feed_data_run` bu run'da ASLA overflow-flush yapmaz → per-line yol `content + \n` üretir, warning üretmez → verbatim yazma hem byte hem davranış (warning) açısından identical. Cap'i aşan run'lar (nadir; `READ_BUF_BYTES = 8 KiB` olduğu için pratikte run'lar ≤ 8 KiB — [runtime.rs:37](../../../src/runtime.rs#L37)) fast-lane'i atlar, mevcut per-line/`feed_data_run` yoluna düşer (overflow-flush + `warn_msg!`'i korur, I-2).
4. **`fast_lane_safe`** — §4.4.
5. **`!compiled.set.is_match(run)`** — fast-lane'i tetikleyen no-match kararı; mevcut `compiled.set` (yeni set YOK).

### 4.4 `fast_lane_safe` — prefilter soundness (review 🔴 → fork çözüldü)

**Sorun (Rust senior 🔴):** Whole-run `compiled.set.is_match(run)`, per-line individual regex'lerine karşı **false-negative** verebilir mi (= byte-divergence)? Evet — anchor'lar yüzünden. Örnek (ampirik, regex 1.12.3): user pattern `^ERROR` per-line `b"ERROR"`'da eşleşir; ama whole-run `b"x\nERROR\ny"`'de `^` = haystack başı → eşleşMEZ → false-negative → o satır renklenmez → divergence. Aynısı `ERROR$`, `\AERROR`, `ERROR\z` için. **`(?m)` ayrı RegexSet (eski lean = Fork B) UNSOUND'dur:** `(?m)` yalnız `^`/`$`'ı satır-sınırına yöneltir; `\A`/`\z` mutlak anchor'lar `(?m)`'den ETKİLENMEZ (ampirik: `(?m)foo\z` over `b"a\nfoo\nb"` → `[]`). → **Fork B DÜŞTÜ.**

**Çözüm (iki review'in sentezi):**
- **Prefilter = mevcut `compiled.set`** (Fork B'nin ikinci set'i YOK; ikinci compile, audit surface, ReDoS yüzeyi yok). `compiled.set` zaten `select_runs`'un kullandığı motorun aynısı ([pipeline.rs:134](../../../src/pipeline.rs#L134), [rules.rs:1072](../../../src/rules.rs#L1072)).
- **Built-in set whole-run-boolean SOUND'dur** (terminal-security ampirik kanıt: `permission` — tek `^`/`$` kullanan builtin — için 320 düzenlemede SIFIR boolean false-negative; çünkü `(?:^|\s)` interior `\n`'i `\s` ile yakalar, `(?:\s|$)` keza; diğer tüm builtin'ler `\b`-anchored, `\b` lokaldir, `\n` non-word olduğu için satır-içi ve run-içi aynı davranır). → Built-in'ler `fast_lane_safe` kontrolünden **MUAF**, ama bu güven committed bir oracle test ile pinlenir (§5).
- **`fast_lane_safe: bool` `Compiled`'a eklenir.** `compile_merged_rules` ([rules.rs:1013](../../../src/rules.rs#L1013)) içinde hesaplanır: `true` **eğer** built-in OLMAYAN (user/theme/profile, `rule.source != Builtin`) hiçbir pattern source'u `^`, `$`, `\A`, `\z` token'larından birini içermiyorsa.
- **Neden raw substring scan SOUND (over-approximation):** regex crate'in look-around'u YOK; `\Z` yok (compile error); whole-run-boolean'ı bozan TEK construct bu dört anchor'dır. Her anchor source'ta literal karakteriyle (`^`/`$`/`\A`/`\z`) görünür — onları yazmanın başka yolu yok. Dolayısıyla substring scan bir anchor'ı ASLA KAÇIRMAZ (under-disable imkânsız → unsound olamaz). Yalnız `\^` (escaped), `[$]` (char-class), `a\$b` gibi durumları fazladan flag'ler → o config'lerde fast-lane kapanır → DOĞRU ama biraz yavaş (over-disable safe). `(?s)`/`(?m)` yalnız *fazla* eşleştirir (false-positive → per-line'a düşer → safe), disable gerektirmez. (Rust senior'ın HIR-walk önerisi daha hassas ama yeni `regex-syntax` direct-dep + walk-bug riski; over-disable nadir olduğu için substring tercih edildi. Impl isterse HIR-walk'a yükseltebilir — ikisi de sound; substring default.)

### 4.5 Partial-tail ve byte-exactness

- Fast-lane yalnız `run[..=last_nl]`'i verbatim yazar; `\n` sonrası tail `feed_data_run`'e gider (identical buffering, `last_write` timestamp, overflow framing — guard (3) sayesinde bu tail'de overflow olamaz).
- **Newline re-emit identity:** per-line no-match yolu satır başına `apply_rules_with(stripped_line)` → boş `runs` → `out.write_all(&line[0..])` (stripped içerik, [pipeline.rs:103](../../../src/pipeline.rs#L103)) + caller `out.write_all(b"\n")` ([pipeline.rs:488](../../../src/pipeline.rs#L488)). Birleştirince = `stripped_0 \n stripped_1 \n …` = orijinal `run[..=last_nl]` BİREBİR. CRLF: `feed_data_run` yalnız `\n`'de böler → `\r` stripped satırın son byte'ı kalır; iki yol da identical korur (gelecekte "trailing whitespace trim" refactor'u bunu bozmasın diye §5'te pinlenir).
- **`tick`/`drain` etkilenmez (explicit non-goal):** fast-lane yalnız `feed`'in Ground branch'inde, `buffer.is_empty()` iken tetiklenir; verbatim prefix zaten wire'da, yalnız tail buffer'lı → `tick` ([pipeline.rs:681](../../../src/pipeline.rs#L681)) / `drain` ([pipeline.rs:699](../../../src/pipeline.rs#L699)) bugünküyle aynı partial'ı görür. Spec bunu non-goal olarak yazar.
