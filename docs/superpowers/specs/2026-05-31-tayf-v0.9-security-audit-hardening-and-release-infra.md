## §4 — Kapsam: dört faz

### Faz A — Hardening & adversarial test altyapısı (TDD, subagent-driven)

**A1 — Fuzzing harness (cargo-fuzz + checked-in regression; Karar 4 hybrid).**
- `fuzz/` ayrı cargo-fuzz workspace (libFuzzer, nightly toolchain). Ürün crate'in dependency tree'sini ETKİLEMEZ (ayrı `fuzz/Cargo.toml`, workspace exclude).
- ~4 target:
  1. `ansi_sm` — `AnsiSm` byte-by-byte feed; chunk-boundary CSI/OSC/DCS/SOS-PM-APC split; cap (`SEQUENCE_BYTES_CAP`) fire; invariant: panic yok, state machine her byte'ı tüketir, ground'a döner.
  2. `line_buffer` — `feed_data_run` + overflow path; invariant: 64 KB cap aşılmaz, panic yok, UTF-8 split'te invalid-slice yok.
  3. `pipeline_feed` — full `Pipeline::feed`. **İki ayrı oracle (paralel review R1 düzeltmesi — naive "byte-identical" YANLIŞTI):**
     - **(a) `apply_rules` granülaritesinde passthrough oracle:** `Compiled::empty()` ile herhangi bir satır için `apply_rules` çıktısı girdiyle byte-for-byte aynı (mevcut `apply_rules_no_set_hits_emits_line_byte_identical` testinin fuzz'a genişletilmiş hali, `src/pipeline.rs:1122`).
     - **(b) `Pipeline::feed` granülaritesinde injection-shape oracle:** `feed`'in girdide olmayan ekleyebileceği TEK bytelar (i) eşleşmeler etrafında SGR introducer `\x1b\[[0-9;]*m` + kesin reset `\x1b[0m` (`src/style.rs:449-476,480`), ve (ii) yalnızca `ForceStringTerminate`'te (cap-overflow) sentetik ST `\x1b\\`. Kural seti boşken (i) hiç ateşlenmez → invariant: *çıkış == girdi, modulo cap-overflow noktalarındaki sıfır-veya-daha-fazla `\x1b\\` ST*. Assert: "orijinalin getirmediği geniş-etkili kod (`\x1b[2J`, DECSET vb.) ASLA introduce edilmez" — ham eşitlik DEĞİL. NOT: naive byte-identity bir fuzzer'ın saniyeler içinde bulacağı 4097-byte terminator'sız OSC'de yanlış crash verirdi.
  4. `regex_compile` — user-pattern derleme; arbitrary pattern string `RegexBuilder` + `size_limit`/`dfa_size_limit` altında; invariant: derleme ya başarılı ya temiz hata, panic/timeout/OOM yok. (Motor linear-time + look-around'suz — backtracking blowup aranmaz; bkz. A3 + [feedback-regex-engine-lookaround-check].)
- Commit'li **seed corpora** (`fuzz/corpus/<target>/`); minimal başlangıç + edge-case seed'leri.
- **Crash → kalıcı regresyon:** bulunan her crash input'u `tests/` altında stable (`cargo test`, nightly gerektirmez) bir regresyon testine indirgenir. Fuzzing keşif, `tests/` koruyucu.
- **CI:** AYRI bir nightly fuzz smoke **job**'ı (`dtolnay/rust-toolchain@nightly`, kendi job'ı — mevcut stable job'ları mutate ETMEZ), her target ~60s; regresyon kapısı, derin keşif değil. Derin keşif local (`cargo fuzz run`). cargo-fuzz nightly + ASan gerektirir (`-Z sanitizer=address`); self-hosted Linux runner'da `llvm-tools` + izin-veren kernel mmap doğrulanmalı (§9 açık soru). Fuzz profili sanitizer için `panic=unwind` kullanır → abort-yolu burada test EDİLEMEZ (o, A2'nin release/abort regresyon testinin işi).
- **Fuzz erişim mekanizması (paralel review R2 + 🔵-3 sentezi; §9.3 ÇÖZÜLDÜ):** dört target'ın hiçbiri şu an external crate'ten erişilebilir DEĞİL (`AnsiSm`/`LineBuffer`/`Pipeline::feed`/regex-builder hepsi `pub(crate)`). Mekanizma: **`#[cfg(fuzzing)] pub mod __fuzz__`** (yeni `ansi_sm` + `line_buffer` wrapper'ları için) — cargo-fuzz path-dep grafiğine `--cfg fuzzing`'i otomatik geçer; normal/`cargo publish` build'inde modül YOK → published API surface sıfır, `cargo metadata`/SBOM temiz (yayımlanan `feature` DEĞİL). `pipeline_feed` + `regex_compile` mevcut always-on `#[doc(hidden)] pub mod __bench__` (`src/lib.rs:1077`, `BenchPipeline` + `load_builtin_rules`/`load_with`) üzerinden — yeni surface yok. **`fuzz/` kendi workspace'i** (`cargo fuzz init` `fuzz/Cargo.toml`'a boş `[workspace]` ekler); **parent'ın `[workspace]` tablosu YOK — eklenmeyecek** (eklenirse `fuzz/` ürün ağacına girer). Impl'de doğrula: kullanılan cargo-fuzz sürümü path-dep'lere `--cfg fuzzing` set ediyor mu (default evet).

**A2 — Adversarial regression testleri (stable, `tests/`).**
- partial-CSI-split: CSI/OSC dizisi her byte sınırında bölünüp ayrı chunk'larla beslenince doğru parse + chunk-boundary byte-identity.

- SGR-line stress: `respect_existing_colors` true/false altında SGR-yoğun satır; passthrough vs apply doğruluğu.
- panic-in-output-thread integration: output thread'de panic tetiklenince child shell termios'u (echo/line-discipline) restore ediliyor mu. **KRİTİK (review R3):** bu test **release/`panic=abort` build altında** çalışmalı — dev/unwind profilinde panic `Drop` ile restore olur ve abort-only yolu sessizce atlanır. `panic=abort`'ta `Drop` (`src/tty_guard.rs:93-108`) çalışmaz (unwind yok → destructor skip); restore TAMAMEN panic-hook'a (`src/tty_guard.rs:113-135`) dayanır. `std::panic::set_hook` abort runtime'ında da hook'u çalıştırır (std docs doğrulandı) → hook abort-öncesi termios restore eder. Test profili pinli olmalı; load-bearing test budur.
- signal-to-foreground-process-group integration: shell altında foreground subprocess'e SIGINT/SIGTERM grup'a ulaşıyor mu, orphan kalıyor mu.

(2) Linear motorun gerçek DoS vektörü match değil **compile/cache büyümesi**: `size_limit`/`dfa_size_limit` reddi ateşliyor mu (mevcut `load_rejects_pattern_exceeding_size_limit` `src/rules.rs:2515`'i *tamamlar*, tekrarlamaz) + 1 MiB cap altında distinct-DFA-state maksimize eden pathological girdide lazy-DFA cache büyümesi bounded (worst-case constant-factor, super-linear değil).
