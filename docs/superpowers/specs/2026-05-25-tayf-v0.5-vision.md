# tayf v0.5 — Genişletilebilirlik + Config TUI (Umbrella Vision)

**Tarih:** 2026-05-25
**Kapsam:** v0.4 minor'ün perf push'u (`apply_rules` RegexSet pre-filter + Pipeline-owned scratch + bench-CI) tamamlandı. v0.5 user-config layer'ına ergonomi getirir: capture-group naming, profile system, built-in profile library, ve `tayf config` interaktif TUI. Dört sub-version, her biri kendi spec/plan/release döngüsüyle ship olur. Bu doküman v0.5'in **çatısıdır**, implementation spec'i değil. Sub-version brainstorming'inde her detay yeniden açılabilir.
**Prereqs:** v0.4.1 yayınlanmış (✅ shipped 2026-05-25, tag `v0.4.1`, SHA `c4548fc`). `cargo audit && cargo deny check` yeşil. `Args`, `Error`, `ThemeRuleErrorKind` `#[non_exhaustive]`. v0.4.1 final cross-cutting review CLEAN_SHIP — v0.5 carryover-free başlar.

## 1. Vizyon

v0.3 minor + v0.4 minor boyunca tayf **doğru ve performant** hale geldi: VTE state machine, alt-screen passthrough, otomatik bg detection, escape hatches, disk themes, capture-group styling, RegexSet pre-filter, bench-CI. v0.5 odağı kullanıcının config layer'ıyla nasıl etkileştiği:

- Pattern override yazarken capture-group'lara isimle erişebilmek (`styles.scheme` vs `styles."1"`).
- Birden fazla rule profile'ı tanımlayıp komut bazında switch etmek (`tayf --profile k8s`).
- Common ecosystem'ler için curated profile library (network/k8s/docker/web/AWS/GCP).
- Config'i text editor yerine fullscreen TUI'da preview'lı düzenleyebilmek.

### 1.1 Hedefler

- **v0.5.0:** GHA `actions/upload-artifact` bump (`@v4` → `@v7`, v0.4.1 N-1 forward-pointer, 2026-06-02 Node.js 20 deprecation cutoff) + capture-group naming retrofit (built-in `permission`/`timestamp` ISO branch/`url` first branch regex'leri `(?P<name>...)` ile retrofit; TOML resolution numeric + named dual-key kabul).
- **v0.5.1:** Profile system. `[profiles.NAME]` TOML sections, `--profile NAME` CLI flag, profile-level rule override / append / disable. v0.5.0 named-key disiplini profile schema'sına inherit edilir.
- **v0.5.2:** Built-in profile library. `assets/profiles/{network,k8s,docker,web,aws,gcp}.toml` curated bundles. Her profile pattern + theme bundle.
- **v0.5.3:** `tayf config` interaktif TUI. `ratatui` ile fullscreen, resize-safe; canlı preview, color picker, theme/profile switch; `tayf config dump` (built-in pattern'ları TOML'a dök) + `tayf config status` (hot-reload watcher state).

### 1.2 Hedef olmayan (v0.6+ veya sonraki)

- **Aho-Corasick direct dep + manuel literal routing.** `aho-corasick` zaten `regex`'in transitive dep'i (`Cargo.lock`'ta mevcut); soru direct dep yapmak. v0.4.0 RegexSet ship sonrası `log_level`-dominated fixture'da pratik kullanıcı feedback'i ile hot-loop görünmüyor; bench-CI baseline'lar mevcut fixture'larda bu shape'i kapsamıyor. Manuel routing ölçmeden eklemek premature. v0.6+'a defer; explicit dep yerine pattern shape değişikliği (örn. `?-u` flag, `\b` kaldırma) öncelikle değerlendirilir.
- **Streaming heuristics** (saniyede X byte üstünde block-level matching'e geçiş) — v0.4.0 sonrası real-world bottleneck signal yok. v1.0+'a defer.
- **Windows ConPTY** — master design §11 "Sonraki" + CLAUDE.md "v1.0+ scope". v0.5 dışı.
- **Per-bench `std_dev_ns`-based dynamic thresholds** (v0.4.1 final review Rec #5). Current fixed thresholds (`apply_rules/*` +20% / `passthrough/write_all` +30%) first-try calibrated correctly: v0.4.1 ubuntu worst-case `passthrough/write_all` +7.57%, macos worst-case +19.33% — comfortably under thresholds. False-positive annotation fires veya runner topology değişir → revisit.
- **Plugin sistemi (WASM)** ve **statistical/contextual rules** (örn. her unique IP'ye farklı renk) — master design §11 "Sonraki" bucket.

## 3. Sub-version scope notları

Her bölüm 1-2 paragraflık scope iskeleti. Full design JIT olarak her sub-version'ın kendi spec'inde yazılır.

### 3.1 v0.5.0 — GHA bump + capture-group naming retrofit

İki ortogonal iş, atomic commits.

**İş A — `.github/workflows/ci.yml` `upload-artifact` bump.** Mevcut `actions/upload-artifact@v4` ([.github/workflows/ci.yml:146](.github/workflows/ci.yml#L146)) → `@v7`. v0.4.1 final review §N-1 forward-pointer `@v5`'i hedeflemişti; v0.5 spec phase'inde release history verified — `@v5` hâlâ Node 20 territory, `@v6` Node 24'e geçiş (`runs.using: node24`, requires runner ≥ 2.327.1), `@v7.0.1` current major (published 2026-04-10). `@v5`'e bumping deprecation uyarısını **temizlemez**; doğru hedef `@v7`. Sub-version spec'te bu correction'ın v0.4.1 review §N-1'e retroactive note olarak işlenmesi de planlanır.

**İş B — Capture-group naming retrofit.** v0.3.5 positional `styles."N"` mekanizmasına named-key kapasitesi eklenir. Üç built-in capture-styled pattern'ın regex source string'leri `(?P<name>...)` ile yeniden yazılır: `permission` (`perm_type` / `perm_owner` / `perm_group` / `perm_other` — Rust senior reviewer I-5 absorb gereği `type`/`user`/`group`/`other` rename'lendi: `type` Rust keyword, `group` Unix-perm + regex-group + TOML-key olarak triple-overloaded, `user` Unix-incorrect → `owner` doğru), `timestamp` ISO branch (`date` / `sep` / `time` / `ms` / `tz`), `url` first branch (`scheme` / `sep` / `body`). `Compiled.group_styles` shape **unchanged** (index-based, `Vec<Vec<Option<Style>>>`); name resolution **compile-time** (`regex.capture_names()` ile name → index map), runtime hot path (`captures.get(idx)`) byte-identical. **Zero perf delta.**

TOML resolution dual-key: `styles."1"` (positional, v0.3.5 byte-identical) ve `styles.scheme` (named) aynı capture-group'u hedefler. Dispatch order **explicit ve fall-through yok** (Rust senior reviewer I-1 absorb gereği): `key == "0"` → `CaptureGroupIndexZeroForbidden`; all-digit key → `validate_styles_map_key` (existing positional path), `None` → `CaptureGroupKeyMalformed` (NOT named fall-through); else → named resolution. Bu order `styles."01"`'in v0.3.5 grammar gate'ini koruması için kritik (existing `integration_capture_groups.rs:385` regression-guarded). Duplicate target (numeric + named same index): `CaptureGroupDuplicateTarget` error.

Tam spec: `docs/superpowers/specs/2026-05-25-tayf-v0.5.0-gha-bump-and-capture-group-naming.md`.

### 3.2 v0.5.1 — Themes Phase-1 grammar gate fix

v0.5.0 final cross-cutting review §I-1 + §I-2 carryover. `themes::validate_theme_rules` Phase-1 grammar gate ([src/themes.rs:421](src/themes.rs#L421)) non-digit styles-map key'lerini (`styles.scheme`, `styles.date` vb.) dispatch'e delege eder. Önceki davranış: tüm non-digit key'leri `CaptureGroupKeyMalformed` reject ediyordu — `RuleSource::Theme` named-key support production'da dead-code'du. Option (b) "mirror dispatch" broadening (~10 LOC production) + 1 unit test + 3 integration test (happy-path + unknown-name + duplicate-target — her biri dispatch'in daha önce unreachable bir Theme arm'ını exercise eder). Public API additive-only; hot-path byte-equal; built-in theme (`dark`/`light`) davranışı değişmedi.

Tam spec: `docs/superpowers/specs/2026-05-25-tayf-v0.5.1-themes-phase1-gate-fix.md`. v0.5.1 spec §11 forward-pointer'ları v0.5.2/v0.5.3 brainstorm'ları için load-bearing.

### 3.3 v0.5.2 — Profile system mekanizması

Profile system kullanıcıya named bundles tanımlama imkânı verir: hangi rule'lar aktif, hangi pattern override edildi, hangi theme uygulandı — hepsi profile-level. **Bu sub-version sadece mekanizma; built-in library v0.5.3'e bırakılır.** v0.5.1 spec §11.1'de absorbed Rust-senior architectural soruları (C-1..I-6) v0.5.2 spec'ine input olarak girer. Aday TOML schema (sub-version brainstorming pin'ler):

```toml
[profile.default]
rules = "all"           # default: tüm built-in'ler

[profile.network]
rules = ["ipv4", "ipv6", "mac", "fqdn", "url"]     # whitelist

[profile.k8s]
rules = ["timestamp", "log_level", "uuid"]
append_rules = [
    { name = "pod_name", pattern = "\\b[a-z]+-[a-z0-9]+\\b", style = { fg = "cyan" } },
]
```

CLI: `tayf --profile network`. Profile yokken (default) tüm built-in'ler aktif (mevcut davranış). Profile shape (rules whitelist mı blacklist mı, multiple profiles birleştirilebilir mi, profile-level theme override mantığı) brainstorm'da netleşir. Capture-group naming (v0.5.0) profile-level rule TOML'ında inherit edilir.

### 3.4 v0.5.3 — Built-in profile library

`assets/profiles/` altında curated profile dosyaları. v0.5.1 spec §11.2'de absorb edilen domain-senior pattern audit'i bu sub-version'a load-bearing input: 9 orijinal aday pattern'den **5 drop** (`namespace`, `project_id`, `image_tag`, `container_id`, `gcp resource_id` — shape-collision veya domain-specific value erozyonu), **3 reshape** (`pod_name` trailing `-[a-z0-9]{5}` suffix + `arn` right-anchor + `container_id` 64-hex veya context-prefix), **1 audit** (`region` exhaustive enumeration), **1 ship-as-is** (`instance_id`). gcp / docker profile filter-only kalır mı yoksa drop edilir mi v0.5.3 brainstorm'da kararlaşır.

Built-in pattern bar (memory `feedback_builtin_pattern_bar`): her yeni profile pattern shape-unique ve prose-immune olmak zorunda; high-FP patterns user-config yoluna düşer. Brainstorm her pattern için adversarial input + benchmark.

### 3.5 v0.5.4 — `tayf config` interaktif TUI

`tayf` binary'sine alt-komut: `tayf config`. `ratatui` dep'iyle (yeni dep, justification: en aktif maintained Rust TUI framework; `crossterm` zaten transitive). Özellikler:

- Pattern list browse + edit
- Color picker (ANSI / 256 / truecolor)
- Theme + profile switch
- Canlı preview (sample input + rendered output)
- `tayf config dump` — built-in pattern'ları TOML'a dök (stdout)
- `tayf config status` — hot-reload watcher state + last error + reload count

**TUI design için frontend-design plugin'iyle iteratif mockup → kod loop'u** (kullanıcı 2026-05-25 mandate). Pixel-perfect kararlar (key bindings, layout, color palette) mockup'larla validate edilir; kod ondan sonra. Sub-version brainstorming bu loop'u plan'a yapıştırır.

## 4. Cross-cutting kararlar

Bu kararlar v0.5'in tüm sub-version'ları için locked. Sub-version spec'lerinde tartışılmaz, refere edilir.

### 4.1 Backward compatibility

- v0.4 boyunca shipped config schema (CLI flags, theme TOML, user rules `[[rules]]`) kırılmaz. v0.5.0+ shimless okunur.
- `Args`, `Error`, `ThemeRuleErrorKind` `#[non_exhaustive]` — yeni variant additive.
- v0.5.0 positional `styles."1"` kontratı byte-identical (named key additive accept).
- v0.5.1 themes Phase-1 broadening additive — built-in theme (`dark`/`light`) davranışı değişmedi; tek değişiklik daha önce reject edilen non-digit theme-TOML styles key'lerinin artık accept edilmesi.
- v0.5.2 profile yokken default davranış mevcut (`--profile` opsiyonel; profile yoksa tüm built-in'ler aktif).
- v0.5.4 `tayf config` alt-komut; mevcut `tayf` invocation (PTY wrapper) davranışı değişmez.

### 4.2 Performans bütçesi

- v0.4.1 baseline JSON canonical (`benches/baselines/v0.4.1/{ubuntu,macos}-latest.json`, `benches/baselines/latest/` mirror). v0.5 hot-path-touching iş için post-tag baseline write step (v0.4.1 ceremony).
- v0.5.0 compile-time-only (zero runtime delta); baseline regen **pro forma skip** — `latest/` mirror v0.4.1'i pointing kalır.
- v0.5.1 Phase-1 broadening config-load path'inde (hot-path-off); baseline regen yok.
- v0.5.2+ profile shape sub-version brainstorm'unda perf evaluation: profile-level rule routing `apply_rules` hot path'ine girer mi? RegexSet pre-filter profile-aware mı? Brainstorm pin'ler.
- v0.5.4 TUI ayrı process / alt-mode; PTY hot path'i etkilemez.

### 4.3 Güvenlik

CLAUDE.md §3 mandates aktif:
- v0.5.0 regex named-group syntax = regex 1.12 stable API; no new attack surface. TOML key parsing path unchanged (`toml` crate deserialization, mevcut path).
- v0.5.1 themes Phase-1 broadening: no new attack surface — non-digit key'ler dispatch'in zaten var olan named-resolution path'ine düşer; theme name validation (`name_is_valid`) değişmedi.
- v0.5.2+ profile TOML schema = mevcut deserialization path; new injection sources yok. Profile names alphanumeric+dash, sanitize before display.
- v0.5.4 `ratatui` dep audit gerekli — maintenance status, transitive deps, `unsafe` lines, license. Security review gate before commit.

### 4.4 Dependency policy

- **v0.5.0 / v0.5.1 / v0.5.2 / v0.5.3: yeni Cargo dep yok.** Memory `feedback_dependency_minimalism` + CLAUDE.md §3.
- **v0.5.4 `ratatui`** — yeni direct dep. Sub-version brainstorm'da audit + justification commit message'da: maintenance status (active, weekly commits), license (MIT), `unsafe` lines (zero per audit), surface area, alternative değerlendirme (cursive, termion, manual termios).

### 4.5 Test stratejisi

- Zero-regression invariant her sub-version'da pin'lenir. v0.5.0: `tests/integration_capture_groups.rs` 9 test byte-identical; `git diff v0.4.1..HEAD -- tests/integration_capture_groups.rs | wc -l` = 0 (existing); additive new tests OK.
- Display tests byte-pinned (memory `feedback_test_assertion_specificity`); `.contains("substring")` yasak.
- Duplicate-formatter audit her sub-version'da grep edilir (memory `feedback_duplicate_formatter_audit`): `grep -n 'format!.*rule .{}' src/rules.rs` — inline format reconstruction yoksa OK.
- bench-CI (v0.4.1 infra) canonical scaffolding; v0.5 hot-path-touching iş için canonical baselines re-recorded post-tag.

### 4.6 Release workflow

Memory `tayf release workflow` + v0.4.1 ceremony pattern:

1. Sub-version commit'leri main'e.
2. Push main → CI yeşil bekle. macOS GHA flake ise `gh run rerun --failed` (memory `feedback_flaky_watch_test`).
3. CHANGELOG TBD commit (`## [X.Y.Z] — TBD`).
4. Version bump commit.
5. Annotated tag (`vX.Y.Z`, `tayf vX.Y.Z — <title>` mesajı).
6. Post-tag:
   - Baseline write (gerekirse) + CHANGELOG date + umbrella shipped marker (§2 row → ✅).
   - **Final cross-cutting opus 4.7 senior review zorunlu** (memory `feedback_cross_cutting_review_value`). Per-task review'lar yakalayamayan latent issue'ları yakalar.
7. Memory updates: `project_vX_Y_Z_shipped.md` + `MEMORY.md` index.
