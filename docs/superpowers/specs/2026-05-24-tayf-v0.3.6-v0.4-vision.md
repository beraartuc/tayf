**Tarih:** 2026-05-24
**Kapsam:** v0.3 minor'üne deferred bugfix patch'iyle son nokta (v0.3.6), ardından v0.4 minor'ü için iki sub-version perf push (v0.4.0 + v0.4.1). Her sub-version için tam tasarım dokümanı (`2026-MM-DD-tayf-vX.Y.Z-<topic>.md`) JIT olarak yazılır.

## 1. Vizyon

v0.3 boyunca tayf **doğru ve özelliklerle dolu** hale geldi: VTE state machine, alt-screen passthrough, otomatik bg detection, escape hatches, disk themes, capture-group styling. v0.3.5 ship sonrası iki kırılma noktası kaldı:

- **v0.3 minor'üne saf semver kapanış.** v0.3.5 final-review ve sonrası post-tag inceleme iki gerçek bug çıkardı (`ThemeRuleErrorKind::CaptureGroupIndexOutOfRange` Display'i edge case'te yanlış, integration + unit test ismi gövdesini hatalı tasvir ediyor). Bunlar pure bugfix → v0.3.6 patch.
- **Performans push'u başlangıcı.** `Compiled.set: RegexSet` v0.1'den beri populated ama unused (`#[allow(dead_code)] // reason: reserved for v0.4 RegexSet fast-path` notuyla `src/rules.rs:549`). `apply_rules` her satırda 13 bireysel regex'i lineer geziyor. v0.3.5 overlap-check refactor'u ipv4-heavy benchmark'ını 7.73 ms → 2.42 ms düşürdü (%68.7); RegexSet pre-filter buna eklenince miss-heavy input'larda ek order-of-magnitude beklenir.

### 1.1 Hedefler

- **v0.3.6:** v0.3 minor'üne pure semver patch — Display message edge case fix + iki test (unit + integration) ismi/gövdesi reconciliation. Hot path'e dokunulmaz, BASELINE.md değişmez.
- **v0.4.0:** `Compiled.set` üzerinden RegexSet pre-filter → sadece hit eden rule'lar için bireysel `find_iter`/`captures_iter` dispatch. `apply_rules` per-call scratch Vec'leri (`accepted_spans`, `runs`, `event_scratch`, `active_scratch`, yeni `set_match_scratch`) Pipeline-owned hale gelir, per-line allocation yok.
- **v0.4.1:** Bench-CI + regression detection. Criterion `--save-baseline` + GitHub Actions workflow ile her PR'da otomatik karşılaştırma, %20 spec threshold breach uyarısı.

### 1.2 Hedef olmayan (v0.5+ veya sonraki'ye ertelenmiş)

- **Aho-Corasick direkt crate kullanımı + manuel literal routing** — `aho-corasick` zaten `regex`'in transitive dep'i (`Cargo.lock`'ta mevcut); soru direct dep yapmak. `regex` crate'in meta-engine'i pure-literal alternation'da Teddy/AC-tabanlı multi-pattern prefilter'a düşebilir, ama bu bizim patternlerimize garanti uygulanmıyor — `\b(ERROR|FAIL|FATAL)\b` gibi anchor'lı veya `(?i)` flag'li alternation prefilter yolundan çıkabilir. - **Streaming heuristics** (saniyede X byte üstünde block-level matching'e geçiş) — pratik kullanıcı feedback'i yok. v0.4.0 RegexSet sonrası BASELINE muhtemelen kullanıcının hissedebileceği bottleneck'leri eliyor. v0.5+'a defer.
- **Capture group naming** (`?P<name>` styling) — v0.5 capability'si.
- **Profile system** ve **`tayf config` interaktif TUI** — v0.5.

## 3. Sub-version scope notları

Her bölüm 1-2 paragraflık scope iskeleti. Full design JIT olarak her sub-version'ın kendi spec'inde yazılacak.

### 3.1 v0.3.6 — Deferred bugfix patch

**Fix A — `ThemeRuleErrorKind::CaptureGroupIndexOutOfRange` Display edge case** (`src/error.rs:97-107`):

Şu anki Display tüm vakaları tek branch'le render ediyor (`let n = captures_len.saturating_sub(1); write!(f, "rule's regex has {n} capture group{s} (valid: 1..={n})")`). `n >= 1` için mesaj **zaten doğru ve pluralization helper'ı (`if n == 1 { "" } else { "s" }`) düzgün çalışıyor** — örn. `captures_len == 3` + `group == 5` durumu `"rule's regex has 2 capture groups (valid: 1..=2)"` üretir, kullanıcıya net. Bug **yalnızca `n == 0`** (`captures_len == 1`, yani no capture groups) branch'inde: `"rule's regex has 0 capture groups (valid: 1..=0)"` — boş range matematiksel olarak anlamsız, kullanıcıya ne yapacağını söylemiyor.

**Specialize:** Display'i iki branch'e böl. `n == 0` → `"styles.\"{group}\": rule's regex has no capture groups; styles cannot be set"`. `n >= 1` → mevcut format aynen korunur (pluralization helper'a dokunulmaz). CLAUDE.md §4 "Error messages are user-facing UX" mandate'iyle uyumlu (what failed + why + what to do).

**Fix B — Test ismi/gövdesi reconciliation** (iki kopya):
- `src/pipeline.rs:539` — `syslog_timestamp_match_renders_one_sgr` unit test. Yorum satırı (`src/pipeline.rs:546`) zaten itiraf ediyor: "log_level rule will catch 'msg' — that's an extra SGR. Assert the substring appears in output (basic survival check)." İsim "renders_one_sgr" diyor ama gövde sadece `s.contains("May 24 10:30:45")` kontrol ediyor.
- `tests/integration_capture_groups.rs:165` — aynı isim, aynı pattern (substring containment only).

Sub-version brainstorming'inde karar: (a) İki testin de ismi `_substring_survives_colorization` olarak rename; veya (b) gövdelere `count_non_reset_sgrs(&s) >= 1` assertion ekle (helper integration test'te zaten `tests/integration_capture_groups.rs:116`). Tercih (a) çünkü syslog branch'in 1 vs N SGR sayısı `log_level` rule'ının fixture'da hit etmesine bağlı — substring survival contract'ı daha net.

**Kapsam dışı:** Hot path'e dokunma yok. BASELINE.md değişmez. `Compiled.set` hâlâ unused (v0.4.0'a ait). CHANGELOG entry "Fixed" başlığı altında iki satır.

### 3.2 v0.4.0 — RegexSet fast-path + Pipeline-owned scratch Vec'leri

**Bölüm A — RegexSet pre-filter:**

`Compiled.set: RegexSet` (`src/rules.rs:550`) v0.1'den beri populated ama `apply_rules` onu kullanmıyor. v0.4.0 değişikliği:

1. `apply_rules` baş tarafında set hit'lerini Pipeline-owned scratch'e yaz (pseudocode, sub-version spec gerçek API'yi pin'ler):
   ```rust
   // pseudocode — gerçek shape sub-version'da pin'lenir.
   pipeline.set_match_scratch.clear();
   pipeline.set_match_scratch.extend(compiled.set.matches(line).iter());
   let hit_indices = &pipeline.set_match_scratch[..];
   ```
   **API notu:** `regex::bytes::RegexSet::matches(haystack) -> SetMatches` (regex 1.12 stable surface); doğrudan `matches_into(&mut Vec)` yok, `SetMatches::iter()` üzerinden `extend` standart pattern. Sub-version spec iki shape'i karşılaştırır: (i) `Vec<usize>` indirection (yukarıda) — extra bounds check ama cache-friendly; (ii) bitset üzerinde inline iter — alloc yok ama dispatch branch'i daha karmaşık. Benchmark her ikisini ölçer.
2. Sonra `compiled.individuals` üzerinde tam tarama yerine sadece `hit_indices` içindeki index'ler için dispatch. Selective dispatch'ın v0.3.5'te kurulan dual-path mantığı (`uses_capture_styling[idx]` → `find_iter` vs `captures_iter` + `emit_capture_runs`) **aynen korunur**, sadece dış loop kısa.
3. `#[allow(dead_code)] // reason: reserved for v0.4 RegexSet fast-path` notu (`src/rules.rs:549`) kaldırılır.

**Capture-group styling kontratı korunur:** RegexSet sadece pre-filter; per-regex capture extraction hâlâ individual regex'lerden gelir. v0.3.5'in `emit_capture_runs` boundary-event sweep algoritması (`src/pipeline.rs:148-225`) ve match-level overlap detection (`accepted_spans` + `partition_point` O(log N)) byte-identical kalır. Bu zero-regression invariant'ı v0.4.0 spec'i test'leriyle açıkça pin'ler.

**Cross-rule ordering invariant:** `RegexSet::matches` index'leri pattern-definition order'ında verir (`sources` rule order'ında inşa olur, `src/rules.rs:841`); `apply_rules`'un first-match-wins overlap kontratı (`src/pipeline.rs:39` doc-comment) korunur. **Implementer notu:** iteration order'ı bozan bir container (HashSet, BTreeSet) ARAYA SOKULMAZ — `SetMatches::iter()` veya sorted `Vec<usize>` zorunlu.

**Bölüm B — Pipeline-owned scratch Vec'leri:**

`apply_rules`'un (`pub(crate) fn apply_rules<W: Write>`, `src/pipeline.rs:48`) her çağrısında allocate edilen 4 Vec — `accepted_spans`, `runs`, `event_scratch`, `active_scratch` — Pipeline struct'a field olarak taşınır + yeni `set_match_scratch` eklenir. `.clear()` ile reuse, per-line allocation sıfır.

**Bench-shim surface'i — kritik:** `apply_rules` `pub(crate)` olmasına rağmen `src/lib.rs:319-347`'de `#[doc(hidden)] pub mod __bench__` üzerinden `pub fn` olarak re-export ediliyor; `benches/throughput.rs:42` `use tayf::__bench__::{apply_rules, load_builtin_rules}` ile çağırıyor. Her iki refactor yaklaşımı da bu shim'i etkiler:
- **(a) free function imzasına `&mut PipelineScratch` parametresi** — shim ya per-call scratch allocate eder (BASELINE ölçümünü kirletir; v0.4.0 sayıları shim allocator'ını ölçer, scanner'ı değil), ya da `CompiledRules` shim newtype'ı scratch'i taşır (shape değişir).
- **(b) `apply_rules`'u Pipeline'ın `&mut self` method'una taşımak** — free function kalkar, shim ya `Pipeline` construct etmek zorunda (şu an `Arc<ArcSwap<Compiled>>` istiyor), ya da yeni `Pipeline::__bench_apply` entrypoint açar.

Sub-version spec **bench-callable shape'i pin'ler** ve "per-call scratch allocation olmadan çağrılabilir" garantisini yazar. Tercih (b) + Pipeline'a `pub fn __bench_apply` shim — bench harness deterministic, scratch reuse zaten Pipeline-içi. v0.4.0 BASELINE'ı bu shim üzerinden ölçer; v0.3.5 baseline'ıyla **like-for-like** karşılaştırma için `benches/throughput.rs` minimal değişiklikle Pipeline construct edip `__bench_apply` çağırır.

**Lifetime constraint — `runs`:** Şu anki shape `runs: Vec<(usize, usize, &Style)>` per-call `Arc<Compiled>` snapshot'ına borrow eder (`pipeline.rs:53`'teki `let snapshot = compiled_handle.load_full();`). Pipeline-owned olursa `'static` lifetime gerekir; üç seçenek (sub-version spec birini seçer): (i) `Style`'ı value olarak sakla (~16 byte, ucuz, clone semantiği temiz); (ii) `(start, end, rule_idx: u16)` sakla, `&Style`'a emit'te resolve et — tercih edilen, en küçük footprint; (iii) `runs` per-call kalsın, sadece `event_scratch` / `active_scratch` / `accepted_spans` / `set_match_scratch` Pipeline-owned olsun — partial fix. **`accepted_spans: Vec<(usize, usize)>`, `event_scratch`, `active_scratch`, `set_match_scratch` zaten lifetime-free; sadece `runs` constraint taşıyor.**

**Scope sınırı:** v0.4.0 sadece **per-line** scratch'leri Pipeline-owned yapar. Per-reload allocate'leri (`compile_merged_rules`'un `sources`, `individuals`, `styles`, `group_styles` allocate'leri, `src/rules.rs:841` civarı) ve startup allocate'leri v0.4.0 scope dışı — reload thread per-line cost'a contribute etmiyor, optimization hedefi değil.

**Beklenen perf delta — directional bands** (v0.3.5 BASELINE.md baseline'ına göre). RegexSet 10 miss-eden rule'u kısa-keser, ama 3 hit-eden rule'un cost'u kaybolmaz; her shape'in band'i hit/miss oranıyla ölçeklenir:

| Shape | v0.3.5 | v0.4.0 band | Gerekçe |
|---|---|---|---|
| `apply_rules/ipv4-heavy` | 2.4199 ms | %30-60 reduction (≈ 1.0-1.7 ms) | hit-heavy; saved work 10 miss'le sınırlı, set-scan cost ekleniyor |
| `apply_rules/mixed-syslog` | 2.2948 ms | %40-70 reduction (≈ 0.7-1.4 ms) | half-and-half hit ratio, RegexSet daha çok kaldıraç |
| `apply_rules/captures-heavy` | 4.5173 ms | %10-20 reduction (≈ 3.6-4.1 ms) | her captures rule fire ediyor; RegexSet pre-filter çoğu kez redundant |
| `passthrough/write_all` | 1.3380 µs | ±%5 (RegexSet hot path'e girmez) | apply_rules'a hiç girmeyen alt-screen/bracketed-paste yolu |

**Band'in altında kalmak ≠ regression**; sub-version spec measurement'a göre kesin sayı pin'ler. Bant'ler umbrella'nın "rev2 sırasındaki en iyi tahmini"dir, kontrat değildir. Floor §4.2'de tanımlanır (per-group noise budget).

### 3.3 v0.4.1 — Bench-CI + regression detection

## 4. Cross-cutting kararlar

Aşağıdaki kararlar v0.3.6 + v0.4'ün tüm sub-version'ları için locked. Sub-version spec'lerinde tartışılmaz, sadece refere edilir.

### 4.1 Backward compatibility

- v0.3 boyunca konuşulan config schema ve theme TOML kırılmaz. v0.4 boyunca v0.3 config dosyalarını shimless okur.
- v0.3'te shipped CLI flag'leri signature aynı kalır.
- `Args`, `Error`, `ThemeRuleErrorKind` `#[non_exhaustive]` — yeni variant additive.
- `Compiled::load_with_theme` imzası v0.4.0'da değişmez (RegexSet kullanımı internal, hot path detail).
- v0.3.6 saf semver patch — public API'de hiçbir değişiklik yok.
- v0.4.0'da `Pipeline` struct'a yeni private field'lar eklenir; `Pipeline::new` imzası değişmez. `apply_rules` `pub(crate)` ama **`src/lib.rs:319-347`'deki `#[doc(hidden)] pub mod __bench__`'ten `pub fn` olarak re-export ediliyor** ve `benches/throughput.rs:42` üzerinden çağrılıyor. Refactor bench-shim contract'ını korumak zorunda — §3.2 Bölüm B'de tercih edilen `Pipeline::__bench_apply` shim yaklaşımı + minimal `benches/throughput.rs` adjust. Per-call scratch allocation **yasak** (yoksa v0.4.0 BASELINE shim allocator'ını ölçer, scanner'ı değil). `#[doc(hidden)]` modül downstream crate'ler için stable contract değil, ama tayf'ın kendi bench harness'ı için load-bearing.

### 4.2 Performans bütçesi

- v0.3.5 BASELINE.md son satırı (2026-05-24, HEAD `e969024`) canonical baseline. v0.4 boyunca floor **per-bench-group** tanımlanır (literal "hiç regression yok" enforce edilmez — sub-µs benchmark'lar release'ler arası ±%15 jitter yapıyor, BASELINE v0.3.4 → v0.3.5 `passthrough/write_all` +%14.81 dalgalanması bunun kanıtı).
- **Per-group floor (v0.4 boyunca):**
  - `apply_rules/*` (ms-scale, deterministic): v0.3.5'ten **>%5 slower → review gate**, **>%20 slower → release-block**.
  - `passthrough/write_all` (sub-µs, jitter-prone): v0.3.5'ten **>%25 slower → review gate** (historical noise band ±%15); release-block yok (gerçek regression'u sub-µs ölçüm yakalayamıyor).
- v0.4.0 RegexSet ile beklenti: §3.2 tablosundaki directional bands. Sub-version spec band'in altında bir kesin sayı pin'ler.
- v0.4.1 CI threshold: workflow'un coarse single-number annotation kuralı (%20 breach → PR comment). **§4.2 floor'dan ayrı** — CI annotation operasyonel-uyarı, floor release-blocking review gate. İki katman ayrı politika.

### 4.3 Güvenlik

CLAUDE.md §3 mandate'leri tüm sub-version'larda geçerli:
- v0.3.6 saf bugfix — Display string'i kullanıcı output'una geçiyor (`Error::ThemeValidation` → stderr); sanitize_for_display zaten var, yeni branch onu kullanmaz çünkü tüm input static (integer literal).
- v0.4.0 RegexSet — `regex` crate zaten dep, RegexSet API'si aynı crate'in stable parçası, yeni runtime attack surface yok. Adversarial PTY output hâlâ `regex` crate'in ReDoS-safe linear-time engine'inden geçer (RegexSet bir bütün olarak aynı engine'i kullanır). `RegexSet::new` compile-time'da aggregate size cap'i (regex crate'in default'u) tetikleyebilir; `src/rules.rs:877` zaten `.map_err(Error::from)` ile handle ediyor, hot path bu hatayı görmez.
- v0.4.1 CI workflow — `benches/baselines/*.json` dosyaları git canonical, repo dışı state yok. Workflow secret'lere ihtiyaç duymaz.

### 4.4 Dependency policy

- **Yeni Cargo dep yok** — v0.3.6 + v0.4'ün tüm scope'u mevcut crates ile çözülür (`regex`, `criterion`, std). Manuel routing eklemeden önce pattern shape değişimi (örn. `?-u` flag, `\b` kaldırma) öncelikle değerlendirilir. v0.4.0 BASELINE ship sonrası `log_level`-dominated fixture'da hâlâ hot-loop görünürse v0.5+'da yeniden açılır.

### 4.6 Release workflow

Memory'deki `tayf release workflow` aynen:
1. Sub-version commit'leri main'e.
2. Push main → CI yeşil bekle. macOS GHA flake oluşursa `gh run rerun --failed` (memory `feedback_flaky_watch_test`).
3. Tag push (`vX.Y.Z`, annotated, `tayf vX.Y.Z — <title>` mesajı).
4. CHANGELOG date bump follow-up commit (release günü gerçek tarihiyle; ilk commit `## [X.Y.Z] — TBD` placeholder ile gider).
5. Bu umbrella doc'unun §2 tablosu güncellenir (shipped satır işaretli + §1.2 "Hedef olmayan"dan ilgili satırlar silinir, oraya yeni defer'lenler eklenir).

## 7. Bu doküman değiştirildiğinde

Umbrella, sub-version brainstorming'lerinin başlangıç noktası. Bir sub-version brainstorming'i sırasında umbrella'daki bir kararla çelişen bir karar ortaya çıkarsa:
- Sub-version spec'i çelişkiyi açıkça not eder.
- Umbrella'yı güncellemek için ayrı bir commit gerekir (umbrella git'te canonical; "memory"deki notlar değil).

`tayf-tasarim.md §11` (Yol Haritası) bu doküman ship olduktan sonra v0.3.6 ve v0.4'ün detaylarına link verecek şekilde güncellenir (separate commit, v0.3.6 release-prep'inden önce).
