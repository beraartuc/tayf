# tayf v0.3.6 + v0.4 — Saf Kapanış + Performans (Umbrella Vision)

**Tarih:** 2026-05-24
**Kapsam:** v0.3 minor'üne deferred bugfix patch'iyle son nokta (v0.3.6), ardından v0.4 minor'ü için iki sub-version perf push (v0.4.0 + v0.4.1). Her sub-version için tam tasarım dokümanı (`2026-MM-DD-tayf-vX.Y.Z-<topic>.md`) JIT olarak yazılır.
**Prereqs:** v0.3.5 yayınlanmış (✅ shipped 2026-05-24). `cargo audit && cargo deny check` yeşil. Tüm public API non-exhaustive (`Args`, `Error`, `ThemeRuleErrorKind`).

Bu doküman v0.3.6 + v0.4'ün **çatısıdır**, implementation spec'i değil. Buradaki kararlar sub-version spec'lerinin başlangıç noktasıdır; sub-version brainstorming aşamasında her detay yeniden açılabilir.

İki release'in tek umbrella altında bundle edilme nedeni: v0.3.5'in deferred 3. item'ı (`apply_rules` per-call scratch Vec allocations) Pipeline shape değişimi gerektiriyor; v0.4.0 RegexSet rewrite'ı zaten Pipeline'a dokunacak. Item'ın iki release arasındaki köprü olması umbrella-level karar — tek doc'ta hikaye coherent kalsın.

## 1. Vizyon

v0.3 boyunca tayf **doğru ve özelliklerle dolu** hale geldi: VTE state machine, alt-screen passthrough, otomatik bg detection, escape hatches, disk themes, capture-group styling. v0.3.5 ship sonrası iki kırılma noktası kaldı:

- **v0.3 minor'üne saf semver kapanış.** v0.3.5 final-review ve sonrası post-tag inceleme iki gerçek bug çıkardı (`ThemeRuleErrorKind::CaptureGroupIndexOutOfRange` Display'i edge case'te yanlış, integration + unit test ismi gövdesini hatalı tasvir ediyor). Bunlar pure bugfix → v0.3.6 patch.
- **Performans push'u başlangıcı.** `Compiled.set: RegexSet` v0.1'den beri populated ama unused (`#[allow(dead_code)] // reason: reserved for v0.4 RegexSet fast-path` notuyla `src/rules.rs:549`). `apply_rules` her satırda 13 bireysel regex'i lineer geziyor. v0.3.5 overlap-check refactor'u ipv4-heavy benchmark'ını 7.73 ms → 2.42 ms düşürdü (%68.7); RegexSet pre-filter buna eklenince miss-heavy input'larda ek order-of-magnitude beklenir.

### 1.1 Hedefler

- **v0.3.6:** v0.3 minor'üne pure semver patch — Display message edge case fix + iki test (unit + integration) ismi/gövdesi reconciliation. Hot path'e dokunulmaz, BASELINE.md değişmez.
- **v0.4.0:** `Compiled.set` üzerinden RegexSet pre-filter → sadece hit eden rule'lar için bireysel `find_iter`/`captures_iter` dispatch. `apply_rules` per-call scratch Vec'leri (`accepted_spans`, `runs`, `event_scratch`, `active_scratch`, yeni `set_match_scratch`) Pipeline-owned hale gelir, per-line allocation yok.
- **v0.4.1:** Bench-CI + regression detection. Criterion `--save-baseline` + GitHub Actions workflow ile her PR'da otomatik karşılaştırma, %20 spec threshold breach uyarısı.

### 1.2 Hedef olmayan (v0.5+ veya sonraki'ye ertelenmiş)

- **Aho-Corasick explicit dep + manuel literal routing** — `regex` crate'in heuristic'i pure-literal alternation'da (`ERROR|FAIL|FATAL|CRITICAL`) zaten internal Aho-Corasick DFA'sına düşüyor; bizim ekleyeceğimiz routing duplicate iş olur. v0.4.0 measurement gösterirse v0.5+.
- **Streaming heuristics** (saniyede X byte üstünde block-level matching'e geçiş) — pratik kullanıcı feedback'i yok. v0.4.0 RegexSet sonrası BASELINE muhtemelen kullanıcının hissedebileceği bottleneck'leri eliyor. v0.5+'a defer.
- **Capture group naming** (`?P<name>` styling) — v0.5 capability'si.
- **Profile system** ve **`tayf config` interaktif TUI** — v0.5.
- **Windows ConPTY** — v1.0+.

## 3. Sub-version scope notları

Her bölüm 1-2 paragraflık scope iskeleti. Full design JIT olarak her sub-version'ın kendi spec'inde yazılacak.

### 3.1 v0.3.6 — Deferred bugfix patch

**Fix A — `ThemeRuleErrorKind::CaptureGroupIndexOutOfRange` Display edge case** (`src/error.rs:97-107`):

Şu an `captures_len == 1` (no capture groups, sadece group 0 = full match) durumunda mesaj `"styles.\"1\": rule's regex has 0 capture groups (valid: 1..=0)"` üretiyor. "valid: 1..=0" matematiksel olarak boş aralık, kullanıcıya ne yapacağını söylemiyor. **Specialize:** `n == 0` ise mesaj `"styles.\"{group}\": rule's regex has no capture groups; styles cannot be set"` olur. CLAUDE.md §4 "Error messages are user-facing UX" mandate'iyle uyumlu (what failed + why + what to do).

**Fix B — Test ismi/gövdesi reconciliation** (iki kopya):
- `src/pipeline.rs:539` — `syslog_timestamp_match_renders_one_sgr` unit test. Yorum satırı (`src/pipeline.rs:546`) zaten itiraf ediyor: "log_level rule will catch 'msg' — that's an extra SGR. Assert the substring appears in output (basic survival check)." İsim "renders_one_sgr" diyor ama gövde sadece `s.contains("May 24 10:30:45")` kontrol ediyor.
- `tests/integration_capture_groups.rs:165` — aynı isim, aynı pattern (substring containment only).

Sub-version brainstorming'inde karar: (a) İki testin de ismi `_substring_survives_colorization` olarak rename; veya (b) gövdelere `count_non_reset_sgrs(&s) >= 1` assertion ekle (helper integration test'te zaten `tests/integration_capture_groups.rs:116`). Tercih (a) çünkü syslog branch'in 1 vs N SGR sayısı `log_level` rule'ının fixture'da hit etmesine bağlı — substring survival contract'ı daha net.

**Kapsam dışı:** Hot path'e dokunma yok. BASELINE.md değişmez. `Compiled.set` hâlâ unused (v0.4.0'a ait). CHANGELOG entry "Fixed" başlığı altında iki satır.

### 3.2 v0.4.0 — RegexSet fast-path + Pipeline-owned scratch Vec'leri

**Bölüm A — RegexSet pre-filter:**

`Compiled.set: RegexSet` (`src/rules.rs:550`) v0.1'den beri populated ama `apply_rules` onu kullanmıyor. v0.4.0 değişikliği:

1. `apply_rules` baş tarafında `let set_matches = pipeline.set_match_scratch.clear(); compiled.set.matches_into(line, &mut set_matches);` — hangi rule indices hit edebilir öğren.
2. Sonra `compiled.individuals` üzerinde tam tarama yerine sadece `set_matches` içindeki index'ler için dispatch. Selective dispatch'ın v0.3.5'te kurulan dual-path mantığı (`uses_capture_styling[idx]` → `find_iter` vs `captures_iter` + `emit_capture_runs`) **aynen korunur**, sadece dış loop kısa.
3. `#[allow(dead_code)] // reason: reserved for v0.4 RegexSet fast-path` notu (`src/rules.rs:549`) kaldırılır.

**Capture-group styling kontratı korunur:** RegexSet sadece pre-filter; per-regex capture extraction hâlâ individual regex'lerden gelir. v0.3.5'in `emit_capture_runs` boundary-event sweep algoritması (`src/pipeline.rs:148-225`) ve match-level overlap detection (`accepted_spans` + `partition_point` O(log N)) byte-identical kalır. Bu zero-regression invariant'ı v0.4.0 spec'i test'leriyle açıkça pin'ler.

**Bölüm B — Pipeline-owned scratch Vec'leri:**

`apply_rules`'un (`pub(crate) fn apply_rules<W: Write>`, `src/pipeline.rs:48`) her çağrısında allocate edilen 4 Vec — `accepted_spans`, `runs`, `event_scratch`, `active_scratch` — Pipeline struct'a field olarak taşınır + yeni `set_match_scratch` eklenir. `.clear()` ile reuse, per-line allocation sıfır. `apply_rules` `pub(crate)` olduğu için imza değişikliği kontrollü iç refactor; iki yaklaşım sub-version brainstorming'inde tartılır — (a) free function imzasına `&mut PipelineScratch` parametresi eklemek, veya (b) `apply_rules`'u Pipeline'ın `&mut self` method'una taşımak. Public API surface'i etkilenmez.

**Beklenen perf delta** (v0.3.5 BASELINE.md baseline'ına göre):

| Shape | v0.3.5 | v0.4.0 hedefi | Gerekçe |
|---|---|---|---|
| `apply_rules/ipv4-heavy` | 2.4199 ms | ≤ 1.0 ms (sub-version'da pin) | 3 hit / 13 miss; RegexSet 10 rule'u atlattırır |
| `apply_rules/mixed-syslog` | 2.2948 ms | ≤ 0.8 ms | benzer miss-ratio |
| `apply_rules/captures-heavy` | 4.5173 ms | ≤ 2.5 ms | Captures path zaten gerekli iş; modest improvement |
| `passthrough/write_all` | 1.3380 µs | ±%5 (RegexSet hot path'e girmez) | apply_rules'a hiç girmeyen alt-screen/bracketed-paste yolu |

Sub-version spec'i kesin sayıları pin'ler. **Floor:** hiçbir bench grup'unda v0.3.5'ten regression olmayacak.

### 3.3 v0.4.1 — Bench-CI + regression detection

İki ortogonal değişiklik:

- **Baseline storage as canonical artifact:** Criterion `--save-baseline <name>` çıktısını `benches/baselines/<version>/` altında JSON olarak commit'le (git canonical). Her tagged release sonrası release notları workflow'unda baseline güncelle. BASELINE.md insan-okur summary olarak kalır (manuel maintenance, release ceremony parçası).
- **GHA workflow:** Her PR'da `cargo bench --bench throughput -- --baseline <last_release>`; criterion'un `change:` line'larını parse → %20 spec threshold breach varsa PR comment + workflow annotation. **Auto-fail değil** (sub-µs jitter koruması; örn. `passthrough/write_all` v0.3.2 → v0.3.3 arasında %9.6 dalgalandı, gerçek regression yoktu).

Sub-version brainstorming'inde detaylar: strict mode opsiyonu (`[bench-ci-strict]` PR label trigger?), criterion `--baseline-lenient` kullanımı, MacOS scheduler jitter için outlier filtering, hangi bench gruplarının kritik (apply_rules/* hard; passthrough/write_all soft).

**Yeni dep yok** — criterion zaten dep, GitHub Actions runner'lar zaten konfigüre.

## 4. Cross-cutting kararlar

Aşağıdaki kararlar v0.3.6 + v0.4'ün tüm sub-version'ları için locked. Sub-version spec'lerinde tartışılmaz, sadece refere edilir.

### 4.1 Backward compatibility

- v0.3 boyunca konuşulan config schema ve theme TOML kırılmaz. v0.4 boyunca v0.3 config dosyalarını shimless okur.
- v0.3'te shipped CLI flag'leri signature aynı kalır.
- `Args`, `Error`, `ThemeRuleErrorKind` `#[non_exhaustive]` — yeni variant additive.
- `Compiled::load_with_theme` imzası v0.4.0'da değişmez (RegexSet kullanımı internal, hot path detail).
- v0.3.6 saf semver patch — public API'de hiçbir değişiklik yok.
- v0.4.0'da `Pipeline` struct'a yeni private field'lar eklenir; `Pipeline::new` imzası değişmez. `apply_rules` `pub(crate)` olduğu için refactor kontrollü iç değişiklik — public API surface'i etkilenmez.

### 4.2 Performans bütçesi

- v0.3.5 BASELINE.md son satırı (2026-05-24, HEAD `e969024`) canonical baseline. v0.4 boyunca **hiçbir bench grup'unda v0.3.5'ten regression olmayacak** (floor).
- v0.4.0 RegexSet ile beklenti: hit-heavy fixture'larda modest, miss-heavy'lerde order-of-magnitude. Spec §3.2 tablosundaki hedefler **sub-version spec'inde pin'lenir + minimum acceptable belirlenir.**
- v0.4.1 threshold: v0.3 boyunca uygulanan %20 (spec §4.2 / §7.4) korunur.

### 4.3 Güvenlik

CLAUDE.md §3 mandate'leri tüm sub-version'larda geçerli:
- v0.3.6 saf bugfix — Display string'i kullanıcı output'una geçiyor (`Error::ThemeValidation` → stderr); sanitize_for_display zaten var, yeni branch onu kullanmaz çünkü tüm input static (integer literal).
- v0.4.0 RegexSet — `regex` crate zaten dep, RegexSet API'si aynı crate'in stable parçası, yeni surface area yok. Adversarial PTY output hâlâ `regex` crate'in ReDoS-safe linear-time engine'inden geçer.
- v0.4.1 CI workflow — `benches/baselines/*.json` dosyaları git canonical, repo dışı state yok. Workflow secret'lere ihtiyaç duymaz.

### 4.4 Dependency policy

- **Yeni dep yok** — v0.3.6 + v0.4'ün tüm scope'u mevcut crates ile çözülür (`regex`, `criterion`, std). Memory `feedback_dependency_minimalism` ve CLAUDE.md §3 ile uyumlu.
- Aho-Corasick explicit dep'i değerlendirildi, **iptal** edildi — `regex` crate'in pure-literal alternation handling'i internal AC DFA'sına düşer; manuel routing duplicate iş.

### 4.5 Test stratejisi

- v0.3.6: birim test'ler — Display fix için `ThemeRuleErrorKind::CaptureGroupIndexOutOfRange { group: 1, captures_len: 1 }` snapshot; test rename/assertion ekleme. Integration test surface'i değişmez.
- v0.4.0: **zero-regression invariant kritik** — v0.3.5'in tüm capture-group testleri (`tests/integration_capture_groups.rs`) byte-identical geçmeli. Pipeline unit testleri scratch Vec reuse'u doğrulayan ek assertion alır (`Vec::capacity` invariant veya allocation count). Yeni bench output (RegexSet hit-ratio histogramı?) sub-version brainstorming'inde.
- v0.4.1: workflow'un kendisi test edilir (sample PR'da intentional regression → annotation görünür mü?). CI matrix değişmez (Linux + macOS + audit/deny).

### 4.6 Release workflow

Memory'deki `tayf release workflow` aynen:
1. Sub-version commit'leri main'e.
2. Push main → CI yeşil bekle. macOS GHA flake oluşursa `gh run rerun --failed` (memory `feedback_flaky_watch_test`).
3. Tag push (`vX.Y.Z`, annotated, `tayf vX.Y.Z — <title>` mesajı).
4. CHANGELOG date bump follow-up commit (release günü gerçek tarihiyle; ilk commit `## [X.Y.Z] — TBD` placeholder ile gider).
5. Bu umbrella doc'unun §2 tablosu güncellenir (shipped satır işaretli + §1.2 "Hedef olmayan"dan ilgili satırlar silinir, oraya yeni defer'lenler eklenir).

## 7. Bu doküman değiştirildiğinde

- Umbrella'yı güncellemek için ayrı bir commit gerekir (umbrella git'te canonical; "memory"deki notlar değil).
