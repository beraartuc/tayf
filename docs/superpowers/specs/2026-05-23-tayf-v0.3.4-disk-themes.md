# tayf v0.3.4 — Disk Themes + Fail-Collected Validator Tasarım Dokümanı

**Tarih:** 2026-05-23
**Kapsam:** v0.3.4 iki ortogonal iş kalemini tek release'te ship eder. **(F1)** Disk-based custom themes — `~/.config/tayf/themes/<name>.toml` (ya da `$XDG_CONFIG_HOME/tayf/themes/<name>.toml`) dosyalarından TOML theme yükleme. `themes::load` signature'ı `Result<&'static str>` → `Result<LoadedTheme>` evrilir; `LoadedTheme.source: Cow<'static, str>` (built-in için `Borrowed`, disk için `Owned`). Aynı symlink-out whitelist + 1 MiB read cap, mevcut `config::read_capped` ile aynı güvenlik kontratı. **(F2)** Built-in isim çakışmasında **error** — `themes/dark.toml` mevcut + `--theme dark` istek = `Error::Config` ("rename to a non-built-in name"); sessiz override yok, sürpriz önlenir. **(F3)** Fail-collected validator — `validate_theme_rules` ilk hatada return etmek yerine tüm violation'ları tek pass'te toplar; yeni `Error::ThemeValidation { theme, source_path, errors: Vec<ThemeRuleError> }` variant'ı ile bundle'lanır. Üç iş de additive (yeni `Error` variant `#[non_exhaustive]` enum'a additive; yeni disk path discovery production'da opt-out yok, sadece dosya yoksa no-op); CLI değişikliği yok, config schema değişikliği yok, yeni dep yok.

**Prereqs:** v0.3.3 yayınlanmış (✅ shipped, tag `v0.3.3`, son commit `2adeaea docs(changelog): v0.3.3 release date`). `cargo audit && cargo deny check` yeşil. v0.2.3 preset themes mimarisi (`src/themes.rs`, `assets/themes/dark.toml`, `assets/themes/light.toml`) yerinde. `validate_theme_rules` v0.2.3'ten beri stabil, fail-on-first. `Error` enum v0.3.3'ten beri `#[non_exhaustive]` (additive variant şart).

**v0.3 umbrella referansı:** `docs/superpowers/specs/2026-05-23-tayf-v0.3-vision.md` §3.5 (umbrella §"v0.3.4 — Disk themes + fail-collected validator" iki iş kalemi tanımı), §4.1 (backward compat), §4.3 (security — disk theme `read_capped` + symlink validation path'ından geçer), §4.4 (dep policy — yeni dep yok), §4.6 (release workflow). Umbrella'da "built-in isim çakışması davranışı brainstorming'de" denildiği yer (Karar **F2 = error**) bu spec'in §2 Karar 4'ünde pinleniyor. Umbrella'nın "error type evrimi gerektirir" diye bıraktığı F3 seçimi (Karar **yeni `Error::ThemeValidation` variant**) §2 Karar 7'de pinleniyor.

## 1. Vizyon

### 1.1 Kapsam F1 — Disk-based custom themes

Kullanıcılar v0.2.3'ten beri `--theme dark` veya `--theme light` ile shipped preset'leri seçebiliyor; `[general] theme = "..."` ile config'den de set edilebiliyor. Üç pratik eksiklik var:

1. **Kişisel preset:** "Benim 'solarized-dark'um vs sizin 'dark'ınız farklı." Kullanıcı kendi color scheme'ini saklamak istiyor; her makinede aynı.
2. **Takım/topluluk paylaşımı:** Kullanıcı bir gist veya repo'dan başkasının theme'ini indirip kullanmak istiyor. Built-in registry'ye PR açmak overkill.
3. **Override + custom rule ayrımı:** Mevcut çözüm `[general] theme = "dark"` + `[[rules]]` override'lar var; ama "saf theme dosyası" (sadece style override'ları, pattern tanımlamaz) ile "kişisel config" (pattern + style + general) ayrımı yok. Bir kullanıcı theme dosyasını `~/.config/tayf/themes/mine.toml`'a koyduğunda bu net bir ayrım.

Çözüm: disk-based theme yükleme. Resolution sırası:

```
themes::load(name) →
  1. <config_base>/themes/<name>.toml dosyası var mı?
     - Hem disk dosyası VAR hem ismi built-in registry'de VAR
       → Error (F2 collision; §1.2)
     - Sadece disk dosyası var → read_capped + symlink validation → Cow::Owned
  2. Built-in registry'de var mı? → Cow::Borrowed(&'static str)
  3. İkisi de yok → Error::Theme { available: built-ins ∪ disk discovered }
```

`config_base` `config::resolve_path`'in kullandığı XDG mantığıyla aynı:
- `$XDG_CONFIG_HOME` set ve non-empty ise `$XDG_CONFIG_HOME/tayf`
- aksi takdirde `$HOME/.config/tayf`
- ikisi de yoksa disk lookup atlanır (no-op; built-in registry'e direkt düşülür)

**Themes alt-dizini:** `<config_base>/themes/`. Dosya adı `<name>.toml` (`.toml` uzantısı zorunlu). Diğer dosyalar (`.bak`, `.example`, alt-dizinler) yok sayılır — discovery sadece `<name>.toml` pattern'i listeler.

**Security kontratı (CLAUDE.md §3 mandate):**
- 1 MiB read cap — mevcut `config::MAX_CONFIG_BYTES` constant'ı yeniden kullanılır (`config::read_capped(path)` çağrılır, yeni cap tanımlanmaz).
- Symlink-out whitelist — disk theme dosyasının canonical target'ı canonical themes-base'in ALTINDA olmalı; aksi takdirde `Error::Config` (mevcut `config::check_default_path`'in mantığıyla aynı, ama themes-base için ayrı helper).
- Regular file check — `metadata().is_file()` (symlink-to-dir veya FIFO reject).
- ASCII control bytes in path → `sanitize_for_display` (mevcut error sanitization gate; yeni helper gerekmez).

**Validation:** disk theme'ler shipped preset'lerle **aynı `validate_theme_rules` gate**inden geçer. Yani:
- Her rule `name` BUILTIN_NAMES içinde olmalı.
- `pattern` field yok (theme = sadece style override).
- `enabled = false` yok.

**Fark (preset vs disk):** Shipped preset'lerin (`assets/themes/dark.toml`, `light.toml`) `shipped_theme_files_parse_and_validate` unit test'i `cfg.rules.len() == BUILTIN_NAMES.len()` invariant'ı tutar — yani preset her built-in'i override etmek **zorunda**. Disk theme'lerde bu zorunluluk YOK — kullanıcı sadece `log_level` ve `ipv4`'ü override eden 2-satırlık bir theme tanımlayabilir; kalan built-in'ler default style'larıyla devam eder.

**Path label (error messages için):**
- Built-in: `<embedded:theme/{name}>` (mevcut `themes::synthetic_path` korunur).
- Disk: gerçek canonical path (örn. `/home/u/.config/tayf/themes/mine.toml`).

Bu path label `validate_theme_rules` hatalarında ve `parse` parse-hatalarında error mesajına dahil edilir → kullanıcı dosyayı editor'de açar.

### 1.2 Kapsam F2 — Built-in isim çakışması = ERROR

**Karar: kullanıcı `~/.config/tayf/themes/dark.toml` veya `light.toml` koyduğunda Error.** Sessiz override yok, sessiz disk-ignore yok.

**Alternatifler değerlendirildi:**

(A) **Disk wins (override):** `--theme dark` disk'i okur, built-in shadow'lanır. Reddedildi:
- Future v0.3.x'te yeni built-in eklemek (örn. `--theme high-contrast`) sessizce kullanıcının disk theme'ini shadow'layabilir → ya da, built-in eklendiğinde kullanıcı disk theme'ini fark etmeden kaybedebilir. Predictability problemi.
- "tayf'ım niye böyle?" → "ah disk'te bir dosya varmış"; debug bedeli yüksek.

(B) **Built-in wins (disk silently ignored):** worst. Disk dosyası "duruyor görünüyor" ama hiç okunmuyor. UX zehri.

(C) **Error:** seçilen.
- `Error::Config { path: <disk_path>, line: 0, message: "theme '<name>' shadows the built-in theme with the same name; rename the file (for example to '<name>-custom.toml') or remove it" }`.
- Kullanıcı dosyayı **rename** ederek kolayca düzeltir (`mv dark.toml my-dark.toml` + `--theme my-dark`).
- Future built-in eklenirken bu davranış aynı kalır — yeni built-in `foo` eklendiğinde kullanıcının `foo.toml`'u varsa startup error verir, kullanıcı net feedback alır.

**Error tetikleme noktası:** `themes::load(name)` çağrıldığında (yani `Compiled::load_with_theme` içinde, theme resolution sonrası). Proactive scan YOK — sadece kullanıcı/auto-detect bir built-in ismi requestlediğinde çakışma fire eder.

**Pratik gerçek:** v0.3.1'in `bg_detect::resolve()`'u her tayf startup'ında "dark" veya "light" üretir → kullanıcı disk'e `dark.toml` koyduysa **her startup error verir**. Bu istenen davranış: feedback hemen gelir, kullanıcı bir kere düzeltir, hayata devam.

**Collision diagnostic:** error mesajı tam aksiyon verir; sanitize_for_display path'a uygulanır (path içinde control byte enjeksiyon riskine karşı defense-in-depth, mevcut `Error::Config` Display gate aynen geçerli).

### 1.3 Kapsam F3 — Fail-collected validator

`themes::validate_theme_rules` mevcut davranışı: ilk violation'da `Err(Error::Config)` return eder. Sonuç: kullanıcı theme'inde 5 hata varsa save→tayf→1. hata→düzelt→save→tayf→2. hata→... döngüsü yaşar.

Yeni davranış: validator tüm rule'ları gezer, tüm violation'ları `Vec<ThemeRuleError>`'a toplar, vec non-empty ise tek `Error::ThemeValidation { theme, source_path, errors }` döner. Kullanıcı tek save→tayf cycle'ında tüm sorunları görür.

**Yeni `Error` variant:**

```rust
/// Multiple validation errors collected from a single pass over a theme's
/// rule list. Surfaced from [`crate::themes::validate_theme_rules`] when at
/// least one violation is found.
///
/// `theme` is the requested theme name (matching `--theme <name>` or
/// `[general] theme`). `source_path` is the embedded synthetic path for
/// shipped presets or the absolute disk path for disk-loaded themes; both
/// are sanitized via [`sanitize_for_display`] in the Display impl.
#[error("{}", format_theme_validation(theme, source_path, errors))]
ThemeValidation {
    theme: String,
    source_path: String,
    errors: Vec<ThemeRuleError>,
},
```

**Yeni public types** (Error variant'ın fields'ına accessible olabilmesi için):

```rust
/// A single violation inside a theme rule list. Bundled into
/// [`Error::ThemeValidation::errors`] when [`crate::themes::validate_theme_rules`]
/// finds one or more issues.
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct ThemeRuleError {
    /// The offending rule's `name` field, echoed verbatim from the TOML.
    pub rule_name: String,
    /// Classification of the violation.
    pub kind: ThemeRuleErrorKind,
}

/// What's wrong with the rule. One variant per validation rule in
/// [`crate::themes::validate_theme_rules`].
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
#[non_exhaustive]
pub enum ThemeRuleErrorKind {
    /// `name` does not match any entry in [`crate::rules::BUILTIN_NAMES`].
    UnknownName,
    /// `pattern` is set — disallowed (themes only override style).
    PatternForbidden,
    /// `enabled = false` is set — disallowed (themes only override style;
    /// use a `[[rules]]` block in the user config to disable a built-in).
    EnabledFalseForbidden,
}
```

**Display formatting** (`format_theme_validation`):

```
theme 'foo' (loaded from /home/u/.config/tayf/themes/foo.toml) has 3 validation errors:
  - rule 'unknown_name': not a built-in name; themes may only override built-ins
  - rule 'ipv4': must not set 'pattern' (themes only override style)
  - rule 'log_level': must not set 'enabled = false' (themes only override style)
```

Path ve rule_name `sanitize_for_display` ile geçer. Singular vs plural ("1 validation error" vs "N validation errors") seçilen.

**`validate_theme_rules` yeni signature:**

```rust
pub(crate) fn validate_theme_rules(
    theme_name: &str,
    source_path: &str,  // YENİ — error message için
    rules: &[UserRule],
) -> Result<()>;
```

Mevcut tek-parametre tüm callers'ı tek yer (`src/rules.rs:507`) — `loaded.path_label` geçirilir. Tek call site, tek update.

**Backwards compat:** `Error::ThemeValidation` yeni variant, `Error` zaten `#[non_exhaustive]` — additive. Mevcut `Error::Config` üzerinden gelen tek-error theme validation case'leri tamamen ortadan kalkar — `validate_theme_rules` artık SADECE `Error::ThemeValidation` (ya da Ok) döner. Bu test güncellemesi gerektirir (mevcut testler `Error::Config` bekliyor); §4.1'de listeli.

**Display contract:** mevcut `Error::Config` testleri (`config_message_includes_path_line_and_message`, vs.) etkilenmez. Yeni `Error::ThemeValidation` testleri eklenir; sanitize_for_display gate'i path ve rule_name için verify edilir.

### 1.4 Hedefler

- F1: `themes::load(name) -> Result<LoadedTheme>` — disk theme `<config_base>/themes/<name>.toml`'da varsa onu okur (`config::read_capped` ile aynı 1 MiB cap + symlink-out whitelist + regular-file check), built-in registry'e fallback eder, hiçbiri yoksa `Error::Theme { available: built-ins ∪ disk discovered }` döner.
- F2: built-in isim ile disk theme dosyası **birlikte** mevcutsa `Error::Config { message: "theme '<name>' shadows the built-in theme..." }`; rename hint ile kullanıcıyı yönlendirir.
- F3: `themes::validate_theme_rules` fail-collected — bir pass'te tüm violation'lar toplanır, non-empty ise `Error::ThemeValidation { theme, source_path, errors: Vec<ThemeRuleError> }` döner.
- Yeni direct dep YOK. Yeni dev-dep YOK.
- Public API additive: `Error::ThemeValidation` yeni variant (enum `#[non_exhaustive]`); `ThemeRuleError` + `ThemeRuleErrorKind` yeni public types (re-export edilir).
- v0.3.3 config dosyaları (ve daha eski) shimless okunur.
- v0.3.3 `tests/integration_themes.rs` davranışları korunur — preset themes yine aynı şekilde çalışır.

### 1.5 Hedef olmayan (sonraki sub-version'lara veya v0.4+'a)

- **Theme inheritance / composition** (örn. `extends = "dark"`). YAGNI; kullanıcı kopyala-yapıştır + override pattern'ini her durumda kullanabilir.
- **Theme hot-reload** (config hot-reload aktifken disk theme dosyası değişirse yeniden yükle). v0.4+ — şu an spawn'ı şart koşar (watcher'ı theme dir'ine de extend etmek + collision detection + atomic swap). v0.3.4 scope dışında.
- **`--themes-dir <path>` CLI flag** veya `[general] themes_dir = "..."`. Disk theme yolu tamamen XDG-derived. Future need olursa v0.3.5+ tartışılır; pratik feedback bekleniyor.
- **System-wide themes** (`/etc/tayf/themes/`, `XDG_DATA_DIRS`). Single-user model (CLAUDE.md §3). YAGNI.
- **`tayf themes list` / `tayf themes show <name>`** discoverability komutları. v0.4+ veya v0.5 `tayf config` interaktif TUI ile birlikte.
- **Theme'in `[[rules]]` dışında [general] override etmesi** (örn. theme içinde `[general] respect_existing_colors = false`). v0.3.4'te validation gate'i değişmez — theme TOML'unda `[general]` table'ı varsa parse zaten kabul eder ama `apply_user_rules` sadece `cfg.rules`'u kullanır → `[general]` field'ları sessizce yok sayılır (mevcut davranış; preset themes için zaten böyle). Future'da reject etmek isteyebiliriz ama v0.3.4 scope dışı.
- **TOML schema migration** (örn. theme dosyaları için ayrı `[theme]` section). YAGNI; theme = `[[rules]]`-only TOML (mevcut preset format).
- **Color depth-aware downgrade'in disk theme'lere AYRI uygulanması.** Mevcut `Compiled::load_with_theme` downgrade pipeline'ı (`rules.rs:521-524`) merged-then-downgraded; disk theme bu pipeline'a inject olur, otomatik kapanır. Integration test ile verify edilir; ek kod yok.
- **`Error::Theme` available list'inde disk theme'leri exhaustively scan etme.** Eğer themes/ dir'i çok büyükse (>1000 dosya) listing yavaş olabilir. v0.3.4 kabul: scan yapar, hata path'ı yavaş olabilir (cold path; kullanıcı yanlış isim girdi). Bound: dir read tek seferlik. Future cap ihtiyaç olursa v0.4'te.
- **CLI flag ile disk theme'leri devre dışı bırakma** (`--no-disk-themes`). YAGNI — disk klasörü yoksa zaten no-op.

## 3. Mimari etki ve dosya bazlı değişiklikler

### 3.1 `src/themes.rs` (en büyük değişiklik — ~216 → ~450 satır)

Mevcut public API:
- `pub(crate) fn load(name: &str) -> Result<&'static str>`
- `pub(crate) fn names() -> &'static [&'static str]`
- `pub(crate) fn validate_theme_rules(theme_name: &str, rules: &[UserRule]) -> Result<()>`
- `pub(crate) fn synthetic_path(theme_name: &str) -> String`

Yeni public API:
- `pub(crate) struct LoadedTheme { source: Cow<'static, str>, path_label: String }`
- `pub(crate) fn load(name: &str) -> Result<LoadedTheme>` — production entry; env'ı okur.
- `pub(crate) fn load_with(name, xdg_closure, home_closure) -> Result<LoadedTheme>` — testable entry.
- `pub(crate) fn validate_theme_rules(theme_name: &str, source_path: &str, rules: &[UserRule]) -> Result<()>` — yeni `source_path` param, fail-collected.
- `pub(crate) fn names() -> &'static [&'static str]` — built-in registry only, değişmez.
- `pub(crate) fn synthetic_path(theme_name: &str) -> String` — built-in path label producer, değişmez.

İç helper'lar (pub(crate) değil, modül-private):
- `fn resolve_disk_path<X, H>(name, xdg, home) -> Result<Option<PathBuf>>` — disk theme path resolution; symlink whitelist + regular-file check + canonical-base validation.
- `fn discover_disk_themes<X, H>(xdg, home) -> Vec<String>` — themes/ dir'inde `*.toml` dosyalarını listele (cold path; Error::Theme available list için).
- `fn name_is_valid(name: &str) -> bool` — name shape validation (no path separators, no `..`, non-empty, alphanumeric + `-` + `_`).
- `fn collision_error(name: &str, disk_path: &Path) -> Error` — F2 error builder.

**Cargo manifest:** zero change.

**Module doc-comment** güncelleme — disk-load semantics, security gate'leri, F2 collision policy belge edilir.

**Kontrat:**

```rust
//! Theme loading: embedded preset registry + disk-based custom themes.
//!
//! Preset theme files live in `assets/themes/` and are baked into the binary
//! at compile time via `include_str!`. Disk themes live in
//! `<config_base>/themes/<name>.toml` and are loaded through the same
//! 1 MiB read cap and symlink-out whitelist as the user config
//! (`config::read_capped` + canonical-base validation).
//!
//! Resolution order in [`load`]:
//! 1. Disk theme `<config_base>/themes/<name>.toml` exists?
//!    - And `name` ∈ [`BUILTIN_NAMES`] → [`Error::Config`] with rename hint.
//!    - Else → load from disk, return `Cow::Owned`.
//! 2. Built-in registry has `name` → return `Cow::Borrowed(&'static str)`.
//! 3. Neither → [`Error::Theme`] with available list (built-ins ∪ disk
//!    discovered, dedup, alphabetically sorted).
//!
//! A theme is a subset of the user-config schema: a sequence of `[[rules]]`
//! blocks with `name` and `style` only. Validation at load time rejects
//! `pattern`, `enabled = false`, and unknown rule names — see
//! [`validate_theme_rules`] for the precise rules. Disk themes are NOT
//! required to override every built-in (partial themes are accepted);
//! shipped preset themes are still required to be exhaustive (unit-tested).
//!
//! Public to crate:
//! - [`LoadedTheme`] — `(source, path_label)` pair returned by [`load`].
//! - [`load`] — resolve a theme name (disk-first, built-in fallback).
//! - [`load_with`] — testable variant accepting env-var closures.
//! - [`names`] — alphabetically-sorted list of BUILT-IN theme names.
//! - [`validate_theme_rules`] — fail-collected schema-shape check.
//! - [`synthetic_path`] — embedded source label for built-in themes.
```

**`LoadedTheme` shape:**

```rust
/// A theme loaded into memory, paired with the path label used in
/// error messages produced during parsing and validation.
```

**`load` + `load_with` skeleton:**

```rust
/// Resolve a theme name to its TOML source, preferring disk themes over
/// built-in presets when both exist for the same `name`. Production entry
/// — reads `$XDG_CONFIG_HOME` and `$HOME` from the environment.
///
/// # Errors
/// - [`Error::Config`] when a disk theme exists for a built-in name
///   (F2 collision policy).
/// - [`Error::Config`] when the disk theme cannot be read, is too large,
///   resolves outside the canonical themes base (symlink-out reject), or
///   is not a regular file.
/// - [`Error::Theme`] when neither a disk theme nor a built-in by this
///   name exists; the `available` list contains built-ins ∪ disk-discovered
///   names, deduplicated and alphabetically sorted.
pub(crate) fn load(name: &str) -> Result<LoadedTheme> {
    load_with(
        name,
        || std::env::var_os("XDG_CONFIG_HOME").map(std::path::PathBuf::from),
        || std::env::var_os("HOME").map(std::path::PathBuf::from),
    )
}

pub(crate) fn load_with(
    name: &str,
    xdg: impl FnOnce() -> Option<std::path::PathBuf>,
    home: impl FnOnce() -> Option<std::path::PathBuf>,
) -> Result<LoadedTheme> {
    // 1. Name shape — fail-fast on path separators / traversal / empty.
    //    Defense-in-depth: name reaches us from CLI args or config TOML,
    //    both of which could carry adversarial values. The XDG path join
    //    later would canonicalize but a malformed name leaks into error
    //    messages and disk listings.
    if !name_is_valid(name) {
        return Err(Error::Theme {
            name: name.to_owned(),
            available: available_theme_names(&xdg, &home),
        });
    }

    // 2. Disk lookup — `resolve_disk_path` runs the symlink-out + regular-
    //    file gates. Returns `Ok(None)` cleanly when the file doesn't exist.
    let disk = resolve_disk_path(name, xdg, home)?;

    // 3. F2 collision check — disk theme present AND name is a built-in.
    let is_builtin = REGISTRY.iter().any(|(n, _)| *n == name);
    if let Some(ref disk_path) = disk {
        if is_builtin {
            return Err(collision_error(name, disk_path));
        }
    }

    // 4. Disk theme — read with cap, wrap in Cow::Owned.
    if let Some(disk_path) = disk {
        let body = crate::config::read_capped(&disk_path)?;
        let path_label = disk_path.display().to_string();
        return Ok(LoadedTheme { source: std::borrow::Cow::Owned(body), path_label });
    }

    // 5. Built-in registry.
    if let Some((_, src)) = REGISTRY.iter().find(|(n, _)| *n == name) {
        return Ok(LoadedTheme {
            source: std::borrow::Cow::Borrowed(*src),
            path_label: synthetic_path(name),
        });
    }

    // 6. Unknown — Error::Theme with full available list.
    //    `name_is_valid` already ran, so `name` here is shape-clean but
    //    not in the registry and has no disk file.
    Err(Error::Theme {
        name: name.to_owned(),
        available: available_theme_names_from_closures_unused(/* re-scan? */),
    })
}
```

**`resolve_disk_path`:**

```rust
/// Resolve `<base>/themes/<name>.toml` if it exists, validating the
/// symlink chain and file type. Returns `Ok(None)` cleanly if the file
/// doesn't exist (themes dir or specific theme not present is non-fatal —
/// caller falls back to the built-in registry).
fn resolve_disk_path(
    name: &str,
    xdg: impl FnOnce() -> Option<std::path::PathBuf>,
    home: impl FnOnce() -> Option<std::path::PathBuf>,
) -> Result<Option<std::path::PathBuf>> {
    let Some(base) = config_base(xdg, home) else { return Ok(None); };
    let themes_dir = base.join("themes");
    let candidate = themes_dir.join(format!("{name}.toml"));
    if !candidate.exists() {
        return Ok(None);
    }
    // Canonicalize both sides; reject if canonical_file is outside canonical
    // themes_dir (symlink-out attack). Mirrors `config::check_default_path`
    // but using `themes_dir` as the base.
    let canonical_file = std::fs::canonicalize(&candidate).map_err(|e| Error::Config {
        path: candidate.display().to_string(),
        line: 0,
        message: format!("cannot canonicalize theme path: {e}"),
    })?;
    let canonical_base = std::fs::canonicalize(&themes_dir).map_err(|e| Error::Config {
        path: themes_dir.display().to_string(),
        line: 0,
        message: format!("cannot canonicalize themes directory: {e}"),
    })?;
    if !canonical_file.starts_with(&canonical_base) {
        return Err(Error::Config {
            path: candidate.display().to_string(),
            line: 0,
            message: format!(
                "theme file must live under {base}; symlinks pointing outside are rejected",
                base = canonical_base.display()
            ),
        });
    }
    let meta = std::fs::metadata(&canonical_file).map_err(|e| Error::Config {
        path: candidate.display().to_string(),
        line: 0,
        message: format!("cannot stat theme target: {e}"),
    })?;
    if !meta.is_file() {
        return Err(Error::Config {
            path: candidate.display().to_string(),
            line: 0,
            message: "theme path is not a regular file".into(),
        });
    }
    Ok(Some(candidate))
}
```

**`name_is_valid`:**

```rust
/// A theme name must be a single non-empty path-segment-safe identifier.
/// Allowed characters: ASCII alphanumeric, `-`, `_`. No path separators,
/// no leading `.` (would shadow hidden files), no traversal.
///
/// Defense-in-depth: `name` reaches us from CLI args or config TOML and
/// is interpolated into a disk path (`base/themes/<name>.toml`). A name
/// like `../../etc/passwd` would still be caught by the canonical-base
/// whitelist downstream, but failing here keeps the error message clear
/// (Error::Theme "not found" rather than Error::Config "symlink out").
fn name_is_valid(name: &str) -> bool {
    !name.is_empty()
        && name.chars().all(|c| c.is_ascii_alphanumeric() || c == '-' || c == '_')
}
```

**Note:** `.` (dot) excluded — disallows `theme.bak`, `theme.example`, hidden files like `.dark`. If a user needs `solarized-dark`, hyphens work; if `solar_dark`, underscores. Simpler is better; ergonomics test in unit tests.

**`discover_disk_themes`:**

```rust
/// List `*.toml` filenames in `<base>/themes/` (alphabetical, basename only,
/// `.toml` extension stripped). Returns an empty Vec when the themes dir
/// doesn't exist or cannot be read — cold path, errors are swallowed
/// because this only feeds the diagnostic-list inside `Error::Theme`.
fn discover_disk_themes(base: &std::path::Path) -> Vec<String> {
    let themes_dir = base.join("themes");
    let Ok(entries) = std::fs::read_dir(&themes_dir) else { return Vec::new(); };
    let mut names: Vec<String> = entries
        .filter_map(|e| e.ok())
        .filter_map(|e| {
            let p = e.path();
            if !p.is_file() { return None; }
            p.file_stem().and_then(|s| s.to_str()).map(str::to_owned)
                .filter(|_| p.extension().and_then(|s| s.to_str()) == Some("toml"))
        })
        .collect();
    names.sort_unstable();
    names.dedup();
    names
}

/// Combined available list: built-ins ∪ disk-discovered, deduplicated,
/// alphabetically sorted. Disk themes that collide with built-in names are
/// EXCLUDED from this list (they would error before being usable).
fn available_theme_names(
    xdg: impl FnOnce() -> Option<std::path::PathBuf>,
    home: impl FnOnce() -> Option<std::path::PathBuf>,
) -> Vec<String> {
    let mut names: Vec<String> = REGISTRY.iter().map(|(n, _)| (*n).to_owned()).collect();
    if let Some(base) = config_base(xdg, home) {
        let disk = discover_disk_themes(&base);
        let builtins: std::collections::HashSet<&str> =
            REGISTRY.iter().map(|(n, _)| *n).collect();
        for d in disk {
            if !builtins.contains(d.as_str()) {
                names.push(d);
            }
        }
    }
    names.sort_unstable();
    names.dedup();
    names
}
```

```rust
pub(crate) fn validate_theme_rules(
    theme_name: &str,
    source_path: &str,
    rules: &[UserRule],
) -> Result<()> {
    let known: std::collections::HashSet<&str> =
        crate::rules::BUILTIN_NAMES.iter().copied().collect();
    let mut errors: Vec<crate::error::ThemeRuleError> = Vec::new();
    for r in rules {
        if !known.contains(r.name.as_str()) {
            errors.push(crate::error::ThemeRuleError {
                rule_name: r.name.clone(),
                kind: crate::error::ThemeRuleErrorKind::UnknownName,
            });
            // Continue collecting; don't `continue` to the next rule —
            // the other gates (pattern, enabled) are still informative
            // for the same rule (user might have multiple issues per rule).
        }
        if r.pattern.is_some() {
            errors.push(crate::error::ThemeRuleError {
                rule_name: r.name.clone(),
                kind: crate::error::ThemeRuleErrorKind::PatternForbidden,
            });
        }
        if !r.enabled {
            errors.push(crate::error::ThemeRuleError {
                rule_name: r.name.clone(),
                kind: crate::error::ThemeRuleErrorKind::EnabledFalseForbidden,
            });
        }
    }
    if errors.is_empty() {
        Ok(())
    } else {
        Err(Error::ThemeValidation {
            theme: theme_name.to_owned(),
            source_path: source_path.to_owned(),
            errors,
        })
    }
}
```

## 6. Açık tasarım soruları
