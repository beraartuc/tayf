## §1 — Özet

Profile system kullanıcıya named bundles tanımlama imkânı verir: hangi built-in rule'lar aktif (whitelist), hangi yeni rule'lar eklenir (append_rules), hangi theme tercih edilir (override) — hepsi profile-level. v0.5.2 sadece **mekanizmayı** ship'ler. v0.5.3 curated built-in library'yi getirir; v0.5.2 `assets/profiles/` dizinini boş oluşturur.

**Schema shape — theme model mirror** (v0.5 vision §3.3'teki Option B/A yerine Option C seçildi): embedded `assets/profiles/X.toml` ve disk `~/.config/tayf/profiles/X.toml` aynı shape, header'sız. Dosya adı = profile adı. `config.toml` sadece `[general] profile = "NAME"` ile referans verir.

**CLI:** `--profile NAME` flag (`Option<String>`, mirror of `--theme`). Composition (multi-profile) defer'd to v0.5.3+ — `Option<String>` shape future composition için additive forward-compat (yeni flag eklenir, mevcut `--profile` kırılmaz).

**Rule merge order:** built-ins → profile.rules whitelist filter → theme overrides → profile.append_rules → user-config rules. User-config takes precedence over profile (user'ın explicit local edit'leri named bundle'ı override eder).

**Theme precedence (C-3, 4-tier):** CLI `--theme` > config `[general] theme` > profile.theme > bg-detect default.

**Collision policy (I-2):** profile `append_rules.name` built-in name ile collide ederse → hard error. User want override → user-config `[[rules]]` mekanizmasını kullansın (concerns separated).

**Public API additivity:** mevcut item'lar değişmiyor. Yeni `Error::Profile`, `Error::ProfileValidation` variant'ları + yeni `ProfileErrorKind`, `ProfileRuleError`, `ProfileRuleErrorKind` types (hepsi `#[non_exhaustive]`).

## §4 — Architecture overview

### §4.1 — Yeni module: `src/profiles.rs`

`src/themes.rs`'in yapısal mirror'ı. ~250 LOC tahmin.

```rust
//! Profile loading, validation, and merging.
//!
//! A profile is a named bundle of rule configuration. v0.5.2 ships the
//! mechanism only; the curated profile library lands in v0.5.3.
//!
//! Profiles are loaded from disk (`~/.config/tayf/profiles/<name>.toml`)
//! or from embedded sources (`assets/profiles/<name>.toml`, none shipped
//! in v0.5.2). Discovery + canonicalization mirrors `src/themes.rs` exactly.

use serde::Deserialize;
use std::collections::BTreeMap;
use std::path::PathBuf;

/// Parsed profile TOML body.
#[derive(Debug, Clone, Deserialize, PartialEq, Eq, Default)]
#[serde(deny_unknown_fields)]
pub(crate) struct Profile {
    /// Whitelist of built-in rule names. `None` = all built-ins kept.
    /// Empty `Vec` = all built-ins dropped (only `append_rules` apply).
    #[serde(default)]
    pub(crate) rules: Option<Vec<String>>,

    /// New rules added by the profile.
    #[serde(default)]
    pub(crate) append_rules: Vec<ProfileRule>,

    /// Optional theme override. Resolved per precedence chain in
    /// `lib.rs` / `reload.rs` (CLI > config > profile.theme > bg-detect).
    #[serde(default)]
    pub(crate) theme: Option<String>,
}

/// A rule defined in a profile's `[[append_rules]]` block.
///
/// Mandatory `pattern` (unlike `UserRule.pattern: Option<String>`) — a
/// profile rule without a pattern has no behavior to append.
#[derive(Debug, Clone, Deserialize, PartialEq, Eq)]
#[serde(deny_unknown_fields)]
pub(crate) struct ProfileRule {
    pub(crate) name: String,
    pub(crate) pattern: String,
    #[serde(default)]
    pub(crate) style: Option<crate::config::UserStyle>,
    #[serde(default)]
    pub(crate) styles: Option<BTreeMap<String, crate::config::UserStyle>>,
}

/// Result of `load(name)`. Mirrors `themes::LoadedTheme` shape.
#[derive(Debug)]
pub(crate) struct LoadedProfile {
    pub profile: Profile,
    pub path_label: String,
}

/// Load a profile by name. Mirror of `themes::load(name)`.
pub(crate) fn load(name: &str) -> Result<LoadedProfile>;

/// Phase 1 shape validation. Fail-collected — every violation across
/// the whole profile is gathered into a single `Error::ProfileValidation`.
pub(crate) fn validate_profile(
    name: &str,
    source_path: &str,
    profile: &Profile,
) -> Result<()>;

/// `<embedded:profile/{name}>` for shipped (v0.5.2 ships none); canonical
/// disk path for disk-loaded profiles.
pub(crate) fn synthetic_path(name: &str) -> String;

/// Re-export of `themes::name_is_valid` — profile names use the same
/// predicate as theme names per §3.1 I-3.
pub(crate) fn name_is_valid(name: &str) -> bool {
    crate::themes::name_is_valid(name)
}
```

**Required visibility bump (D1 Rust senior 🟡):** `src/themes.rs:78` `fn name_is_valid(name: &str) -> bool` is currently module-private. v0.5.2 makes it `pub(crate) fn name_is_valid(...)` so `profiles.rs` can re-export it. One-line change in `src/themes.rs`; verified non-breaking via grep (no external callers outside themes.rs test module).

**`ProfileRule` no-`enabled` field rationale (D1 test/QA 🟡):** Unlike `UserRule { ..., enabled: bool, ... }`, `ProfileRule` deliberately omits `enabled`. A disabled append-rule has no behavior to contribute. Users disable rules via the user-config `[[rules]] name = "X" enabled = false` precedence path (Step 5 of the merge order — user-config wins over profile per §5.4). This split keeps the profile schema purpose-focused.

**`LoadedProfile.path_label` vs `synthetic_path` semantics (D1 Rust senior 🟡):**
- `LoadedProfile.path_label`: canonical-disk-path-string for disk-loaded profiles, OR `<embedded:profile/{name}>` synthetic for embedded.
- `synthetic_path(name)` helper: ALWAYS returns the synthetic form (`<embedded:profile/{name}>`), regardless of whether disk or embedded was used. Used in error construction when the load failed before discovery completed (so no canonical path exists), e.g., `NotFound` diagnostic.

### §4.45 — `BuiltinRule` source discriminator refactor (D1 Rust senior 🔴 fix)

**Required schema change** — without this, `rule_source_of` cannot return `EmbeddedProfile` correctly. v0.5.2 replaces the two-boolean discriminant on `BuiltinRule` with a single `source: RuleSource` field. This is **load-bearing**, not optional.

`src/rules.rs:21-73`:

```rust
// Before (v0.5.1):
pub(crate) struct BuiltinRule {
    pub(crate) name: String,
    pub(crate) pattern: String,
    pub(crate) style: Style,
    pub(crate) group_styles: Vec<Option<Style>>,
    pub(crate) is_user_supplied: bool,
    pub(crate) styles_override: Option<BTreeMap<String, UserStyle>>,
    pub(crate) styles_override_from_theme: bool,
}

// After (v0.5.2):
pub(crate) struct BuiltinRule {
    pub(crate) name: String,
    pub(crate) pattern: String,
    pub(crate) style: Style,
    pub(crate) group_styles: Vec<Option<Style>>,
    pub(crate) styles_override: Option<BTreeMap<String, UserStyle>>,
    /// Provenance tag: Builtin (default), UserConfig (override or
    /// addition via user-config `[[rules]]`), Theme (style-only
    /// override via theme TOML), or EmbeddedProfile (added via
    /// profile `append_rules`).
    pub(crate) source: RuleSource,
}
```

The two booleans `is_user_supplied` + `styles_override_from_theme` are removed. `rule_source_of` ([src/rules.rs:794](src/rules.rs#L794)) collapses to direct field access — or deletes entirely and call sites read `rule.source` inline.

**Impact on existing call sites:**
- `builtin_rules()` constructors ([src/rules.rs:351-..](src/rules.rs#L351)) — every `BuiltinRule { ... }` struct literal updates `is_user_supplied: false, styles_override_from_theme: false` to `source: RuleSource::Builtin`. ~15 sites (one per built-in rule + `filename` dynamic).
- `apply_user_rules_with_source` (`src/config.rs:430`) — `from_theme: bool` parameter changes to `source: RuleSource`. Callers pass `RuleSource::Theme` or `RuleSource::UserConfig` directly. New caller (Step 4 in §5.4) passes `RuleSource::EmbeddedProfile`.
- Test fixtures constructing `BuiltinRule` (across `src/rules.rs::tests`) — same field swap.

**Why now, not v0.5.3:** without this, profile-sourced rules get misclassified as `UserConfig` or `Theme` and the `EmbeddedProfile` dispatch arms added in §4.3 are unreachable — same dead-code failure mode as v0.5.0's §I-1 (memory `feedback_phase1_grammar_gate_blind_spot`).

**Migration discipline:** v0.5.2 D2 dispatch (Phase 2) adds the `RuleSource` enum variant in `src/rules.rs`. D4 dispatch (Phase 4) applies the `BuiltinRule` schema swap. Plan Phase 4 Task 11 pins the implementation site.

## §5 — TOML schema + rule merge order

### §5.1 — Profile file shape (disk + embedded uniform)

```toml
# Yer:
# - ~/.config/tayf/profiles/myaws.toml (disk, user-authored)
# - assets/profiles/<future>.toml (embedded, v0.5.2 ships none — v0.5.3 library)
#
# Aynı shape; dosya adı = profile adı.

# Optional. Omit = "all built-in rules active" (current default behavior).
# []  (empty array) = "filter out all built-ins" (only append_rules apply).
# ["timestamp", "log_level"] = whitelist of named built-ins.
rules = ["timestamp", "log_level", "url"]

# Optional (default []). Each entry is a NEW rule with mandatory pattern.
[[append_rules]]
name = "instance_id"
pattern = '\bi-[a-f0-9]{17}\b'
style = { fg = "cyan" }

[[append_rules]]
name = "region"
pattern = '\b(?:us|eu|ap)-(?:east|west|north|south|central)-[0-9]\b'
style = { fg = "green" }

# Optional. Profile-level theme override (slot 3 of precedence chain).
theme = "dark"
```

**`#[serde(deny_unknown_fields)]` aktif** — typo'lar (örn. `aapend_rules`) load-time'da reject. v0.4.x convention.

**Inline-table vs array-of-tables**: `append_rules` array-of-tables (`[[append_rules]]`) — multi-line, readable for >2 entries. Inline form (`append_rules = [{...}, {...}]`) de valid TOML (serde accept).

### §5.2 — `Config.general.profile` reference shape

```toml
# ~/.config/tayf/config.toml
[general]
profile = "myaws"     # references ~/.config/tayf/profiles/myaws.toml
                      # OR assets/profiles/myaws.toml (embedded)

# Profile-defined append_rules don't go here — they live IN the profile file.
# User-config [[rules]] is for explicit local overrides (existing v0.4.x behavior).
[[rules]]
name = "ipv4"
enabled = false       # disables a built-in independently of any active profile
```

### §5.3 — Effective profile resolution

Mirror of `--theme` precedence:

| CLI `--profile` | config `[general] profile` | Effective |
|---|---|---|
| `Some("aws")` | _any_ | `aws` (CLI wins) |
| `None` | `Some("myaws")` | `myaws` |
| `None` | `None` | none (current behavior — all built-ins active) |

### §5.4 — Rule merge order

```text
Step 1 — Built-ins
  • Start: 13 built-in rules (BUILTIN_NAMES).

Step 2 — Profile.rules whitelist (NEW)
  • If profile_def.rules = Some(whitelist): filter built-ins to entries in whitelist.
  • If None: keep all built-ins (current behavior).
  • Unknown names in whitelist caught at Phase 1 validation (ProfileRuleErrorKind::RuleUnknown).

Step 3 — Theme overrides (style-only) — EXISTING LOGIC
  • Apply to surviving rules from Step 2.

Step 4 — Profile.append_rules (NEW)
  • Append each ProfileRule as a new BuiltinRule with RuleSource::EmbeddedProfile.
  • Name-collision checks done at Phase 1 validation:
    - Collision with built-in → AppendRuleConflictsWithBuiltin (hard error).
    - Duplicate within append_rules → AppendRuleConflictsWithOther.
  • Pattern compile + styles-key dispatch in Step 6.

Step 5 — User-config (overrides / adds / disables) — EXISTING LOGIC
  • User-config takes precedence over profile.
  • [[rules]] name = X enabled = false: drops rule X regardless of source.
  • [[rules]] name = X pattern = "...": overrides rule X's pattern.
  • [[rules]] name = X with new name: appends a new rule (RuleSource::UserConfig).

Step 6 — Compile + styles-key dispatch
  • Patterns compile (RegexCompile errors fail-fast).
  • Capture-group key validation via dispatch (Step 1/2/3 from v0.5.0):
    - Theme source → theme_errors (collected → Error::ThemeValidation).
    - EmbeddedProfile source → profile_errors (collected → Error::ProfileValidation, NEW).
    - UserConfig source → return Err(Error::Config) immediately (fail-fast).
    - Builtin source → unreachable!() (styles_override == None for built-ins).
```

### §6.2 — Yeni public types

```rust
// D1 Rust senior 🔴 fix: NO Clone derive — toml::de::Error and std::io::Error
// are not Clone. Consistent with existing Error enum (also no Clone derive).
//
// D1 🟡 fix: thiserror Error derive omitted from ProfileErrorKind directly;
// the variants carry their data as owned strings (no #[from] needed). This
// avoids leaking toml/io types into the public API surface (no Cargo dep
// coupling in tayf's public types).
#[derive(Debug)]
#[non_exhaustive]
pub enum ProfileErrorKind {
    NotFound {
        searched: Vec<std::path::PathBuf>,
    },
    /// TOML deserialization failure. `message` is the
    /// `toml::de::Error.to_string()` rendering, captured at construction
    /// time so the variant stays public-API-stable across future `toml`
    /// crate major bumps.
    ParseError {
        message: String,
    },
    /// `std::fs::canonicalize` or path-safety check failed. `message` is
    /// the `io::Error.to_string()` rendering.
    PathCanonicalization {
        path: std::path::PathBuf,
        message: String,
    },
    /// `regex::Regex::new` rejected an `append_rules` entry's pattern.
    /// `message` is the `regex::Error.to_string()` rendering.
    RegexCompile {
        rule_name: String,
        pattern: String,
        message: String,
    },
}

// ProfileRuleError + ProfileRuleErrorKind: Clone + PartialEq + Eq OK because
// all fields are owned types (String, Vec<String>) and ThemeRuleErrorKind
// already derives Clone + PartialEq + Eq.
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct ProfileRuleError {
    pub rule_name: String,    // append_rules entry name; sentinel "<rules>" or "<theme>" for non-rule errors

}

#[derive(Debug, Clone, PartialEq, Eq)]
#[non_exhaustive]
pub enum ProfileRuleErrorKind {

    RuleUnknown { name: String, known: Vec<String> },
    RuleNameInvalid { name: String },
    AppendRuleConflictsWithBuiltin { name: String },
    AppendRuleConflictsWithOther { name: String },
```

### §6.25 — `format_profile_load` + `format_profile_validation` helper signatures (D1 Rust senior 🟡 fix)

The `#[error("{}", format_profile_load(...))]` and `#[error("{}", format_profile_validation(...))]` attributes in §6.1 reference free functions that must be declared in `src/error.rs`. Mirror of the existing `format_theme_validation` helper ([src/error.rs:326-346](src/error.rs#L326)):

```rust
fn format_profile_load(
    name: &str,
    source_path: &str,
    kind: &ProfileErrorKind,
) -> String {
    match kind {
        ProfileErrorKind::NotFound { searched } => {
            let paths = searched.iter()
                .map(|p| p.display().to_string())
                .collect::<Vec<_>>()
                .join(", ");
            format!(
                "profile '{name}' not found (searched: {paths})",
                name = sanitize_for_display(name),
            )
        }
        ProfileErrorKind::ParseError { message } => format!(
            "profile '{name}' at {path}: {message}",
            name = sanitize_for_display(name),
            path = sanitize_for_display(source_path),
        ),
        ProfileErrorKind::PathCanonicalization { path, message } => format!(
            "profile '{name}' path '{path}': {message}",
            name = sanitize_for_display(name),
            path = sanitize_for_display(&path.display().to_string()),
        ),
        ProfileErrorKind::RegexCompile { rule_name, pattern, message } => format!(
            "profile '{name}': failed to compile rule '{rule_name}' pattern '{pattern}': {message}",
            name = sanitize_for_display(name),
            rule_name = sanitize_for_display(rule_name),
            pattern = sanitize_for_display(pattern),
        ),
    }
}

fn format_profile_validation(
    profile: &str,
    source_path: &str,
    errors: &[ProfileRuleError],
) -> String {
    use std::fmt::Write;
    let n = errors.len();
    let plural = if n == 1 { "error" } else { "errors" };
    let mut out = format!(
        "profile '{profile}' (loaded from {path}) has {n} validation {plural}:",
        profile = sanitize_for_display(profile),
        path = sanitize_for_display(source_path),
    );
    for e in errors {
        let _ = write!(
            out,
            "\n  - rule '{name}': {msg}",
            name = sanitize_for_display(&e.rule_name),
            msg = e.kind,
        );
    }
    out
}
```

Both helpers use `sanitize_for_display` to honour CLAUDE.md §3 BEL-leak invariant on arbitrary bytes.

**Public API additivity:**
- `Error` is `#[non_exhaustive]` (existing). Two new variants additive.
- `ProfileErrorKind`, `ProfileRuleError`, `ProfileRuleErrorKind` — new public types, all `#[non_exhaustive]` where applicable.
- No modifications to existing public items.

### §6.3 — Diagnostic wording (byte-exact)

`ProfileRuleErrorKind::Display`:

| Variant | Wording (byte-exact) |
|---|---|
| `RuleUnknown { name: "ipv5", known: [...sorted...] }` | `rules entry "ipv5": not a built-in name (known: filename, ipv4, ipv6, log_level, mac, permission, regex, timestamp, url, ...)` |
| `RuleNameInvalid { name: "my rule" }` | `append_rules entry "my rule": name must be ASCII alphanumeric with '-' or '_'` |
| `AppendRuleConflictsWithBuiltin { name: "ipv4" }` | `append_rules entry "ipv4": collides with built-in rule; use [[rules]] at the user-config level to override built-ins` |
| `AppendRuleConflictsWithOther { name: "foo" }` | `append_rules: duplicate entry "foo"` |
| `ThemeNameInvalid { name: "bad name" }` | `theme "bad name": name must be ASCII alphanumeric with '-' or '_'` |
| `StylesKey(inner)` | Delegates: `write!(f, "{inner}")` — inner ThemeRuleErrorKind's existing Display. |

`format_profile_validation` wrapper:
```
profile '<name>' (loaded from <path>) has N validation error(s):
  - rule '<rule_name>': <kind_display>
```

Where `<rule_name>` is the `ProfileRuleError.rule_name` field. Sentinels:
- `<rules>` for `RuleUnknown` (rule name = the unknown built-in name being whitelisted).
- `<theme>` for `ThemeNameInvalid`.
- Actual `name` for the four `append_rules`-related variants.

`format_profile_load` (single-error variants):
- `NotFound { searched }`: `profile '<name>' not found (searched: /a/b/c, /d/e/f)`
- `ParseError { message }`: `profile '<name>' at <path>: <message>`
- `PathCanonicalization { path, message }`: `profile '<name>' path '<path>': <message>`
- `RegexCompile { rule_name, pattern, message }`: `profile '<name>': failed to compile rule '<rule_name>' pattern '<sanitized_pattern>': <message>` (sanitize_for_display on pattern bytes per CLAUDE.md §3 BEL-leak invariant)

**Quoting prefix divergence (D1 test/QA 🟡 note):** ProfileRuleErrorKind Display uses `rules entry "<X>"` and `append_rules entry "<X>"` prefixes — different from ThemeRuleErrorKind's `styles."<key>"` convention. This is intentional: profile errors live in `[[append_rules]]` / `rules = [...]` namespaces, not `styles.` map keys. The `StylesKey(inner)` wrapper variant DOES use `styles."<key>"` (delegated to inner ThemeRuleErrorKind) because those errors ARE in the styles map. D7 review should expect this divergence — not flag it as duplicate-formatter drift.

**Cross-path identity test extension (D1 Rust senior 🔵 absorbed as 🟡):** `duplicate_formatter_theme_and_user_paths_byte_identical_diagnostic` ([src/rules.rs:2601](src/rules.rs#L2601)) currently pins theme-source == user-config-source byte-equal Display for the 5 capture-group key variants. v0.5.2 extends to 3-way: theme == user-config == embedded-profile. This becomes a new test `cross_path_identity_three_way_byte_identical_diagnostic` (or extension of the existing test) covered in plan Phase 3 Task 9.

### §6.4 — Validation phases

**Phase 1 — shape-only (`validate_profile`)**, fail-collected:
1. `profile.rules` (if `Some`): each entry exists in `BUILTIN_NAMES`. Unknown → `RuleUnknown { name, known }`.
2. `profile.append_rules`: each `name` passes `name_is_valid`. Bad → `RuleNameInvalid`.
3. `profile.append_rules`: each `name` not in `BUILTIN_NAMES`. Collision → `AppendRuleConflictsWithBuiltin`.
4. `profile.append_rules`: no duplicate name within the array. Duplicate → `AppendRuleConflictsWithOther`.
5. `profile.theme` (if `Some`): passes `name_is_valid`. Bad → `ThemeNameInvalid`. (Existence check deferred to theme-load in lib.rs/reload_once — surfaces as `Error::Theme { kind: NotFound }`.)

**Phase 2 — pattern compile + styles-key dispatch (`Compiled::load_with_theme`)**:
6. Each `append_rules.pattern` compiles via `regex::Regex::new`. Failure → `Error::Profile { kind: RegexCompile }` (single-error, fail-fast).
7. Each `append_rules.styles` map key validated via dispatch Step 1/2/3 (v0.5.0/v0.5.1 logic). `RuleSource::EmbeddedProfile` arm pushes errors into `profile_errors: Vec<ProfileRuleError>` with `kind = ProfileRuleErrorKind::StylesKey(<inner>)`. Surfaces as `Error::ProfileValidation` at end of dispatch.

### §6.5 — Where `validate_profile` fires

`profiles::load(name)` flow:
1. Discover file (`assets/profiles/<name>.toml` embedded fallback, `~/.config/tayf/profiles/<name>.toml` disk).
2. Canonicalize path; reject traversal outside `~/.config/tayf/profiles/` (mirror theme path validation per CLAUDE.md §3).
3. Parse TOML → `Profile`.
4. `validate_profile(name, source_path, &profile)` → Phase 1 fail-collect.
5. Return `LoadedProfile { profile, path_label }`.

### §7.2 — `reload_once` precedence re-resolution flow

```rust
// 1. Re-read user-config if path is Some.
let config = path.map(|p| parse_user_config(p)).transpose()?;

// 2. Resolve effective profile name: CLI > config.
let effective_profile_name = profile.or_else(|| {
    config.as_ref().and_then(|c| c.general.profile.as_deref())
});

// 3. Load profile (if any). Failure surfaces as Error::Profile / ProfileValidation
//    — caught by reload thread, emitted via banner, prior valid Compiled retained.
let loaded_profile = effective_profile_name.map(crate::profiles::load).transpose()?;

// 4. Resolve effective theme: CLI > config > profile.theme.
//    (bg-detect kicks in inside Compiled::load_with_theme or upstream if all None.)
let effective_theme = theme
    .or_else(|| config.as_ref().and_then(|c| c.general.theme.as_deref()))
    .or_else(|| loaded_profile.as_ref().and_then(|lp| lp.profile.theme.as_deref()));

// 5. Compile.
let new_compiled = Compiled::load_with_theme(
    config.as_ref(),
    path.and_then(|p| p.to_str()),
    effective_theme,
    loaded_profile.as_ref().map(|lp| &lp.profile),
    loaded_profile.as_ref().map(|lp| lp.path_label.as_str()),    // YENİ — six-param shape
    depth,
)?;

// 6. Swap.
handle.store(Arc::new(new_compiled));
Ok(())
```

**Critical invariant (C-4 mandate):** Every reload re-resolves the FULL precedence chain. User edits config to change `[general] profile = "aws"` → `"k8s"`; reload picks it up (CLI not overriding). Snapshot rule: CLI `--profile` snapshotted at startup; never mutated during session.

### §7.3 — `lib.rs` initial-load orchestration

`reload_once` flow ile aynı, sadece startup-time:
1. `effective_profile_name = args.profile.or_else(|| config.general.profile)`
2. `loaded_profile = effective_profile_name.map(profiles::load).transpose()?`
3. `effective_theme = args.theme.or(config.theme).or(loaded_profile.theme)`
4. If `effective_theme.is_none()` → bg-detect → `dark`/`light`.
5. `Compiled::load_with_theme(..., loaded_profile.as_ref().map(|lp| &lp.profile), ...)`.
6. `ReloadOrchestrator::spawn(..., args.theme, args.profile, ...)` — CLI snapshots.

### §7.4 — Hot-reload error semantics

Profile load failure (NotFound, ParseError, ProfileValidation) during hot reload → reload thread catches `Error` from `reload_once`, emits banner via existing pattern, retains prior valid `Compiled`. **Profile broken → prior known-good rules continue to apply.** Existing reload error handling is profile-aware automatically (just a new `Error` variant in the chain).
