## 1. Vizyon

`src/pipeline.rs::TuiModeSm` (v0.1) byte stream'inde sadece `CSI ? Pm h/l` sequence'lerini tanıyor. Geri kalan her şey (OSC, SGR, non-CSI ESC, DCS/PM/APC) `Ground` state'ine atılıyor → byte'lar line buffer'a giriyor → regex'lere maruz kalıyor. Sonuçlar:

- **OSC hyperlink** (`\e]8;;https://...\alabel\e]8;;\a`) URL'si `url` rule'una takılıyor → görsel kaza.
- **OSC title** (`\e]2;...\a`), **OSC prompt marker** (`\e]133;A\a`), **OSC clipboard** (`\e]52;...\a`) ile aynı sorun.
- **SGR sequence** (`\e[31m`) line buffer'a giriyor; mevcut `respect_existing_colors = true` config field'ı hot path'a girmediği için no-op.
- **Non-CSI ESC** (`\eM`, `\e7`, `\e=`) ve özellikle `\ec` (RIS, full terminal reset) line buffer'a girip rule'lara takılabiliyor.
- **Multi-byte ESC** (`\e(B` G0 designate, `\e#8` DEC alignment test) — `vim`, `less`, `reset(1)` bunları gönderir; line buffer'a giriyor.
- **DCS/PM/APC** (`\eP...\e\\`, `\e^...\e\\`, `\e_...\e\\`) — kitty graphics, tmux passthrough, terminal device attribute query'leri kullanır; line buffer'a giriyor.

v0.3.0 mevcut SM'i **Paul Williams' VT500 parser şemasına** (https://vt100.net/emu/dec_ansi_parser) oturtarak yukarıdaki tüm kategorileri doğru parse eder; byte'larını line buffer dışında veya line-position-preserving şekilde ele alır; `respect_existing_colors` config'ini hot-reload-aware olarak devreye sokar.

### Hedefler

- Williams VT500 parser şemasının tayf'ın ihtiyacına gore yeterli alt-kümesi: 12 state.
- Pipeline.feed üç-yollu (TUI passthrough / sequence-bytes-into-line-buffer / OSC-payload-direct-to-stdout).
- `respect_existing_colors = true` iken SGR'lı satıra rule uygulanmaz; **byte ordering bozulmaz**.
- Hot-reload-aware: `respect_existing_colors`'ı `Compiled` struct'ına koy, mevcut `ArcSwap<Compiled>` üzerinden atomic okuma.
- State machine kendi modülünde (`src/ansi.rs`, ~250 satır). `src/pipeline.rs` SM'den temizlenir, sadece Pipeline + apply_rules kalır.
- Adversarial test corpus'u: 18+ unit, 6+ integration test.
- Throughput regression < %20 (umbrella §4.2 bütçesi); criterion baseline ile doğrulanır.
- Yeni dependency yok.

### Hedef olmayan (sonraki sub-version'lara veya v0.4+'a)

- **VTE crate entegrasyonu.** Karar 1 (aşağıda) kapatıyor.
- **Segment-level `respect_existing_colors` semantiği** — Karar 2.
- **OSC 8 hyperlink label'ına rule uygulama** — v0.4+'da değerlendirilebilir; bu spec'in scope'unda OSC payload tamamen verbatim.
- **CAN/SUB cancel byte handling** (0x18, 0x1A) — YAGNI; ESC ile resync mevcut.
- **8-bit C1 controls** (0x80..0x9F gibi tek-byte CSI/OSC/ST eşdeğerleri) — Karar 6 (aşağıda).
- **Otomatik bg detection / pattern polish / escape hatches / disk themes** — v0.3.1, v0.3.2, v0.3.3, v0.3.4.

## 3. State machine — Williams VT500 şeması

### 3.1 Referans

Paul Williams' parser şeması (https://vt100.net/emu/dec_ansi_parser) modern ANSI terminal parser'larının canonical referansı. `vte` crate, `Alacritty`, `WezTerm`, `kitty`, ve `xterm` hepsi Williams şemasını implement ediyor — küçük varyasyonlarla. `src/ansi.rs`'in module doc-comment'ı bu referansa explicit link verir; **gelecekte bir sequence türü eklemek isteyen herkes Williams'a bakmak zorundadır, kendi state'ini icat etmez.**

### 3.2 State listesi

Williams'ın tam 18 state'inden tayf'a yeten 12'si:

| State | Anlam |
|---|---|
| `Ground` | Normal text; her byte data |
| `Escape` | `\e` tüketildi (mevcut SM'deki `EscSeen` ile aynı) |
| `EscapeIntermediate` | `\e` + intermediate byte (0x20..0x2F); multi-byte ESC için (örn. `\e(B`, `\e#8`) |
| `CsiEntry` | `\e[` tüketildi (mevcut SM'deki `Csi` ile aynı) |
| `CsiParam` | CSI parametre toplama (mevcut SM'deki `Digits`); `?`/`<`/`=`/`>` private prefix burada da kabul |
| `CsiIntermediate` | CSI parametre sonrası intermediate byte (0x20..0x2F); örn. `\e[ q` (DECSCUSR cursor style) |
| `CsiIgnore` | CSI ortasında geçersiz byte; final byte gelene kadar drop |
| `OscString` | `\e]` payload toplama; terminator: BEL (0x07) veya 7-bit ST (`\e\\`) |
| `DcsEntry` | `\eP` tüketildi; parametre/intermediate fazına geçilebilir |
| `DcsParam` | DCS parametre toplama (CSI ile analog) |
| `DcsIntermediate` | DCS intermediate byte |
| `DcsPassthrough` | DCS final byte tüketildi, payload bekleniyor; terminator: ST |
| `DcsIgnore` | DCS ortasında geçersiz byte; ST gelene kadar drop |
| `SosPmApcString` | `\eX` / `\e^` / `\e_` ile başlayan string sequence; terminator: ST |

### 3.3 Byte range adlandırması (Williams' nomenclature)

```
0x00..0x17, 0x19, 0x1C..0x1F          C0_CONTROL    (BS, BEL, vd. — passthrough)
0x18, 0x1A                             CAN_SUB       (YAGNI — Karar 4)
0x1B                                   ESC           (sequence başlatır)
0x20..0x2F                             INTERMEDIATE  (intermediate byte)
0x30..0x3F                             PARAMETER     (digit + ;:<=>?)
0x40..0x7E                             FINAL         (CSI/ESC final byte)
0x7F                                   DEL           (passthrough)
0x80..0xFF                             UTF8/8BIT     (data; 8-bit C1 destek dışı — Karar 6)
```

`PARAMETER` range'i mevcut spec'in yanlış grupladığı `0x30..0x3B` (digits + `:` + `;`) ve `0x3C..0x3F` (`<=>?` private prefix) birleşimini içerir. Williams'ta ikisi de aynı state'te (`CsiParam`) tutulur; sadece parametre yorumu farklılaşır (final byte gelene kadar accum'a yazılır). Bu spec aynı yapıyı izler.

### 3.4 Transition tablosu (özet)

Williams' tam tablosunun tayf'ın ihtiyacına alt-kümesi. "Anywhere" satırı tüm state'lerden geçerli; ESC her zaman `Escape`'e atlar.

```
Anywhere     + ESC                 → Escape       (resync; entry actions clear)
Anywhere     + (8-bit C1)          → (ignored)    (Karar 6: 7-bit only)

Ground       + PARAMETER..FINAL    → (data byte; line_buffer'a)
Ground       + ESC                 → Escape

Escape       + INTERMEDIATE        → EscapeIntermediate
Escape       + [                   → CsiEntry
Escape       + ]                   → OscString
Escape       + P                   → DcsEntry
Escape       + X | ^ | _           → SosPmApcString
Escape       + 0x30..0x4F | 0x51..0x57 | 0x59..0x5A | 0x5C | 0x60..0x7E → Ground (single-byte ESC final consumed)
                                                                          (Bu range "ESC + tek-byte final" demek;
                                                                           `\e=`, `\eM`, `\e7`, `\e8`, `\ec`, `\eD`, ... hepsi burada.)

EscapeIntermediate + INTERMEDIATE  → EscapeIntermediate (chain)
EscapeIntermediate + 0x30..0x7E    → Ground         (final consumed; `\e(B`, `\e#8` tamamlanır)

CsiEntry     + PARAMETER           → CsiParam
CsiEntry     + INTERMEDIATE        → CsiIntermediate
CsiEntry     + FINAL               → Ground         (sequence complete; if 'm', SgrConsumed event)
CsiEntry     + ?                   → CsiParam (private prefix; accum tutulur)
CsiEntry     + 0x3A                → CsiIgnore       (colon-as-separator yok; standart yorum)

CsiParam     + PARAMETER           → CsiParam       (accum'a digit, ';' separator)
CsiParam     + INTERMEDIATE        → CsiIntermediate
CsiParam     + FINAL               → Ground         (if 'h'/'l' and private prefix saw, toggle TUI flag;
                                                     if 'm', SgrConsumed event)
CsiParam     + 0x3A                → CsiIgnore

CsiIntermediate + INTERMEDIATE     → CsiIntermediate
CsiIntermediate + 0x30..0x3F       → CsiIgnore       (parametre intermediate'tan sonra: invalid)
CsiIntermediate + FINAL            → Ground

CsiIgnore    + 0x40..0x7E          → Ground          (final consume, sequence dropped)
CsiIgnore    + (other)             → CsiIgnore

OscString    + 0x07 (BEL)          → Ground
OscString    + ESC                 → (Williams: OscString'den çık ve ESC re-process; sonuç: lone ESC OSC abort, EscSeen'e dön)
OscString    + (data)              → OscString       (StringPayloadByte event)

DcsEntry     + PARAMETER           → DcsParam
DcsEntry     + INTERMEDIATE        → DcsIntermediate
DcsEntry     + FINAL               → DcsPassthrough  (data fazına geç)

DcsParam     + PARAMETER           → DcsParam
DcsParam     + INTERMEDIATE        → DcsIntermediate
DcsParam     + FINAL               → DcsPassthrough

DcsIntermediate + INTERMEDIATE     → DcsIntermediate
DcsIntermediate + 0x30..0x3F       → DcsIgnore
DcsIntermediate + FINAL            → DcsPassthrough

DcsPassthrough + ESC               → (string sequence terminate; Williams: ESC re-process; sonuç: ST tamamlanırsa Ground, değilse abort)
DcsPassthrough + (data)            → DcsPassthrough  (StringPayloadByte event)

DcsIgnore    + ESC                 → (string terminate; ST handling)
DcsIgnore    + (other)             → DcsIgnore

SosPmApcString + ESC               → (string terminate; ST handling)
SosPmApcString + (data)            → SosPmApcString  (StringPayloadByte event)
```

Williams' "Anywhere + ESC → Escape" kuralı: bir sequence ortasındayken lone ESC görmek sequence'i abort eder. Bu kural **çağdaş terminallerin (vte/tmux/xterm) davranışı**dır; `kitty` keyboard protocol gibi nadir senaryolarda DCS payload içinde ESC byte'ı varsa parser abort eder. **Karar:** Williams uyumlu davranış ship edilir; ileride bir uyumluluk şikayeti gelirse v0.4'te per-sequence-type ESC handling değerlendirilir.

### 3.5 `StepEvent` enum (Karar 7)

`AnsiSm::step(byte) -> StepEvent` döner. Pipeline.feed event'a göre byte'ı route eder.

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub(crate) enum StepEvent {
    /// Data byte in Ground state. Line-position-preserving.
    Data,
    /// Byte that's part of a sequence visible in the output (CSI prefix/params/intermediates/final,
    /// single-byte ESC final, EscIntermediate sequence bytes). Line-position-preserving.
    /// `apply_rules` will see this byte in the line; `respect_existing_colors=true` skips if any
    /// such byte is in the line and it terminates a sequence we recognize as visual (SGR).
    SequenceByte,
    /// Byte that's part of an OSC / DCS-passthrough / PM / APC payload. NOT line-position-preserving;
    /// goes direct to stdout. Line buffer holds whatever partial line was there before the sequence.
    StringPayloadByte,
    /// TUI mode flag just turned on. Pipeline.feed should write segment so far and switch to
    /// passthrough mode.
    EnteredTuiMode,
    /// TUI mode flag just turned off. Pipeline.feed should switch back to line-buffering.
    ExitedTuiMode,
    /// SGR sequence just terminated (CSI ... m). Side effect: caller sets `line_has_sgr = true`.
    /// Returned ALONGSIDE the `m` byte: caller treats this as SequenceByte for the m, then handles SgrConsumed.
    /// In implementation: enum variant carries both meanings; alternative is a separate flag — Karar 7 picks enum.
    SgrConsumed,
}
```

**Implementation note:** `m` final byte için `step` iki bilgi taşımalı (byte SequenceByte gibi line_buffer'a girer + SgrConsumed semantik). İki seçenek:

- `SgrConsumed`'ı standalone variant olarak tut; SM step çağrısı `m`'i tükettiğinde Pipeline ayrı bir `step` çağrısı yapmadan event'i okur. Implementation: `step` `(StepEvent, bool /* sgr_just_consumed */)` tuple döner. **Brüt ama açık.**
- `SgrConsumed` `SequenceByte`'ın özel formu: `SequenceByte { sgr: bool }`. Daha tip-güvenli.

**Karar:** `SequenceByte { sgr: bool }` ile başlanır; sade. Tüm diğer SequenceByte case'leri `sgr: false`.

### 3.6 `tui_mode_active()` ve `in_string_payload()`

Pipeline.feed iki predicate'i okur:

- `tui_mode_active() -> bool`: Mevcut behavior — alt-screen / paste / mouse bayraklarından biri set. State'ten bağımsız, ayrı `flags: u32` field'ı. **Bu set olduğunda byte'lar verbatim stdout'a, line_buffer hiç görmüyor.**
- (Implicit) Step event `StringPayloadByte` döndüyse Pipeline byte'ı direkt stdout'a yazar; line_buffer'a sokmaz, ama line_buffer'ın partial line'ını korur. Bu predicate explicit method değil, event-driven.

## 4. Yeni davranışlar

### 4.1 OSC / DCS / PM / APC passthrough — **partial line preserved**

OSC sequence başladığında (`\e]`) SM `OscString` state'ine geçer. SM her byte için `StringPayloadByte` event'i döner. Pipeline.feed bu event için **byte'ı direkt out.write_all'a yazar, line_buffer'a sokmaz**.

Kritik: line_buffer'ın o anki içeriği (kısmi line) **korunur**. Sequence bittikten sonra normal data byte'ları line_buffer'a girmeye devam eder; `\n` geldiğinde line_buffer'da biriken byte'lar (sequence'in öncesi + sonrası) tek satır olarak `apply_rules`'a geçer. OSC payload **rule'lara hiç gösterilmez** (zaten stdout'a yazıldı; line_buffer'da yok).

Senaryo: `error \e]8;;https://x\aclick\e]8;;\a here\n`
- `error ` → Data event'leri → line_buffer.
- `\e]8;;https://x\a` → OscString state, StringPayloadByte event'leri → stdout direct.
- `click` → OSC payload içinde → stdout direct.
- `\e]8;;\a` → OSC ikinci kez → stdout direct.
- ` here\n` → Data event'leri → line_buffer.
- `\n` line'ı kapatır → apply_rules `error  here` üzerinde çalışır (OSC byte'larını görmez, ama stdout'a zaten doğru sırada yazıldı).

Stdout output: `error \e]8;;https://x\aclick\e]8;;\a here\n` — hyperlink intakt, regex hyperlink URL'sine müdahale etmedi.

### 4.2 SGR-aware line flag

`Pipeline` struct'ına alan:

```rust
pub(crate) struct Pipeline {
    sm: crate::ansi::AnsiSm,
    buffer: LineBuffer,
    rules: Arc<ArcSwap<Compiled>>,
    line_has_sgr: bool,
}
```

SM `SequenceByte { sgr: true }` döndüğünde (yani CSI'da `m` final byte tüketildiğinde) Pipeline `self.line_has_sgr = true` yapar. Byte aynı zamanda line_buffer'a girer — **bu kritik**: SGR bytes line'da pozisyonunu korur, ya `apply_rules` skip edilir (`respect_existing_colors=true`) ya da regex çalışırken SGR bytes da görünür (eski v0.2 davranışı).

`\n` geldiğinde:

```rust
let compiled = self.rules.load_full();  // ArcSwap snapshot
if compiled.respect_existing_colors && self.line_has_sgr {
    out.write_all(&line)?;          // verbatim
} else {
    apply_rules(&line, &compiled, out)?;
}
self.line_has_sgr = false;          // reset
```

`respect_existing_colors` `Compiled`'da olduğu için **hot-reload-aware**: config'ten değişirse bir sonraki `\n`'de yeni değer okunur.

**False-positive uyarısı:** `respect_existing_colors=false` (default v0.2 davranışı) iken SGR byte'ları line_buffer'da; regex'ler bunlara potansiyel false-match yapabilir (örn. `\e[31m` içindeki `31` `http_status` pattern'ına takılma). **Bu mevcut v0.2 davranışıdır**, v0.3.0 bunu değiştirmez — kullanıcı isterse `respect_existing_colors=true` ile opt-in eder. v0.4'te segment-level mode bunu çözebilir.

### 4.3 Non-CSI ESC ve EscIntermediate

Williams'a göre `\e=` (single-byte) ve `\e(B` (intermediate + final) farklı path'lerden geçer:

- `\e=`: `Escape + 0x3D` (FINAL range) → Ground. 2 byte SequenceByte event'i; line_buffer'a girer ama "data" değil, byte stream'inde görünür.
- `\e(B`: `Escape + 0x28` (INTERMEDIATE) → `EscapeIntermediate`; `EscapeIntermediate + 0x42` (FINAL) → Ground. 3 byte SequenceByte event'i.

Her ikisi de line_buffer'a girer; `apply_rules` SGR-skip kontrolünü `line_has_sgr` ile yapar — ESC sequence'leri SGR sayılmaz, bu byte'lar regex'lere maruz kalabilir. **Bu kabul edilebilir** çünkü `\e=`, `\e(B` payload'ı insan-okunabilir text değil; tayf'ın 13 built-in pattern'i bu byte'larla anlamlı bir false-match yapmaz (test edilecek).

**Özel durum: `\ec` (RIS — Reset to Initial State).** Tek-byte final, `Escape + 0x63 → Ground`. Bu sequence terminal'i resetler — herhangi bir tayf SGR'ı da sıfırlar. Line_buffer'a girer; apply_rules onu görür; çıktıya geçer. Davranış doğru; **özel testi eklenir** (senior review 🟡-3).

### 4.4 Config bağlama — `Compiled.respect_existing_colors`

Senior review 🟡-2 sonucu, mevcut "Pipeline::new'a bool geçir + warning on reload mismatch" tasarımı drop. Yerine:

```rust
// src/rules.rs::Compiled
pub(crate) struct Compiled {
    pub(crate) set: RegexSet,
    pub(crate) individuals: Vec<Regex>,
    pub(crate) styles: Vec<Style>,
    pub(crate) respect_existing_colors: bool,   // NEW
}
```

`Compiled::load_with_theme(...)` config'ten field'ı okur ve struct'a yazar. Hot reload tetiklendiğinde `ArcSwap` yeni `Compiled`'ı atomic olarak swap eder; Pipeline her satırda `self.rules.load_full()` ile mevcut Compiled'ı snapshot alır ve `respect_existing_colors` field'ını okur. **Sıfır ek infra**; mevcut atomic swap mekanizması zaten doğru çalışıyor.

`Pipeline::new` imzası değişmez:

```rust

```

`respect_existing_colors` `Pipeline` field'ı değil; her satırda `Compiled` snapshot'ından okunur. Bu, mevcut "rule'lar mid-line değişmesin" garantisi ile aynı şemada — line bazlı snapshot.

## 5. Pipeline.feed mimari — three-path (Karar 10)

Senior review 🔴-2 byte ordering bug'ını çözen mimari.

```rust
pub(crate) fn feed<W: Write>(&mut self, chunk: &[u8], out: &mut W) -> std::io::Result<()> {
    for &byte in chunk {
        // 1. TUI mode aktif mi? Mevcut davranış: tüm byte'lar stdout direct.
        if self.sm.tui_mode_active() {
            // SM'i adımla (mode-flag değişebilir) ama byte zaten stdout'a.
            out.write_all(&[byte])?;
            self.sm.step(byte);
            continue;
        }

        // 2. SM'i adımla, event'a göre route et.
        let event = self.sm.step(byte);
        match event {
            StepEvent::Data | StepEvent::SequenceByte { .. } => {
                // Line-position-preserving: byte line_buffer'a girer.
                if let Some(line) = self.buffer.feed_byte_with_overflow(byte) {
                    self.apply_or_passthrough(&line, out)?;
                }
                if let StepEvent::SequenceByte { sgr: true } = event {
                    self.line_has_sgr = true;
                }
            }
            StepEvent::StringPayloadByte => {
                // OSC/DCS-passthrough/PM/APC payload: stdout direct.
                // line_buffer'ın partial line'ı korunur; sequence sonrası devam edilir.
                out.write_all(&[byte])?;
            }
            StepEvent::EnteredTuiMode => {
                // Önce mevcut line_buffer'ı flush et (tamamlanmamış line var mı?).
                // Sonra byte'ı stdout'a (sequence sonu byte'ı zaten).
                self.flush_partial(out)?;
                out.write_all(&[byte])?;
            }
            StepEvent::ExitedTuiMode => {
                // Byte stdout'a (sequence sonu byte'ı zaten); sonra Ground'da line_buffer'a devam.
                out.write_all(&[byte])?;
            }
        }
    }
    Ok(())
}

fn apply_or_passthrough<W: Write>(&mut self, line: &[u8], out: &mut W) -> std::io::Result<()> {
    let compiled = self.rules.load_full();
    if compiled.respect_existing_colors && self.line_has_sgr {
        out.write_all(line)?;
    } else {
        apply_rules_with(&compiled, line, out)?;
    }
    self.line_has_sgr = false;
    Ok(())
}
```

**Önemli noktalar:**

- **Per-byte step çağrısı** (eski "segment break on passthrough toggle" yerine). Performans: byte başına SM step + match. Mevcut `feed` zaten her byte için step çağırıyor; ek maliyet sadece event enum branch. Throughput regression < %20 bütçesi içinde (criterion ile doğrulanır).

- **`feed_byte_with_overflow`** yeni LineBuffer API'sı: tek byte alır, `\n` görürse Some(line) döner. Mevcut `feed_with_overflow(slice)` korunur (callers'da kullanılıyorsa); yeni metod overload veya wrapper olabilir.

- **`flush_partial`** yeni Pipeline method'u: line_buffer'da kısmi line varsa, TUI mode'a geçerken ve drain'de flush eder. Mevcut `drain` ve `tick` benzer iş yapıyor; refactor edilir.

- **`tui_mode_active`** flag-based (Karar 10 invariant): SM'in state'inden bağımsız, sadece DEC private mode bayrak set/reset'i ile değişir. State'in `Ground` veya `Escape` olması bunu etkilemez.

- **`StringPayloadByte` event'leri sırasında line_buffer dokunulmuyor** — kısmi line korunuyor. OSC bitince Pipeline normal data event'lerine geri döner, line_buffer kaldığı yerden devam eder.

### 5.1 Byte ordering invariant testi

## 7. Güvenlik (CLAUDE.md §3)

### 7.1 Adversarial input

**OSC / DCS / PM / APC payload size cap (senior review 🔴-5):**
- Hiçbir explicit cap yok; payload byte'ları doğrudan `out.write_all`'a gidiyor.
- **Risk:** Sonsuz OSC (`\e]` + sürekli payload, BEL/ST hiç gelmeyen) durumda SM `OscString`'de sticky kalır.
- **Mitigation:** Output writer her byte'ı pump eder; backpressure yok ama memory büyümez (payload sadece geçer). Drain semantiği: child shell'in stdin'i kapanırsa Pipeline.drain çağrılır; `OscString` state'inde line_buffer'da kısmi line varsa (sequence öncesi yazılan), o partial line `apply_rules`'a geçer. Sequence "ortada" kalmış olur ama bytes zaten stdout'a yazıldı. **Test:** §8.1 `osc_no_terminator_then_eof_drains_partial_line`.
- **DoS:** Yok. Attacker child shell'i kontrol ediyorsa zaten tayf'ı bypass edebilir; tayf'ın işi memory'i sabit tutmak, başardı.

**`accum` overflow (senior review 🟡-4):**
- Mevcut SM `accum: u32` ve `saturating_mul`/`saturating_add` kullanıyor (`src/pipeline.rs:88-89`).
- Yeni SM Williams şemasıyla; parametre toplama yine `saturating_*` ile. `\e[?9999999999h` → `accum = u32::MAX`; `flag_for_mode(u32::MAX) = 0` (lookup fail); ignored. SM `Ground`'a döner, corruption yok.
- **Test:** §8.1 `accum_overflow_does_not_corrupt_state`.

**DCS embedded ESC trade-off (senior review 🔴-4):**
- VT510 spec'i ESC mid-string-sequence için: legal only as ST partial.
- Terminallerin davranışı: `vte`/`tmux`/`xterm-current` lone ESC'de abort + EscSeen'e re-process. `xterm-very-old` bazı modlarda preserve.
- **Karar:** Williams uyumlu davranış (`vte`/`tmux` ile aynı): lone ESC abort. Bu kabul edilmiş bir trade-off; `kitty` keyboard protocol veya tmux passthrough sequence'lerinde nadiren mid-payload ESC olabilir. v0.4'te per-sequence ESC handling değerlendirilir.
- **Test:** §8.1 `dcs_lone_esc_aborts_and_resyncs` — kitty-style DCS with embedded ESC test.

**OSC 52 truncation (senior review 🔴-5):**
- Gerçek terminallerin OSC 52 payload limiti var (xterm default 8KB, configurable). tayf payload'ı verbatim geçirir; **amplifier riski yok** (terminal kendi limit'ini uygular). Worth bir cümle güvenlik bölümünde.

### 7.2 Memory

- SM: `state: SmState` (1 byte `#[repr(u8)]`), `flags: u32` (4 byte), `accum: u32` (4 byte), `param_idx: u8` (1 byte, intermediate count). Total ~10 byte. Allocation yok.
- Pipeline: `line_has_sgr: bool` (1 byte). Allocation yok (`Compiled`'dan okunuyor).

### 7.3 No new attack surface

- Yeni dep yok → cargo audit/deny aynı.
- Yeni FS path yok.
- Yeni public API yok (`pub(crate)` boundaries değişmiyor).
- `Error` enum değişmiyor.

### 7.4 Performans güvenliği

- Mevcut TuiModeSm hot path baseline'ı `benches/throughput.rs`'da ölçülüyor; tam ns/byte değeri criterion output'undan okunur.
- Yeni SM 12 state, byte başına 1 match expression + 1 transient parametre işlemi. Beklenti: küçük regression.
- Three-path Pipeline.feed: byte başına 1 step + 1 match. Mevcut "segment break on passthrough toggle" loop'tan basit; bazı senaryolarda hatta hızlanma olabilir.
- Umbrella §4.2 bütçesi: < %20 regression. `BASELINE.md` benchmark sonuçlarıyla güncellenir.
- Spec ns/byte tahmin etmiyor — gerçek ölçüm release-prep'te yapılır.
