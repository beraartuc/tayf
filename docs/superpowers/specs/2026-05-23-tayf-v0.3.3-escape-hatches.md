**Tarih:** 2026-05-23
**Kapsam:** v0.3.3 üç ortogonal "escape hatch" iş kalemini tek release'te ship eder. **(F1)** `--bypass` CLI flag'i + `TAYF_DISABLE` env var — whole-binary bypass; PTY wrap ve signal forwarding korunur, ama `Pipeline::apply_rules` çalışmaz ve `bg_detect::resolve()` skip edilir. ## 1. Vizyon

### 1.1 Kapsam F1 — `--bypass` CLI + `TAYF_DISABLE` env

Kullanıcılar tayf'ı PATH'in başına geçici olarak alıyor, sonra spesifik komutlar / spesifik shell session'ları için baypas etmek istiyor. Üç birincil kullanım hikayesi:

1. **`.zshrc` koşullu wrap:** `[[ -n "$TAYF_DISABLE" ]] || exec tayf` veya benzeri. Kullanıcı env var'ı set ederek (örn. CI session'unda, ya da debug için bir shell'de) tayf'ı baypas eder; başka shell'leri etkilemez.
2. **Tek komutluk override:** `TAYF_DISABLE=1 my-tool` — özellikle çıktısı tayf'ın pattern'lerinden biriyle çakışan bir alet için.
3. **Sorun raporlama:** Kullanıcı bir bug yaşadığında "tayf'ı geçici devre dışı bırak, davranış aynı mı?" diyebilmek için tek CLI flag.

Kritik davranış kontratı: **bypass aktifken tayf hâlâ PTY wrap ediyor olmalı.** Yani:

- Shell child process tayf'ın spawn ettiği PTY altında çalışır (terminal size, controlling terminal davranışı korunur).
- `signals.rs` thread'i `SIGWINCH`/`SIGINT`/`SIGTERM`/`SIGHUP` forwarding'ini yapmaya devam eder (yoksa child process group orphan kalır).
- `tty_guard::TtyGuard` raw mode + Drop restore davranışı korunur (yoksa kullanıcının terminal'i bypass mode'a girip exit ederken bozuk kalır).
- ANSI state machine (`src/ansi.rs::Parser`) çalışmaya devam eder — TUI mode detection + OSC string handling correctness için. Bypass mode'da pattern uygulama olmayacak ama `Pipeline.feed` ANSI sequence boundary'lerini yine de doğru tanımalı; aksi takdirde bypass mode "kontrolsüz dump" olur ve future feature'ları (örn. cross-line SGR tracking) bypass'ta görünmez olur.

**Bypass aktifken ÇALIŞAN tam liste:** `shell::discover`, `tty_guard::TtyGuard::engage`, `pty::PtySession::spawn`, `signals::spawn_handler` (`reload_tx = None`), `runtime::run` (`apply_colors = false`, raw passthrough). Hepsi bu kadar.

**Bypass aktifken SKIP edilen tam liste (Rev2 explicit enumeration, C-3):**
- `terminfo::detect_depth()` (`src/lib.rs:79`) — bypass'ta SGR enjekte edilmiyor; color depth bilmek gereksiz.
- `terminfo::stdout_is_tty()` (`src/lib.rs:81`) — `apply_colors` zaten `false` zorla; TTY tespiti decision'a girmiyor.
- `config::load()` (`src/lib.rs:91`) — config dosyası okunmaz; user rule'lar yüklenmez.
- `bg_detect::resolve()` (`src/lib.rs:108`) — terminal background tespiti yapılmaz; startup latency (en kötü 100 ms OSC 11 timeout) sıfırlanır.
- Theme resolution (`src/lib.rs:98-112`) — explicit ya da auto-detected theme uygulanmaz.
- `rules::Compiled::load_with_theme()` (`src/lib.rs:120-125`) — rule compilation yapılmaz; yerine `Compiled::empty()` (§3.3, C-1 sonrası doğru shape) Arc'a sarılır.
- `watch::ConfigWatcher::spawn` ve `reload::ReloadOrchestrator::spawn` — file watcher + reload thread'leri spawn edilmez. Hot reload `--no-hot-reload`'a delege edilmez; bypass implicitly kapatır.
- `Pipeline::apply_rules` — `runtime::run`'ın output thread'inde `apply_colors == false` `feed`/`tick`/`drain` çağrılarını short-circuit'ler (`src/runtime.rs:196, 211, 229`). Pipeline `runtime::run:64`'te construct edilir ama feed edilmez; `Compiled::empty()` semantik olarak valid olmalı (boş RegexSet, boş Vec'ler) ama hiç iterate edilmez. **Önceki rev1 claim'i "Pipeline never constructed" yanlıştı (C-2).**

**Bypass aktivasyonu, precedence:**

```
CLI --bypass (bool flag, default false)
  > TAYF_DISABLE env var (truthy: "1"/"true"/"yes" case-insensitive)
  > default: bypass = false
```

CLI explicit'liği env var implicit'liğini yener (klasik POSIX precedence). Negatif yön YOK — CLI `--bypass=false` veya `--no-bypass` tanımlanmaz (YAGNI; env var'ı unset etmek aynı işi yapar).

**Tek read garantisi:** `TAYF_DISABLE` env var'ı `Tayf::run`'ın başında **tek sefer** okunur; runtime'da yeniden okunmaz. Mid-session davranış değişikliği yok — bu signal handler thread'inde race olmamasını garanti eder ve mental model'i basit tutar (bir tayf process bypass ya tüm session boyunca aktif ya değil).

### 1.2 Kapsam F2 — `--no-hot-reload` + SIGHUP behavior fix

İki bağlı değişiklik:

**(F2-a) `--no-hot-reload` CLI flag.** Default `false`. True olduğunda:
- `watch::ConfigWatcher::spawn` çağrılmaz (file watcher thread + debounce thread spawn edilmez).
- `reload::ReloadOrchestrator::spawn` çağrılmaz (reload thread spawn edilmez).
- `reload_tx` mpsc channel oluşturulur ama dağıtılmaz — signal handler'a `None` geçer (mevcut Option<Sender> şekli korunur).

Motivasyon: düşük-kaynak ortamlar (busybox-like container, CI smoke test), file system aktivitesi watcher event flood'una yol açıyor ortamlar, ve "config'i değiştirmeyeceğim, kesinlikle yeni thread istemiyorum" demek isteyen kullanıcılar.

**(F2-b) SIGHUP davranış düzeltmesi.** Mevcut `signals.rs:84-90` davranışı:

```rust
SIGHUP => {
    if let Some(tx) = &reload_tx {
        let _ = tx.send(ReloadRequest::SignalHup);
    }
}
```

`reload_tx` None ise (yani config dosyası yokken ya da v0.3.3'te `--no-hot-reload` ile) SIGHUP **silently dropped** — child process group'a forward edilmez. Bu v0.2.1 hot-reload tasarımının istemeden gelen yan etkisi: v0.2.0'da SIGHUP `signal_hook::Signals::new`'in listesinde yoktu (sadece WINCH/INT/TERM), default disposition (process termination) ya da inherited disposition geçerliydi; v0.2.1 SIGHUP'ı reload trigger olarak intercept etti ama "intercept edilmeyen" durumda forward fallback'i koymadı.

Operasyonel sonuç: `tmux detach`, terminal emulator kapanması, `kill -HUP` ile graceful shutdown beklentisi — bunların hiçbiri child shell'e ulaşmıyor. Detach sonrası shell ve onun altındaki foreground process (vim, less, ssh, ...) orphan kalıyor; tayf zombie parent olarak takılı kalıyor.

v0.3.3 fix: **SIGHUP her durumda child process group'a forward edilir.** Pseudo-code:

```rust
SIGHUP => {
    // Forward to child process group regardless of hot-reload state.
    // Mirrors SIGINT/SIGTERM handling.
    if let Some(pid) = child_pid {
        if let Ok(pid_i32) = i32::try_from(pid) {
            forward_to_pgid(pid_i32, SIGHUP);
        }
    }
    // Additionally trigger reload when hot-reload is wired.
    if let Some(tx) = &reload_tx {
        let _ = tx.send(ReloadRequest::SignalHup);
    }
}
```

İki action sırası (forward önce, sonra reload-notify): forward `killpg` syscall'u kernel'e gider, hızlıdır ve operasyonel doğruluk için kritik. Reload notification mpsc channel send — orchestrator thread'in çekme süresine bağlı. Forward önce ki kullanıcının `kill -HUP` intent'i (graceful shutdown) önce iletilir.

**Rev2 (I-4) — Post-forward reload waste, intentional benign residual:** Forward sonrası child shell typically die eder (trap'i olmayan default disposition); tayf yine de reload yapar (mpsc kanaldan `SignalHup` çekilip `reload_once` çağrılır) — bu yapılan iş **kullanılmadan boşa gider**, çünkü I/O loop child'ın ölmesiyle drain'e geçer ve yeni rule'lar sadece residual stdout flush'ında uygulanır. `info_msg!("config reloaded ...")` ise child öldükten sonra stderr'e basabilir (post-exit terminal'i hafifçe kirletir). **Kararlı kabul edilen davranış**: işlevsel etkisi yok, stderr noise minimal (`TAYF_LOG=info` gated), v0.2.1 contract'ını korur (`kill -HUP` reload tetikler, bazıları bu davranışa bağımlı olabilir). Future maintainer'ın "optimize" etmemesi için bu paragraf bilinçli açıklayıcı.

**Backward compatibility:** v0.2.1+ kullanıcısı `kill -HUP <tayf-pid>` ile config reload tetikliyor olabilir. Yeni davranışta aynı `kill -HUP` hâlâ reload tetikler (`reload_tx.send` korundu) **ama aynı sinyal child process group'a da gider**. Eğer child shell SIGHUP'ı default disposition (terminate) ile alıyorsa, kullanıcının session'ı sonlanır. **Bu davranış değişikliği prominent CHANGELOG entry alır** (Changed bölümünde, "BEHAVIOR CHANGE" işaretiyle).

Mitigation: shell'ler (`bash`, `zsh`, `fish`) interactive olduklarında genelde `trap '' HUP` veya equivalent ile SIGHUP'ı yutarlar; non-interactive shell'de risk var ama tayf use case'i interactive shell. Foreground program (vim, less) için SIGHUP genelde "save & exit" anlamına gelir — kullanıcı buna alışkın olmalı çünkü tmux/screen detach yapınca alacağı davranış zaten bu.

**Alternatif değerlendirildi: opt-in flag** (`--forward-sighup` veya `[general] forward_sighup = true`). Reddedildi:
- Default-correct davranış = forward. Yutmak v0.2.1 regression'u idi; opt-in mode yapmak regression'u "feature" olarak donduruyor.
- Bir flag daha → mental model karmaşası. tayf'ın signal handling kontratı "WINCH/INT/TERM/HUP'ı child process group'a forward et" şeklinde tutarlı olur.

### 1.3 Kapsam F3 — Reload banner (opt-in)

Hot reload başarılı olduğunda kullanıcının çıktısına minimal bir visual confirmation. Üç motivasyon:

1. **Discoverability:** Kullanıcı config dosyasını editör'de kaydediyor; tayf 200 ms debounce + reload yapıyor; ama kullanıcının görsel feedback'i yok. "Bir şey oldu mu?" sorusu.
2. **Debugging:** Config'in valid olduğunu ve gerçekten yeniden yüklendiğini anlamak için kullanıcının `TAYF_LOG=info` set etmesi gerekiyor (mevcut info_msg!). Bu çok intrusive (her reload bir stderr satırı + tüm tayf info log'ları).
3. **CI/headless monitoring:** `tayf` arkada uzun çalışan bir oturum; admin SIGHUP gönderdi; banner ekrana tek satırda düşüyor → görsel confirmation.

**Davranış:**
- Yeni config field: `[general] show_reload_banner: bool`, default `false` (**opt-in**). Mevcut `GeneralSection`'a additive field.
- True olduğunda: `reload::reload_once`'un success path'i (yani `ArcSwap::store` sonrası) `/dev/tty`'a şu byte sequence'i yazar (**Rev2 string — I-2 + I-3 fix**):
  ```
  \x1b[s\r\x1b[K\x1b[2mtayf: config reloaded\x1b[22m\n\x1b[u
  ```
  Anlamı:
  - `\x1b[s` (DECSC) → cursor pozisyonunu save.
  - `\r` → satır başına dön.
  - `\x1b[K` → satırın geri kalanını sil (kullanıcının yarım promptu üzerine yazmamak için).
  - `\x1b[2m` → dim attribute aç; metin; `\x1b[22m` → dim/bold cancel (sadece bizim enjekte ettiğimiz attribute reset'lenir; **`\x1b[0m` ALL reset'i kullanılmaz** çünkü prompt'un kendi tutmuş olabileceği SGR state'i clobber eder — Rev2 I-3).
  - `\n` → yeni satıra geç.
  - `\x1b[u` (DECRC) → cursor pozisyonunu restore (save edilmiş prompt yeri).

  DECSC/DECRC (cursor save/restore) modern terminal'lerde geniş destekli (xterm, iTerm2, kitty, alacritty, gnome-terminal, Windows Terminal, tmux). Bu pattern, **multi-line zsh ZLE prompt'larında** (`PROMPT_SP`, `RPROMPT`, multi-line edit buffer'ı) cursor visual position'unu drift'tirmez — Rev2 I-2 fix. Tek-satır prompt'larda da temiz redraw.
- Reload **FAILURE** durumunda banner yazılmaz; mevcut `warn_msg!` (stderr'e) yeterli. Failure ekranı kirletmemeli (kullanıcı zaten config dosyasında hata yaptığını editor'de görüyor).
- `show_reload_banner = false` (default) ise banner write hiç yapılmaz; mevcut `info_msg!` davranışı korunur.

**Hot reload reload event source agnostic:** Banner hem `ReloadRequest::FileChanged` (file watcher) hem `ReloadRequest::SignalHup` (kill -HUP) için yazılır — kullanıcı hangi yolla tetiklediğini banner içinde ayırt etmeye ihtiyaç duymaz (`TAYF_LOG=info` zaten ayırt eder).

**Pipeline bypass:** Banner string'i kendi içinde balanced SGR (`\x1b[2m` open, `\x1b[0m` close). Banner write `/dev/tty`'a doğrudan yapılır — `runtime`'ın stdout pipe'ından geçmez, dolayısıyla `Pipeline::apply_rules` banner byte'larını hiç görmez (yani regex match riski yok, banner metni "config" "reloaded" gibi kelimelerde tayf rule'larıyla çakışmaz).

**OSC 133 prompt marker wrap YOK.** OSC 133 `\x1b]133;A\x1b\\` (prompt start), `\x1b]133;B\x1b\\` (prompt end) gibi semantic prompt marker'ları modern terminal'lerin "scroll to prompt", "copy command" özellikleri için var. Banner'ı OSC 133 ile wrap edersek terminal banner satırını "user input" olarak algılar ve copy/scroll davranışını bozar. v0.4'te (alt-screen-aware banner queuing ile birlikte) tekrar değerlendirilir; v0.3.3 scope'unda **explicit non-goal** (§1.7).

**TUI mode awareness YOK.** v0.3.0 ANSI SM `tui_active` durumunu tutuyor (`src/ansi.rs::Parser` alt-screen state). Banner write TUI mode'u kontrol etmez; opt-in default olduğu için kullanıcı banner'ı aktif ederken vim/less içindeyken görmeyi kabul etmiş sayılır. Alt-screen "üzerine bant geçme" davranışı yine ekrana basar (alt-screen buffer'da görünür → main screen restore olunca silinir, dolayısıyla "kaybolur" — annoying ama not catastrophic). v0.4'te alt-screen-aware queueing (banner'ı main screen'e dönünce yaz) yapılır. README'de explicit not.

**Default-off (opt-in) rationale (Rev2 — I-7):** Üst paragraf'taki discoverability/debugging motivation'ları default-on'u öneriyor gibi gözükebilir, ama I-2 (multi-line ZLE corruption — DECSC/DECRC ile büyük ölçüde mitigate ediliyor ama tüm shell/prompt framework'lerinde garantili değil) + TUI-mode awareness yokluğu (alt-screen pollution) + kullanıcı'nın visual environment'ına invazyon riski, default-on'u **net loss** yapar. Discoverability iki alternatif yolla sağlanır: (a) `TAYF_LOG=info` kullanıcı reload'ları stderr'de görür (mevcut davranış korunur); (b) README'de `--bypass` / `--no-hot-reload` ile birlikte `show_reload_banner = true` opt-in örneği prominent. Default-on tartışması v0.4 alt-screen-aware queueing ile birlikte tekrar açılır (o noktada I-2'nin tüm edge case'leri biliniyor olur).

**`/dev/tty` open failure:** `OpenOptions::new().write(true).open("/dev/tty")` başarısız olursa (örn. `tayf < /dev/null > /dev/null` gibi tuhaf invocation, ya da `/dev/tty` mevcut değil) banner write **silently dropped** (warn log yok). tayf'ın main I/O path'i `/dev/tty`'a değil PTY master fd'sine yazıyor; banner side-channel, bozulması session'u etkilemez. Reload başarılı oldu, sadece visual confirmation gitmedi.

### 1.4 Hedefler

- F1: `--bypass` flag ve `TAYF_DISABLE` env var resolved at startup; bypass aktivasyonu PTY/signal/tty_guard'ı koruyup Pipeline regex + bg_detect + config load + rule compile + hot reload'u skip eder. CLI > env precedence. Tek read garantisi.

- Yeni direct dep YOK. Yeni dev-dep YOK.
- Public API değişmez (yeni CLI flag = additive; yeni opt-in config field = additive; SIGHUP davranış değişikliği = minor-version-acceptable çünkü v0.2.1 davranışı dokümante edilmemiş accidental sink'ti).

### 1.5 Hedef olmayan (sonraki sub-version'lara veya v0.4+'a)

- **Alt-screen-aware banner queuing.** vim/less içindeyken banner suppress + main screen'e dönünce flush. ANSI SM `tui_active` state'i ile yapılır ama complexity v0.3.3 scope'unda fazla; v0.4.

- **Banner format / template / color customization.** YAGNI; default `tayf: config reloaded` dim metin yeterli. Eğer kullanıcı talebi olursa v0.4+ (custom `[general] reload_banner_text = "..."` veya benzeri).
- **`TAYF_DISABLE_HOT_RELOAD` env var.** `--no-hot-reload` CLI-only ship olur. Env var ihtiyacı pratik feedback'ten sonra eklenir (YAGNI); pattern `TAYF_DISABLE`'ın verb namespace'i ile uyumlu olur ama v0.3.3'te `--no-hot-reload` yeterli.

- **Bypass mode runtime toggle.** SIGUSR1 ile mid-session bypass açıp kapama gibi. YAGNI; v0.4+ "operational" işi.
- **Reload banner için diğer eventler** (config load on startup, theme resolution sonucu, vb.). Banner reload event'lerine özel; başlangıçta gözükmesi UX'i kalabalık eder.

### 3.3 `src/lib.rs` (`Tayf::run` bypass branching — Rev2 contiguous block)

`Tayf::run`'a bypass resolution + iki kod yolu eklenir: (a) bypass aktif → kısa yol (sadece PTY + signal + I/O loop); (b) bypass değil → mevcut full pipeline, `--no-hot-reload` ile reload thread'leri conditional.

**Rev2 C-2 düzeltmesi:** Rev1 "Pipeline never constructed in bypass" claim'i yanlıştı — `Pipeline::new(rules)` `runtime::run:64`'te UNCONDITIONAL çağrılır. `apply_colors == false` sadece output thread'in `feed`/`tick`/`drain` çağrılarını short-circuit'ler (`runtime.rs:196, 211, 229`). **Rev2 C-4 — Tam contiguous `Tayf::run` body**, Drop ordering invariants mevcut `lib.rs:152-156` + `lib.rs:175-184` yorumlarını mirror'larak annotated:

```rust
pub fn run(args: Args) -> Result<ExitCode> {
    log::init_from_env();

    // Resolve bypass at process start; tek read garantisi (race-free).
    // CLI flag wins over env var; both default to false.
    let bypass = args.bypass || crate::env_truthy("TAYF_DISABLE");

    if bypass {
        // ============================================================
        // BYPASS BRANCH (Rev2 C-3 — explicit enumeration of what runs)
        //
        // RUNS:    shell::discover, tty_guard::TtyGuard::engage,
        //          pty::PtySession::spawn, signals::spawn_handler (with
        //          reload_tx = None), runtime::run (apply_colors = false).
        //
        // SKIPS:   terminfo::detect_depth, terminfo::stdout_is_tty,
        //          config::load, bg_detect::resolve, theme resolution,
        //          rules::Compiled::load_with_theme,
        //          watch::ConfigWatcher::spawn,
        //          reload::ReloadOrchestrator::spawn.
        //
        // Pipeline IS constructed inside runtime::run, but apply_colors=false
        // short-circuits all feed/tick/drain. Compiled::empty() satisfies the
        // Arc<ArcSwap<Compiled>> signature with a structurally valid (but
        // never iterated) empty rule set.
        // ============================================================

        // Rev2 I-10: diagnostic so users debugging with TAYF_LOG=info see
        // why no colorization is happening.
        crate::log::info_msg!(
            "bypass active (CLI={}, TAYF_DISABLE={:?})",
            args.bypass,
            std::env::var("TAYF_DISABLE").ok()
        );

        let spec = shell::discover(args.shell.as_deref(), args.login)?;
        let empty_rules: Arc<ArcSwap<rules::Compiled>> =
            Arc::new(ArcSwap::from_pointee(rules::Compiled::empty()));

        let guard = tty_guard::TtyGuard::engage()?;
        let session = pty::PtySession::spawn(&spec)?;
        let (reader, writer, resizer, child) = session.into_parts()?;
        let child_pid = child.pid();

        // No reload pipeline in bypass — pass None to signal thread.
        // SIGHUP is still forwarded to the child PG (signals.rs handler
        // body, Rev2 F2-b fix; tested by tests/integration_signal_hup.rs
        // bypass variant).
        let signal_guard = signals::spawn_handler(resizer, child_pid, None)?;

        let exit_code =
            runtime::run(reader, writer, child, Arc::clone(&empty_rules), false)?;

        // Explicit ordered shutdown for symmetry with the non-bypass branch:
        // signal_guard joined first, tty_guard restored last.
        drop(signal_guard);
        drop(guard);

        #[allow(clippy::cast_possible_truncation, clippy::cast_sign_loss)]
        // reason: exit_code & 0xff is structurally in 0..=255
        let code = (exit_code & 0xff) as u8;
        return Ok(ExitCode::from(code));
    }

    // ================================================================
    // NON-BYPASS BRANCH (existing v0.3.2 flow + --no-hot-reload gating)
    // ================================================================

    let depth = terminfo::detect_depth();
    let apply_colors =
        !args.no_color && terminfo::stdout_is_tty() && depth != terminfo::ColorDepth::None;
    let effective_depth = if apply_colors { depth } else { terminfo::ColorDepth::None };

    let spec = shell::discover(args.shell.as_deref(), args.login)?;

    let loaded = config::load(args.config.as_deref())?;
    let config_ref = loaded.as_ref().map(|(c, _)| c);
    let config_path: Option<String> = loaded.as_ref().map(|(_, p)| p.display().to_string());

    let explicit_theme: Option<String> =
        args.theme.clone().or_else(|| config_ref.and_then(|c| c.general.theme.clone()));

    let effective_theme: Option<String> = explicit_theme.or_else(|| {
        if apply_colors {
            Some(bg_detect::resolve().as_theme_name().to_owned())
        } else {
            None
        }
    });

    let compiled = rules::Compiled::load_with_theme(
        config_ref,
        config_path.as_deref(),
        effective_theme.as_deref(),
        effective_depth,
    )?;
    let rules: Arc<ArcSwap<rules::Compiled>> = Arc::new(ArcSwap::from_pointee(compiled));

    // F2: --no-hot-reload gates BOTH the file watcher AND the reload
    // orchestrator. Channel still constructed; receiver dropped on the
    // else branch so no orphan rx lives past the decision point.
    let hot_reload_enabled = !args.no_hot_reload;

    // Snapshot the banner-opt-in flag while config_ref is still live.
    // (config_ref borrows from `loaded`; once we move into the orchestrator
    // we can no longer call config_ref.is_some_and().)
    let show_reload_banner =
        config_ref.is_some_and(|c| c.general.show_reload_banner);

    let (reload_tx, reload_rx) = std::sync::mpsc::channel::<reload::ReloadRequest>();

    let guard = tty_guard::TtyGuard::engage()?;

    let session = pty::PtySession::spawn(&spec)?;
    let (reader, writer, resizer, child) = session.into_parts()?;
    let child_pid = child.pid();

    // F2: signal thread always receives child_pid; reload_tx only when
    // hot-reload is wired. The SIGHUP handler in signals.rs forwards to
    // the child PG unconditionally (Rev2 F2-b), and additionally sends to
    // reload_tx when Some.
    let signal_reload_tx = if hot_reload_enabled { Some(reload_tx.clone()) } else { None };
    let signal_guard = signals::spawn_handler(resizer, child_pid, signal_reload_tx)?;

    // Spawn the file watcher only when (a) a config file was loaded AND
    // (b) hot-reload is enabled. Either condition false → no watcher,
    // and the corresponding reload_tx clone is never created.
    let watcher = if hot_reload_enabled {
        loaded
            .as_ref()
            .map(|(_, p)| watch::ConfigWatcher::spawn(p, reload_tx.clone()))
            .transpose()?
    } else {
        None
    };

    // Orchestrator: spawned only when hot-reload is enabled. Drop ordering
    // (mirrors lib.rs:152-156 invariant): orchestrator is declared LAST so
    // that on any earlier `?` returning Err, no orchestrator exists →
    // no join-deadlock where its Drop blocks on a channel still held by
    // already-spawned signal/watcher threads.
    let _orchestrator = if hot_reload_enabled {
        Some(reload::ReloadOrchestrator::spawn(
            Arc::clone(&rules),
            loaded.as_ref().map(|(_, p)| p.clone()),
            effective_theme.clone(),
            effective_depth,
            reload_rx,
            // F3 (Rev2 I-1): inject banner sink; production = DevTtySink
            // when banner enabled, None when disabled.
            if show_reload_banner {
                Some(Box::new(reload::DevTtySink) as Box<dyn reload::BannerSink>)
            } else {
                None
            },
        ))
    } else {
        // Hot-reload off: receiver is never consumed. Drop it explicitly so
        // the channel reaches zero-receivers immediately; any stray future
        // `reload_tx.send(...)` returns Err (intended). Note: there are no
        // clones live — signal_reload_tx was None and watcher was not
        // spawned, so dropping `reload_rx` here is safe and explicit.
        drop(reload_rx);
        None
    };

    // Drop the local sender now (mirrors lib.rs:171). Remaining clones
    // live in signal_guard (when hot_reload_enabled) and watcher (when
    // both hot_reload_enabled and config present). When BOTH guards Drop
    // at shutdown their clones go away, the orchestrator's recv() returns
    // Err, and its loop exits cleanly. When hot_reload disabled, reload_tx
    // here is the only sender (none was cloned to signal thread); dropping
    // is trivially safe — receiver is already gone.
    drop(reload_tx);

    let exit_code = runtime::run(reader, writer, child, Arc::clone(&rules), apply_colors)?;

    // Explicit ordered shutdown (mirrors lib.rs:175-184 invariant):
    // - watcher first: closes notify's raw_tx, which lets the debounce
    //   thread observe Disconnected and exit, which drops the debounce
    //   thread's reload_tx clone.
    // - signal_guard next: closes signal_hook iterator, joins signal
    //   thread, which drops the signal thread's reload_tx clone (if any).
    // - implicit _orchestrator drop at end of scope: recv() returns Err
    //   (all senders gone), loop exits, join completes.
    // - guard last: explicit for ordering clarity; Drop restores termios.
    drop(watcher);
    drop(signal_guard);

    drop(guard);

    #[allow(clippy::cast_possible_truncation, clippy::cast_sign_loss)]
    // reason: exit_code & 0xff is structurally in 0..=255
    let code = (exit_code & 0xff) as u8;
    Ok(ExitCode::from(code))
}
```

`BannerSink` trait ve `DevTtySink` implementation §3.6'da (F3 banner detayları). `BannerSink: Send + 'static` zorunlu — orchestrator thread'ine `Box<dyn BannerSink>` move edilir.

```rust
//! Hot-reload orchestrator.
//!
//! ... existing module doc ...

/// Banner byte sequence written on successful reload when
/// `show_reload_banner = true`. See spec §1.3 for the per-byte semantics.
///
/// - `\x1b[s` (DECSC) save cursor — multi-line zsh ZLE prompts retain
///   their visual cursor position after the banner draws.
/// - `\r\x1b[K` return to col 0 and erase to EOL (overwrites half prompt).
/// - `\x1b[2m` enable dim; banner text; `\x1b[22m` cancel dim/bold ONLY
///   (NOT `\x1b[0m` ALL-reset, which would clobber prompt-side SGR state).
/// - `\n` advance one line.
/// - `\x1b[u` (DECRC) restore cursor to the saved position.
pub(crate) const BANNER_BYTES: &[u8] =
    b"\x1b[s\r\x1b[K\x1b[2mtayf: config reloaded\x1b[22m\n\x1b[u";

/// Sink for the reload banner. Production wires `DevTtySink` (writes to
/// `/dev/tty`); tests wire `VecSink` (captures bytes in-memory for
/// assertion). `None` injection from `Tayf::run` means banner disabled.
pub(crate) trait BannerSink: Send + 'static {
    /// Write the banner bytes. Best-effort: implementations swallow I/O
    /// errors silently — the banner is a side-channel and its absence
    /// does not affect session correctness.
    fn write_banner(&mut self, bytes: &[u8]);
}

/// Production banner sink. Opens `/dev/tty` per call (no fd caching —
/// see audit note below), writes the bytes, flushes, closes on drop of
/// the local `File` (Drop runs `close(2)` synchronously).
///
/// fd-leak audit (Rev2 I-8): `File` Drop is sync; `notify`'s debounce
/// is 200 ms (`src/watch.rs:23`), so the maximum reload rate is 5/s.
/// Even a sustained 5/s reload stream produces 5 open/close cycles per
/// second — well below any fd-budget threshold. Caching the fd at
/// orchestrator spawn was considered (N-6) and rejected: holding a
/// `/dev/tty` fd for the entire session is a small surface increase,
/// while reload events are rare enough that per-event open is trivial.
pub(crate) struct DevTtySink;

impl BannerSink for DevTtySink {
    fn write_banner(&mut self, bytes: &[u8]) {
        use std::io::Write;
        if let Ok(mut tty) = std::fs::OpenOptions::new().write(true).open("/dev/tty") {
            // Best-effort: ignore write errors. Banner is a side-channel.
            let _ = tty.write_all(bytes);
            let _ = tty.flush();
            // `tty` dropped at scope end → close(2) syncs.
        }
    }
}

/// Test-only in-memory banner sink. Captures written bytes for assertion.
#[cfg(test)]
pub(crate) struct VecSink {
    pub(crate) bytes: std::sync::Arc<std::sync::Mutex<Vec<u8>>>,
}

#[cfg(test)]
impl BannerSink for VecSink {
    fn write_banner(&mut self, bytes: &[u8]) {
        if let Ok(mut g) = self.bytes.lock() {
            g.extend_from_slice(bytes);
        }
    }
}
```

**`ReloadOrchestrator::spawn` signature güncellemesi:**

```rust
impl ReloadOrchestrator {
    pub(crate) fn spawn(
        rules_handle: Arc<ArcSwap<Compiled>>,
        config_path: Option<PathBuf>,
        theme: Option<String>,
        depth: ColorDepth,
        rx: Receiver<ReloadRequest>,
        // F3 (Rev2 I-1): None = banner disabled; Some(sink) = enabled.
        // The sink is moved into the reload thread.
        banner_sink: Option<Box<dyn BannerSink>>,
    ) -> Self {
        let handle = thread::Builder::new()
            .name("tayf-reload".into())
            .spawn(move || {
                let mut banner_sink = banner_sink;
                while let Ok(req) = rx.recv() {
                    match reload_once(
                        &rules_handle,
                        config_path.as_deref(),
                        theme.as_deref(),
                        depth,
                    ) {
                        Ok(()) => {
                            crate::log::info_msg!("config reloaded ({req:?})");
                            if let Some(sink) = banner_sink.as_mut() {
                                sink.write_banner(BANNER_BYTES);
                            }
                        }
                        Err(e) => {
                            crate::log::warn_msg!(
                                "config reload failed ({req:?}): {e}; keeping previous rule set"
                            );
                            // Failure path: no banner (intentional — see spec §1.3).
                        }
                    }
                }
            })
            .expect("reload thread must spawn");
        ReloadOrchestrator { handle: Some(handle) }
    }
}
```

  signal, AND (when hot-reload is wired) the orchestrator additionally
  receives the reload trigger. Users who relied on the v0.2.1 silent-drop
  behavior (rare — it was undocumented and arose from the v0.2.1 hot-reload
  design accidentally intercepting `SIGHUP` without a forwarding fallback)

  trap on detach / `kill -HUP`. Most interactive shells (`bash`, `zsh`,
  `fish`) install a `SIGHUP` trap and tolerate the signal cleanly.

### 4.4 Test edilmeyen davranışlar (justification)

- **F3 banner'ın gerçek `/dev/tty`'a yazıldığı (production `DevTtySink`):** Rev2 I-1 öncesi "manual smoke test" idi; **Rev2 sonrası `BannerSink` trait seam'i ile banner byte sequence orchestrator unit test'inde `VecSink` ile birebir assert ediliyor** (`orchestrator_writes_banner_on_success_when_sink_present`). `DevTtySink::write_banner` body'si trivial (`OpenOptions::open + write_all + flush + Drop`) ve `/dev/tty` open failure davranışı (`if let Ok(...)` swallow) tek `if let` branch; unit test gerektirmeyecek kadar küçük surface. Production path manual smoke test'i release ceremony'de hâlâ yapılır (§5.6 step 5), ama Done checklist'te artık zorunlu gate değil; otomatik test bytes equality'yi garantiler.

- **Bypass mode'da config dosyası MEVCUTSA bile compile edilmediği:** integration test "SGR injection yok" kontrolü ile dolaylı pinlenir; explicit "Compiled::new çağrılmadı" assert'i mümkün değil (private state).

- **F2'nin SIGHUP'ı zaten hot-reload aktifken DE forward ettiği:** `integration_signal_hup` test'i hot-reload OFF case'i pinler. Hot-reload ON case için ayrı bir test gerekmez — `signals.rs` handler body single-branch SIGHUP arm'ı her iki path'ı da çalıştırıyor. Spec §3.4 pseudo-kodu reviewer için doğrulanabilir; bench/test surface şişirmenin değer/maliyet oranı düşük.

- `Tayf::run` public signature değişmez. `Args` struct'a iki yeni field eklendi VE **Rev2 (I-6):** `Args`'a `#[non_exhaustive]` attribute eklendi. Rev1 "clap derive convention" rationale'ı yetersizdi — `Args` `pub use cli::Args` ile library API surface'inde re-export edildiği için downstream struct-literal construct'ları (`Args { shell: None, login: false, ... }`) yeni field eklemekle break edilirdi. `#[non_exhaustive]`'in kendisi tek seferlik break (mevcut field set'iyle birlikte); v0.3.3 sonrası yeni field eklemek (örn. v0.3.5 capture-group config CLI flag'i) semver-minor güvenli olur. Downstream'lerin migration: struct-literal construct yerine `Args::try_parse_from(...)` (zaten test pattern'i) veya `..Default::default()` (eğer `Args: Default` impl'i eklenirse — v0.3.3 scope dışı, future PR).

### 5.2 Performans bütçesi

`benches/throughput.rs` v0.3.2 baseline'ı (`benches/BASELINE.md`) korunur. v0.3.3 sonrası throughput **%20'den fazla düşmemeli**.

- F1 (bypass): hot path'tan **çıkış**. `apply_colors == false` path zaten mevcut; bypass mode bu path'ı tetikler. Bypass kullanıcısı için throughput **artar** (regex skip).
- F2 (`--no-hot-reload`): hot path etkilenmez. File watcher thread CPU/RAM tasarrufu — pure win.
- F2 (SIGHUP forward): signal thread'de tek `killpg` syscall eklenir. Microsecond cost, event-driven (signal delivery rate). Hot path değil.
- F3 (reload banner): reload event'inde tek `/dev/tty` open + write + flush. Mikrosaniye cost; reload event'leri saniye-skalalı (file save), hot path değil.

Bench mandate'i §5.6'da; F1/F2/F3 hiçbiri throughput regression yapamaz ama disciplined check zorunlu.

### 5.3 Güvenlik (CLAUDE.md §3 mandate'leri)

- **Bypass mode adversarial input:** bypass mode'da Pipeline yok, raw passthrough. Adversarial PTY output (escape sequence injection, OSC injection) terminal'e doğrudan ulaşır. Bu kullanıcının açık tercihi (bypass = "tayf'ı geç"); tayf hâlâ ANSI SM çalıştırmıyor olduğundan, kullanıcı kabul ediyor. README'de prominent not.
- **F1 env var read:** `bg_detect::env_truthy` `std::env::var` + ASCII lowercase + literal match. Allocation bounded (env string copy), no parser, no regex. ReDoS / memory exhaustion riski yok.
- **F2 SIGHUP forward:** `killpg(SIGHUP)` mevcut `forward_to_pgid` yolundan geçer; `signal_hook` SIGINT/SIGTERM ile aynı kod path'ı. Yeni surface yok.
- **F3 banner write:** `/dev/tty` open + 33-byte constant write + flush. Open failure swallow (sessiz fail). Banner bytes SGR-balanced; sequence escape injection riski yok (constant bytes, user input girmez). Adversarial config dosyası `show_reload_banner = true` set edebilir — bu zaten kullanıcı'nın kendi config'i; kullanıcı kendi kendine "saldırı" yapmıyor.
- **`/dev/tty` race:** Banner write reload thread'inden yapılır; main I/O thread `stdout`'a yazıyor (`runtime::run`). İki farklı fd; race yok. `/dev/tty` per-process resource; concurrent open OK.
- `cargo audit` ve `cargo deny` mevcut CI gate'leri korunur; yeni dep yok, advisory veya license sürprizi yok.
