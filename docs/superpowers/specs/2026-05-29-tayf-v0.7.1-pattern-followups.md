## 3. Yük taşıyan teknik kısıt — neden 3 item ACCEPT-DOCUMENTED

tayf `regex = "1.12"` (`regex::bytes::Regex`) kullanır — CLAUDE.md §3'ün ReDoS mandate'i tam olarak bu lineer-zaman motoru zorunlu kılar. Bu crate **look-around assertion desteklemez** (`(?=…)`, `(?!…)`, `(?<=…)`, `(?<!…)` — hiçbiri derlenmez).

Bunun sonucu: v0.7.0 Known-issues prose'unda önerilen fix'lerin 3'ü **derlenemez**:

- **E-1** `(?!\.\d)` negative lookahead → derlenmez.
- **C-4** `(?<=[/\s])` path-anchor lookbehind → derlenmez.
- **C-9** fix'i zaten yok (known-TLD allowlist = 4000+ entry maintenance burden).

Look-around olmadan "önünde `.` var mı / arkasında `.digit` var mı" ayrımı **komşu karakter tüketmeyi** gerektirir; bu da (E-1 brainstorm'unda detaylandırıldığı üzere) corpus'un yakalamadığı gerçek-dünya regresyonları doğurur:

- **Sentence-final-period FN:** `10.0.0.1.5` (5. oktet, reddet) ile `Server at 10.0.0.1.` (cümle sonu nokta, geçerli IP) ayrımı `.`'dan sonrasına bakmayı gerektirir → naïve trailing guard cümle-sonu IP'leri styling'ten düşürür. Corpus'ta bu sınıf için POS yok → "0%" yanıltıcı olur.
- **Cosmetic delimiter coloring** (tüketilen non-space sınırlayıcılar IP rengiyle boyanır).
- **Single-space adjacency FN** (`1.1.1.1 8.8.8.8` → ikincisi styling'siz).
- Ayrıca `ipv4`'e capture-group eklemek, `ipv4`'ü "no named capture groups / `captures_len == 1`" exemplar'ı olarak kullanan ~8–12 testi (3 dosyada) kırar.

**Karar (kullanıcı onaylı):** C-4/C-9/E-1 için pattern dokunulmaz; gerçek-dünya frekansında bu builtin'ler common-case'de değerli (`main.c`, `example.com`, IP'ler), corpus ise adversarial stress-test'tir (frequency-weighted değil). Disposition = **ACCEPT-DOCUMENTED** + README user-config recipe. Yalnızca C-8 temiz bir data fix'idir (look-around gerektirmez).

| KALSIN | Pattern as-is kabul; pin regression guard. | İzin: `fp_rate <= 0.05`. |

## 7. README "Known limitations" + recipes

`README.md`'ye yeni `## Known limitations` bölümü (Configuration bölümünden sonra). İçerik (English, user-facing):

- **`filename` prose collision (C-4):** prose ending in a single-letter source extension (`a.b.c`, `u.v.w`) may be styled as a filename, because `main.c`/`top.v` are suffix-identical to such prose and tayf's linear-time regex engine cannot use surrounding context. Rare in real output.
- **`fqdn` matches JWT/base64url tokens (C-9):** a 3-segment dotted base64url token (e.g. a JWT `eyJhbGc.eyJzdWI.signature`) matches `fqdn`. Distinguishing requires a 4000+ entry TLD allowlist.
- **`ipv4` matches the leading 4 octets of a 5+-segment version (E-1):** `1.2.3.4.5` styles `1.2.3.4`. Bare 5-segment dotted versions are uncommon in terminal output.

**Recipe (generic, all three):** disable a noisy built-in via user config:

```toml
# ~/.config/tayf/config.toml — turn off a built-in whose matches you don't want
[[rules]]
name = "fqdn"
enabled = false
```

(Aynı şablon `filename` / `ipv4` için.) Implementasyonda `enabled = false`'ın builtin'i gerçekten suppress ettiği doğrulanır (`UserRule.enabled`; delete/profile testlerinin dayandığı yol).
