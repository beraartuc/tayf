# tayf v0.3 — ANSI Doğruluğu (Umbrella Vision)

**Tarih:** 2026-05-23
**Kapsam:** v0.3 minor sürüm umbrella'sı — 5 sub-version'ın hikayesini, sıralamasını ve bağımlılıklarını sabitler. Her sub-version için tam tasarım dokümanı (`2026-MM-DD-tayf-v0.3.X-<topic>.md`) JIT olarak yazılır.
**Prereqs:** v0.2.4 yayınlanmış (✅ shipped). `cargo audit && cargo deny check` yeşil. Mevcut public API'yi v0.2 boyunca koruyoruz.

Bu doküman v0.3'ün **çatısıdır**, implementation spec'i değil. Buradaki kararlar sub-version spec'lerinin başlangıç noktasıdır; sub-version brainstorming aşamasında her detay yeniden açılabilir.

---

## 1. Vizyon

v0.2 boyunca tayf "kullanıma alınabilir" bir colorizer haline geldi: user config, hot reload, 13 built-in pattern, light/dark theme'ler. Ama hâlâ **byte-stream cahil** — incoming PTY verisini line-bazlı regex'liyor, terminal'in state machine'ini bilmiyor. Bunun pratik sonuçları:

- **TUI uygulamaları "patlıyor"** — vim, lazygit, k9s, Claude Code, Codex CLI, Gemini CLI, btop, ranger gibi alt-screen kullanan her şey aslında "patlamıyor" (tayf çıktıyı bozmamaya çalışıyor) ama tayf onların ürettiği byte'lara regex uyguluyor; gereksiz iş ve nadir görsel kaza.
- **`respect_existing_colors` config field'ı yok yere parse ediliyor** — hot path'a girmiyor; mevcut SGR state'i ne korunuyor ne de saygı görüyor.
- **Light-bg detection manuel** — v0.2.3 theme'leri shipped ama kullanıcı her seferinde `--theme light` yazmak zorunda.
- **Duration pattern eksik bırakıldı** — bare `s`/`m`/`h` unit'leri v0.2.2'de SGR final-byte çakışması yüzünden çıkarıldı; VTE awareness olunca güvenle geri eklenir.
- **Escape hatch yok** — kullanıcı tayf'ı geçici devre dışı bırakmak isterse `--bypass` / `TAYF_DISABLE` gibi bir mekanizma yok.

v0.3 "ANSI doğruluğu" başlığı altında bu beş eksiği kapatır. **Çekirdek:** VTE state machine entegrasyonu; ondan kaynaklanan downstream pattern polish; ortogonal escape hatch ve disk-based themes işleri.

### Hedefler

- Alt-screen kullanan **her** TUI uygulamasında otomatik passthrough — vim/htop/Claude Code/Codex/k9s/lazygit, hepsi.
- Mevcut SGR state'in respect edilmesi (`[general] respect_existing_colors = true` gerçekten devreye girer).
- Otomatik bg detection ile theme'in zero-config çalışması.
- Pattern polish: URL trim, `git@host:path`, bare duration units.
- Operational escape hatches: `--bypass`, `TAYF_DISABLE`, `--no-hot-reload`, reload banner.
- Disk-based custom theme dosyaları (`~/.config/tayf/themes/<name>.toml`).

### Hedef olmayan (v0.4+ veya v1.0+'a ertelenmiş)

- **Windows ConPTY desteği** — v1.0+ ("Sonraki" başlığı).
- **Profile system** — v0.5.
- **`tayf config` interaktif TUI** — v0.5.
- **RegexSet fast-path** — v0.4.
- **Statistical/contextual rules** ("her IP'ye farklı renk") — sonraki.
- **OSC 133 semantic prompt marker'larını tayf'ın kendi UI mesajlarına eklemek** — v0.3.3'te reload banner kapsamında tartışılacak ama scope iyi tutulacak.

## 3. Sub-version scope notları

Her bölüm 1 paragraflık scope iskeleti. Full design JIT olarak her sub-version'ın kendi spec'inde yazılacak.

### v0.3.0 — VTE Entegrasyonu

`vte` crate'i (Alacritty'nin parser'ı; battle-tested, no_std uyumlu, geniş kullanım) entegre edilir. `Pipeline`'ın byte-input akışı VTE state machine'inden geçirilir; `Performer` impl'i şu üç bayrağı çıkartır:
- `alt_screen_active: bool` (DECSET 1049 / 47 / 1047)
- `current_sgr_state: SgrState` (mevcut renk/atribut)
- `in_bracketed_paste: bool` (DECSET 2004)

`alt_screen_active` veya `in_bracketed_paste` true iken `apply_rules` skip edilir, byte'lar verbatim geçer. OSC sequence'leri (hyperlink, title, semantic prompts) parser tarafından "intact passthrough" — tayf onlara dokunmaz. `respect_existing_colors = true` iken bir satırın içinde halihazırda SGR varsa o aralıkta tayf rule uygulamaz (current_sgr_state'in `is_default()` olmadığı segment'ler atlanır).

Performans bütçesi: VTE parse hot path'da byte başına ~10ns hedef (mevcut throughput ~500 MB/s civarı; %20 regression toleransı dahilinde). `benches/throughput.rs`'a alt-screen ve respect-existing-colors senaryoları eklenir.

**Açık tasarım soruları (brainstorming sırasında çözülecek):**
1. `vte` crate vs alternatif (custom CSI parser, `anstream`)?
2. `Pipeline` mimari değişikliği — line-snapshot model VTE state ile nasıl evlenir?
3. `respect_existing_colors` semantiği — "satırda SGR varsa hiç rule uygulama" mı, yoksa "SGR aralığını atla, kalan kısmı renklendir" mi?
4. Alt-screen detection sadece DECSET 1049 mi, yoksa 47 / 1047 dahil mi? `tmux`/`screen` içinde çalışırken davranış?
5. Bracketed paste passthrough scope — sadece paste pencerisinde rule skip mi, yoksa paste bayrağını da unutmadan event olarak takip mi?
6. Hot reload + alt-screen interaction — vim açıkken `[[rules]]` edit'i nasıl ele alınır (reload tetiklenir, ama alt-screen kalkana kadar görünmez; problem yok)?

### v0.3.1 — Otomatik bg detection

Startup'ta sıralı detection:
1. `COLORFGBG` env var (eski xterm/rxvt; iTerm2 set etmez).
2. OSC 11 query (`\e]11;?\a`) — tty'ye yaz, response'u 50ms içinde oku, parse et.
3. Fallback: `dark` varsayımı.

Detection sonucu → theme auto-resolution:
- Kullanıcı CLI/`--theme` veya `[general] theme = ...` set etmemişse, detection sonucunu uygula.
- Kullanıcı explicit set etmişse hiç override etme.

OSC 11 query'nin hangi terminallerle çalıştığı, query timeout edge case'leri, tmux/screen pass-through edip etmediği — sub-version brainstorming'de.

### v0.3.2 — Pattern polish

Üç additive pattern değişikliği:
- **URL trailing trim:** `https://example.com.` → `.` dışarda. Regex değil look-behind tekniği; tayf'ın current rust-regex'inde look-behind yok, alternatif: pattern'in son grubunu non-greedy yap + post-match trim. Brainstorming'de net çözüm.
- **`git@host:path` SSH URL:** `url` pattern'in 4. alternation branch'i. Mevcut HTTPS/SSH/FTP scheme listesine ek.
- **Bare duration units (`5s`, `30m`, `2h`):** v0.2.2'de SGR çakışması yüzünden çıkarılmıştı. **v0.3.0 (VTE) ile birlikte ship olur** çünkü VTE state machine SGR sequence'leri parse edip ayırırken `\b\d+s\b` regex'i SGR final byte'ıyla çakışmaz.

### v0.3.3 — Escape hatches

Üç ortogonal flag:
- **`--bypass` / `TAYF_DISABLE=1`:** tayf sessizce passthrough'a düşer — PTY wrap eder ama hiç regex çalıştırmaz, hiç SGR inject etmez. Kullanıcının `.zshrc`'sinde `[[ -n "$TAYF_DISABLE" ]] || exec tayf` gibi sıkça istediği pattern.
- **`--no-hot-reload`:** file watcher thread spawn edilmez, SIGHUP de yutulur (veya forwarded — sub-version'da karar). Düşük-kaynak ortamlar için.
- **Reload banner:** config reload başarılı olduğunda kullanıcının görüntüsüne minimal bir overlay basılır: `tayf: config reloaded`. OSC 133 marker'larıyla wrapped — shell prompt'la karışmaz. Sub-version'da: tek satırlık inline banner mı, alt-screen escape mı, opt-in mi opt-out mu?

### v0.3.4 — Disk themes + fail-collected validator

İki ortogonal değişiklik:
- **`themes::load` signature evrimi:** `Result<&'static str>` → `Result<Cow<'static, str>>`. Built-in registry hâlâ `&'static`, ama `~/.config/tayf/themes/<name>.toml` (veya `$XDG_CONFIG_HOME`'a göre) varsa onu okur ve `Cow::Owned`'a sarar. Disk theme bulunamazsa built-in registry'e düşer. Built-in isim çakışması: disk override ediyor mu? Brainstorming'de.
- **`validate_theme_rules` fail-collected:** Şu an fail-on-first; multi-error mode ekleyerek tek editor session'da tüm hataları kullanıcıya sun. Error type evrimi gerektirir (`Vec<Error::Config>` veya `Error::ThemeValidation { errors: Vec<...> }`).

## 4. Cross-cutting kararlar

Aşağıdaki kararlar v0.3'ün tüm sub-version'ları için locked. Sub-version spec'lerinde tartışılmaz, sadece refere edilir.

### 4.1 Backward compatibility

- v0.2 boyunca konuşulan config schema **kırılmaz**. Her v0.3.x release'i v0.2 config dosyalarını shimless okur.
- v0.2'de shipped CLI flag'leri (`--config`, `--no-color`, `--shell`, `--login`, `--theme`) signature aynı kalır.
- `Error` enum `#[non_exhaustive]` — yeni variant'lar additive (örn. v0.3.4'te `Error::ThemeValidation`).
- `Compiled::load_with_theme` imzası v0.3.0'da değişebilir (yeni VTE-aware parametre); bu **pub(crate)** olduğu için public API değil — kontrollü iç refactor.

### 4.2 Performans bütçesi

- v0.2.4 benchmark baseline'ı korunur (`benches/throughput.rs`). v0.3.0 sonrası throughput **%20'den fazla düşmemeli**.
- VTE parse maliyeti hot path'da; alt-screen aktif olduğunda regex skip edildiği için kazançla telafi edilebilir (net throughput artabilir bile).
- Allocation budget: VTE parser per-byte allocation yapmamalı (state machine'i in-place çalıştırır).

### 4.3 Güvenlik

CLAUDE.md §3 mandate'leri tüm sub-version'larda geçerli:
- Adversarial PTY output VTE parser'a girer; parser'ın kendisi malformed input'a resilient olmalı (vte crate bu kontratı taşır, audit edilmiş).
- OSC payload'ları (özellikle OSC 8 hyperlink URL'leri) verbatim passthrough — tayf onları parse etmez, sadece pass eder.
- `TAYF_DISABLE` env var kontrolü process start'ta tek bir read; runtime'da yeniden okunmaz (race-free).
- Disk-based themes (v0.3.4) user-config dosyasıyla aynı `read_capped` + symlink validation path'ından geçer.

### 4.4 Dependency policy

- **Yeni dep şart:** `vte` crate (v0.3.0). MIT/Apache-2.0, Alacritty maintainer'ları, `unsafe` minimum, no_std uyumlu. Cargo.toml justification commit message'ında.
- Başka sub-version yeni dep getirmemeli. v0.3.1 (bg detection) OSC 11 query için `nix` (zaten dep) yeterli. v0.3.4 disk themes için yeni dep yok — mevcut `toml` + `serde` + `std::fs`.

### 4.5 Test stratejisi

- Her sub-version: unit + integration test'leri spec'inde tanımlar.
- VTE-bağımlı test'ler (alt-screen detection, SGR state preservation): byte-by-byte fixture'lar — gerçek terminal değil, ham byte sequence'leri.
- `tests/integration_themes.rs` paterni mirror edilir: `tests/integration_<feature>.rs` her özellik için.
- CI matrix değişmez (Linux + macOS + audit/deny).

### 4.6 Release workflow

Memory'deki `tayf release workflow` aynen:
1. Sub-version commit'leri main'e.
2. Push main → CI yeşil bekle.
3. Tag push (`vX.Y.Z`, annotated, `tayf vX.Y.Z — <title>` mesajı).
4. CHANGELOG date bump follow-up commit (release günü gerçek tarihiyle).
5. GitHub Release sayfası açma yok (proje convention'ı tag-only).

## 5. Sıralama önerisi ve gerekçesi

```
v0.2.4 (current)
  ↓
v0.3.0 — VTE foundation        ← unblocks v0.3.2 duration units
  ↓
v0.3.1 — bg detection           ← finishes v0.2.3 theme story
  ↓
v0.3.2 — pattern polish         ← bare duration units now safe
  ↓
v0.3.3 — escape hatches         ← ortogonal, kullanıcı talebi
  ↓
v0.3.4 — disk themes            ← v0.4+ extensibility için zemin
  ↓
v0.3 done → v0.4 (RegexSet fast-path) brainstorming
```

**Neden bu sıra:**
- v0.3.0 önce — en büyük taş; sonraki polishlerin yarısı buna bağlı.
- v0.3.1 ikinci — v0.2.3 theme'lerinin UX kapanışı (zero-config light/dark). v0.3.0'a bağımlı değil, paralel yapılabilir ama VTE öncesi sırada kalması theme story'sini bütünleştirir.
- v0.3.2 üçüncü — küçük additive iş, bare duration units VTE ile mümkün.
- v0.3.3 dördüncü — operational; ne kadar geç gelirse o kadar iyi (kullanıcılar tayf'ı yeterince severse `--bypass` ihtiyaçları azalır).
- v0.3.4 son — v0.4 ve sonrasının extension point'i; v0.3'ün vitrin işi değil.

**Pause noktaları:** Her sub-version'dan sonra v0.3 stop edilebilir. v0.3.0 + v0.3.1 ship olduktan sonra "v0.3 minor'ü bu kadar, gerisi v0.4+" demek mümkün. Karar her sub-version sonrasında yeniden verilir.

## 7. Bu doküman değiştirildiğinde

Umbrella, sub-version brainstorming'lerinin başlangıç noktası. Bir sub-version brainstorming'i sırasında umbrella'daki bir kararla çelişen bir karar ortaya çıkarsa:
- Sub-version spec'i çelişkiyi açıkça not eder.
- Umbrella'yı güncellemek için ayrı bir commit gerekir (umbrella git'te canonical; "memory"deki notlar değil).

`tayf-tasarim.md` §11 (Yol Haritası) bu doküman ship olduktan sonra v0.3'ün detaylarına link verecek şekilde güncellenir (separate commit, v0.3.0 release-prep'inden önce).
