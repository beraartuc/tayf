# tayf v0.8.2 — H4 chunk-level pipeline (spike-first, security-gated)

**Tür:** Performance cycle, **spike-first** (measure-first'in bu cycle'a uyarlanmış hali). Faz 1 = atılabilir spike ile chunk-level kazanç **tavanını ölç**; Checkpoint = veriyle scope + N hedefi sabitle; Faz 2 = seçilen optimizasyonların TDD'li, temiz, güvenlik-gate'li implementasyonu.
**Base:** `v0.8.1` @ `fc02a43` (CI green, 2026-05-30).
**Kapsam:** v0.8.1 attribution'ı kanıtladı ki darboğaz I/O loop değil, **pipeline** ve CPU-bound (`Vec` sink'e bile ~12–28 MiB/s vs cat ~150). Kalan baskın maliyet `src/pipeline.rs::Pipeline::feed`'in **per-byte loop**'u: her byte için `AnsiSm::step` + dispatch `match` + (Data yolunda) tek-byte `line_buffer` feed. H4 = bunu chunk-level işlemeye çevir (Data run'larını toplu işle).

**Hedef:** v0.8.1 e2e + micro-bench baseline'a göre **ölçülebilir throughput iyileştirmesi** (N, spike sonrası checkpoint'te sabitlenir). Spec §7'nin literal `<%20-vs-cat`'ı bir byte-dönüştüren wrapper için yine ulaşılmayabilir; onu hedef yapmıyoruz — relative ilerleme + güncellenmiş `BASELINE.md` disposition.

> **DOKUNULMAZ duruşu — bu cycle DEĞİŞTİ (kullanıcı onaylı):** v0.8.2 `src/pipeline.rs`'e (ve gerekirse non-DOKUNULMAZ `src/line_buffer.rs`'e) **dokunabilir**, ANCAK `src/pipeline.rs`'e dokunan shipping değişiklik faz sonu **`security-review` gate**'inden geçer (CLAUDE.md §3). **`src/runtime.rs` ve `src/pty.rs`'e DOKUNULMAZ** — termios / raw-mode / signal-forwarding orada; bu cycle byte-işleme hot-path'i, güvenlik sınırı değil. Spike (Faz 1) atılabilir branch'te kalır, main'e merge edilmez → security-review yalnız shipping rewrite'a (Faz 2).

## 2. Faz 1 — Spike (atılabilir, kazanç tavanını ölç)

**Amaç:** chunk-level Data-run fast-path'inin pipeline throughput tavanını ölçmek; Faz 2 scope'unu ve N hedefini veriyle bilgilendirmek. **Hiçbir spike kodu main'e merge edilmez** (`v0.8.2-spike` throwaway branch).

### 2.1 H4a — çekirdek spike (chunk-level Data run)

`Pipeline::feed`'i, per-byte loop yerine **state-güdümlü iki-kovalı** bir loop'a çevir:

- **Fast path (SM `Ground`'da):** `memchr(0x1b, &chunk[i..])` ile bir sonraki ESC'yi bul. `[i, esc)` aralığı = saf Data run (Ground+non-ESC = `Data`, alan-mutasyonsuz — bkz. §4 invariant kanıtı). Run'ı:
  - TUI-aktif ise → tek `out.write_all(run)` (şu an byte başına `write_all(&[byte])`).
  - değilse → **var olan** `LineBuffer::feed_with_overflow(run)` + emitted lines üzerinde `apply_or_passthrough` loop'u (SGR dispatch'inin [pipeline.rs:568-578](src/pipeline.rs#L568-L578) yaptığı mekanizmanın aynısı). Slice-yolu `\n`'i satırda tuttuğundan, per-byte yolundaki `byte == b'\n'` re-add hack'i ([pipeline.rs:505-507](src/pipeline.rs#L505-L507)) kaybolur.
  - SM step'lenmez (Ground'da non-ESC step = no-op). `i = esc`.
- **Slow path (SM sequence state'inde, veya fast-path ESC'ye ulaştı):** byte-by-byte mevcut `step` + dispatch akışı (`ForceStringTerminate` re-step yolu dahil, aynen) — SM `Ground`'a dönene kadar.

Spike test'siz, temizliksiz, throwaway kalitesinde. Tek amaç: ölçüm.

### 2.2 Ölçüm (tee → Read → verify; feedback-transcribe-measured-numbers)

- **Birincil:** `cargo bench --bench pipeline_feed` (prose/log/ansi, in-process, PTY yok → dakikalar). before (v0.8.1 HEAD) / after (spike) karşılaştırması.
- **İkincil (tavan umut vaat ederse):** `cargo bench --bench e2e_overhead` cross-check.
- Ham çıktı `tee` → tmp dosya → **Read ile geri oku** → checkpoint'e digit-for-digit aktar. Bu sayılar BASELINE.md'ye YAZILMAZ (spike throwaway); checkpoint kararını besler.

### 2.3 İkinci spike katmanı — H4b (koşullu)

H4a sonrası `LineBuffer::feed_with_overflow`'un iç verimi yeni taban olursa ölç: mevcut `while let Some(pos) = memchr_newline(...) { self.inner.drain(..=pos).collect() }` ([line_buffer.rs:73-76](src/line_buffer.rs#L73-L76)) çok-satırlı bir chunk'ta her satırda kalan buffer'ı kaydırır (~O(L²)) ve `memchr_newline` naive `.iter().position()`. H4b spike katmanı = gelen slice'ı kopyasız böl (buffer boşsa segmenti doğrudan ödünç al) + opsiyonel `memchr` crate (SIMD newline). Ayrı ölç → her kazanç atfedilebilir.

## 4. Faz 2 — aday kaldıraçlar (checkpoint sonrası, veri seçer)

| # | Optimizasyon | Konum | DOKUNULMAZ? | Risk |
|---|---|---|---|---|
| **H4a** | chunk-level Data run (çekirdek) | `pipeline.rs` | Evet (gate) | Orta |
| **H4b** | `feed_with_overflow` kopyasız böl + (ops.) memchr | `line_buffer.rs` | Hayır | Düşük |
| **H2** | satır başına çift `Arc::load_full` → tek snapshot alt-çağrıya geçir | `pipeline.rs` | Evet (gate) | Düşük |

**H4a equivalence kanıtı (neden "provably equivalent"):**
- [ansi.rs:231](src/ansi.rs#L231): `SmState::Ground => StepEvent::Data` — Ground arm hiçbir SM alanını mutate etmez. ESC kontrolü ([ansi.rs:177](src/ansi.rs#L177)) `0x1b`'yi zaten en başta yakalar. `sequence_bytes_seen` Ground'da 0; cap ([ansi.rs:203](src/ansi.rs#L203)) Ground'da fire etmez. → Ground'da non-ESC byte'ları step'lememek state açısından no-op.
- Data-run'ı `feed_with_overflow` slice-yolu zaten SGR/OtherCsi dispatch'lerinde production'da kullanılıyor; `apply_or_passthrough` satır-sınırında `line_has_sgr`/`line_has_string_payload`'ı sıfırlıyor → batch'teki ilk satır önceki bayrağı görür, sonrakiler temiz. Davranış korunur.
- `feed_byte_with_overflow` (v0.8.1 O(1) per-byte path) H4a sonrası **dead code** olur → silinir (zero tech debt). Onun `debug_assert` guard'ı zaten "H4 chunk-level rewrite" senaryosunu adıyla anıyor ([line_buffer.rs:119-125](src/line_buffer.rs#L119-L125)).

**H2 bonus:** şu an `apply_or_passthrough` ([pipeline.rs:607](src/pipeline.rs#L607)) ve `apply_rules` ([pipeline.rs:75](src/pipeline.rs#L75)) **ayrı ayrı** `load_full()` yapıyor. İki load arası reload düşerse `respect_existing_colors` (snapshot A) vs styling (snapshot B) ayrışır — latent tutarsızlık. Tek snapshot'ı alt-çağrıya geçirmek hem H2 perf'ini sağlar hem bu Karar-11 invariant'ını sıkılaştırır.

## 5. Güvenlik (CLAUDE.md §3) — byte-identical ZORUNLU invariant'lar

Faz 2 `pipeline.rs`'e dokunduğu için faz sonunda **`security-review` skill** çalışır. Byte-for-byte korunacaklar:

- **TUI passthrough geçişleri:** `tui_mode_active()` dalı + toggle-on/off sıralaması; TUI-aktif Data run batch-write'ı verbatim olmalı (rule yok).
- **OSC/DCS/PM/APC payload drain sırası:** `StringPayloadByte` yolundaki buffer-drain → scratch-flush → payload-byte sırası ([pipeline.rs:513-535](src/pipeline.rs#L513-L535)); `line_has_string_payload` semantiği.
- **`ForceStringTerminate` (OSC cap) yolu:** synthetic ST yaz + re-step; TUI-içi ve TUI-dışı iki kol ([pipeline.rs:457-477](src/pipeline.rs#L457-L477)) aynen korunur.
- **`line_buffer` 64KB cap + overflow flush** ([line_buffer.rs:12](src/line_buffer.rs#L12), `MAX_BUFFER_BYTES`): chunk-level feed cap'i byte-identical tetiklemeli (overflow flush rule-application'sız, warning loglu).
- **UTF-8 sınır güvenliği:** multi-byte codepoint chunk sınırına denk gelirse partial sequence güvenli (regex::bytes raw slice).
- **`line_has_sgr` satır-sınırı semantiği:** SGR bir satırın ortasında geldiğinde, o satır `respect_existing_colors` ile rule-skip olur.
- **ReDoS / pattern lineerliği:** apply_rules'a dokunulmuyor; korunur.
- **termios/raw-mode/signal-forwarding:** `runtime.rs`/`pty.rs` **dokunulmaz**.

`memchr` (eğer direct-dep'e çıkarılırsa): `2.8.0` zaten ağaçta (regex transitive) → **sıfır yeni audit yüzeyi**; yalnız `Cargo.toml`'a direct girdi + commit'te justification (memory feedback-dependency-minimalism).
