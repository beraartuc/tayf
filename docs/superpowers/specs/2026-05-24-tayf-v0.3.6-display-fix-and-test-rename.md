## 1. Motivasyon

v0.3.5 capture-group styling feature'ı ship sonrası iki ayrı zayıflık ortaya çıktı:

1. **`ThemeRuleErrorKind::CaptureGroupIndexOutOfRange` Display'i `n == 0` edge case'inde anlamsız.** Tek-branch'li `write!` `captures_len == 1` (no capture groups) durumunda `"(valid: 1..=0)"` üretiyor — boş integer aralığı, kullanıcıya ne yapacağı söylemiyor. CLAUDE.md §4 "Error messages are user-facing UX" mandate'ini ihlal ediyor (what + why + what to do testinde "what to do" yok).
2. **İki `syslog_timestamp_match_renders_one_sgr` testinin ismi gövdesini overstate ediyor.** Hem `src/pipeline.rs:539` (unit) hem `tests/integration_capture_groups.rs:165` (integration) sadece substring containment kontrol ediyor, ama isim "renders_one_sgr" iddiasını taşıyor. Mevcut unit test'in yorumu (`src/pipeline.rs:546`) bile itiraf ediyor: "log_level rule will catch 'msg' — that's an extra SGR. Assert the substring appears in output (basic survival check)." Yanıltıcı isim → gelecek bir contributor'ın yanlış tarafta refactor yapma riski.

Her ikisi de pure bugfix. Hot path'e dokunulmuyor, public API yüzeyi etkilenmiyor, BASELINE.md aynı kalıyor.

## 2. Değişiklik envanteri

### 2.1 Fix A — Display two-branch specialization

**Dosya:** `src/error.rs` (Display impl)
**Mevcut (lines 97-107):**

```rust
Self::CaptureGroupIndexOutOfRange { group, captures_len } => {
    let n = captures_len.saturating_sub(1);
    write!(
        f,
        "styles.\"{}\": rule's regex has {} capture group{} (valid: 1..={})",
        group,
        n,
        if n == 1 { "" } else { "s" },
        n
    )
}
```

**Yeni:**

```rust
Self::CaptureGroupIndexOutOfRange { group, captures_len } => {
    let n = captures_len.saturating_sub(1);
    if n == 0 {
        write!(
            f,
            "styles.\"{group}\": rule's regex has no capture groups; styles cannot be set"
        )
    } else {
        write!(
            f,
            "styles.\"{}\": rule's regex has {} capture group{} (valid: 1..={})",
            group,
            n,
            if n == 1 { "" } else { "s" },
            n
        )
    }
}
```

**Kontrat:**
- `captures_len == 1` (n == 0): yeni mesaj.
- `captures_len >= 2` (n >= 1): mevcut format **byte-identical** korunur, pluralization helper'a dokunulmaz.

**Niçin iki branch:** Tek `write!`'da `if n == 0 { "no" } else { &n.to_string() }` ile in-place formatleme kısalır ama "(valid: 1..=0)" suffix'i de conditional yapmak gerekir; iki branch okumayı kolaylaştırıyor ve regression guard test'i daha net.

### 2.2 Fix B — Misnamed test rename

**İki dosyada aynı sembol:**
- `src/pipeline.rs:539` — unit test
- `tests/integration_capture_groups.rs:165` — integration test (kullandığı `count_non_reset_sgrs` helper'ı bu rename'den etkilenmez)

**Rename:** `syslog_timestamp_match_renders_one_sgr` → `syslog_timestamp_substring_survives_colorization`

**Test gövdeleri değişmez** — her ikisi de `s.contains("May 24 10:30:45")` kontrol ediyor; bu davranış doğru (syslog branch capture-less, rule'un default style'ı ile wrap'lanır, substring zarar görmemeli). Sadece isim iddiası gövdeyle uyumlu hale gelir.

**Yorum güncellemesi** (`src/pipeline.rs:545-548`, yanıltıcı 3 satır):

Mevcut:
```rust
// Syslog branch has no captures -> entire match wrapped in one default-style SGR.
// Plus log_level rule will catch "msg" — that's an extra SGR.
// Assert the substring appears in output (basic survival check).
```

Yeni:
```rust
// Syslog branch has no captures -> match wrapped with the rule's default style.
// Other rules (e.g., log_level on "msg") may add additional SGRs; this test
// only asserts the timestamp substring survives colorization intact.
```

Integration test'te (`tests/integration_capture_groups.rs:160-163`) yorum zaten doğru; dokunulmaz.

### 2.3 Yeni unit test (Fix A regression guard)

**Lokasyon:** `src/error.rs` test module (`mod tests` `#[cfg(test)]`, line 317-civarı), mevcut iki `CaptureGroupIndexOutOfRange` snapshot test'inden sonra (~line 574):

```rust
#[test]
fn theme_rule_error_kind_out_of_range_no_capture_groups_specialized() {
    let k = ThemeRuleErrorKind::CaptureGroupIndexOutOfRange {
        group: 1,
        captures_len: 1,
    };
    let s = k.to_string();
    assert!(s.contains("styles.\"1\""), "got: {s}");
    assert!(s.contains("no capture groups"), "got: {s}");
    assert!(s.contains("styles cannot be set"), "got: {s}");
    assert!(!s.contains("valid: 1..=0"), "regression guard: {s}");
}
```

**Mevcut iki snapshot test'i** (`captures_len: 4` plural ve `captures_len: 2` singular) **byte-identical korunur** — pluralization helper'ın hâlâ çalıştığının kanıtı. Bu üçlü, üç davranışı pin'ler:
1. n == 0 → yeni özelleştirilmiş mesaj.
2. n == 1 → "1 capture group" (singular).
3. n >= 2 → "N capture groups" (plural).
