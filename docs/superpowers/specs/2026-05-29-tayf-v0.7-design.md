### 3.1 Mevcut davranış (v0.6.2-v0.6.3)

`src/config_tui/merge.rs:204-213` her üç tarafta `Item::ArrayOfTables(_)` olan key için:

```rust
    });

```

Sonuç: `[[rules]]` array'inin tek bir element'inde değişiklik bile tüm array'i conflict yapıyor. Test pin: `merge_array_of_tables_yields_whole_array_block_conflict_v0_6_2_limitation` ([merge.rs:534](src/config_tui/merge.rs#L534)).

### 3.2 v0.7 davranışı: name-keyed per-element merge

**Element identity key (Q1 kararı):** Element'in `name = "..."` field'ı. UserRule struct (config.rs:93-94) `name: String` REQUIRED — well-formed config'de identity her zaman mevcuttur.

**Fallback (malformed config defensive guard):** İlk önce identity validation:
- ANY side'da bir element `name` field'ı taşımıyorsa veya `name` field'ı Item::Value(String) değilse → **whole-array fallback** (v0.6.2 davranışı korunur, `is_array_block: true`).

**Algoritma (`merge_table` içinde yeni branch):**

```text
all three Item::ArrayOfTables(aoa, aob, aot):
  1. Identity validate (her element için name field zorunluluğu).
     Bir elementin name yoksa → whole-array fallback (v0.6.2).

  2. Identity collect:
       base_names   = aob.iter().map(|e| e["name"].as_str().unwrap()).collect::<Vec<_>>()
       ours_names   = aoa.iter() ...
       theirs_names = aot.iter() ...
     Duplicate name same-side içinde ALLOW edilir (toml_edit grammar'ı izin verir),
     ama merge_three_way için warning — duplicate-on-same-side ALL elements ile
     positional sub-pairing yapılır (degraded mode). Spec §3.5'te tartışılır.

  3. Distinct ordered name list:
       order = base_names + (ours-only in ours order) + (theirs-only in theirs order)
     (Stable: aynı 3-input → aynı output)

  4. Yeni ArrayOfTables alloc; her name için:
       be = aob.find_by_name(name)
       oe = aoa.find_by_name(name)
       te = aot.find_by_name(name)

     Per-key merge_table kuralı (ama Table-on-Table specialised):
       be == oe == te                 → push be
       be == oe, be != te             → push te
       be == te, be != oe             → push oe
       oe == te (convergent)          → push oe
       be present, oe absent, te absent → DROP (convergent deletion)
       be present, oe absent, te present, te == be → DROP (ours deleted, theirs untouched-or-restored)
       be present, oe present, te absent, oe == be → DROP (theirs deleted, ours untouched)
       be absent, oe present, te absent → push oe (ours insertion)
       be absent, oe absent, te present → push te (theirs insertion)
       be absent, oe present, te present, oe == te → push oe (convergent insertion)
       hepsi present, hepsi farklı, hepsi Table → recurse merge_table on element fields,
         path = [...key, name], element-içi field conflicts üretilir (path = [...key, name, field])
       shape mismatch                  → element-level conflict, shape: Block, path = [...key, name]

  5. Edge case'ler:
       be absent, oe present, te present, oe != te → element-level conflict, shape: Block
       be present, oe absent, te present, te != be → "theirs modified what ours deleted"
         → element-level conflict, shape: Block (delete-modify çarpışması)
       symmetric: be present, oe present, te absent, oe != be → "ours modified what theirs deleted"
         → element-level conflict, shape: Block
```

**`KeyConflict::is_array_block` semantiği** (sözleşme daralır):
- v0.6.2: AoT olan her tablo karşılaştırması `is_array_block: true`.
- v0.7: SADECE whole-array fallback durumunda (identity invariant kırıldı) `true`. Per-element conflict'lerde `false` (path daha derindir: `["rules", "log_level", "pattern"]`).

**`ConflictValueShape` sözleşmesi:** Per-element conflict element-level alındığında `Block` (path = `[..., name]`), field-level alındığında `Leaf` veya `Block` (path = `[..., name, field]`, field'ın gerçek şekline göre). Mevcut `classify_shape` helper'ı path leaf'in son segment'inin tipine bakar — değişiklik gerekmiyor.

### 3.3 `write_to_path` etkisi

`write_to_path(doc, path, source)` ([merge.rs:335](src/config_tui/merge.rs#L335)) bugün `path: &[String]` üzerinden source AST'sini descend ediyor. Per-element merge yeni path shape'leri üretir:

- `["rules", "log_level", "pattern"]` — `rules` AoT, `log_level` name'li element, `pattern` field.
- `["rules", "log_level"]` — element-level conflict (Block shape, full element replacement).

`write_to_path`'in mevcut implementation'ı sadece `Item::as_table()` descend kullanıyor — AoT element içine inmek için `[i]` indexing gerekiyor. v0.7'de **yeni helper**: `descend_aot_by_name(doc, path) -> Result<&Item, WriteToPathError>` ve sembolik counterpart `descend_aot_by_name_mut`.

Açıkçası daha temiz seçim: `write_to_path` zaten dotted path semantiği yapıyor; segment'i AoT element name'i olarak yorumlamak descend logic'inin bir genişlemesi. AoT segment için lookup:

```text
cur is Item::ArrayOfTables(aot):
    find_index = aot.iter().position(|e| e.get("name").and_then(Item::as_str) == Some(seg))
    if find_index is None: return MissingIntermediate
    cur = aot.get(find_index).unwrap().as_item() (table item içinden)
```

**Yeni error variant:** `WriteToPathError::AotElementMissing { path, element_name }` — disambiguate `MissingIntermediate` (table descend'inin başarısızlığı) vs. AoT içinde isim bulunamadı.

**Spec contract:** auto_merged konfigürasyonu UI'nin per-key choice tuple'ını uygularken consistent — conflict path'i write_to_path'in başarılı descend edebileceği bir path olmak zorunda. Yani: per-element merge conflict üretirken aynı path'i write_to_path'le test etmek implementer'ın sorumluluğu (TDD: yeni test'lerden biri "her conflict.path için write_to_path(auto_merged, path, source) Ok döner" round-trip).

## 4. Item 5 — LCS-DP line diff

### 4.1 Mevcut davranış (v0.5.4 inline impl)

```rust
fn build_diff(old: &[u8], new: &[u8]) -> String {
    let old_lines: HashSet<&str> = old_str.lines().collect();
    let new_lines: HashSet<&str> = new_str.lines().collect();
    // emit lines in old not in new with "-"
    // emit lines in new not in old with "+"
    // if no edits → "(no changes)"
}
```

**Bug (documented limitation, save_diff.rs:236-238):** `HashSet` aynı line'ı tek key olarak gördüğünden, `"a\na\nb\n" → "a\nb\n"` değişikliğini "(no changes)" gösteriyor. Removing one of N duplicate copies invisible.

### 4.2 v0.7 davranışı: LCS-DP

**Algoritma (Hunt-McIlroy / line-oriented LCS):**

1. `old_lines = old_str.lines().collect::<Vec<_>>()`, `new_lines = new_str.lines().collect::<Vec<_>>()`.
2. `n = old_lines.len(); m = new_lines.len()`.
3. **Bounded cap guard:** `n * m > MAX_DP_CELLS (= 100_000)` ise → cap fallback (4.4).
4. DP table: `dp[i][j] = LCS(old_lines[0..i], new_lines[0..j]).len()`.
   - Recurrence: `dp[i][j] = if old_lines[i-1] == new_lines[j-1] { dp[i-1][j-1] + 1 } else { max(dp[i-1][j], dp[i][j-1]) }`.
5. Trace-back: i=n, j=m'den başlayıp:
   - `old[i-1] == new[j-1]` → `Same(old[i-1])`, i--, j--.
   - `dp[i-1][j] >= dp[i][j-1]` → `Remove(old[i-1])`, i--.
   - else → `Add(new[j-1])`, j--.
6. Ters çevir, format: `Same` → `"  {line}\n"`, `Remove` → `"- {line}\n"`, `Add` → `"+ {line}\n"`.
7. Tüm ops `Same` ise → `"(no changes)\n"` literal döndür (sözleşme aynı).

### 5.3 Corpus harness yapısı

**Yeni klasör:** `tests/audit_corpus/` (her item için bir `.txt` corpus + bir `README.md`).

**Corpus dosya formatı (parse-friendly, line-oriented):**

```text
# Audit item: C-4
# Rule under test: filename
# Audit doc: docs/superpowers/reviews/2026-05-27-builtin-pattern-fp-audit.md §C-4
# Decision: <to be populated by implementer after measurement>

POS: a.b.c => a.b.c
POS: see config.txt is broken => config.txt
POS: cat /etc/hosts.conf => hosts.conf
NEG: a.b.c.d
NEG: numpy.linalg.norm
NEG: com.acme.proj.Service
...
```

**Grammar:**
- `#` ile başlayan satır → yorum.
- Boş satır → ignore.
- `POS: <input> => <expected_match_string>` → kural ismi (file header'da) bu input için *exactly* `<expected_match_string>` span dönmeli.
- `NEG: <input>` → kural bu input için match dönmemeli (None).

**Harness modülü** (`tests/audit_corpus.rs`, top-level integration test):

```rust
use std::path::PathBuf;
use std::fs;

struct AuditCase {
    item_id: String,
    rule_name: String,
    positives: Vec<(String, String)>,
    negatives: Vec<String>,
}

fn parse_corpus_file(path: &PathBuf) -> AuditCase { ... }

/// Returns (fp_count, fn_count, total_pos, total_neg).
fn measure(case: &AuditCase) -> (usize, usize, usize, usize) {
    let mut fp = 0;
    let mut fn_ = 0;
    for (input, expected) in &case.positives {
        let actual = tayf::testing::match_rule(&case.rule_name, input);
        if actual.as_deref() != Some(expected.as_str()) {
            fn_ += 1;
        }
    }
    for input in &case.negatives {
        if tayf::testing::match_rule(&case.rule_name, input).is_some() {
            fp += 1;
        }
    }
    (fp, fn_, case.positives.len(), case.negatives.len())
}
```

**`tayf::testing::match_rule(&str, &str)` helper:** tayf crate'ine `#[doc(hidden)] pub mod testing` yeni surface; mevcut `rules.rs`'in `match_string` test helper'ının external-test versiyonu. Memory `project_v0_6_3_shipped` `__test_api` pattern'ı bunun precedent'i. Şart: rules pipeline'ı public-shadow değil; sadece corpus'un single-rule-by-name testi.

**Helper API:**

```rust
// src/config_tui/test_support.rs

use ratatui::backend::TestBackend;
use ratatui::buffer::Buffer;
use ratatui::layout::Rect;
use ratatui::Terminal;
use ratatui::Frame;

use crate::config_tui::app::App;

/// Render bir `App` state'ini fixed-size TestBackend'e, buffer'ı plaintext'e
/// stringify et, snapshot golden'la karşılaştır.
///
/// `snap_name` is the snapshot file basename without `.snap` extension.
/// Snapshot files live in `src/config_tui/snapshots/<snap_name>.snap`.
///
/// `UPDATE_SNAPSHOTS=1` env var: regenerate the golden file (write `rendered`).
/// Default: read golden, compare, panic on mismatch with LCS diff message.
pub(crate) fn assert_render_snapshot(
    width: u16,
    height: u16,
    app: &App,
    draw: impl Fn(&mut Frame, Rect, &App),
    snap_name: &str,
) {
    let backend = TestBackend::new(width, height);
    let mut terminal = Terminal::new(backend).expect("TestBackend init");
    terminal.draw(|f| draw(f, Rect::new(0, 0, width, height), app)).expect("draw");
    let rendered = stringify_buffer(terminal.backend().buffer());

    let snap_path = format!("src/config_tui/snapshots/{snap_name}.snap");
    let abs_path = format!("{}/{snap_path}", env!("CARGO_MANIFEST_DIR"));

    if std::env::var("UPDATE_SNAPSHOTS").is_ok() {
        std::fs::write(&abs_path, &rendered).expect("write snapshot");
        eprintln!("UPDATED snapshot: {snap_path}");
        return;
    }

    let expected = std::fs::read_to_string(&abs_path).unwrap_or_else(|_| {
        panic!(
            "snapshot not found: {snap_path} — rerun with UPDATE_SNAPSHOTS=1 to create"
        )
    });

    if rendered != expected {
        // Dogfood Item 5 LCS diff for the failure message.
        let diff = crate::config_tui::widgets::save_diff::build_diff(
            expected.as_bytes(), rendered.as_bytes(),
        );
        panic!(
            "render snapshot mismatch for {snap_name}:\n{diff}\n\
            re-run with UPDATE_SNAPSHOTS=1 to accept the new output"
        );
    }
}

fn stringify_buffer(buf: &Buffer) -> String {
    // Plain-text only. SGR/style assertion separate task; v0.7 baseline
    // captures layout regressions only.
    let mut out = String::with_capacity(buf.area().area() as usize);
    for y in 0..buf.area().height {
        for x in 0..buf.area().width {
            let cell = buf.get(x, y);
            out.push_str(cell.symbol());
        }
        out.push('\n');
    }
    out
}
```

**Tasarım kararı:** Plain-text only — SGR ve color bilgisi snapshot'a dahil edilmez. Sebep:
- Layout regressions (Block border kayması, scroll offset, Paragraph wrap) snapshot'la yakalanır.
- Style regressions (color theme'ler arası test variants gerekirdi) ayrı bir test gear'la (v0.8'e DEFER edilebilir).
- Plain-text snapshot diff'leri okunabilir; binary buffer dump gerekmiyor.
