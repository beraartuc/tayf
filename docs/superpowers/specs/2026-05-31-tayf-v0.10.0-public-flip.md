## §5 — Phase B: CI runner sertleştirmesi (`ci.yml`) — GÜVENLİK-KRİTİK

### Mevcut durum (risk)
`ci.yml` 5 job'un HEPSİ `runs-on: [self-hosted, Linux, X64]`: `test`, `audit`, `bench-regression`, `msrv`, `fuzz-smoke`. Trigger: `push` (main) + `pull_request` (main). **Repo public olunca fork-PR'lar bu job'ları self-hosted runner'da çalıştırır = kullanıcının makinesinde RCE.** (macOS CI job'u yok; macOS yalnız release matrix'inde.)

### Değişmez güvenlik kuralı
**Fork-PR kodu self-hosted runner'a ASLA dispatch edilmez.**

### Mekanizma
1. **Self-hosted job'lara trusted-context `if`-gate** (her 5 job'a job-seviyesi):
   ```yaml
   if: >-
     github.event_name != 'pull_request' ||
     github.event.pull_request.head.repo.full_name == github.repository
   ```
   → push (main) + same-repo PR çalışır; **fork PR atlanır** (runner'a dispatch edilmez).
2. **Yeni `smoke` job (GitHub-hosted)** — fork-PR'lar için:
   ```yaml
   runs-on: ubuntu-latest
   if: >-
     github.event_name == 'pull_request' &&
     github.event.pull_request.head.repo.full_name != github.repository
   ```
   Adımlar: checkout + toolchain (stable, rustfmt+clippy) + `cargo fmt --check` + `cargo clippy --all-targets -- -D warnings` + `cargo test`. Env: `TAYF_DISABLE_BG_DETECT=1` (OSC 11 hang, environment-general) + `RUST_TEST_THREADS=1` (defensif; reload-orchestrator hang self-hosted-spesifik olabilir ama GH-hosted'da doğrulanana dek serileştir).
   - **mold yok** → A2'deki `.cargo/config.toml` removal bu job'ı unblock eder (default linker).
3. **Repo ayarı (defense-in-depth):** Actions → "Fork pull request workflows from outside collaborators" = **"Require approval for all outside collaborators"**. Kullanıcı toggle'lar ya da onayıyla `gh api` (§11.4). Bu, fork-PR workflow'unun (smoke dahil) maintainer onayı olmadan çalışmamasını sağlar (CI-abuse/crypto-mining koruması).

### Neden güvenli (doğrulanacak invariant'lar — §13)
- tayf `pull_request` kullanıyor (`pull_request_target` DEĞİL) → fork-PR, **base branch'in** workflow tanımını çalıştırır; fork `if`-gate'i değiştiremez. GITHUB_TOKEN read-only + secret'lar fork-PR'a expose edilmez (public-repo default).
- `if: false` olan job runner'a dispatch EDİLMEZ (skip), fork kodu self-hosted'ta execute olmaz.

### Doğrulama (CI round-trip beklenir)
[[feedback-msrv-floor-from-ci-not-local]] dersi: GH-hosted smoke'un ilk koşusu, self-hosted-spesifik test-exclude'ların (RUST_TEST_THREADS, bg-detect) GH-hosted'da gerekli/yeterli olup olmadığını ortaya çıkarır. Bir CI round-trip bütçele; ilk sonucu "discovery" say, regression değil.

## §6 — Phase C: `release.yml` dry-run → CANLI

### Mevcut (dry-run)
`workflow_dispatch`-only; build matrix (ubuntu-latest + macos-14 + macos-13) → per-target `.sha256` → `attest-build-provenance@v3` (SLSA L2) → `cargo publish --dry-run` + `cargo cyclonedx` SBOM → artifact upload. **Sıfır `secrets.*`, publish yok.**

### Canlı eklemeler
1. **Trigger:** `on: push: tags: ['v*']` eklenir (`workflow_dispatch` dry-run için kalır). Canlı/dry-run ayrımı: `IS_RELEASE: ${{ github.event_name == 'push' }}` → publish/release adımları yalnız tag-push'ta.
2. **Birleşik SHA256SUMS:** tüm target binary'leri için tek `SHA256SUMS` dosyası (per-target `.sha256` yerine/yanında), release'e eklenir.
3. **Sigstore Public-Good verify (in-workflow):** `attest-build-provenance@v3` (public-good Fulcio/Rekor'a yazar) sonrası bir **verify adımı** — `gh attestation verify <binary> --repo beraartuc/tayf` — provenance'ın **public transparency log**'da doğrulandığını teyit eder. (v0.9 dry-run'da bu re-verify yapılmamıştı; carryover.) **Exact komut + instance OPEN-2 (§14), paralel review ampirik doğrular.**
4. **crates.io publish (idempotent):**
   - Job `environment: release` (korumalı; **required reviewer** = manuel onay kapısı, Actions UI'da bekler; `CARGO_REGISTRY_TOKEN` secret'ı bu environment'a scope'lu → build-matrix job'larına sızmaz).
   - **Idempotency guard:** publish'ten önce `https://crates.io/api/v1/crates/tayf/<version>` sorgulanır; 200 (var) → publish SKIP (log); 404 → `cargo publish --locked`. Bu, manuel-ilk-publish (§7) ile otomatik-sonraki-publish'i çatışmasız bir arada tutar + kazara çift-publish'i engeller.
5. **`gh release create`:** GitHub Release oluştur — binary'ler + `SHA256SUMS` + SBOM + provenance ekli; release notes CHANGELOG `[0.10.0]`'dan. (Projenin eski tag-only konvansiyonundan [[tayf-release-workflow]] EVRİM: GH-release-create + imzalı-binary artık seremoninin parçası.)
6. **Permissions:** minimal job-bazında (`contents: write` yalnız release-create job'ında; `id-token: write` + `attestations: write` attest job'ında; publish job'ı yalnız `release` environment secret'ı).

### Güvenlik
- Tag-trigger → yalnız tag push edebilen (maintainer) tetikler; fork-PR tag push edemez.
- `release` environment + required reviewer → tag push'tan SONRA bile publish/release manuel onay bekler (ikinci kapı, "her outward adımdan önce onay" §11 ile hizalı).
- Token: crate-scoped + publish-update + expiry; environment-scoped; loglanmaz.

## §8 — Phase E: Always-on UX (`TAYF_SESSION` marker)

### E1 — Marker (src — tek dar dokunuş)
`src/pty.rs:80-85` spawn path'inde, `spawn_command` öncesi:
```rust
cmd.env("TAYF_SESSION", "1");
```
Sabit değer; kullanıcı girdisi yok. Child shell + altındaki her şey miras alır. **Güvenlik:** benign — exec semantiğini (no-sh-c, direct argv) değiştirmez; audit'in spawn-path bulgusunu etkilemez (§13'te re-review).

### E2 — TDD
- **Test (RED→GREEN):** integration testi — `tayf` ile spawn edilen shell `echo $TAYF_SESSION` → `1` döndürür. (Mevcut `tests/common/` helper'ları + PTY-substring-SGR fragmentation farkındalığı [[feedback-pty-substring-sgr-fragmentation]]: marker-scan, has_sgr-helper değil.)
- Nested-tayf farkındalığı testi (opsiyonel): tayf içinde `TAYF_SESSION=1` zaten set → rc-guard'ın nasıl davranacağı dokümante.

### E3 — Docs (README "Always-on" bölümü)
İki yol:
- **(A) Terminal-emülatör başlangıç komutu** (önerilen): iTerm2/Terminal.app/Alacritty/kitty/GNOME Terminal/Konsole per-terminal `command = tayf`. Rekürsiyon yok (rc temiz).
- **(B) rc-exec (power-user), güvenli guard:**
  ```sh
  # ~/.zshrc / ~/.bashrc
  [[ $- == *i* && -t 1 && -z $TAYF_SESSION ]] && exec tayf
  ```
  `TAYF_SESSION` guard'ı rekürsiyonu keser (marker olmadan sonsuz döngü olurdu). Interactive + TTY check'leri non-interactive/SSH/scp'yi korur.

## §11 — Release seremonisi (tek-yönlü, her outward adımda ONAY)

Sıra (🔒 = açık kullanıcı onayı şart):

1. Tüm v0.10.0 işi `main`'e iner (feature branch → FF veya self-PR; subagent-driven impl).
2. Push `main` → **CI green BEKLE** (self-hosted full matrix; fork-smoke push'ta tetiklenmez). [[tayf-release-workflow]]. İlk koşu Linux/env sürprizi çıkarabilir → fix-commit bütçele.
3. 🔒 **[ONAY] repo public toggle ÖNCESİ:** son-durum secret-scan re-run (§A1) → kullanıcı onayı → **repo'yu public yap** (kullanıcı flip'ler veya onayıyla `gh repo edit --visibility public`). Runner-fix zaten merged → fork riski kapalı.
4. 🔒 **[ONAY] Repo Actions fork-onay ayarı:** "require approval for all outside collaborators" (kullanıcı veya onaylı `gh api`).
5. 🔒 **[ONAY] crates.io ilk publish (manuel, §7 D1):** kullanıcı makinesinden kısa-expiry `publish-new` token → `cargo publish --locked` → doğrula (crates.io sayfası) → token revoke.
6. 🔒 **[ONAY] tag `v0.10.0` push** → `release.yml` tetiklenir.
7. Build/sign/SBOM çalışır; **`release` environment'ta DURUR** (required reviewer).
8. 🔒 **[ONAY] environment approve** → crates.io publish (idempotent: v0.10.0 zaten var → SKIP) + `gh release create` (binary'ler + SHA256SUMS + SBOM + provenance).
9. **Doğrula:** crates.io sayfası, `gh attestation verify` (Public-Good log), GH release sayfası, SHA256SUMS. [[feedback-transcribe-measured-numbers]]: checksum/digest doğrulamaları tee→Read→verify.
10. 🔒 **[ONAY] Homebrew tap (§7 D2):** `beraartuc/homebrew-tayf` create → `Formula/tayf.rb` (released sha256) → commit → `brew install beraartuc/tayf/tayf` test.
11. CHANGELOG tarih-bump follow-up commit ([[tayf-release-workflow]]).
12. Memory: `project-v0-10-0-shipped` yaz.

> **Sıralama notu:** public-flip (3) tag/release'den (6-8) ÖNCE → repository/homepage linkleri ve GH release public görünür. crates.io ilk-publish (5) repo-visibility'den bağımsız ama crate'in repository linki resolve etsin diye public-flip sonrası. Runner-fix (2'de merged) public-flip'ten önce → fork RCE penceresi hiç açılmaz.

## §13 — Güvenlik değerlendirmesi (public-flip threat model)

Bu cycle'a özgü, security-review skill + paralel review + final cross-cutting doğrulayacak:

1. **Fork-PR RCE (self-hosted):** §5 mekanizması. Doğrulanacak invariant'lar: (a) `pull_request` (not `_target`) → fork base-workflow çalıştırır; (b) `if`-gate'li job runner'a dispatch edilmez; (c) GITHUB_TOKEN read-only + fork-PR'a secret yok; (d) repo-onay-ayarı smoke'u da gate'ler.
2. **crates.io token:** crate-scoped + publish-update + expiry; `release` environment-scoped (build-matrix'e sızmaz); loglanmaz; ilk-publish token kısa-expiry + revoke. Doğrulanacak: token hiçbir log/echo/artifact'a düşmez.
3. **TAYF_SESSION marker:** sabit env-injection; exec semantiği değişmez; nested-tayf benign (double-colorize yok çünkü rc-guard veya kullanıcı bilir). Re-review spawn-path.
4. **release.yml supply-chain:** GHA SHA-pin korunur; yeni adımlar (gh release create, attestation verify) script-injection yüzeyi açmaz (matrix sabit, `github.event.*` yalnız boolean'a). cargo tools version-pinned. SBOM graph-based (fancy-regex prune sonrası tutarlı).
5. **Public-repo açılışı:** secret-scan CLEAN (A1); `.cargo/config.toml`/repro removal contributor-build'i bozmaz; CLAUDE.md/README stale-ref temizliği dangling-link bırakmaz.
6. **DEFER — `__bench__` cfg-gating:** publish build'inde `#[doc(hidden)]` thin-wrapper kalır (v0.5.3 deliberate pattern; behavior-neutral; adversarial-input-unreachable). §1 dispositionu; bu cycle'da risk değişmez.
