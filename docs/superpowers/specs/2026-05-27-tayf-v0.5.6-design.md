**Priority tier system** (post-review absorpsiyon §13 R2-B2; reviewer Rust

| Tier | Değer | Hangi rule'lar | Rasyonel |
|------|------:|---------------|----------|
| Envelope | `200` | Profile envelope rules: `arn`, `image_tag` | Domain-context rule'lar profile'ın kendi interior rule'larından bile öncelikli olmalı; iteration order'da strict-first olarak yer alır |

## 4. Architectural priority — algorithm + örnekler

### 4.1 Priority field semantics

```rust
pub(crate) struct BuiltinRule {
    pub(crate) name: String,
    pub(crate) pattern: String,
    pub(crate) style: Style,
    pub(crate) group_styles: Vec<Option<Style>>,
    pub(crate) styles_override: Option<...>,
    pub(crate) source: RuleSource,
    /// Overlap-resolution priority.
    ///
    /// Rules with higher `priority` iterate first in [`apply_rules`]; their
    /// accepted spans block overlapping matches from lower-priority rules.
    /// `overlaps_accepted` is **bidirectional** — a higher-priority rule
    /// that has accepted span S blocks any lower-priority candidate whose
    /// span overlaps S in either direction (nested inside S or enveloping
    /// S). This is the load-bearing property that lets envelope rules
    /// suppress interior built-ins.
    ///
    /// Tier convention (§2.1.B):
    /// - `0`  — built-in defaults; user-config rules without explicit `priority`.
    /// - `100` — profile interior rules (instance_id, region, container_id, pod_name).
    /// - `200` — profile envelope rules (arn, image_tag).
    /// - Any i32 — user-config opt-in (`#[serde(default)] priority: Option<i32>`).
    ///
    /// Tie-breaking when two rules have equal priority: lower rule index
    /// (pattern-definition order) wins. Preserves v0.5.5 "first-match-wins
    /// by pattern order" for all priority-0 built-in pairs.
    ///
    /// Negative values are legal — a user-config rule with `priority = -1`
    /// will yield overlap-acceptance to any overlapping built-in match.
    pub(crate) priority: i32,
}
```

### 4.2 Compiled-side mirror

(reviewer Rust senior N2):
```

                 == styles.len()
                 == group_styles.len()
                 == uses_capture_styling.len()
```

`Compiled::build_from_loaded` (src/rules.rs:661+) Step 6 `compile_merged_rules`'da

### 4.3 Pipeline algorithm

Yeni `apply_rules` iç akışı (mevcut algoritma + sort step). Sort idiom
`std::cmp::Reverse` wrapper (reviewer Rust senior B1 — operand-swap idiom
fragile; future contributor swapping operands silently flips direction).
**`sort_by` ZORUNLU; `sort_unstable_by` DEĞİL** — stable sort tie-break
invariance'ı korur (priority 0 == priority 0 case'i pattern-definition
order'a düşer).

```rust

// 1. RegexSet pre-filter (unchanged).
scratch.set_match_scratch.extend(compiled.set.matches(line).iter());

// 2. NEW: stable sort by (priority DESC, rule_index ASC).
//    K ≤ rule_count (~20); sort cost O(K log K) negligible vs match work.
scratch.set_match_scratch.sort_by(|&a, &b| {
    Reverse(compiled.priorities[a]).cmp(&Reverse(compiled.priorities[b]))
        .then_with(|| a.cmp(&b))
});

// 3. Accept loop (unchanged) — iterates the now-priority-sorted indices.
for &i in &scratch.set_match_scratch {
    // ... existing find_iter / captures_iter accept logic ...
}
```

**Örnek 5: Same-priority envelope vs interior fails (tradeoff documented)**

```toml
[[rules]]

priority = 50
pattern = '\d+'           # matches digit runs
```

Input: `[123]`. Both rules match — outer span `[0, 5)`, inner span `[1, 4)`.

(lower index) → iterates first → accepts `[0, 5)`. `inner` overlap → REJECT.

But if `inner` was defined first in the user config:
Sort tie-break → `inner` first → accepts `[1, 4)`. `outer` envelope
overlaps interior → REJECT.

**strictly higher priority** than the interior rule. Same-priority rules
fall through to rule_index order, which is *config-author-controlled*
(authoring discipline shapes the outcome). v0.5.6 ships envelope tier
(200) > interior tier (100) for profile rules; user-config opt-in extends
this with custom values.

### 4.5 Nesting invariant under priority (CORRECTED)

`overlaps_accepted` (pipeline.rs:132) bidirectional. Reads:
```rust
pub(crate) fn overlaps_accepted(spans: &[(usize, usize)], start: usize, end: usize) -> bool {
    let i = spans.partition_point(|&(s, _)| s < start);
    if i > 0 && spans[i - 1].1 > start { return true; }
    if i < spans.len() && spans[i].0 < end { return true; }
    false
}
```

Bu, "candidate span ⊂ accepted span" (nested) ve "candidate span ⊃
accepted span" (envelope-around-accepted) iki durumu da overlap olarak
işaretler. Yani ACCEPT order load-bearing:

- **Önce-envelope ACCEPT** → interior REJECT (envelope rule önce iter eder).
- **Önce-interior ACCEPT** → envelope REJECT (interior priority eşit veya
  yüksekse, envelope kazanmaz — bu yüzden envelope tier 200, interior tier 100).

v0.5.3'te tek priority tier (rule_index ASC) yüzünden interior rule'lar
hep önce iterate ediyordu (lower index); v0.5.6 tier sistemi bu sırayı
data-driven olarak ters çevirir.

## 5. http_status removal — migration recipe (CHANGELOG)

Tüm tayf user'ları için CHANGELOG `[Removed]` section'ında:

```markdown
### Removed

- `http_status` built-in rule. Pattern `(?:^|[\s/:])([1-5]\d{2})\b`
  matched **any** 3-digit number 100-599 preceded by whitespace, `/`, or
  `:` — producing false positives on VLAN IDs, line numbers, port numbers,
  AWS account-ID prefixes, and other unrelated 3-digit literals. The
  built-in fired magenta on these prose 3-digit numbers, which was a
  net negative for most users.

  **Migration recipe (preserves v0.5.5 built-in behavior exactly):**

  \`\`\`toml
  [[rules]]
  name = "http_status"
  pattern = '(?:^|[\s/:])([1-5]\d{2})\b'
  style = { fg = "magenta", bold = true }
  \`\`\`

  This recipe colors the entire match span — including the leading
  `[\s/:]` whitespace/`/`/`:` — just like the removed built-in did.

  **Improved recipe (leading punctuation neutral, FP-audit F-8 fix):**

  \`\`\`toml
  [[rules]]
  name = "http_status"
  pattern = '(?:^|[\s/:])([1-5]\d{2})\b'
  style = {}
  styles = { "1" = { fg = "magenta", bold = true } }
  \`\`\`

  Here the empty top-level `style = {}` leaves non-captured bytes
  (the leading punct) un-styled; `styles."1"` paints only the
  captured 3-digit group. Cosmetically cleaner; matches what the
  built-in *should have* done.

  v0.6+ may ship an opt-in `http` profile that bundles this rule with
  HTTP-domain-specific append_rules (method names, URL paths, etc.).
```

**Schema verification (implementation phase, §9.4):** `apply_user_rules`
validation requires `pattern` AND `style` BOTH present for new rules
(rules where `name` doesn't match a built-in). So `style = {}` (empty
inline table, parses as `UserStyle` with all fields None/false) is the
minimum legal value for a new rule with neutral default coloring.
`user_rule_styles_only_with_empty_top_level_style_compiles` smoke-tests
this. The "improved recipe" shipped above must pass this test before the
CHANGELOG migration recipe goes public.

## 6. ipv6 pattern body — before / after

Mevcut (src/rules.rs:435):
```regex
(?:[0-9A-Fa-f]{1,4}:){7}[0-9A-Fa-f]{1,4}
| (?:[0-9A-Fa-f]{1,4}:){1,6}:[0-9A-Fa-f]{0,4}
| ::[0-9A-Fa-f]{1,4}
| ::1
```

**Dead-branch tespit (reviewer regex senior I1):** mevcut pattern'in 4.
branch'ı `::1` literal'i, branch 3 `::[hex]{1,4}` tarafından zaten
gölgelenmiş — `1` `[hex]{1,4}` içinde geçerli; branch 3 leftmost-longest
alternation'da `::1`'i match eder; branch 4 hiç çalışmaz. Defensive
addition olarak duruyor ama fonksiyonel olarak no-op.

Yeni (POST-IMPLEMENTATION; Task 2 spec correction):
```regex
::1
| \b(?:[0-9A-Fa-f]{1,4}:){7}[0-9A-Fa-f]{1,4}
| \b[0-9A-Fa-f]{3,4}:(?:[0-9A-Fa-f]{1,4}:){0,5}:[0-9A-Fa-f]{0,4}
| ::[0-9A-Fa-f]{1,4}(?::[0-9A-Fa-f]{1,4}){2,}
```

**Spec correction (Task 2 implementer finding):** original spec proposed
`(?:[hex]{1,4}:){1,6}:[hex]{0,4}` for branch 3 and `(?::[hex]{1,4})+`
(≥1 trailing group) for branch 4. Both insufficient against
`serde::de::Deserialize`:
- Spec said "trailing tail at `D` non-hex" — but `D` IS hex (0xD = 13).
  Branch 3 matched `de::D` (`de:` as first group, `:D` as trailing).
- Branch 4 `(:hex)+` matched `::de:D` (2 hex segments total).

Implementer applied conservative corrections (strictly tighter than spec,
zero positive-case regression):
- Branch 2/3: prefix `\b` word-boundary + `[hex]{3,4}` minimum leading
  group length on branch 3 (3-4 hex chars; blocks 2-char Rust idents
  like `de`, `bc`).
- Branch 4: `(:hex){2,}` instead of `+` (requires ≥2 trailing groups
  = 3 total hex segments; blocks `::de:D` 2-segment shape).

**Branch ordering ratiocination:** `::1` literal yeni 4. branch'ın `{2,}`
quantifier'ı tarafından ELIMINATE edilir; `::1` standalone match için
literal branch'ın 1. sırada olması zorunlu. Bu noktada mevcut "dead" 4.
branch (v0.5.5'te `::1` LAST branch — branch 3 zaten matchliyordu) artık
load-bearing.

**ReDoS güvenliği (CLAUDE.md §3 mandate):** yeni branch'ın `+` quantifier'ı
non-overlapping prefix-anchored `(?::[hex]{1,4})` üzerinde; her iteration
`:` + 1-4 hex char tüketir. Sibling alternation içermez. Hex quantifier
bounded `{1,4}`. **Linear time, ReDoS-clean.** Verify edildi.

Test coverage gap önceki yokluğunu kapatır: E4 (Rust path FP), E5
(loopback + compressed positive forms).

kabul edilir. Negatif değerler legal. i32 üzerinde `Ord` direct
comparison; overflow yok. Range check yapılmaz — kullanıcının ayağına
sıkma hakkı (örn. `i32::MAX` veya `i32::MIN` legal).

**TOML deserialization corner cases (reviewer Rust senior I4):**
- `priority = 100` → `Some(100)` ✅
- `priority = -100` → `Some(-100)` ✅ (TOML unary-minus prefix)
- `priority = "100"` (string) → `serde::Error` type mismatch → wrapped in
  `Error::Config` with actionable wording
- `priority = 100.5` (float) → `serde::Error` type mismatch → `Error::Config`
- `priority = 99999999999999` (TOML i64 overflow into i32) →
  `serde::Error::out_of_range` → `Error::Config` "priority value
  99999999999999 out of i32 range (i32::MIN..=i32::MAX)"

```markdown
## [0.5.6] - 2026-05-XX

### Added
- **Per-rule overlap-resolution priority (`priority: i32`).** Tier convention:
  - `0`  — built-in rules; user-config rules without explicit `priority`.
  - `100` — profile interior rules (instance_id, region, container_id, pod_name).
  - `200` — profile envelope rules (arn, image_tag).
  - Any i32 — user-config opt-in (`priority = N`, negative legal).

  Higher-priority rules accept their match span before lower-priority rules,
  with overlap detection bidirectional (interior or envelope overlap both
  block). Resolves AWS profile interior-collision issues where envelope
  rules (`arn`, `image_tag`) used to lose to interior built-ins (`uuid`,
  `ipv4`, `region`, `fqdn`).
- `UserRule::priority: Option<i32>` schema field (additive, backward-
  compatible). Themes cannot override priority (rejected with typed
  `ThemeRuleError::StraySchemaField`).
- ipv6 pattern: dedicated `::1` loopback branch and tightened
  `::hex{1,4}(:hex{1,4})+` form for compressed addresses (≥2 hex groups
  required). Negative regression for Rust module paths (`foo::bar::baz`,
  `std::io::Read`, `serde::de::Deserialize`).
- Test coverage for IPv4 invalid octets (256.0.0.0, leading-zero), MAC
  7-pair shape, log_level delimiter contexts, μs Greek-letter duration,
  URL trailing-punct trim across schemes.

### Changed
- **AWS ARN now wins envelope styling over interior IPv4, UUID, region
  matches** (was: interior won, AWS spec was rendered fragmented).
  Profile pin tests `aws_arn_yields_to_interior_region_pattern_v0_5_3_limitation`
  and `docker_image_tag_registry_host_yields_to_fqdn_v0_5_3_limitation`
  renamed to `aws_arn_wins_over_interior_region_pattern` and
  `docker_image_tag_wins_over_registry_host_fqdn` with flipped assertions.
- **Docker `container_id` now wins over the built-in `uuid` rule when a
  UUID's 12 leading hex chars match the container_id shape.** Inside the
  docker profile, container_id (priority 100) iterates before uuid
  (priority 0); accepts its 12-hex span; uuid's 36-char envelope sees
  bidirectional overlap → suppressed. Before v0.5.6, uuid won the
  envelope. Outside the docker profile, uuid behavior is unchanged.
  User-visible: a logged UUID whose first 12 hex chars form a valid
  container_id substring now renders as container_id color (cyan) inside
  `--profile docker`, not uuid color (bright magenta).
- `src/pipeline.rs:35-50` doc-comment block updated for the priority
  contract; "first-match-wins by pattern order" replaced with "highest-
  priority match wins; ties broken by pattern-definition order; overlap
  detection bidirectional".

  \`\`\`toml
  [[rules]]
  name = "http_status"
  pattern = '(?:^|[\s/:])([1-5]\d{2})\b'
  style = {}
  styles = { "1" = { fg = "magenta", bold = true } }
  \`\`\`

  v0.6+ may ship an opt-in `http` profile bundling HTTP-domain rules.

### Fixed
```

## 11. Known limitations — design tradeoffs (Bölüm §11)

### 11.1 Filename single-letter extensions prose collision (C-4)

`FILENAME_EXTENSIONS` listesi single-letter ext'ler içerir (canonical
1-to-1 attribution, regex senior I6):

- `.a` — static library archive
- `.c` — C source
- `.h` — C header
- `.m` — Objective-C source
- `.o` — object file
- `.r` — R script
- `.v` — Verilog source

Tradeoff: prose girdileri ki single-letter ile bitiyor (örn. `a.b.c.d` →
matches `a.b.c`) filename olarak boyanır. Frequency düşük; v0.6+ "path
separator prefix required" tighten için açık. Şu an: ACCEPT, doc.

### 11.2 Design-correct overlap cases (C-5, C-6, C-10, C-11, C-15, C-16)

Bu case'lerde shape gerçekten ambigous ve mevcut davranış yazılım-mühendisi-
sezgisi ile uyumlu:

- `config.json` → filename. Tek bir token, filename yorumu dominant.
- `10s.example.com` → fqdn (envelope). `10s` duration sub-span suppressed
  doğru — fqdn üst-yapı.
- `prose.with.dots.txt` → filename (önek + extension).
- `config.json.tmp` → filename (`config.json` 2-segment, `.tmp` trail).
- `git@github.com:user/repo` → url (SCP-style URL branch).
- `(see https://example.com/x)` → url span includes trailing `)` —
  Wikipedia URL'leri parantez içerir (örn. `Foo_(disambiguation)`); markdown
  link parantezi mis-include küçük tradeoff. v0.7+ per-context trim profile
  konusu.

### 11.3 Domain-specific FPs requiring user-config or future profiles (C-8, C-9)

- **C-8 — Go pkg paths (`pkg.go.dev/foo`):** filename `pkg.go` matches
  ön ek; geri kalan `.dev/foo` colored değil. Go developer terminal'inde
  rahatsız edici. v0.7+ "Go profile" bu üst-yapıyı whitelist'leyebilir
  (filename rule'unu disable + go-pkg-path rule append).
- **C-9 — JWT 3-segment dotted tokens (`eyJhbGc.eyJzdWI.signature`):**
  fqdn pattern yakalar (her segment label-shaped, son segment 9-char TLD-
  legitimate). User-config recipe:
  ```toml
  [[rules]]
  name = "jwt"
  pattern = '\beyJ[A-Za-z0-9_-]+\.[A-Za-z0-9_-]+\.[A-Za-z0-9_-]+\b'
  priority = 50
  style = { fg = "yellow" }
  ```

  **Priority 50 rationale (regex senior I6):** JWT envelope ⊇ fqdn envelope
  at the same span shape. JWT priority 50 > fqdn priority 0 → JWT iterates
  first in DESC sort, accepts envelope; fqdn second, bidirectional overlap
  → REJECTED. This is **envelope-vs-envelope** disambiguation (both rules
  match the same span shape; priority picks which wins). Distinct from
  the **envelope-vs-interior** case (e.g., aws.arn ⊃ ipv4) which needs
  the 200 tier reserved for profile envelope rules.

  The 50 value places JWT firmly above built-in (0) and below profile
  interior (100) — leaves room for user-config rules to use 1-99 as
  "user-defined overrides between built-in and profile-interior tiers".
