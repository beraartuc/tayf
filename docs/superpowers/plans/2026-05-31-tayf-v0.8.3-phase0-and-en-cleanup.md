# tayf v0.8.3 — Phase 0 (measurement) + EN-cleanup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run the measurement-first Phase 0 of the v0.8.3 perf finale — land the deterministic EN-cleanup, spike the H5 no-match fast-lane to read its ceiling, attribute the H6 `apply_rules` cost — and produce a checkpoint decision that scopes the (separately-authored) Phase 1 implementation plan.

**Architecture:** This is the FIRST of two plans (mirrors v0.8.2's spike-then-implementation split). It contains only deterministic work: a comment-only EN rename, a *throwaway* H5 spike (never merged) whose only output is numbers, and a profiler-based H6 attribution. No shipping behavior change lands here except the EN-cleanup. Phase 1 (the actual byte-identical lever implementation, TDD) is authored as **Plan 2** immediately after the §8 checkpoint, once the data picks the winners.

**Tech Stack:** Rust, `regex::bytes` 1.12, `memchr` (direct dep), criterion benches (`pipeline_feed`, `throughput`, `e2e_overhead`), a local sampling profiler (`samply` or macOS Instruments). Spec: [docs/superpowers/specs/2026-05-30-tayf-v0.8.3-apply-rules-and-no-match-fast-lane.md](../specs/2026-05-30-tayf-v0.8.3-apply-rules-and-no-match-fast-lane.md).

**Branch model:**
- `v0.8.3-perf-finale` — the real branch (off `main`). EN-cleanup is its FIRST commit; Plan 2's perf commits follow. FF-merged to `main` at release.
- `v0.8.3-h5-spike` — THROWAWAY scratch branch (off `v0.8.3-perf-finale`). Spike code lives here, is measured, and is **never merged**. Discarded after numbers are recorded.

**Discipline reminders (from spec + memories):**
- **Transcribe numbers verbatim** (feedback-transcribe-measured-numbers): bench → `tee` tmp file → **Read the tmp file** → write into the doc digit-for-digit → verify before commit. NEVER from memory.
- **Trust local `pipeline_feed`/`e2e`** over `throughput.rs` CI-runner deltas (v0.8.2 GOTCHA).
- **Do not background `cargo bench` with a grep-pipe redirect** (0-byte output files); `tee` to a file, foreground.

- [ ] **Step 3: Implement the crude (builtins-only) fast-lane in `feed`'s Ground non-TUI branch**

Replace the existing `else { for (line, trailing_newline) in self.buffer.feed_data_run(run) { ... } }` block (~[pipeline.rs:482-491](../../../src/pipeline.rs#L482)) with the spike. The spike omits the `fast_lane_safe` user-anchor guard because the benches load builtins only (so it is implicitly true):

```rust
} else if self.buffer.is_empty()
    && !self.line_has_sgr
    && !self.line_has_string_payload
    && run.len() <= crate::line_buffer::MAX_BUFFER_BYTES
    && !self.rules.load().set.is_match(run)
{
    // SPIKE (throwaway): no-match fast-lane. Boolean gate only; emit stays
    // byte-identical to the per-line path (verbatim complete-line prefix +
    // buffer the partial tail). NOT for shipping — no fast_lane_safe guard.
    if let Some(last_nl) = memchr::memrchr(b'\n', run) {
        out.write_all(&run[..=last_nl])?;
        let tail = &run[last_nl + 1..];
        if !tail.is_empty() {
            // tail has no '\n' and run <= cap, so this never emits/overflows;
            // it only buffers the partial. (Shippable form handles emits.)
            let _ = self.buffer.feed_data_run(tail);
        }
    } else {
        let _ = self.buffer.feed_data_run(run);
    }
} else {
    for (line, trailing_newline) in self.buffer.feed_data_run(run) {
        self.apply_or_passthrough(&line, out)?;
        if trailing_newline {
            out.write_all(b"\n")?;
        }
    }
}
```
