# tayf v0.3.6 — Deferred Bugfix Patch Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship v0.3.6 — a pure semver patch that closes the v0.3 minor with two surgical bugfixes deferred from v0.3.5: (a) specialize `ThemeRuleErrorKind::CaptureGroupIndexOutOfRange` Display for the `n == 0` edge case, and (b) rename two misnamed `syslog_timestamp_match_renders_one_sgr` tests whose names overstate what their bodies assert.

**Architecture:** No architectural change. Hot path (`apply_rules`, `Compiled.set`, `emit_capture_runs`) untouched. Public API surface byte-identical except for one error variant's Display string content (documented in CHANGELOG). BASELINE.md unchanged — v0.3.6 does not record a new bench row. The pluralization helper (`if n == 1 { "" } else { "s" }`) inside the modified Display branch is preserved byte-identical with two existing regression-guard snapshot tests.

**Tech Stack:** Rust 2021, no new dependencies, no dependency version bumps. Pre-commit gate: `cargo fmt && cargo clippy -- -D warnings && cargo test`.

**Spec reference:** `docs/superpowers/specs/2026-05-24-tayf-v0.3.6-display-fix-and-test-rename.md` (rev2).

### Task 2: Implement Display two-branch specialization

**Files:**
- Modify: `src/error.rs:97-107` (Display arm for `CaptureGroupIndexOutOfRange`)

**Rationale:** TDD green. Specialize the `n == 0` branch to produce a user-actionable message; preserve the `n >= 1` branch byte-identical.

- [ ] **Step 1: Locate the current Display branch**

Expected: one match at line 97 (the Display arm; the variant declaration itself is at line 64).

- [ ] **Step 2: Replace the existing single-branch with the two-branch form**

In `src/error.rs`, change lines 97-107 from:

```rust
Self::CaptureGroupIndexOutOfRange { group, captures_len } => {
    let n = captures_len.saturating_sub(1);
    write!(
        f,
        "styles.\"{}\": rule's regex has {} capture group{} (valid: 1..={})",
        group,
        n,
        if n == 1 { "" } else { "s" },
        n
    )
}
```

…to:

```rust
Self::CaptureGroupIndexOutOfRange { group, captures_len } => {
    let n = captures_len.saturating_sub(1);
    if n == 0 {
        write!(
            f,
            "styles.\"{group}\": rule's regex has no capture groups; styles cannot be set"
        )
    } else {
        write!(
            f,
            "styles.\"{}\": rule's regex has {} capture group{} (valid: 1..={})",
            group,
            n,
            if n == 1 { "" } else { "s" },
            n
        )
    }
}
```

Note: the `n >= 1` branch (the inner `else { write!(...) }`) is **byte-identical** to the original — same format string, same positional args, same pluralization helper. This is intentional and required by the regression contract.
