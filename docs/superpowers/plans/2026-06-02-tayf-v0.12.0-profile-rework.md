# Profile rework (v0.12.0 sub-project C) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Promote the six FP-safe domain regex rules into the built-in catalog (so tayf "just works" without selecting a profile), re-cast profiles as personal switchable presets, and add a first-class per-rule enable/disable toggle.

**Architecture:** A `BuiltinRule.enabled` field (seeded per-rule, the "default-enabled" state) replaces the lossy `retain`-drop disable; the compile merge mutates `enabled` in place and a single final `retain(|r| r.enabled)` runs before regex compilation. The six domain patterns become built-ins at fixed indices 12–17. `config.toml` is the default profile; named disk profiles (`Profile { rules: Vec<UserRule>, theme }`) replace its `[[rules]]` when active. The embedded profile library is deleted; `RuleSource::EmbeddedProfile` becomes `DiskProfile` for disk-profile error routing.

**Tech Stack:** Rust, `regex::bytes`, `serde`/`toml`, `ratatui` (TUI), `arc_swap`.

**Spec:** `docs/superpowers/specs/2026-06-02-tayf-v0.12.0-profile-rework.md` (rev2). Read it before starting.

**Pre-commit gate (EVERY commit):** `cargo fmt --check` && `cargo clippy --all-targets -- -D warnings` && tests. The full `cargo test` hangs locally on `e2e_overhead_smoke` (PTY) — run `cargo test --lib` plus the named integration targets per task instead. No `unwrap`/`expect`/`panic` in library code.

**Direct on `main`** (no feature branch). Working tree is clean at HEAD `b7b4144`.

```rust
/// Phase-1 shape validation for a disk profile: each rule's name must pass
/// [`name_is_valid`] and names must be unique within the profile. New-rule
/// "must have a pattern" + styles-key/range validation happen later in the
/// shared compile path (`apply_user_rules_with_source` →
/// `Compiled::load_with_theme`), routed to `Error::Profile*` with the profile
/// path via `RuleSource::DiskProfile`.
///
/// # Errors
/// Returns [`Error::ProfileValidation`] with at least one [`ProfileRuleError`]
/// when any name is invalid or duplicated.
pub(crate) fn validate_profile(name: &str, source_path: &str, profile: &Profile) -> Result<()> {
    use std::collections::HashSet;
    let mut errors: Vec<ProfileRuleError> = Vec::new();
    let mut seen: HashSet<&str> = HashSet::new();
    for r in &profile.rules {
        if !name_is_valid(&r.name) {
            errors.push(ProfileRuleError {
                rule_name: r.name.clone(),
                kind: ProfileRuleErrorKind::RuleNameInvalid { name: r.name.clone() },
            });
            continue;
        }
        if !seen.insert(r.name.as_str()) {
            errors.push(ProfileRuleError {
                rule_name: r.name.clone(),
                kind: ProfileRuleErrorKind::AppendRuleConflictsWithOther { name: r.name.clone() },
            });
        }
    }
    if let Some(ref theme) = profile.theme {
        if !name_is_valid(theme) {
            errors.push(ProfileRuleError {
                rule_name: "<theme>".to_owned(),
                kind: ProfileRuleErrorKind::ThemeNameInvalid { name: theme.clone() },
            });
        }
    }
    if errors.is_empty() {
        Ok(())
    } else {
        Err(Error::ProfileValidation { profile: name.to_owned(), source_path: source_path.to_owned(), errors })
    }
}
```

pub(crate) fn resolve_active(
