# tayf v0.9.1 — Neon Default Palette Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the built-in default styles (named-ANSI) with a curated 24-bit "Neon" palette, ship a hand-authored light-adapted variant as a selectable theme, preserve the old palette as an opt-in `classic` theme, and harmonize the profile rule colors — all on a fixed default terminal background.

**Architecture:** Built-ins move from named-ANSI `Color` to `Color::Rgb` (Neon, dark-tuned). The `dark` theme stays byte-equal to the built-ins (parity contract). `light` becomes a hand-authored light-adapted Neon that also overrides capture-group sub-colors (fixing a latent washout); it is a palette the user *selects* (via `--theme light` or the existing background detection), NOT an automatic per-pixel conversion of the dark colors. `classic` re-introduces the old ANSI palette. Profile `.toml`s carry a single dark-Neon RGB color each; on a light background the user overrides them in their own config — automatic background-conversion of arbitrary rule colors is explicitly out of scope (it can never be 100% correct). The merge pipeline and theme-validation are **untouched**. Lower-color terminals are handled by the existing `Color::downgrade()`.

**Tech Stack:** Rust, `toml` config, integration tests. No new dependencies. No core-pipeline changes.

**Version:** v0.9.1 (point release). v0.10.0 is reserved for the parallel public-release session.

> ⚠️ **Parallel-session note:** another session targets v0.10.0 (public release). This plan edits `src/rules.rs` (`builtin_rules()` body + a few unit-test assertions), `src/themes.rs` (registry add only), `assets/themes/*`, `assets/profiles/*`. It does **not** touch the merge pipeline or theme validation, so conflict risk is low. Coordinate on `src/rules.rs`/`src/themes.rs` before executing. See [[feedback_parallel_session_scope]].

| Rule(s) | Category | Color |
|---|---|---|
| `container_id`, `instance_id`, `pod_name` | resource id | coral `#ff7a4d` |

> Profile rules are dark-tuned. On a light background, document the one-line config override (e.g. `[[rules]] name="container_id" style={fg="#b3401a"}`). We do NOT auto-convert them — per design decision, automatic background adaptation of arbitrary colors is never 100% correct, so the user updates manually when they change background.

### Classic theme = the pre-v0.9.1 ANSI palette
Exactly today's `dark.toml` / `light.toml` values (named ANSI). Preserves terminal-theme-adaptivity for users who want it.
