# tayf v0.2.1 — Hot Reload Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add config hot reload to tayf v0.2.1. File-system watcher (notify 8.2) + SIGHUP both feed a single `ReloadRequest` channel; an orchestrator thread parses, compiles, and atomically swaps the in-memory `Compiled` rule set behind an `Arc<ArcSwap<Compiled>>`. Pipeline takes a per-line snapshot so reloads never split a line. Parse/compile failures preserve the previous set and emit `warn_msg!` to stderr.

**Architecture:** Six threads at runtime (was 4 in v0.2.0): main, `tayf-output`, `tayf-input`, `tayf-signals` (now also handles SIGHUP), plus two new: `tayf-watch` (notify events → 200ms debounce → channel) and `tayf-reload` (channel → re-load + re-compile + arc-swap store). The single `Receiver<ReloadRequest>` lives in the reload thread. All threads use RAII guards; drop order in `Tayf::run` cascades to clean shutdown.

**Tech Stack:** Rust 2021, `arc-swap = "1.9"` (new dep — wait-free atomic Arc swap), `notify = { version = "8.2", default-features = false, features = ["macos_fsevent"] }` (new dep — cross-platform fs watcher), existing `signal-hook = "0.4"`, `regex 1.12`, `serde + toml 0.9`. Test infra: `tempfile` (already a dev-dep), `portable-pty` 0.9 (already a dev-dep via integration smoke).

**Spec reference:** `docs/superpowers/specs/2026-05-22-tayf-v0.2.1-hot-reload.md`. Section §2 decisions and §8 resolved questions are load-bearing — re-read them before writing code if anything is ambiguous.

**Non-goals (explicit, do not implement):**
- `--no-hot-reload` flag (deferred to v0.3+).
- `TAYF_RELOAD_DEBOUNCE_MS` env var (YAGNI — 200ms fixed).
- `tayf config dump` / TUI status (deferred).
- Inline reload banner in user terminal (`tayf: config reloaded`) — deferred to v0.3 (needs alt-screen aware logic).
- Watcher fallback to polling on inotify-limit-exhausted hosts (notify already has `PollWatcher` opt-in; we don't enable it here).

**Workflow constraint:** Per `~/.claude/projects/-Users-bera-tayf/memory/project_release_workflow.md`: every task's commit gets pushed to `main` only after the pre-commit triad is clean locally; final `v0.2.1` tag is pushed only after CI is fully green on the release commit. **Within this plan, individual tasks do not push; the controller pushes after each successful task and runs CI between tasks.** The release tag is the final controller step (Task 12 in the TodoWrite list, not a plan task).

```rust
/// Spawn `cmd` inside a PTY and return the master plus the child handle so
/// the caller can write to stdin, read from stdout, send signals, and
/// observe exit. Caller is responsible for killing the child on test
/// failure paths (use a guard or `child.kill()` in a Drop).
pub fn spawn_for_interaction(
    cmd: &str,
    args: &[&str],
    size: portable_pty::PtySize,
) -> (Box<dyn portable_pty::MasterPty + Send>, Box<dyn portable_pty::Child + Send + Sync>) {
    let pty_system = portable_pty::native_pty_system();
    let pair = pty_system.openpty(size).expect("openpty");

    let mut builder = portable_pty::CommandBuilder::new(cmd);
    for a in args {
        builder.arg(a);
    }
    let child = pair.slave.spawn_command(builder).expect("spawn");
    drop(pair.slave);

    (pair.master, child)
}
```

```rust
//! Integration tests for signal forwarding.
//!
//! These tests verify the v0.2.0 signal path end-to-end: signals
//! delivered to the tayf process are correctly routed to either the
//! child process group (SIGINT/SIGTERM) or to the PTY master
//! (SIGWINCH) by the signal thread (see src/signals.rs).
//!
//! Adding these tests was a recommendation from the senior code
//! reviewer of the signal-hook 0.4 dependency bump (commit 7da37d0).

#![allow(clippy::expect_used)]

mod common;

use std::thread;
use std::time::Duration;

use portable_pty::PtySize;

#[test]
fn sigwinch_to_tayf_resizes_child_pty() {
    // Spawn tayf running `tput cols` after a small delay so we can
    // observe the resize before the child reads. We use sh -c so the
    // shell reports the post-resize size, not the spawn-time size.
    let tayf = env!("CARGO_BIN_EXE_tayf");
    let (mut master, mut child) = common::spawn_for_interaction(
        tayf,
        &["--shell", "/bin/sh"],
        PtySize { rows: 24, cols: 80, pixel_width: 0, pixel_height: 0 },
    );

    // Give tayf time to fully install the signal handler and spawn the
    // shell. 200ms is generous; on CI macOS we have seen ~80ms latency.
    thread::sleep(Duration::from_millis(200));

    // Resize the master. portable-pty propagates this as TIOCSWINSZ
    // on the master fd, which the kernel translates to a SIGWINCH on
    // the foreground process group of the slave. tayf's signal thread
    // catches the SIGWINCH and re-forwards it via the resizer.
    master
        .resize(PtySize { rows: 50, cols: 132, pixel_width: 0, pixel_height: 0 })
        .expect("resize master");

    // Drive the shell to report its current window size and exit.
    use std::io::Write;
    let mut writer = master.take_writer().expect("take writer");
    writer.write_all(b"stty size; exit\n").expect("write stty");
    drop(writer);

    // Collect stdout until child exit or timeout.
    use std::io::Read;
    let mut reader = master.try_clone_reader().expect("clone reader");
    let mut out = Vec::new();
    let start = std::time::Instant::now();
    let mut buf = [0u8; 4096];
    while start.elapsed() < Duration::from_secs(5) {
        match reader.read(&mut buf) {
            Ok(0) => break,
            Ok(n) => out.extend_from_slice(&buf[..n]),
            Err(_) => break,
        }
        if let Ok(Some(_status)) = child.try_wait() {
            // Drain a final read before breaking.
            if let Ok(n) = reader.read(&mut buf) {
                out.extend_from_slice(&buf[..n]);
            }
            break;
        }
    }
    let _ = child.kill();

    let text = String::from_utf8_lossy(&out);
    // `stty size` prints "rows cols" on a single line.
    assert!(
        text.contains("50 132"),
        "expected '50 132' in stty output after SIGWINCH; got: {text:?}"
    );
}
```

use std::path::Path;
use std::sync::Arc;

use arc_swap::ArcSwap;

use crate::error::Result;
use crate::rules::Compiled;
use crate::terminfo::ColorDepth;

/// Re-load the config from `path` (or rebuild built-ins when `None`),
/// re-compile the rule set at `depth`, and atomically store the new
/// `Arc<Compiled>` into `handle`.
///
/// On failure (parse error, regex compile error, etc.) the previous
/// `Arc<Compiled>` remains in `handle` untouched and the error is
/// returned to the caller.
///
/// # Errors
/// Returns any error surfaced by [`crate::config::load_with`] (with
/// the caller's explicit `path`) or [`crate::rules::Compiled::load`].
pub(crate) fn reload_once(
    handle: &ArcSwap<Compiled>,
    path: Option<&Path>,
    depth: ColorDepth,
) -> Result<()> {
    // Load using the same resolver the initial run used.
    // `config::load` returns `Some((config, path_loaded_from))` when
    // a file was read, or `None` when nothing applies. We pass the
    // explicit path down so the resolver doesn't re-walk XDG fallbacks.
    let loaded = crate::config::load(path)?;
    let cfg = loaded.as_ref().map(|(c, _)| c);
    let path_str = loaded.as_ref().map(|(_, p)| p.display().to_string());

    let compiled = Compiled::load(cfg, path_str.as_deref(), depth)?;
    handle.store(Arc::new(compiled));
    Ok(())
}

use std::path::PathBuf;
use std::sync::mpsc::Receiver;
use std::thread::{self, JoinHandle};

/// Owns the reload thread. Drop joins the thread; the thread exits
/// when its `Receiver` returns `Err` (sender side closed).
pub(crate) struct ReloadOrchestrator {
    handle: Option<JoinHandle<()>>,
}

impl ReloadOrchestrator {
    /// Spawn the orchestrator thread.
    ///
    /// `rules_handle` is shared with `Pipeline` (read side) and is the
    /// target of all `store` operations performed here.
    /// `config_path` is the path resolved at startup; it is re-used on
    /// every reload (we do NOT re-walk XDG fallbacks at runtime —
    /// avoids env-race surprises mid-session).
    pub(crate) fn spawn(
        rules_handle: Arc<ArcSwap<Compiled>>,
        config_path: Option<PathBuf>,
        depth: ColorDepth,
        rx: Receiver<ReloadRequest>,
    ) -> Self {
        // reason: thread::Builder::spawn fails only on OS resource
        // exhaustion. As with the runtime threads, we accept the
        // panic on that path; the TtyGuard's Drop restores the
        // terminal during unwind.
        let handle = thread::Builder::new()
            .name("tayf-reload".into())
            .spawn(move || {
                loop {
                    match rx.recv() {
                        Ok(req) => {
                            // Log the source for diagnostics; the
                            // reload work itself is identical either way.
                            if let Err(e) = reload_once(
                                &rules_handle,
                                config_path.as_deref(),
                                depth,
                            ) {
                                crate::log::warn_msg!(
                                    "config reload failed ({req:?}): {e}; keeping previous rule set"
                                );
                            } else {
                                crate::log::info_msg!(
                                    "config reloaded ({req:?})"
                                );
                            }
                        }
                        Err(_) => break, // sender side closed
                    }
                }
            })
            .expect("reload thread must spawn");
        ReloadOrchestrator { handle: Some(handle) }
    }
}

impl Drop for ReloadOrchestrator {
    fn drop(&mut self) {
        if let Some(h) = self.handle.take() {
            let _ = h.join();
        }
    }
}

//! Config-file watcher abstraction over `notify`.
//!
//! Spawns a debounce thread that coalesces a burst of `notify`
//! events into a single [`crate::reload::ReloadRequest::FileChanged`]
//! per 200 ms quiescent window. The watcher itself runs on its own
//! thread (`tayf-watch`); the debounce loop runs on `tayf-debounce`.
//!
//! See `docs/superpowers/specs/2026-05-22-tayf-v0.2.1-hot-reload.md` §3.1.

use std::path::Path;
use std::sync::mpsc::{self, Sender};
use std::thread::{self, JoinHandle};
use std::time::Duration;

use notify::{RecommendedWatcher, Watcher};

use crate::error::{Error, Result};
use crate::reload::ReloadRequest;

/// Manual debounce quiescence window. 200 ms covers a typical
/// editor save sequence (vim swap → write → rename ≈ 100–150 ms)
/// without making interactive edits feel laggy.
const DEBOUNCE_WINDOW: Duration = Duration::from_millis(200);

/// Owns the watcher and the debounce thread. Drop closes both:
/// the watcher's OS resource (`Drop` on `RecommendedWatcher`) and
/// the debounce thread (channel close → loop exits → join).
pub(crate) struct ConfigWatcher {
    debounce_handle: Option<JoinHandle<()>>,
    // Keep the watcher alive for the lifetime of the struct.
    // notify::RecommendedWatcher is platform-typed via the `Watcher`
    // trait; storing it as the concrete type avoids dyn dispatch.
    _watcher: RecommendedWatcher,
}

impl ConfigWatcher {
    /// Begin watching `path`. Bursts of events are debounced into a
    /// single `ReloadRequest::FileChanged` per quiescent window.
    ///
    /// # Errors
    /// Returns [`Error::Watch`] if notify cannot register the path
    /// (e.g., inotify watch limit exhausted, path does not exist),
    /// or if the debounce thread cannot be spawned.
    pub(crate) fn spawn(
        path: &Path,
        tx: Sender<ReloadRequest>,
    ) -> Result<Self> {
        Self::spawn_with_window(path, tx, DEBOUNCE_WINDOW)
    }

    /// Same as [`spawn`] but with a configurable debounce window.
    /// Test-only — production always uses [`DEBOUNCE_WINDOW`].
    pub(crate) fn spawn_with_window(
        path: &Path,
        tx: Sender<ReloadRequest>,
        window: Duration,
    ) -> Result<Self> {
        let (raw_tx, raw_rx) = mpsc::channel::<notify::Result<notify::Event>>();
        let mut watcher: RecommendedWatcher = notify::recommended_watcher(
            move |res| {
                // Best-effort: if the debounce thread already exited
                // because ConfigWatcher was dropped, just drop the
                // event silently.
                let _ = raw_tx.send(res);
            },
        )
        .map_err(Error::Watch)?;

        watcher
            .watch(path, notify::RecursiveMode::NonRecursive)
            .map_err(Error::Watch)?;

        let debounce_handle = thread::Builder::new()
            .name("tayf-debounce".into())
            .spawn(move || debounce_loop(raw_rx, tx, window))
            .map_err(|e| Error::Watch(notify::Error::io(e)))?;

        Ok(ConfigWatcher {
            debounce_handle: Some(debounce_handle),
            _watcher: watcher,
        })
    }
}

impl Drop for ConfigWatcher {
    fn drop(&mut self) {
        // _watcher Drop releases the OS resource (closes the inotify
        // fd / kqueue). That closes the notify::Event channel from
        // the watcher side, which makes the debounce thread's recv
        // eventually return Disconnected and exit.
        //
        // Note that ordering matters only for promptness — debounce
        // join still finishes even if events arrive in flight.
        if let Some(h) = self.debounce_handle.take() {
            let _ = h.join();
        }
    }
}

/// The debounce loop: collect raw notify events, emit one
/// `ReloadRequest::FileChanged` per quiescent window.
fn debounce_loop(
    raw_rx: mpsc::Receiver<notify::Result<notify::Event>>,
    tx: Sender<ReloadRequest>,
    window: Duration,
) {
    use std::sync::mpsc::RecvTimeoutError;

    let mut pending = false;
    loop {
        let timeout = if pending {
            window
        } else {
            // Long idle — but bounded so that we eventually notice
            // a Disconnected if the watcher dropped without sending
            // any event since spawn.
            Duration::from_secs(60)
        };
        match raw_rx.recv_timeout(timeout) {
            Ok(event_or_err) => {
                // notify delivers `Result<Event>` to the callback.
                // Errors (events_dropped, must_rescan, path_not_found)
                // should still trigger a reload attempt — the watcher
                // typically needs reattention — but the operator
                // deserves a diagnostic when they happen.
                if let Err(e) = event_or_err {
                    crate::log::warn_msg!("watch error: {e}");
                }
                pending = true;
                // Keep draining: any further event within the
                // window will reset the timer (because pending is
                // true, the next recv_timeout uses `window`).
            }
            Err(RecvTimeoutError::Timeout) => {
                if pending {
                    // Quiescent — emit one event.
                    if tx.send(ReloadRequest::FileChanged).is_err() {
                        // Orchestrator dropped; nothing more to do.
                        break;
                    }
                    pending = false;
                }
                // Else: long idle, just keep waiting.
            }
            Err(RecvTimeoutError::Disconnected) => break,
        }
    }
}

## Task 9: Wire watcher + orchestrator into `Tayf::run`

**Files:**
- Modify: `src/lib.rs`

- [ ] **Step 1: Plan the drop order with the error-path deadlock in mind**

The naive shape — declare `_orchestrator` early, then engage tty, then spawn PTY, then spawn signal handler, then spawn watcher — has a **critical bug** flagged by the senior reviewer of this plan:

> If `engage()?`, `PtySession::spawn(&spec)?`, `spawn_handler(...)?`, or `ConfigWatcher::spawn(...)?` returns `Err`, the function unwinds via `?`. Locals drop in reverse-declaration order. `_orchestrator` drops, calling `JoinHandle::join`, which blocks indefinitely because the channel's `reload_tx` (and possibly already-spawned signal/watcher clones) is still alive. The terminal is stuck because TtyGuard's Drop is queued behind the orchestrator's join.

The fix is to declare `_orchestrator` **LAST** — after all fallible setup succeeds. On any `?` returning before that point, `reload_tx` and `reload_rx` are still owned by `Tayf::run`; if they drop unused, no thread was spawned and nothing leaks.

The new declaration order, top to bottom in `Tayf::run`:

1. `rules: Arc<ArcSwap<Compiled>>` — already constructed by Task 3.
2. `(reload_tx, reload_rx) = mpsc::channel()` — both ends still owned locally; no thread reads from `reload_rx` yet.
3. `guard = TtyGuard::engage()?` — fallible. If Err, locals 1–2 drop (no threads spawned, no leak).
4. `session = PtySession::spawn(&spec)?` — fallible. Same property.
5. `(reader, writer, resizer, child) = session.into_parts()?` — fallible.
6. `child_pid = child.pid()` — infallible.
7. `_signal_guard = signals::spawn_handler(resizer, child_pid, Some(reload_tx.clone()))?` — fallible. On Err, the signal thread did not spawn, the clone we passed in dropped, locals 1–6 drop (guard restores terminal); no orchestrator was spawned.
8. `_watcher = loaded.as_ref().map(...).transpose()?` — fallible. On Err, signal thread is already running (with one `reload_tx` clone); locals drop in reverse: `_signal_guard` joins the signal thread (which exits cleanly when its `Signals::Handle::close()` is called by `SignalGuard::Drop`); then locals 1–6 drop; no orchestrator was spawned.
9. `_orchestrator = ReloadOrchestrator::spawn(Arc::clone(&rules), config_path, depth, reload_rx)` — infallible (spawn panics on OS resource exhaustion, same property as the runtime threads; CLAUDE.md §3 reasoning is unchanged). At this point all the fallible setup is done. The orchestrator now owns `reload_rx`.
10. `drop(reload_tx)` — locally drop the original sender. Clones remain in the signal thread (always) and the watcher thread (when present). When BOTH of those threads exit at shutdown, the orchestrator's `Receiver::recv()` returns `Err(Disconnected)` and the orchestrator exits.
11. `exit_code = runtime::run(reader, writer, child, Arc::clone(&rules), apply_colors)?` — runtime loop. When this returns, the child has exited.
12. `drop(guard)` — the existing explicit drop (already in the file). Restores terminal state immediately.

After the function body ends, reverse-decl drops:

1. `_orchestrator`'s Drop — Receiver Disconnected once `_watcher` and `_signal_guard` have dropped their clones. Join.
2. (nothing else owns the channel; `reload_rx` was moved into `_orchestrator`)
3. `_watcher` — closes the OS watcher (releases inotify fd / FSEvents stream), joins debounce thread, which drops the watcher's `reload_tx` clone.
4. `_signal_guard` — closes the signal-hook handle, joins signal thread, which drops the signal-thread's `reload_tx` clone.

Wait — reverse-decl says drops happen in REVERSE source order. The orchestrator is declared LAST (step 9), so it drops FIRST. Its Drop calls `join()` on the reload thread, but the channel still has live senders in the signal and watcher threads → join would block forever.

That's still broken. The real fix is to drop the senders BEFORE the orchestrator. Two options:

(a) **Manual scope drop**: explicitly `drop(_watcher); drop(_signal_guard);` BEFORE the function returns and before `_orchestrator`'s implicit drop runs.

(b) **Wrap the orchestrator handle in a struct that explicitly signals shutdown**: extend `ReloadOrchestrator` with an internal `Arc<AtomicBool>` "stop flag" or a dedicated shutdown sender that the reload loop checks; then `ReloadOrchestrator::Drop` sets the flag, the loop exits regardless of channel state, and `join()` returns.

(a) is simpler and matches the rest of the codebase's RAII style. Use it:

```rust
// Inside Tayf::run, after runtime::run returns:
let exit_code = runtime::run(reader, writer, child, Arc::clone(&rules), apply_colors)?;

// Explicit ordered shutdown. Drop both senders' owners BEFORE the
// implicit reverse-decl drop hits _orchestrator. Without this, the
// orchestrator's Drop joins a thread whose Receiver still has live
// senders (held by signal thread / watcher thread) -> deadlock.
drop(_watcher);
drop(_signal_guard);
// Both threads have now joined and dropped their reload_tx clones;
// the channel is closed and the orchestrator's recv returns
// Disconnected. The implicit `_orchestrator` Drop at end-of-scope
// joins cleanly.

drop(guard); // existing explicit drop; restores terminal immediately
```

This explicit-shutdown pattern is what makes the layout safe on BOTH the error path (where `_orchestrator` was never declared) and the happy path (where `_watcher` and `_signal_guard` drop before `_orchestrator`).

pub fn spawn_for_interaction_with_env(
    cmd: &str,
    args: &[&str],
    env: &[(&str, &str)],
    size: portable_pty::PtySize,
) -> (Box<dyn portable_pty::MasterPty + Send>, Box<dyn portable_pty::Child + Send + Sync>) {

    for a in args {
        builder.arg(a);
    }
    for (k, v) in env {
        builder.env(k, v);
    }
    let child = pair.slave.spawn_command(builder).expect("spawn");
    drop(pair.slave);

    (pair.master, child)
}

            Err(_) => break,

### Hot reload

As of v0.2.1, tayf watches your config file and reloads it whenever you save:

- Editing `~/.config/tayf/config.toml` (or the file passed to `--config`) takes effect within ~250 ms.
- `pkill -HUP tayf` (or `kill -HUP <pid>`) forces an immediate reload, bypassing the file-watcher debounce. Useful when you switch profiles in a script.
- If your edit produces invalid TOML or a bad regex, tayf keeps the **previous** rule set in effect and logs a warning to stderr (`TAYF_LOG=warn`, the default). Your terminal session is never disrupted by a typo.
- The child shell is never restarted. tayf only swaps its in-process rule set; the PTY, signal handlers, and the running shell are untouched.

If tayf was launched without a config file, the file watcher is not active — but `SIGHUP` still works as a manual reload trigger. If you create a config later, send `SIGHUP` to pick it up.
