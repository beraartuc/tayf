# tayf v0.8.2 Phase 1 — H4a chunk-level spike Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Measure the throughput ceiling of a chunk-level Data-run rewrite of `Pipeline::feed`, via a throwaway spike, so the user checkpoint can fix the Phase 2 scope and N target on data — not guesswork.

**Architecture:** Replace the per-byte `feed` loop with a two-bucket loop: when the ANSI SM is in `Ground`, scan to the next ESC (`0x1b`) and process the Data run as a single slice (line buffer feed, or verbatim write in TUI mode); otherwise fall back to the existing per-byte `step` + dispatch for the sequence. The spike is **throwaway** (branch `v0.8.2-spike`, never merged), so it uses the naive `feed_with_overflow` reuse that the spec §5 (C-2/I-3) proved is NOT byte-identical — acceptable here because the bench corpus (short lines, no >64KB runs, no adversarial anchors) does not exercise those divergences, and we are measuring a common-case ceiling, not shipping.

**Tech Stack:** Rust, `criterion` (pipeline_feed micro-bench), the in-tree `portable_pty` e2e harness. No new dependencies (the spike uses `slice::iter().position`, not the `memchr` crate — the memchr ROI is a separate checkpoint question, spec §10).

**This plan is PHASE 1 ONLY.** Phase 2 (the byte-identical, TDD'd, security-gated shipping implementation) is planned in a separate document AFTER the checkpoint, because its scope (H4a / +H4b / +H2) is data-bound (spec §3, §10).

- [ ] **Step 2: Replace `Pipeline::feed` with the two-bucket spike loop**

In `src/pipeline.rs`, replace the entire current `feed` method (the `for &byte in chunk { ... }` loop, lines 451-481) with:

```rust
    /// SPIKE (v0.8.2 Phase 1, throwaway): chunk-level Data-run feed.
    /// Fast path batches a Ground run up to the next ESC; slow path keeps the
    /// existing per-byte step + dispatch. NAIVE reuse of `feed_with_overflow`
    /// (NOT byte-identical per spec §5 C-2/I-3) — fine for a ceiling measure.
    pub(crate) fn feed<W: Write>(&mut self, chunk: &[u8], out: &mut W) -> std::io::Result<()> {
        let mut i = 0;
        while i < chunk.len() {
            // Fast path: in Ground, the run up to the next ESC is all Data and
            // mutates no SM field (spec §4), so skip per-byte stepping.
            if self.sm.is_ground() {
                let rest = &chunk[i..];
                let run_len = rest.iter().position(|&b| b == 0x1b).unwrap_or(rest.len());
                if run_len > 0 {
                    let run = &rest[..run_len];
                    if self.sm.tui_mode_active() {
                        out.write_all(run)?;
                    } else {
                        let (lines, overflow) = self.buffer.feed_with_overflow(run);
                        if let Some(Error::BufferOverflow { cap }) = overflow {
                            crate::log::warn_msg!("line buffer overflowed; cap={cap}");
                        }
                        for line in lines {
                            self.apply_or_passthrough(&line, out)?;
                        }
                    }
                    i += run_len;
                    continue;
                }
                // run_len == 0 → chunk[i] is ESC; fall through to the slow path.
            }

            // Slow path: existing per-byte logic for one byte.
            let byte = chunk[i];
            if self.sm.tui_mode_active() {
                out.write_all(&[byte])?;
                let event = self.sm.step(byte);
                if matches!(event, crate::ansi::StepEvent::ForceStringTerminate) {
                    out.write_all(b"\x1b\\")?;
                }
                i += 1;
                continue;
            }
            let event = self.sm.step(byte);
            if let crate::ansi::StepEvent::ForceStringTerminate = event {
                out.write_all(b"\x1b\\")?;
                let event = self.sm.step(byte);
                debug_assert!(
                    !matches!(event, crate::ansi::StepEvent::ForceStringTerminate),
                    "ForceStringTerminate must not recur after re-step"
                );
                self.dispatch_classification_event(event, byte, out)?;
                i += 1;
                continue;
            }
            self.dispatch_classification_event(event, byte, out)?;
            i += 1;
        }
        Ok(())
    }
```
(`Error` is already imported at pipeline.rs:30 via `use crate::error::Error;`. `dispatch_classification_event`, `apply_or_passthrough`, `feed_byte_with_overflow` are all left intact — the slow path still uses them for sequences and the ForceStringTerminate re-step.)
