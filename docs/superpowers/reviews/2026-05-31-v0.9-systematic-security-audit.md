## Axis verdicts (full per-agent records summarized; all CLEAN)

### 1. Terminal-state / PTY / signal / process-spawning — CLEAN
Files: `tty_guard.rs`, `signals.rs`, `pty.rs`, `shell.rs`, `runtime.rs`, `terminfo.rs`.
- **R3 panic-abort termios restore — VERIFIED against actual std source.** `Cargo.toml` `[profile.release] panic = "abort"`. Traced `library/std/src/panicking.rs`: the panic hook runs **before** the abort runtime (hook at the documented ordering, abort after), and tayf's hook (`tty_guard.rs:123-133`) does only mutex-lock + `tcsetattr` (no panicking op → the double-panic guard does not pre-empt it). Under abort, `Drop` is skipped (no unwind) so the hook is the **sole** restorer — and it reaches the restore. `PANIC_RESTORE_STATE = None` on Drop prevents stale double-restore. No exit path (normal / `?`-return / thread panic / panic-under-abort) leaves termios unrestored.
- **Signal forwarding — killpg-to-process-group verified.** portable-pty 0.9 runs `libc::setsid()` in the child's `pre_exec` (`unix.rs:257`), so the child is its own process-group leader (`pgid == pid`); `killpg(Pid::from_raw(child_pid), sig)` (`signals.rs:130`) therefore hits the child's group. SIGINT/SIGTERM + SIGHUP arms both confirmed by passing integration tests (incl. the new `integration_signal_int.rs`). Defensive `i32::try_from(pid)` drops rather than wrapping to a wrong target.
- **No shell injection.** `CommandBuilder::new(spec.path)` direct argv[0] (`pty.rs:80`); `--shell`/`$SHELL`/passwd flow as path values, never concatenated into a command string.
- **All 3 `unsafe` blocks sound** with correct `// SAFETY:` comments (terminfo TIOCGWINSZ read-only ioctl on owned fd; runtime master-fd borrow with the poll fd distinct from the dup'd reader/writer fds, owner outlives the borrow).

### 2. Adversarial PTY input (ReDoS / escape-injection / SGR / UTF-8 / memory) — CLEAN
Files: `pipeline.rs`, `ansi.rs`, `line_buffer.rs`, `style.rs`, `rules.rs`. Fuzzed: ansi_sm 2.3M runs, line_buffer 369K, pipeline_feed (empty-rules byte-identity oracle) + regex_compile 77K — **zero crashes, zero artifacts, no OOM, oracle held.**
- 64 KB line-buffer hard cap + flush-on-overflow (never unbounded); `until_overflow >= 1` proven for all reachable states; UTF-8 splits safe (regex::bytes on raw bytes; memchr on `\n` which is never a continuation byte).
- **SGR injection is structurally SGR-only:** `Style::to_sgr` can only emit `\x1b[<numeric;params>m` (params are numeric literals / u8-bounded), with the precise reset `\x1b[0m` — it is *structurally incapable* of emitting a wide-effect code. The audit-gate unit test backs a property that holds by construction.
- The ONLY synthetic non-input byte tayf emits (besides SGR-around-matches) is the 2-byte 7-bit ST `\x1b\\` on `ForceStringTerminate` (4 KiB `SEQUENCE_BYTES_CAP` overflow). Verified at both emit sites (`pipeline.rs:506`/`:513`); payload bytes preserved, exactly one ST, nothing wider.
- OSC/DCS/PM/APC payloads treated as **opaque** (terminators located, never interpreted — no OSC-52/2/8/133 action).
- `regex` 1.12 linear-time, no look-around/backtracking; **every** user/TUI compile path enforces both `size_limit` + `dfa_size_limit` = 1 MiB (`rules.rs:1045-1047`, `config_tui/compile_pending.rs:214-216`, `events.rs:1186-1188`, `fuzz_compile_pattern`). The one bare `Regex::new` on a user pattern (`rules.rs:1160`) is only reachable AFTER the size-limited compile already succeeded for the same pattern.

### 3. Config / filesystem / credentials / logging — CLEAN
Files: `config.rs`, `config_tui/*`, `themes.rs`, `profiles.rs`, `log.rs`, `reload.rs`.
- All three disk-load paths (config + themes + profiles) share the identical `canonicalize(file).starts_with(canonicalize(base))` + `is_file` + 1 MiB `read_capped` gate; theme/profile names pass `name_is_valid` (ASCII alnum + `-`/`_`, no `.`/separators) blocking `../` traversal.
- **No string-exec from config:** grep for `Command`/`exec`/`sh -c`/`eval`/`system` reachable from config parsing = zero. Schema is declarative with `#[serde(deny_unknown_fields)]`.
- Config TUI save: atomic tmpfile + `O_EXCL` (`create_new`) + `sync_all` + atomic rename + parent-dir sync + mode-preservation + two-layer `lstat`(no-follow)-symlink-reject + canonical-parent-`starts_with(root)` destination gate. A malicious symlink at the write target is rejected before the O_EXCL tmpfile is created.
- Logging is `TAYF_LOG`-gated, **stderr-only**; PTY stream bytes are written exclusively to process stdout, never to a file. `reload.log` is metadata-only (timestamps/status); banner → `/dev/tty`.

### 4. Supply-chain / CI / release infrastructure (mostly NEW in v0.9) — CLEAN
Files: `Cargo.toml`/`.lock`, `deny.toml`, `ci.yml`, `release.yml`, `SECURITY.md`, `fuzz/`, `build.rs`. Ran: `cargo deny check` (advisories/bans/licenses/sources ok), `cargo audit` (0 vulns / 0 unmaintained / 0 yanked over 272 deps), `cargo publish --dry-run --locked` (84 files, verify-compile passed), `cargo tree --duplicates`, 5 gh-api SHA spot-checks.
- **release.yml cannot publish or leak a secret:** `workflow_dispatch`-only, zero `secrets.*`, only `cargo publish --dry-run`, no `gh release create`, minimal permissions (`contents: read`, `id-token: write`, `attestations: write`). No script-injection surface (matrix values are hardcoded constants; the only `github.event.*` use is `contains(...) → boolean → env var`, the safe pattern). `attest-build-provenance@v3` = SLSA Build L2 keyless (verified).
- **deny.toml:** correct ≥0.18.2 schema (`unmaintained`/`unsound` as scope selectors `all`; `yanked = "deny"`; `ignore = []`); every `skip`/`skip-tree` is real + load-bearing (proven by removal); no real advisory silently suppressed.
- **All actions SHA-pinned** (5 SHAs resolve to their commented tags); dtolnay/rust-toolchain pinned to master SHA + explicit `toolchain:` input; cargo tools version-pinned (cargo-deny 0.19.8 ≥ 0.18.2).
- **fuzz/ fully isolated:** its own workspace, `publish = false`, no libfuzzer-sys in the tayf dep tree; `#[cfg(fuzzing)]` items absent from normal/publish builds (`cargo metadata` exposes 0 features for tayf).

### 5. Red-team (adversarial-PTY) — ZERO violations
Every named scenario empirically exercised and held:
- **Terminal-query response injection** (DA1/DA2/DECRQSS/CPR, hostile OSC-11): tayf passes queries through byte-identically, never synthesizes a reply; bg-detect is startup-only (`lib.rs:222`, queries `/dev/tty` once before the I/O loop) and provably **unreachable** from the PTY output stream.
- **Bracketed-paste / alt-screen mode confusion** (unbalanced toggles split across chunk boundaries at strides 1..N): no SM corruption, no byte loss/duplication.
- **OSC opaqueness** (OSC-52/2/8/9, embedded newline/ESC, over-cap): byte-identical passthrough; over-cap injects exactly one `\x1b\\` ST and nothing wider.
- **Config-symlink TOCTOU / cross-user escape:** symlink-out config/theme rejected (exit 64); `../` traversal blocked by `name_is_valid`; whole-base redirect is the documented single-user opt-in. No cross-user escape.
- **Free-for-all:** BEL/ESC flood bounded; 5 MiB no-newline line flushes with zero byte loss; UTF-8 torture byte-identical; pathological user regex `([01]{4,1000000})+` rejected at startup (1 MiB limit); linear scan (3 MB in ~5.8 ms); 4 fuzz targets clean.
- The `security-review` skill identification pass independently confirmed **no high-confidence exploitable vulnerability** newly introduced (the src changes are `#[cfg(fuzzing)]`-gated to zero shipped surface or comment-only; CI/config changes carry no untrusted-input attack path).

## Phase B byproduct (recorded for the cycle): a real packaging bug caught

The v0.9 dry-run release pipeline (`cargo publish --dry-run`) surfaced a latent, ship-blocking bug: `assets/profiles/*.toml` were missing from `Cargo.toml`'s `include` list, yet `src/profiles.rs` embeds them via `include_str!` at compile time. A crate published to crates.io would have **failed to compile for every downstream user.** Fixed in `9da0c0b`; a full embed-sweep confirmed profiles was the only uncovered family (themes were already included). This validates building (and dry-running) the release pipeline in v0.9, before the v1.0 public flip.

## Informational notes (🔵) and dispositions

All informational; none change the CLEAN verdict. Triaged:

1. **Signal teardown reap→join `killpg` window** (terminal + red-team).** A theoretical sub-ms TOCTOU exists: `child.wait()` reaps the child before `drop(signal_guard)` stops the signal thread, so a signal in that window calls `killpg` on a just-reaped pgid. **Benign:** `killpg` on an empty group returns `ESRCH` (swallowed by `let _`); mis-targeting requires full pgid recycling to an unrelated `setsid` group-leader within a sub-ms window and is **not attacker-controllable from the PTY output stream** (tayf's actual threat surface). This is the standard race every PTY wrapper (tmux/script/sudo) accepts; closable only with Linux `pidfd`. **Disposition: ACKNOWLEDGED, no code change** — recorded here per the red-team's recommendation that the v0.9 threat-model doc note it explicitly.
2. **Stale `fancy-regex 0.11.0` orphan in Cargo.lock** (adversarial). Present as a lock stanza but **NOT reachable** (`cargo tree -i` shows no edge); never compiled; no backtracking engine ever on a user-pattern path; `cargo deny`/`cargo audit` both pass. The resolved dependency graph (and thus the cargo-cyclonedx SBOM, which is graph-based) does not include it. **Disposition: DEFER** — cosmetic lock-text noise; will prune on the next natural lock-rewriting op. Not touched in v0.9 to avoid churning the audited/deny-checked lock right before release.
3. **`__bench__` is `#[doc(hidden)]` but not `#[cfg]`-gated** (adversarial). Ships in publish builds (pre-existing v0.8 design — intentional always-on thin wrappers over `pub(crate)` internals per the v0.5.3 convention; behavior-neutral, no adversarial-input reachability). **Disposition: DEFER** — deliberate existing pattern; gating it would require gating its bench/test consumers (scope-creep, not a v0.9 concern).
4. **`integration_signals.rs` (SIGWINCH) lacks `TAYF_DISABLE_BG_DETECT` in its spawned env** (terminal). Relies on CI's global env; hangs on local runs without it. Pre-existing, test-only, passes in CI. **Disposition: DEFER** (carryover candidate) — pre-existing test-hygiene, out of v0.9 scope.
5. **Pre-release version state** (supply-chain). `Cargo.toml version = 0.8.3` while the branch targets 0.9 and SECURITY.md references 0.9.x; CHANGELOG `[0.9.0]` documents only the MSRV bump so far. **Disposition: HANDLED in Phase D** (version bump + full CHANGELOG at release, per the project release workflow).
